# فصل 91 - Session

در فصل قبل با **Cookie** آشنا شدیم و یاد گرفتیم که چگونه اطلاعات کوچکی را داخل مرورگر کاربر ذخیره کنیم.

اما یک سؤال مهم وجود دارد:

اگر بخواهیم اطلاعات حساس کاربران را ذخیره کنیم چه؟

مثلاً:

* اطلاعات ورود کاربر
* سطح دسترسی
* سبد خرید
* اطلاعات پرداخت
* داده‌های حساس

آیا باید همه این اطلاعات داخل Cookie ذخیره شوند؟

قطعاً خیر.

راه‌حل مناسب، استفاده از **Session** است.

Session یکی از مهم‌ترین مفاهیم توسعه Backend است و تقریباً تمام وب‌سایت‌های بزرگ از آن استفاده می‌کنند.

در این فصل با Session، نحوه کار آن، تفاوتش با Cookie، پیاده‌سازی آن در Node.js و Express و نکات امنیتی آشنا می‌شویم.

---

# Session چیست؟

Session روشی برای نگهداری اطلاعات کاربران **در سمت سرور** است.

برخلاف Cookie که اطلاعات داخل مرورگر ذخیره می‌شوند، در Session اطلاعات روی سرور قرار دارند.

مرورگر فقط یک شناسه (Session ID) را نگهداری می‌کند.

---

# چرا Session ایجاد شد؟

فرض کنید کاربر وارد سایت می‌شود.

اگر اطلاعات ورود داخل مرورگر ذخیره شود:

```text
Browser

↓

username
password
role
permissions
```

امنیت بسیار پایین خواهد بود.

اما با Session:

```text
Browser

↓

Session ID
```

و اطلاعات واقعی:

```text
Server

↓

User Data
Permissions
Role
Shopping Cart
```

# Session ID چیست؟

Session ID یک شناسه تصادفی است.

مثلاً:

```text
ab38cd9ef12873a9d123ef90
```

این مقدار هیچ اطلاعاتی درباره کاربر ندارد.

فقط برای پیدا کردن Session استفاده می‌شود.

---

# مثال ساده

کاربر Login می‌کند.

سرور:

```text
Session:

ID = xyz123

User:

username = Ali

role = admin
```

مرورگر فقط:

```text
Cookie:

connect.sid=xyz123
```

را ذخیره می‌کند.

# Session کجا ذخیره می‌شود؟

مثلاً:

* حافظه (Memory)
* فایل
* Redis
* Database

معروف‌ترین پکیج:

---

# راه‌اندازی

```javascript
const express = require("express");
const session = require("express-session");

const app = express();

app.use(session({

    secret: "my-secret-key",

    resave: false,

    saveUninitialized: false

}));

app.listen(3000);
```

---

# secret چیست؟

برای امضای Session Cookie استفاده می‌شود.

```javascript
secret: "my-secret-key"
```

در پروژه واقعی:

* باید طولانی باشد.
* تصادفی باشد.
* داخل فایل `.env` ذخیره شود.

---

# ساخت Session

```javascript
app.get("/login", (req, res) => {
```

# بررسی ورود کاربر

```javascript

    if (!req.session.user) {

        return res.status(401).send("Unauthorized");

    }
```

---

# Session Regeneration

بعد از Login بهتر است Session جدید ساخته شود.

```javascript
req.session.regenerate((err) => {

    if (err) {

        return res.status(500).send("Error");

    }

    req.session.user = {

        id: 1,

        username: "Ali"

    };

    res.send("Logged In");

});
```

این کار احتمال حملات Session Fixation را کاهش می‌دهد.

---

# Session و Logout

```javascript
req.session.destroy(() => {

    res.clearCookie("connect.sid");

    res.send("Logout");

});
```

# تفاوت Cookie و Session

| Cookie                  | Session                       |
| ----------------------- | ----------------------------- |
| سمت مرورگر              | سمت سرور                      |
| ظرفیت حدود ۴KB          | محدودیت وابسته به فضای سرور   |
| اطلاعات قابل مشاهده است | اطلاعات روی سرور ذخیره می‌شوند |
| امنیت کمتر              | امنیت بیشتر                   |
| مناسب تنظیمات کوچک      | مناسب اطلاعات حساس            |

# Session یا JWT؟

Session مناسب است برای:

* پنل مدیریت
* سیستم‌های سنتی
* برنامه‌های Server-Rendered
* پروژه‌هایی که امکان باطل کردن نشست‌ها اهمیت دارد

JWT مناسب است برای:

* REST API
* Microservices
* Mobile Application
* سیستم‌های Stateless

هر دو ابزارهای قدرتمندی هستند و انتخاب آن‌ها به معماری پروژه بستگی دارد.

* ذخیره وضعیت کاربر
* مراحل چندمرحله‌ای فرم‌ها
* سطح دسترسی کاربران

# اشتباهات رایج

### استفاده از MemoryStore در Production

MemoryStore فقط برای توسعه مناسب است و با Restart شدن سرور، تمام Sessionها از بین می‌روند.

---

### قرار دادن اطلاعات بسیار زیاد در Session

Session محل ذخیره فایل‌ها یا داده‌های حجیم نیست. فقط اطلاعات ضروری را ذخیره کنید.

---

### عدم استفاده از HttpOnly

اگر Session Cookie دارای `HttpOnly` نباشد، در برابر حملات XSS آسیب‌پذیرتر خواهد بود.

---

### استفاده از Secret ضعیف

رشته‌های ساده مانند `"123456"` یا `"secret"` امنیت کافی ندارند.

---

### فراموش کردن حذف Session هنگام Logout

اگر فقط Cookie حذف شود ولی Session روی سرور باقی بماند، منابع سرور بی‌دلیل اشغال خواهند شد.

---

# نکات حرفه‌ای

* در محیط Production از Redis یا Storeهای پایدار استفاده کنید.
* مقدار `secret` را در فایل `.env` نگهداری کنید.
* بعد از ورود موفق، Session را با `regenerate()` بازسازی کنید.
* هنگام خروج کاربر، هم Session را حذف کنید و هم Cookie را پاک کنید.
* برای Session Cookie از `HttpOnly`، `Secure` و `SameSite` استفاده کنید.
* فقط شناسه کاربر و اطلاعات ضروری را داخل Session ذخیره کنید.

## اهداف آموزشی

پس از پایان این پروژه، خواهید توانست:

* مفهوم Session و تفاوت آن با Cookie را درک کنید.
* `express-session` را در پروژه‌های Express راه‌اندازی کنید.
* اطلاعات کاربران را در Session ذخیره و مدیریت کنید.
* دسترسی به مسیرهای محافظت‌شده را بر اساس Session کنترل کنید.
* Session را به‌صورت امن ایجاد، بازسازی (Regenerate) و حذف کنید.
* برای استفاده از Session در پروژه‌های واقعی و اتصال آن به Storeهایی مانند Redis آماده شوید.
