# فصل 83 - Routing

## Routing چیست؟

در فصل قبل اولین Web Server خود را ساختیم.

اما یک مشکل وجود داشت.

اگر کاربر وارد آدرس‌های مختلف شود، سرور باید پاسخ‌های متفاوتی ارسال کند.

مثلاً:

```text
GET /
```

صفحه اصلی

---

```text
GET /about
```

صفحه درباره ما

---

```text
GET /users
```

لیست کاربران

---

تصمیم‌گیری درباره اینکه هر آدرس (URL) به کدام بخش از برنامه هدایت شود، **Routing** نام دارد.

---

# Route چیست؟

هر ترکیب از:

* URL
* HTTP Method

یک **Route** نامیده می‌شود.

مثلاً:

```text

```

یک Route است.

---

```text

```

یک Route دیگر است.

فرض کنید فروشگاه اینترنتی داریم.

# ساده‌ترین Routing

در Node.js می‌توان با استفاده از شرط‌ها Routeها را مدیریت کرد.

```javascript
const http = require("http");

const server = http.createServer((req, res) => {

    if (req.url === "/") {

        return res.end("Home");

    }

    if (req.url === "/about") {

        return res.end("About");

    }

    res.statusCode = 404;

    res.end("Not Found");

});

server.listen(3000);
```

---

# بررسی Method

تنها بررسی URL کافی نیست.

این دو درخواست متفاوت هستند:

```text
GET /users
```

---

```text
POST /users
```

پس باید Method نیز بررسی شود.

```javascript
if (req.method === "GET" && req.url === "/users") {

    res.end("Users");

}
```

---

# چند Route

```javascript
const http = require("http");

const server = http.createServer((req, res) => {

    if (req.method === "GET" && req.url === "/") {

        return res.end("Home");

    }

    if (req.method === "GET" && req.url === "/about") {

        return res.end("About");

    }

    if (req.method === "GET" && req.url === "/users") {

        return res.end("Users");

    }

    res.statusCode = 404;

    res.end("Not Found");

});

server.listen(3000);
```

# Route Parameter چیست؟

گاهی بخشی از URL متغیر است.

مثلاً:

```text
/users/10
```

عدد ۱۰ شناسه کاربر است.

به آن:

> Route Parameter

گفته می‌شود.

---

# استخراج Route Parameter

در ماژول `http` این کار به‌صورت دستی انجام می‌شود.

```javascript
const id = req.url.split("/")[2];

console.log(id);
```

اگر آدرس باشد:

```text
/users/25
```

خروجی:

```text
25
```

---

# Query Parameter

گاهی اطلاعات در انتهای URL قرار می‌گیرند.

```text
/users?page=2
```

یا

```text
/products?category=laptop
```

این قسمت‌ها Route نیستند.

به آن‌ها Query Parameter گفته می‌شود.

---

# خواندن Query

با استفاده از کلاس URL:

```javascript
const url = new URL(req.url, "http://localhost");

console.log(url.searchParams.get("page"));
```

---

اگر درخواست باشد:

```text
/users?page=3
```

خروجی:

```text
3
```

---

# مسیر پیش‌فرض

اگر هیچ Routeای پیدا نشود:

```javascript
res.statusCode = 404;

res.end("Not Found");
```

---

# استفاده از switch

به جای شرط‌های زیاد:

```javascript
switch (req.url) {

    case "/":

        res.end("Home");

        break;

    case "/about":

        res.end("About");

        break;

    default:

        res.statusCode = 404;

        res.end("Not Found");

}
```

# ساخت Routeهای جداگانه

در پروژه‌های بزرگ نباید تمام Routeها داخل یک فایل باشند.

مثلاً:

```text
routes/

    users.js

    products.js

    auth.js
```

هر فایل مسئول Routeهای مربوط به خودش است.

---

# ترتیب بررسی Routeها

فرض کنید:

```text
/users
```

و

```text
/users/10
```

وجود داشته باشند.

ابتدا Routeهای دقیق‌تر بررسی شوند تا مسیر اشتباه انتخاب نشود.

---

# Routeهای ثابت و پویا

Route ثابت:

```text
/about
```

---

Route پویا:

```text
/users/:id
```

در Express این مسیر به شکل بالا تعریف می‌شود، اما در ماژول `http` باید این رفتار را به‌صورت دستی پیاده‌سازی کنیم.

---

# Routing در فریمورک‌ها

در Node.js معمولاً Routing توسط فریمورک انجام می‌شود.

مثلاً در Express:

```javascript
app.get("/users", handler);

app.post("/users", handler);
```

اما قبل از یادگیری Express، باید منطق Routing را به‌خوبی درک کنیم.

---

# مزایای Routing

* سازمان‌دهی بهتر پروژه
* خوانایی بیشتر کد
* توسعه آسان‌تر
* مدیریت ساده‌تر درخواست‌ها
* جداسازی مسئولیت‌ها

---

# محدودیت Routing دستی

* تعداد زیاد شرط‌ها
* نگهداری دشوار
* افزایش احتمال خطا
* مناسب نبودن برای پروژه‌های بزرگ

به همین دلیل در پروژه‌های واقعی از Routerهای فریمورک‌ها استفاده می‌شود.

---

# اشتباهات رایج

### ۱- بررسی نکردن Method

اشتباه:

```javascript
if (req.url === "/users") {

}
```

درست:

```javascript
if (req.method === "GET" && req.url === "/users") {

}
```

---

### ۲- فراموش کردن Route پیش‌فرض

همیشه باید پاسخ 404 وجود داشته باشد.

---

### ۳- نوشتن تمام Routeها در یک فایل

این کار باعث بزرگ شدن فایل و سخت شدن نگهداری پروژه می‌شود.

---

### ۴- استخراج اشتباه Route Parameter

قبل از استفاده از `split()` ساختار URL را بررسی کنید تا از خطا جلوگیری شود.

---

### ۵- مخلوط کردن منطق Route و منطق برنامه

Route فقط باید درخواست را به بخش مناسب هدایت کند. پردازش اصلی بهتر است در توابع یا فایل‌های جداگانه انجام شود.

---

# نکات حرفه‌ای

* مسیرها را با اسم‌های واضح و مبتنی بر Resource طراحی کنید.
* از اسم جمع برای Resourceها استفاده کنید؛ مانند `/users` و `/products`.
* Routeها را بر اساس دامنه کاری در فایل‌های جداگانه قرار دهید.
* پاسخ‌های 404 و 405 (Method Not Allowed) را مدیریت کنید.
* از ساختار یکسان برای نام‌گذاری Routeها در کل پروژه استفاده کنید.
* در پروژه‌های بزرگ از Routerهای داخلی فریمورک‌ها مانند Express یا Fastify استفاده کنید.
