# فصل 87 - Authentication

## Authentication چیست؟

فرض کنید یک وب‌سایت فروشگاهی داریم.

هر کسی می‌تواند صفحه محصولات را مشاهده کند، اما فقط کاربران واردشده (Login کرده) می‌توانند:

**سرور چگونه تشخیص می‌دهد درخواست واقعاً توسط همان کاربر ارسال شده است؟**

# Authentication با Middleware

در Express معمولاً Authentication داخل Middleware انجام می‌شود.

```javascript
function auth(req, res, next) {

    const token = req.headers.authorization;

    if (!token) {

        return res.status(401).send("Unauthorized");

    }

    next();

}
```

# اشتباهات رایج

### ۱- ذخیره رمز عبور به‌صورت ساده

اشتباه:

```text
123456
```

همیشه از Hash استفاده کنید.

---

### ۲- قرار دادن رمز عبور داخل JWT

Payload باید فقط اطلاعات ضروری را نگهداری کند.

---

### ۳- استفاده از Secret Key ضعیف

کلید امضای JWT باید طولانی، تصادفی و محرمانه باشد و در متغیرهای محیطی (`.env`) ذخیره شود.

---

### ۴- استفاده از Token بدون تاریخ انقضا

تمام Tokenها باید زمان انقضا داشته باشند.

---

### ۵- اعتماد به اطلاعات ارسال‌شده توسط کاربر

همیشه Token را در سرور اعتبارسنجی کنید.

---

### ۶- ارسال Token از طریق URL

اشتباه:

```text
/users?token=...
```

از Header یا Cookie استفاده کنید.

---

### ۷- فراموش کردن استفاده از HTTPS

بدون HTTPS امکان شنود اطلاعات در مسیر ارتباط وجود دارد.

---

# نکات حرفه‌ای

* از `bcrypt` یا `argon2` برای Hash کردن رمز عبور استفاده کنید.
* Secret Key را داخل فایل `.env` نگهداری کنید.
* Access Token را کوتاه‌مدت و Refresh Token را بلندمدت در نظر بگیرید.
* از HttpOnly Cookie برای نگهداری Token در برنامه‌های وب استفاده کنید.
* قبل از اجرای Controller، Authentication را در Middleware انجام دهید.
* اطلاعات حساس را هرگز داخل JWT قرار ندهید.
* تمام مسیرهای حساس را با Middleware محافظت کنید.
* برای هر Login موفق، زمان و IP کاربر را ثبت کنید.
* در صورت چندین تلاش ناموفق ورود، محدودیت (Rate Limiting) اعمال کنید.

# پاسخ تشریحی

## پاسخ تمرین ۱

Authentication برای شناسایی هویت کاربر است، در حالی که Authorization مشخص می‌کند کاربر پس از احراز هویت به چه منابع یا عملیاتی دسترسی دارد.

---

## پاسخ تمرین ۲

* Session Authentication
* Token Authentication
* JWT Authentication

---

## پاسخ تمرین ۳

```javascript
function auth(req, res, next) {

    const authHeader = req.headers.authorization;

    if (!authHeader) {

        return res.status(401).send("Unauthorized");

    }

    next();

}
```

---

## پاسخ تمرین ۴

```javascript
const jwt = require("jsonwebtoken");

const token = jwt.sign(

    {

        id: 1

    },

    process.env.JWT_SECRET,

    {

        expiresIn: "1h"

    }

);

console.log(token);
```

---

## پاسخ تمرین ۵

```javascript
const bcrypt = require("bcrypt");

const password = "password123";

const hash = await bcrypt.hash(password, 10);

const isValid = await bcrypt.compare(password, hash);

console.log(isValid);
```

# مینی‌پروژه

## سیستم احراز هویت کاربران (User Authentication System)

### هدف

پیاده‌سازی یک سیستم Authentication کامل با استفاده از Express، JWT و bcrypt برای مدیریت ورود کاربران.

### امکانات

* ثبت‌نام کاربر جدید
* ورود کاربران با ایمیل و رمز عبور
* Hash کردن رمز عبور با `bcrypt`
* تولید Access Token با `jsonwebtoken`
* Middleware بررسی اعتبار Token
* محافظت از Routeهای خصوصی
* دریافت اطلاعات کاربر واردشده
* خروج از حساب کاربری
* مدیریت خطاهای احراز هویت
* پاسخ‌های JSON استاندارد
