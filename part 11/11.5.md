# فصل 86 - Validation

## Validation چیست؟

فرض کنید کاربری قصد دارد یک حساب کاربری ایجاد کند.

اطلاعات زیر را ارسال می‌کند:

```json
{
    "name": "Ali",
    "email": "ali@example.com",
    "password": "123456"
}
```

اما اگر اطلاعات به این شکل باشند چه؟

```json
{
    "name": "",
    "email": "abc",
    "password": "12"
}
```

یا حتی:

```json
{
    "name": 123,
    "email": true,
    "password": null
}
```

آیا باید این اطلاعات در پایگاه داده ذخیره شوند؟

قطعاً خیر.

قبل از پردازش یا ذخیره هر داده‌ای باید مطمئن شویم که اطلاعات **صحیح، کامل و معتبر** هستند.

به این فرآیند:

> **Validation**

گفته می‌شود.

---

# Validation چیست؟

Validation یعنی بررسی کنیم داده‌های ورودی مطابق قوانین تعریف‌شده باشند.

برای مثال:

* مقدار وجود داشته باشد.
* نوع داده صحیح باشد.
* طول متن مناسب باشد.
* ایمیل معتبر باشد.
* شماره تلفن معتبر باشد.
* مقدار عددی در بازه مشخص باشد.

---

# چرا Validation مهم است؟

بدون Validation ممکن است:

* اطلاعات اشتباه ذخیره شوند.
* برنامه خطا دهد.
* امنیت برنامه به خطر بیفتد.
* پایگاه داده نامعتبر شود.
* کاربران تجربه بدی داشته باشند.

---

# Validation در کجا انجام می‌شود؟

در یک پروژه حرفه‌ای معمولاً Validation قبل از اجرای Controller انجام می‌شود.

```text
Client

↓

Request

↓

Validation Middleware

↓

Controller

↓

Model

↓

Database
```

اگر داده معتبر نباشد:

```text
400 Bad Request
```

یا

```text
422 Unprocessable Entity
```

برگردانده می‌شود.

---

# انواع Validation

به طور کلی دو نوع Validation داریم.

## Client Side Validation

در Frontend انجام می‌شود.

مثلاً:

* React
* Vue
* Angular

هدف:

* تجربه بهتر کاربر
* جلوگیری از ارسال درخواست‌های غیرضروری

---

## Server Side Validation

در Backend انجام می‌شود.

این نوع Validation **همیشه ضروری است.**

هرگز نباید فقط به اعتبارسنجی سمت کاربر اعتماد کرد.

---

# مثال ساده

فرض کنید:

```json
{
    "age": 20
}
```

بررسی کنیم:

```javascript
if (typeof age !== "number") {

    return "Invalid";

}
```

---

# Required Validation

بررسی وجود مقدار

```javascript
if (!name) {

    return res.status(400).send("Name is required");

}
```

---

# Type Validation

بررسی نوع داده

```javascript
if (typeof name !== "string") {

    return res.status(400).send("Invalid name");

}
```

---

# Minimum Length

```javascript
if (password.length < 8) {

    return res.status(400).send("Password is too short");

}
```

---

# Maximum Length

```javascript
if (username.length > 30) {

    return res.status(400).send("Username is too long");

}
```

---

# Number Validation

```javascript
if (age < 18) {

    return res.status(400).send("Invalid age");

}
```

---

# Email Validation

معمولاً با Regular Expression انجام می‌شود.

```javascript
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

if (!emailRegex.test(email)) {

    return res.status(400).send("Invalid email");

}
```

---

# Enum Validation

فرض کنید نقش کاربران فقط این موارد باشد:

```javascript
const roles = [

    "admin",

    "user",

    "editor"

];
```

بررسی:

```javascript
if (!roles.includes(role)) {

    return res.status(400).send("Invalid role");

}
```

---

# Array Validation

```javascript
if (!Array.isArray(tags)) {

    return res.status(400).send("Tags must be array");

}
```

---

# Object Validation

```javascript
if (typeof profile !== "object") {

    return res.status(400).send("Invalid profile");

}
```

---

# اعتبارسنجی Body

نمونه درخواست:

```json
{
    "name": "Ali",
    "email": "ali@test.com",
    "password": "12345678"
}
```

همه فیلدها باید بررسی شوند.

---

# اعتبارسنجی Query

```text
/users?page=2
```

بررسی:

```javascript
const page = Number(req.query.page);

if (Number.isNaN(page)) {

    return res.status(400).send("Invalid page");

}
```

---

# اعتبارسنجی Route Parameter

```text
/users/25
```

بررسی:

```javascript
const id = Number(req.params.id);

if (Number.isNaN(id)) {

    return res.status(400).send("Invalid id");

}
```

---

# Validation با Middleware

بهترین محل Validation:

```text
Request

↓

Validation Middleware

↓

Controller
```

نمونه:

```javascript
function validateUser(req, res, next) {

    if (!req.body.name) {

        return res.status(400).send("Name required");

    }

    next();

}
```

---

# Validation با Joi

یکی از محبوب‌ترین کتابخانه‌ها:

```text
Joi
```

نمونه:

```javascript
const schema = Joi.object({

    name: Joi.string().required(),

    age: Joi.number().min(18)

});
```

---

# Validation با Zod

کتابخانه مدرن:

```text
Zod
```

نمونه:

```javascript
const schema = z.object({

    name: z.string(),

    age: z.number()

});
```

---

# پیام خطا

بهتر است پیام‌ها واضح باشند.

نامناسب:

```text
Error
```

مناسب:

```text
Email is required.
```

یا

```text
Password must be at least 8 characters.
```

---

# ساختار پاسخ خطا

نمونه:

```json
{
    "success": false,
    "message": "Validation Failed",
    "errors": [
        {
            "field": "email",
            "message": "Invalid email"
        }
    ]
}
```

---

# اعتبارسنجی و امنیت

Validation اولین خط دفاعی برنامه است.

اما جایگزین موارد زیر نیست:

* Authentication
* Authorization
* SQL Injection Protection
* XSS Protection

همه این موارد باید در کنار Validation استفاده شوند.

---

# مزایای Validation

* جلوگیری از ورود اطلاعات نامعتبر
* افزایش امنیت
* کاهش خطاهای برنامه
* بهبود کیفیت داده‌ها
* تجربه بهتر کاربران
* ساده‌تر شدن عیب‌یابی

---

# اشتباهات رایج

### ۱- اعتماد به Validation سمت کاربر

هر کاربری می‌تواند درخواست HTTP را به‌صورت مستقیم ارسال کند.

همیشه اعتبارسنجی را در Backend نیز انجام دهید.

---

### ۲- استفاده نکردن از Middleware

نوشتن Validation داخل تمام Controllerها باعث تکرار کد می‌شود.

---

### ۳- ارسال پیام‌های خطای نامفهوم

اشتباه:

```text
Error
```

درست:

```text
Password must contain at least 8 characters.
```

---

### ۴- بررسی نکردن نوع داده

حتی اگر مقدار وجود داشته باشد، ممکن است نوع آن اشتباه باشد.

---

### ۵- استفاده از Regular Expressionهای بسیار پیچیده

تا حد امکان از کتابخانه‌های معتبر مانند Joi یا Zod استفاده کنید.

---

### ۶- اعتبارسنجی نکردن Query و Route Parameterها

اعتبارسنجی فقط برای Body نیست؛ پارامترهای مسیر و Query String نیز باید بررسی شوند.

---

# نکات حرفه‌ای

* Validation را در Middleware انجام دهید.
* قوانین اعتبارسنجی را در فایل‌های جداگانه نگهداری کنید.
* از کتابخانه‌هایی مانند Joi یا Zod برای پروژه‌های واقعی استفاده کنید.
* پیام‌های خطا را استاندارد و قابل فهم طراحی کنید.
* تمام ورودی‌های کاربر را بررسی کنید؛ شامل Body، Query، Params و Header.
* از یک ساختار ثابت برای پاسخ‌های خطا استفاده کنید.
* قوانین Validation را در تمام بخش‌های پروژه یکسان نگه دارید.

* email
* password
* age

باشد.

# پاسخ تشریحی

## پاسخ تمرین ۱

```javascript
if (!username) {

    return res.status(400).send("Username is required");

}
```

---

## پاسخ تمرین ۲

```javascript
if (password.length < 8) {

    return res.status(400).send("Password must be at least 8 characters");

}
```

---

## پاسخ تمرین ۳

```javascript
if (typeof age !== "number" || age < 18) {

    return res.status(400).send("Invalid age");

}
```

---

## پاسخ تمرین ۴

```javascript
function validateEmail(req, res, next) {

    if (!req.body.email) {

        return res.status(400).send("Email is required");

    }

    next();

}
```

---

## پاسخ تمرین ۵

نمونه با Joi:

```javascript
const Joi = require("joi");

const schema = Joi.object({

    name: Joi.string().required(),

    email: Joi.string().email().required(),

    password: Joi.string().min(8).required(),

    age: Joi.number().min(18).required()

});
```

نمونه با Zod:

```javascript
import { z } from "zod";

const schema = z.object({

    name: z.string(),

    email: z.string().email(),

    password: z.string().min(8),

    age: z.number().min(18)

});
```

# مینی‌پروژه

## سیستم اعتبارسنجی کاربران (User Validation System)

### هدف

پیاده‌سازی یک سیستم اعتبارسنجی برای API ثبت‌نام و ویرایش کاربران با استفاده از Middleware و یک کتابخانه اعتبارسنجی.

### امکانات

* بررسی وجود تمام فیلدهای ضروری
* اعتبارسنجی ایمیل
* بررسی حداقل و حداکثر طول نام کاربری
* بررسی قدرت رمز عبور
* اعتبارسنجی سن کاربران
* بررسی معتبر بودن نقش کاربر (`admin`، `user` یا `editor`)
* اعتبارسنجی پارامترهای مسیر و Query String
* ارسال پیام‌های خطای استاندارد به‌صورت JSON

### ساختار پیشنهادی پروژه

```text
project/

├── middleware/
│   ├── validateUser.js
│   ├── validateLogin.js
│   └── validateProduct.js
│
├── validators/
│   ├── user.schema.js
│   ├── auth.schema.js
│   └── product.schema.js
│
├── controllers/
├── routes/
└── app.js
```

### قابلیت‌های تکمیلی

* استفاده از Joi یا Zod برای تمام اعتبارسنجی‌ها
* ساخت Middleware عمومی برای اجرای Schemaها
* پشتیبانی از اعتبارسنجی Body، Query، Params و Header
* یکپارچه‌سازی پاسخ‌های خطا
* ترجمه پیام‌های خطا برای کاربران
* آماده‌سازی ساختار پروژه برای پیاده‌سازی Authentication و Authorization در فصل‌های بعدی
