# فصل 85 - MVC

## MVC چیست؟

هرچه پروژه بزرگ‌تر می‌شود، مدیریت کدها سخت‌تر می‌شود.

فرض کنید تمام کدهای زیر را داخل یک فایل نوشته باشیم:

* ساخت Web Server
* Routing
* اتصال به پایگاه داده
* اعتبارسنجی اطلاعات
* منطق برنامه
* ارسال Response

بعد از مدتی فایل ما هزاران خط کد خواهد داشت.

این کار باعث می‌شود:

* پیدا کردن خطاها سخت شود.
* توسعه پروژه دشوار شود.
* خواندن کد زمان‌بر شود.
* همکاری چند برنامه‌نویس تقریباً غیرممکن شود.

برای حل این مشکل از **معماری MVC** استفاده می‌کنیم.

---

# MVC چیست؟

MVC مخفف سه بخش زیر است:

```text
Model

View

Controller
```

هر بخش مسئولیت مشخصی دارد.

---

# هدف MVC

هدف MVC:

> جداسازی مسئولیت‌ها (Separation of Concerns)

یعنی هر قسمت فقط مسئول انجام یک کار باشد.

---

# معماری MVC

```text
            Client
               │
               ▼
          HTTP Request
               │
               ▼
          Controller
          │         │
          ▼         ▼
       Model      View
          │         │
          └────┬────┘
               ▼
         HTTP Response
```

---

# Model چیست؟

Model مسئول مدیریت داده‌ها است.

کارهای Model:

* ارتباط با Database
* خواندن اطلاعات
* ذخیره اطلاعات
* بروزرسانی اطلاعات
* حذف اطلاعات
* قوانین مربوط به داده

مثال:

```javascript
User.find();

User.create();

User.update();

User.delete();
```

Model هیچ اطلاعی از HTTP یا مرورگر ندارد.

---

# Controller چیست؟

Controller مغز برنامه است.

وظایف Controller:

* دریافت Request
* اعتبارسنجی اولیه
* فراخوانی Model
* پردازش اطلاعات
* ارسال Response

مثال:

```javascript
function getUsers(req, res) {

    const users = User.find();

    res.json(users);

}
```

---

# View چیست؟

View مسئول نمایش اطلاعات است.

در برنامه‌های وب سنتی، View فایل HTML تولید می‌کند.

نمونه:

```html
<h1>Users</h1>
```

---

# آیا Backend همیشه View دارد؟

در بسیاری از پروژه‌های امروزی خیر.

اگر Backend فقط REST API یا GraphQL ارائه دهد:

```text
Browser

↓

React

↓

Node.js API
```

Node.js فقط JSON برمی‌گرداند.

در این حالت عملاً View در Frontend قرار دارد.

---

# مثال ساده

```text

```

ابتدا Route اجرا می‌شود.

سپس:

```text

```

```text

```

Model اطلاعات را از Database می‌گیرد.

سپس:

```text
Controller

↓

JSON Response
```

# ارتباط Route و Controller

```javascript
app.get("/users", userController.index);
```

Route فقط درخواست را هدایت می‌کند.

تمام منطق داخل Controller قرار می‌گیرد.

---

# ارتباط Controller و Model

```javascript
const users = User.find();
```

Controller مستقیماً با Database کار نمی‌کند.

بلکه از طریق Model اطلاعات را دریافت می‌کند.

---

# نمونه کامل

Route:

```javascript
app.get("/users", getUsers);
```

Controller:

```javascript
function getUsers(req, res) {

    const users = User.find();

    res.json(users);

}
```

Model:

```javascript
const User = {

    find() {

        return [];

    }

};
```

# مزایای MVC

* جداسازی مسئولیت‌ها
* خوانایی بیشتر
* توسعه آسان‌تر
* تست ساده‌تر
* کاهش تکرار کد
* نگهداری راحت‌تر
* مناسب پروژه‌های بزرگ

---

# معایب MVC

* تعداد فایل‌ها بیشتر می‌شود.
* برای پروژه‌های بسیار کوچک ممکن است کمی پیچیده به نظر برسد.
* نیاز به رعایت ساختار مشخص دارد.

---

# MVC در Express

Express هیچ معماری خاصی را اجبار نمی‌کند.

اما رایج‌ترین معماری در Express همان MVC است.

تقریباً تمام پروژه‌های حرفه‌ای Express از MVC یا معماری‌های مشابه استفاده می‌کنند.

---

# MVC و ORM

زمانی که از ORMهایی مانند Prisma یا Mongoose استفاده می‌کنیم:

```text
Controller

↓

Model (ORM)

↓

Database
```

Model مسئول ارتباط با Database خواهد بود.

---

# MVC و Middleware

Middleware قبل از Controller اجرا می‌شود.

```text
Request

↓

Middleware

↓

Route

↓

Controller

↓

Model

↓

Response
```

---

# MVC و Service Layer

در پروژه‌های بزرگ معمولاً بین Controller و Model یک لایه دیگر قرار می‌دهند.

```text
Controller

↓

Service

↓

Model
```

Service منطق تجاری (Business Logic) را نگهداری می‌کند.

در فصل‌های معماری نرم‌افزار بیشتر با این الگو آشنا خواهیم شد.

---

# MVC در پروژه‌های API

در پروژه‌های REST API:

```text
Client

↓

Controller

↓

Model

↓

JSON
```

View وجود ندارد یا نقش آن را پاسخ JSON ایفا می‌کند.

# اشتباهات رایج

### ۱- نوشتن تمام منطق داخل Controller

اشتباه:

```javascript
function getUsers() {

    // صدها خط کد

}
```

Controller باید سبک باشد.

---

### ۲- اتصال مستقیم Controller به Database

اشتباه:

```javascript
db.query(...);
```

بهتر است ارتباط با پایگاه داده در Model انجام شود.

---

### ۳- قرار دادن Validation داخل Model

اعتبارسنجی درخواست معمولاً در Middleware یا Controller انجام می‌شود، نه در تمام Modelها.

---

### ۴- قرار دادن منطق Route داخل Route

اشتباه:

```javascript
app.get("/users", (req, res) => {

    // منطق طولانی

});
```

بهتر است Route فقط Controller را فراخوانی کند.

---

### ۵- مخلوط کردن مسئولیت‌ها

هر فایل فقط یک مسئولیت داشته باشد.

---

# نکات حرفه‌ای

* Controllerها را کوتاه و خوانا نگه دارید.
* Model فقط مسئول داده‌ها باشد.
* Routeها فقط عملیات مسیریابی انجام دهند.
* از Middleware برای اعتبارسنجی و احراز هویت استفاده کنید.
* منطق پیچیده را به Service Layer منتقل کنید.
* ساختار پوشه‌ها را از ابتدای پروژه استاندارد انتخاب کنید.
* برای هر Resource یک Controller و یک Model مجزا ایجاد کنید.

# مینی‌پروژه

## ساخت REST API مدیریت محصولات با معماری MVC

### هدف

پیاده‌سازی یک REST API با استفاده از معماری MVC که امکان مدیریت محصولات را فراهم کند.

### ساختار پروژه

```text
project/

├── app.js
├── package.json
│
├── routes/
│   └── products.js
│
├── controllers/
│   └── productController.js
│
├── models/
│   └── Product.js
│
├── middleware/
│   ├── logger.js
│   └── errorHandler.js
│
├── services/
│   └── productService.js
│
├── config/
│   └── database.js
│
└── utils/
    └── response.js
```

### امکانات

* دریافت لیست محصولات
* دریافت اطلاعات یک محصول
* ایجاد محصول جدید
* بروزرسانی محصول
* حذف محصول
* ثبت لاگ درخواست‌ها
* مدیریت خطاها
* ارسال پاسخ‌های JSON استاندارد

### قابلیت‌های تکمیلی

* اتصال به پایگاه داده با Prisma یا Mongoose
* اعتبارسنجی داده‌ها با Middleware
* افزودن احراز هویت با JWT
* استفاده از Service Layer برای منطق تجاری
* پیاده‌سازی صفحه‌بندی، جستجو و مرتب‌سازی محصولات
* آماده‌سازی ساختار پروژه برای توسعه به یک فروشگاه اینترنتی کامل
