# فصل 84 - Middleware

## Middleware چیست؟

تا اینجا یاد گرفتیم که چگونه یک Web Server بسازیم و درخواست‌ها را به Routeهای مختلف هدایت کنیم.

اما فرض کنید قبل از اجرای هر Route بخواهیم کارهای زیر انجام شوند:

* ثبت اطلاعات درخواست (Logging)
* بررسی احراز هویت (Authentication)
* بررسی مجوز دسترسی (Authorization)
* اعتبارسنجی اطلاعات (Validation)
* مدیریت خطاها
* اندازه‌گیری زمان پاسخ
* اضافه کردن Headerهای امنیتی

اگر این کدها را داخل تمام Routeها تکرار کنیم، برنامه بسیار شلوغ و نگهداری آن دشوار می‌شود.

راه‌حل این مشکل:

> **Middleware**

---

# Middleware چیست؟

Middleware تابعی است که **قبل از رسیدن درخواست به Route یا قبل از ارسال پاسخ** اجرا می‌شود.

این تابع می‌تواند:

* درخواست را تغییر دهد.
* پاسخ را تغییر دهد.
* عملیات جانبی انجام دهد.
* درخواست را متوقف کند.
* یا آن را به مرحله بعدی ارسال کند.

---

# Middleware در مسیر درخواست

```text id="6lxtul"
   │

   │
Middleware 3
   │

   │

   │

```

# چرا Middleware مهم است؟

فرض کنید ۱۰۰ Route مختلف دارید.

اگر بخواهید در تمام آن‌ها این کد را بنویسید:

```javascript id="v0y8ga"
console.log(req.method);
```

کد شما بارها تکرار می‌شود.

اما با Middleware فقط یک بار نوشته می‌شود.

---

# مفهوم زنجیره (Pipeline)

Middlewareها پشت سر هم اجرا می‌شوند.

```text id="trqqrk"
Request

↓

Middleware A

↓

Middleware B

↓

Middleware C

↓

Route

↓

Response
```

هر Middleware تصمیم می‌گیرد:

* ادامه دهد.
* پاسخ ارسال کند.
* خطا ایجاد کند.

---

# Middleware در Express

در Express ساختار Middleware به این صورت است:

```javascript id="sga2sn"
function middleware(req, res, next) {

    next();

}
```

پارامترها:

* `req`
* `res`
* `next`

---

# next چیست؟

تابع `next()` باعث می‌شود Middleware بعدی اجرا شود.

```javascript id="o8q39u"
app.use((req, res, next) => {

    console.log("Middleware");

    next();

});
```

اگر `next()` اجرا نشود، درخواست متوقف می‌شود.

---

# ترتیب اجرا

فرض کنید:

```javascript id="7ax9jh"
app.use((req, res, next) => {

    console.log("One");

    next();

});

app.use((req, res, next) => {

    console.log("Two");

    next();

});

app.get("/", (req, res) => {

    res.send("Home");

});
```

خروجی:

```text id="ow7fem"
One

Two
```

سپس پاسخ ارسال می‌شود.

# Middleware عمومی

با `app.use()` می‌توان Middleware را برای تمام درخواست‌ها اجرا کرد.

```javascript id="mr57wl"

    console.log(req.url);

    next();

});
```

# Middleware مخصوص یک مسیر

```javascript id="7xqqy2"

    console.log("Users");

    next();

```

فقط درخواست‌های مربوط به `/users` از این Middleware عبور می‌کنند.

# Middleware برای Logging

# Middleware برای زمان اجرا

```javascript id="c9d9wo"
app.use((req, res, next) => {

    console.time("Request");

    res.on("finish", () => {

        console.timeEnd("Request");

    });

    next();

});
```

---

# Middleware برای احراز هویت

```javascript id="egjq76"
app.use((req, res, next) => {

    const token = req.headers.authorization;

    if (!token) {

        return res.status(401).send("Unauthorized");

    }

    next();

});
```

---

# Middleware برای اعتبارسنجی

```javascript id="94iwwn"
function validate(req, res, next) {

    if (!req.body.name) {

        return res.status(400).send("Name Required");

    }

    next();

}
```

# Middleware برای مدیریت خطا

در Express Middleware مدیریت خطا چهار پارامتر دارد.

```javascript id="ck4p0u"
function errorHandler(err, req, res, next) {

    res.status(500).send("Server Error");

}
```

# Middleware داخلی Express

Express چند Middleware داخلی دارد.

برای تبدیل JSON دریافتی به شیء جاوااسکریپت.

```javascript id="agjlwm"
    extended: true

}));
```

برای پردازش داده‌های فرم.

# ترتیب Middlewareها

ترتیب بسیار مهم است.


# پایان دادن به درخواست

یک Middleware می‌تواند بدون اجرای Route پاسخ ارسال کند.

```javascript id="7c4i2v"
app.use((req, res) => {

    res.send("Maintenance");

});
```

در این حالت Routeهای بعدی اجرا نمی‌شوند.

---

# Middleware در Node.js خام

در ماژول `http` مفهوم Middleware به‌صورت داخلی وجود ندارد، اما می‌توان آن را با فراخوانی توابع پشت‌سرهم پیاده‌سازی کرد.

```javascript id="d1m6wp"
function logger(req, res) {

    console.log(req.method);
}
```

سپس قبل از اجرای Route فراخوانی می‌شود.

* نگهداری بهتر

# اشتباهات رایج

### ۱- فراموش کردن `next()`

اشتباه:

```javascript id="44bctc"
app.use((req, res, next) => {

    console.log(req.url);

});
```

در این حالت درخواست متوقف می‌شود.

---

### ۲- ارسال پاسخ و سپس اجرای `next()`

اشتباه:

```javascript id="tk7xko"
res.send("Done");

next();
```

پس از ارسال پاسخ نباید `next()` فراخوانی شود.

---

### ۳- قرار دادن Middlewareها با ترتیب نامناسب

مثلاً اجرای Route قبل از Middleware احراز هویت باعث می‌شود درخواست بدون بررسی امنیتی پردازش شود.

---

### ۴- انجام منطق پیچیده داخل Middleware

Middleware باید وظیفه مشخصی داشته باشد و از انجام چندین مسئولیت مختلف خودداری کند.

---

### ۵- تغییر مستقیم اطلاعات Request بدون دلیل

تنها زمانی اطلاعات `req` را تغییر دهید که این تغییر برای Middlewareهای بعدی لازم باشد.

---

# نکات حرفه‌ای

* هر Middleware فقط یک مسئولیت داشته باشد.
* Middlewareها را در فایل‌های جداگانه قرار دهید.
* از نام‌های واضح مانند `authMiddleware` و `loggerMiddleware` استفاده کنید.
* Middlewareهای عمومی را قبل از Routeها ثبت کنید.
* Middlewareهای مدیریت خطا را در انتهای برنامه قرار دهید.
* از کتابخانه‌های معتبر برای Middlewareهای رایج استفاده کنید.
* از ثبت اطلاعات حساس مانند رمز عبور یا توکن در لاگ‌ها خودداری کنید.

# مینی‌پروژه

## ساخت مجموعه Middleware برای REST API کاربران

### هدف

ایجاد یک REST API ساده با Express و استفاده از Middlewareهای مختلف برای مدیریت درخواست‌ها.

### امکانات

* Middleware ثبت Method و URL درخواست‌ها
* Middleware اندازه‌گیری زمان پردازش درخواست
* Middleware بررسی وجود Header مربوط به احراز هویت
* Middleware اعتبارسنجی اطلاعات ورودی هنگام ایجاد کاربر
* Middleware مدیریت خطاهای برنامه
* ارسال پاسخ‌های JSON استاندارد
* مدیریت مسیرهای ناشناخته با پاسخ `404 Not Found`

### ساختار پیشنهادی پروژه

```text
project/
│
├── app.js
├── routes/
│   └── users.js
├── middleware/
│   ├── logger.js
│   ├── auth.js
│   ├── validator.js
│   ├── timer.js
│   └── errorHandler.js
└── package.json
```

### قابلیت‌های تکمیلی

* استفاده از `morgan` برای ثبت لاگ درخواست‌ها
* استفاده از `helmet` برای افزودن Headerهای امنیتی
* استفاده از `cors` برای مدیریت درخواست‌های Cross-Origin
* ثبت لاگ خطاها در فایل
* ساخت Middleware سفارشی برای بررسی نقش کاربران (Role-Based Access Control)
* آماده‌سازی پروژه برای فصل‌های بعدی مانند MVC، Authentication و Authorization
