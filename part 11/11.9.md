# فصل 90 - Cookie

کوکی (Cookie) یکی از مهم‌ترین مفاهیم دنیای وب است. تقریباً تمام وب‌سایت‌هایی که وارد آن‌ها می‌شوید از کوکی استفاده می‌کنند؛ از ورود به حساب کاربری گرفته تا ذخیره تنظیمات سایت، سبد خرید، زبان انتخابی و حتی تحلیل رفتار کاربران.

در Node.js نیز کوکی‌ها نقش بسیار مهمی در پیاده‌سازی احراز هویت (Authentication)، مدیریت نشست کاربران (Session)، ذخیره تنظیمات و ارتباط امن بین مرورگر و سرور دارند.

در این فصل با مفهوم Cookie، نحوه ارسال و دریافت آن، ویژگی‌های امنیتی و بهترین روش‌های استفاده از آن آشنا می‌شویم.

---

# Cookie چیست؟

Cookie یک فایل بسیار کوچک متنی است که توسط سرور در مرورگر کاربر ذخیره می‌شود.

مرورگر در درخواست‌های بعدی، این اطلاعات را دوباره برای همان سرور ارسال می‌کند.

روند کار به صورت زیر است:

```
Browser ---- Request ----> Server

Server ---- Set-Cookie ----> Browser

Browser (Cookie Stored)

Browser ---- Cookie ----> Server
```

---

# چرا Cookie ساخته شد؟

پروتکل HTTP بدون حالت (Stateless) است.

یعنی:

```
هر Request مستقل از Request قبلی است.
```

سرور به صورت پیش‌فرض هیچ اطلاعاتی از کاربران ذخیره نمی‌کند.

مثلاً:

```
کاربر Login می‌کند.

بعد از ۱ ثانیه:

یک درخواست دیگر ارسال می‌شود.

سرور نمی‌داند این همان کاربر قبلی است.
```

اینجاست که Cookie وارد عمل می‌شود.

---

# مثال واقعی

فرض کنید وارد فروشگاه اینترنتی شده‌اید.

سبد خرید شما پر است.

صفحه را Refresh می‌کنید.

اگر Cookie وجود نداشت:

```
سبد خرید خالی می‌شد.
```

اما Cookie اطلاعات موردنیاز را نگهداری می‌کند.

# Cookie چگونه کار می‌کند؟

مرحله اول:

مرورگر درخواست ارسال می‌کند.

```

```

---

```

```

---

مرورگر Cookie را ذخیره می‌کند.

```

```

---

```

```

سرور متوجه می‌شود کاربر همان فرد قبلی است.

# Header مربوط به Cookie

ارسال Cookie از سمت سرور:

```
Set-Cookie
```

دریافت Cookie از سمت مرورگر:

```
Cookie
```

---

# ساخت اولین Cookie

در Node.js:

```javascript
const http = require("http");

http.createServer((req, res) => {

    res.setHeader(
        "Set-Cookie",
        "username=Ali"
    );

    res.end("Cookie Set");

}).listen(3000);
```

---

در مرورگر:

```
Application
↓

Cookies
↓

username = Ali
```

---

# ارسال خودکار Cookie

بعد از ذخیره شدن:

```
GET /profile

Cookie: username=Ali
```

مرورگر این کار را کاملاً خودکار انجام می‌دهد.

---

# خواندن Cookie در Node.js

Cookie داخل Header قرار دارد.

```javascript
const http = require("http");

http.createServer((req, res) => {

    console.log(req.headers.cookie);

    res.end();

}).listen(3000);
```

خروجی:

```
username=Ali
```

---

# چند Cookie

```
username=Ali

theme=dark

language=fa
```

Header:

```
Cookie:
username=Ali;
theme=dark;
language=fa
```

---

# تبدیل Cookie به Object

```javascript
function parseCookies(cookieHeader = "") {

    return cookieHeader
        .split(";")
        .filter(Boolean)
        .reduce((obj, item) => {

            const [key, value] = item.trim().split("=");

            obj[key] = value;

            return obj;

        }, {});
}
```

استفاده:

```javascript
const cookies = parseCookies(req.headers.cookie);

console.log(cookies.username);
```

# Cookie در Express

برای کار راحت‌تر معمولاً از پکیج **cookie-parser** استفاده می‌شود.

نصب:

```bash
npm install cookie-parser
```

---

استفاده:

```javascript
const express = require("express");
const cookieParser = require("cookie-parser");

const app = express();

app.use(cookieParser());

app.get("/", (req, res) => {

    console.log(req.cookies);

    res.send("Hello");

});

app.listen(3000);
```

---

# ایجاد Cookie در Express

```javascript
app.get("/", (req, res) => {

    res.send("Done");

});
```

# ویژگی‌های Cookie

یک Cookie فقط مقدار نیست.

ویژگی‌های زیادی دارد.

مثلاً:

```
Set-Cookie:

username=Ali;

HttpOnly;

Secure;

SameSite=Lax;

Max-Age=3600
```

---

# HttpOnly

اگر فعال باشد:

JavaScript مرورگر به Cookie دسترسی ندارد.

```
document.cookie
```

این Cookie را نمایش نمی‌دهد.

مزیت:

```
مقابله با XSS
```

---

در Express:

```javascript
res.cookie("token", token, {

    httpOnly: true

});
```

---

# Secure

فقط روی HTTPS ارسال می‌شود.

```javascript
secure: true
```

در HTTP ارسال نمی‌شود.

---

# SameSite

برای جلوگیری از حملات CSRF استفاده می‌شود.

مقادیر:

```
Strict

Lax

None
```

---

## Strict

فقط درخواست‌های همان سایت.

امن‌ترین حالت.

---

## Lax

حالت پیش‌فرض اکثر مرورگرها.

---

## None

ارسال در همه درخواست‌ها.

نیازمند:

```
Secure=true
```

# Signed Cookie

برای جلوگیری از تغییر مقدار Cookie.

```javascript

```

```javascript

    "user",

    "Ali",

    {

);
```

```javascript

```

# Cookie و JWT

بسیاری از برنامه‌ها JWT را داخل Cookie ذخیره می‌کنند.

```javascript

    httpOnly: true,

    secure: true,

    sameSite: "lax"
```

# اشتباهات رایج

### ذخیره اطلاعات حساس به صورت متن ساده

هرگز اطلاعات محرمانه را بدون رمزنگاری یا توکن مناسب داخل Cookie قرار ندهید.

---

### فراموش کردن HttpOnly

اگر Cookie حاوی اطلاعات احراز هویت باشد و `HttpOnly` فعال نباشد، اسکریپت‌های مخرب می‌توانند به آن دسترسی پیدا کنند.

---

### استفاده از Secure فقط در محیط Production

فعال کردن `secure: true` روی HTTP باعث می‌شود Cookie ارسال نشود. در محیط توسعه معمولاً از HTTP استفاده می‌شود.

---

### تنظیم نکردن SameSite

عدم تنظیم `SameSite` می‌تواند برنامه را در برابر حملات CSRF آسیب‌پذیر کند.

---

### ذخیره داده‌های حجیم

Cookie برای داده‌های کوچک طراحی شده است و ارسال آن در تمام درخواست‌ها باعث افزایش حجم ترافیک می‌شود.

---

# نکات حرفه‌ای

* برای توکن‌های احراز هویت همیشه از `HttpOnly` استفاده کنید.
* در محیط Production از `Secure` همراه با HTTPS استفاده کنید.
* برای اکثر برنامه‌ها مقدار `SameSite=Lax` انتخاب مناسبی است.
* مقدار Cookie را تا حد امکان کوچک نگه دارید.
* اطلاعات مهم را در سمت سرور نگهداری کنید و فقط شناسه (Session ID) یا توکن را داخل Cookie ذخیره کنید.
* برای جلوگیری از دستکاری داده‌ها از Signed Cookie یا توکن‌های امضاشده مانند JWT استفاده کنید.
* تاریخ انقضای مناسبی برای Cookie تعیین کنید و از نگهداری دائمی اطلاعات غیرضروری خودداری کنید.

# پاسخ تشریحی

## پاسخ تمرین ۱

```javascript
const http = require("http");

http.createServer((req, res) => {
    res.setHeader("Set-Cookie", "username=Sobhan");
    res.end("Cookie Set");
}).listen(3000);
```

---

## پاسخ تمرین ۲

```javascript
function parseCookies(cookieHeader = "") {
    return cookieHeader
        .split(";")
        .filter(Boolean)
        .reduce((result, item) => {
            const [key, value] = item.trim().split("=");
            result[key] = value;
            return result;
        }, {});
}

const http = require("http");

http.createServer((req, res) => {
    console.log(parseCookies(req.headers.cookie));
    res.end();
}).listen(3000);
```

---

## پاسخ تمرین ۳

```javascript
const express = require("express");
const cookieParser = require("cookie-parser");

const app = express();

app.use(cookieParser());

app.get("/", (req, res) => {
    res.cookie("theme", "dark");
    res.send("Cookie Created");
});

app.listen(3000);
```

---

## پاسخ تمرین ۴

```javascript
res.cookie("token", "jwt-token", {
    httpOnly: true,
    secure: true,
    sameSite: "lax",
    maxAge: 60 * 60 * 1000
});
```

---

## پاسخ تمرین ۵

```javascript
app.get("/logout", (req, res) => {
    res.clearCookie("token");
    res.send("Logged out");
});
```

# مینی‌پروژه

## سیستم انتخاب تم سایت (Theme Preference)

### هدف

پیاده‌سازی سیستمی که کاربر بتواند بین حالت روشن و تیره جابه‌جا شود و انتخاب او با استفاده از Cookie در مراجعات بعدی نیز حفظ شود.

---

## امکانات پروژه

* ایجاد Cookie با نام `theme`
* مقدارهای `light` و `dark`
* خواندن Cookie در هر درخواست
* نمایش تم فعلی کاربر
* امکان تغییر تم از طریق مسیرهای مجزا
* حذف Cookie و بازگشت به تنظیمات پیش‌فرض

---


نمایش تم فعلی.

---

تغییر تم به روشن.

---

```

```

تغییر تم به تیره.

---


## اهداف آموزشی

پس از پایان این پروژه، خواهید توانست:

* Cookie ایجاد کنید.
* Cookie را بخوانید و پردازش کنید.
* از `cookie-parser` در Express استفاده کنید.
* ویژگی‌های مهم Cookie مانند `HttpOnly`، `Secure` و `SameSite` را به‌درستی تنظیم کنید.

* از Cookie برای نگهداری تنظیمات کاربران در پروژه‌های واقعی استفاده کنید.
