# فصل 89 - JWT

## JWT چیست؟

در فصل قبل با **Authentication** و **Authorization** آشنا شدیم.

یکی از رایج‌ترین روش‌های پیاده‌سازی Authentication در REST APIها استفاده از **JWT** است.

JWT به سرور اجازه می‌دهد بدون ذخیره Session، هویت کاربران را بررسی کند.

امروزه تقریباً اکثر APIهای مدرن از JWT یا مفاهیم مشابه آن استفاده می‌کنند.

---

# JWT مخفف چیست؟

JWT مخفف عبارت زیر است:

```text id="jwt01"
JSON Web Token
```

JWT یک استاندارد برای انتقال امن اطلاعات بین دو طرف است.

استاندارد آن:

```text id="jwt02"
RFC 7519
```

است.

---

# چرا JWT ایجاد شد؟

در گذشته بیشتر برنامه‌ها از Session استفاده می‌کردند.

اما با رشد:

* REST API
* Mobile App
* SPA
* Microservices

استفاده از Session سخت‌تر شد.

JWT این مشکل را حل می‌کند.

# Middleware بررسی JWT

```javascript id="jwt30"
const jwt = require("jsonwebtoken");

function authenticate(req, res, next) {

    const authHeader = req.headers.authorization;

    if (!authHeader) {

        return res.status(401).send("Unauthorized");

    }

    const token = authHeader.split(" ")[1];

    try {

        req.user = jwt.verify(

            token,

            process.env.JWT_SECRET

        );

        next();

    } catch {

        return res.status(401).send("Invalid Token");

    }

}
```

# اشتباهات رایج

### ۱- قرار دادن اطلاعات حساس داخل Payload

اشتباه:

```json id="jwt36"
{
    "password": "123456"
```

---

### ۲- استفاده از Secret Key ضعیف

اشتباه:

```text id="jwt37"

```

از کلیدهای طولانی و تصادفی استفاده کنید و آن‌ها را در فایل `.env` نگهداری کنید.

---

### ۳- استفاده نکردن از زمان انقضا

همیشه از:

```javascript id="jwt38"
expiresIn
```

استفاده کنید.

---

### ۴- استفاده از `decode()` به جای `verify()`

اشتباه:

```javascript id="jwt39"
jwt.decode(token);
```

برای احراز هویت باید از:

```javascript id="jwt40"
jwt.verify(token, secret);
```

استفاده شود.

---

### ۵- ارسال JWT در URL

اشتباه:

```text id="jwt41"
/users?token=...
```

از Header یا HttpOnly Cookie استفاده کنید.

---

### ۶- استفاده نکردن از HTTPS

بدون HTTPS امکان سرقت Token در مسیر ارتباط وجود دارد.

---

### ۷- استفاده از یک Access Token با عمر بسیار طولانی

بهتر است عمر Access Token کوتاه باشد و از Refresh Token برای تمدید آن استفاده شود.

---

# نکات حرفه‌ای

* Secret Key را در فایل `.env` نگهداری کنید.
* همیشه از `jwt.verify()` برای اعتبارسنجی استفاده کنید.
* Access Token را کوتاه‌مدت و Refresh Token را بلندمدت طراحی کنید.
* اطلاعات حساس را داخل Payload قرار ندهید.
* از HttpOnly Cookie برای برنامه‌های وب استفاده کنید.
* برای جلوگیری از حملات Brute Force از Rate Limiting استفاده کنید.
* در صورت نیاز، از Blacklist برای Tokenهای باطل‌شده استفاده کنید.
* الگوریتم‌های امن مانند `HS256` یا در سناریوهای مناسب `RS256` را به‌کار ببرید.

## پاسخ تمرین ۵

# مینی‌پروژه

## سیستم احراز هویت مبتنی بر JWT

### هدف

پیاده‌سازی یک سیستم Authentication کامل با استفاده از JWT، Express و bcrypt که کاربران بتوانند ثبت‌نام، ورود و دسترسی به Routeهای محافظت‌شده را تجربه کنند.

### امکانات

* ثبت‌نام کاربران
* ورود با ایمیل و رمز عبور
* Hash کردن رمز عبور با `bcrypt`
* تولید Access Token و Refresh Token
* Middleware اعتبارسنجی JWT
* محافظت از Routeهای خصوصی
* تمدید Access Token با Refresh Token
* خروج از حساب کاربری
* مدیریت خطاهای مربوط به Token
* ارسال پاسخ‌های JSON استاندارد

### قابلیت‌های تکمیلی

* ذخیره Refresh Token در HttpOnly Cookie
* پیاده‌سازی Blacklist برای Tokenهای باطل‌شده
* استفاده از `RS256` با کلید عمومی و خصوصی
* چرخش (Rotation) Refresh Tokenها برای افزایش امنیت
* ثبت تاریخ و دستگاه آخرین ورود کاربر
* اعمال Rate Limiting روی Route ورود
* آماده‌سازی پروژه برای پیاده‌سازی **OAuth 2.0** و ورود با سرویس‌های شخص ثالث در فصل‌های بعدی
