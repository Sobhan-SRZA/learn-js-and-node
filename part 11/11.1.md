# فصل 82 - ساخت Web Server

## Web Server چیست؟

تا اینجا با مفاهیم HTTP، Socket، WebSocket، REST API و GraphQL آشنا شدیم.

اما هنوز یک سؤال مهم باقی مانده است:

**چه چیزی درخواست‌های کاربران را دریافت می‌کند؟**

پاسخ:

> **Web Server**

وب سرور برنامه‌ای است که درخواست‌های HTTP را از کاربران دریافت می‌کند، آن‌ها را پردازش می‌کند و پاسخ مناسب را برمی‌گرداند.

برای مثال:

```text
Browser
    │
HTTP Request
    │
Node.js Web Server
    │
HTTP Response
    │
Browser
```

---

# Web Server در Node.js

در Node.js بدون نصب هیچ کتابخانه‌ای می‌توان یک Web Server ساخت.

ماژول داخلی:

```javascript
http
```

این ماژول در هسته Node.js قرار دارد.

---

# وارد کردن ماژول

در CommonJS:

```javascript
const http = require("http");
```

در ES Module:

```javascript
import http from "node:http";
```

---

# ساخت اولین Web Server

```javascript
const http = require("http");

const server = http.createServer();

server.listen(3000);

console.log("Server Started");
```

اجرای برنامه:

```bash
node app.js
```

---

# متد listen()

این متد سرور را روی یک پورت اجرا می‌کند.

```javascript
server.listen(3000);
```

عدد 3000 شماره پورت است.

---

# Port چیست؟

هر برنامه‌ای که از شبکه استفاده می‌کند روی یک پورت اجرا می‌شود.

مثال:

```text
localhost:3000

localhost:5000

localhost:8080
```

پورت‌ها مانند شماره واحدهای یک ساختمان هستند.

کامپیوتر با استفاده از شماره پورت تشخیص می‌دهد درخواست باید به کدام برنامه ارسال شود.

---

# localhost چیست؟

زمانی که می‌گوییم:

```text
http://localhost:3000
```

منظور همان کامپیوتر خودمان است.

آدرس:

```text
127.0.0.1
```

و

```text
localhost
```

تقریباً معادل یکدیگر هستند.

---

# دریافت Request

تابع `createServer` یک Callback دریافت می‌کند.

```javascript
const http = require("http");

const server = http.createServer((req, res) => {

    console.log("New Request");

});

server.listen(3000);
```

هر بار که مرورگر درخواست ارسال کند، این تابع اجرا می‌شود.

---

# شیء Request

پارامتر اول:

```javascript
req
```

نماینده درخواست کاربر است.

برخی از ویژگی‌های مهم:

```javascript
req.method

req.url

req.headers
```

---

# مشاهده آدرس درخواست

```javascript
const http = require("http");

const server = http.createServer((req, res) => {

    console.log(req.url);
```

اگر مرورگر وارد آدرس زیر شود:

```text

```

خروجی:


# مشاهده Method

```javascript
console.log(req.method);
```

خروجی:

```text

```

---

# شیء Response

پارامتر دوم:

```javascript
res
```

برای ارسال پاسخ به کاربر استفاده می‌شود.

یا به صورت کوتاه‌تر:


# ارسال خطای 404

```javascript

```

---

# تنظیم Header

```javascript
res.setHeader("Content-Type", "text/plain");
```

---

ارسال HTML:

```javascript

res.end("<h1>Hello</h1>");
```

---

ارسال JSON:

```javascript
res.setHeader("Content-Type", "application/json");

res.end(JSON.stringify({

    name: "Ali",

    age: 24

}));
```

---

# بررسی مسیرها

```javascript
const http = require("http");

const server = http.createServer((req, res) => {

    if (req.url === "/") {

        return res.end("Home");

    }

    if (req.url === "/about") {

        return res.end("About");

    }

    res.statusCode = 404;

    res.end("Not Found");

});

server.listen(3000);
```

---

# بررسی Method

```javascript
if (req.method === "GET") {

    res.end("GET Request");

}
```

---

# ترکیب Method و URL

```javascript
if (req.method === "GET" && req.url === "/users") {

    res.end("Users");

}
```

---

# توقف سرور

```javascript
server.close();
```

این متد باعث می‌شود سرور درخواست جدیدی را نپذیرد.

---

# رویداد listening

```javascript
server.on("listening", () => {

    console.log("Server Ready");

});
```

---

# مدیریت خطا

```javascript
server.on("error", (err) => {

    console.error(err);

});
```

# تغییر پورت با متغیر محیطی

بهتر است شماره پورت را ثابت ننویسیم.

```javascript
const PORT = process.env.PORT || 3000;

server.listen(PORT);
```

این روش هنگام استقرار پروژه روی سرورهای واقعی بسیار کاربردی است.

# Web Server خام یا Express؟

ساخت Web Server با ماژول `http` برای یادگیری بسیار مهم است.

اما در پروژه‌های واقعی معمولاً از فریمورک‌هایی مانند Express.js یا Fastify استفاده می‌شود؛ زیرا امکاناتی مانند Routing، Middleware و مدیریت درخواست‌ها را ساده‌تر می‌کنند.

---

# مزایای استفاده از ماژول http

* بدون نیاز به نصب کتابخانه
* سبک و سریع
* مناسب برای یادگیری HTTP
* کنترل کامل روی درخواست و پاسخ
* پایه‌ای برای درک فریمورک‌هایی مانند Express.js

---

# محدودیت‌ها

* مدیریت Routeها به‌صورت دستی
* عدم وجود Middleware
* مدیریت دشوار پروژه‌های بزرگ
* نیاز به کدنویسی بیشتر نسبت به فریمورک‌ها

---

# اشتباهات رایج

### ۱- فراموش کردن `res.end()`

بدون فراخوانی این متد، پاسخ کامل نمی‌شود و مرورگر منتظر می‌ماند.

---

### ۲- ارسال چندباره پاسخ

اشتباه:

```javascript
res.end("Hello");

res.end("World");
```

هر درخواست فقط یک پاسخ می‌تواند داشته باشد.

---

### ۳- تنظیم نکردن Header مناسب

اگر نوع محتوا مشخص نشود، ممکن است مرورگر پاسخ را به شکل مورد انتظار نمایش ندهد.

---

### ۴- استفاده از پورت ثابت

به‌جای:

```javascript
3000
```

از:

```javascript
process.env.PORT
```

استفاده کنید.

---

### ۵- نداشتن مسیر پیش‌فرض

اگر هیچ Routeای مطابقت نداشته باشد، بهتر است پاسخ `404 Not Found` ارسال شود.

---

# نکات حرفه‌ای

* همیشه `Content-Type` مناسب را تنظیم کنید.
* برای پاسخ‌های JSON از `JSON.stringify()` استفاده کنید.
* منطق هر Route را در فایل جداگانه قرار دهید تا پروژه قابل نگهداری باشد.
* از متغیرهای محیطی برای تنظیم پورت و اطلاعات حساس استفاده کنید.
* قبل از ارسال پاسخ، اعتبارسنجی داده‌های ورودی را انجام دهید.
* در پروژه‌های واقعی از فریمورک‌هایی مانند Express.js یا Fastify استفاده کنید، اما ابتدا نحوه کار ماژول `http` را به‌خوبی یاد بگیرید.

# مینی‌پروژه

## ساخت Web Server چندصفحه‌ای

### هدف

ساخت یک Web Server ساده با استفاده از ماژول `http` که بتواند چندین مسیر مختلف را مدیریت کند.

### امکانات

* صفحه اصلی (`/`)
* صفحه درباره ما (`/about`)
* صفحه تماس (`/contact`)
* مسیر `/users` با خروجی JSON
* مسیر `/health` برای بررسی سلامت سرور
* مدیریت خطای `404`
* تنظیم `Content-Type` مناسب برای پاسخ‌ها
* ثبت Method و URL هر درخواست در ترمینال

### قابلیت‌های تکمیلی

* خواندن شماره پورت از `process.env.PORT`
* نمایش زمان دریافت هر درخواست
* ارسال فایل HTML به‌جای متن ساده
* تفکیک Routeها در فایل‌های جداگانه
* اضافه کردن لاگ درخواست‌ها برای عیب‌یابی
* آماده‌سازی ساختار پروژه برای استفاده از Express.js در فصل‌های بعدی
