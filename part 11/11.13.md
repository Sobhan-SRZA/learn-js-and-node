# فصل 94 - Error Handling حرفه‌ای

در فصل 39 با مفاهیم پایه‌ای مدیریت خطا در JavaScript آشنا شدیم و یاد گرفتیم چگونه از `try...catch` و `throw` استفاده کنیم.

اما در پروژه‌های واقعی، مدیریت خطا بسیار فراتر از یک `try...catch` ساده است.

در یک API حرفه‌ای باید:

* خطاها ساختار مشخصی داشته باشند.
* اطلاعات حساس به کاربر نمایش داده نشود.
* تمام خطاها ثبت (Log) شوند.
* پاسخ‌های استاندارد ارسال شوند.
* خطاهای غیرمنتظره باعث Crash شدن برنامه نشوند.

در این فصل با اصول **Professional Error Handling** در Node.js و Express آشنا می‌شویم.

---

# Error Handling حرفه‌ای چیست؟

مدیریت حرفه‌ای خطا یعنی:

* تشخیص نوع خطا
* ثبت خطا
* ارسال پاسخ مناسب
* جلوگیری از Crash شدن برنامه
* نمایش پیام مناسب به کاربر

---

# چرا Error Handling مهم است؟

فرض کنید داخل یک API:

```javascript
const user = null;

console.log(user.name);
```

خروجی:

```text
TypeError:
Cannot read properties of null
```

اگر این خطا مدیریت نشود:

* درخواست شکست می‌خورد.
* ممکن است برنامه Crash کند.
* اطلاعات داخلی برنامه لو برود.

---

# انواع خطا

به طور کلی:

```text
Operational Errors

Programmer Errors
```

---

# Operational Error

خطاهایی که ممکن است در زمان اجرای برنامه رخ دهند.

مثلاً:

* کاربر پیدا نشد.
* فایل وجود ندارد.
* Token نامعتبر است.
* اتصال Database قطع شده است.
* Validation ناموفق.

---

# Programmer Error

خطاهای برنامه‌نویسی.

مثلاً:

```javascript
const user = null;

user.name
```

یا:

```javascript
undefined.method()
```

این خطاها باید در زمان توسعه برطرف شوند.

# Middleware مدیریت خطا در Express

Express یک Middleware مخصوص Error دارد.

```javascript
app.use((err, req, res, next) => {

    res.status(500).json({

        success: false,

        message: err.message

    });

});
```

---

نکته:

Middleware خطا همیشه چهار پارامتر دارد.

```javascript
(err, req, res, next)
```

---

# ارسال خطا به Middleware

```javascript
app.get("/", (req, res, next) => {

    next(new Error("Something Wrong"));

});
```

# Async Error

در Async Function نیز باید خطا مدیریت شود.

```javascript
app.get("/", async (req, res, next) => {

    try {

        throw new Error("Error");

    }

    catch(err){

        next(err);

    }

});
```

---

# ساخت Wrapper

برای جلوگیری از تکرار:

```javascript
const asyncHandler = fn => {

    return (req, res, next) => {

        Promise.resolve(

            fn(req, res, next)

        ).catch(next);

    };

};
```

---

استفاده:

```javascript
app.get(

    "/",

    asyncHandler(async (req, res) => {

        throw new Error("Failed");

    })

);
```

---

# ساخت کلاس Error

```javascript
class AppError extends Error {

    constructor(message, statusCode) {

        super(message);

        this.statusCode = statusCode;

    }

}
```

---

استفاده:

```javascript
throw new AppError(

    "User Not Found",

    404

);
```

# Middleware حرفه‌ای

```javascript
app.use((err, req, res, next) => {

    const status = err.statusCode || 500;

    res.status(status).json({

        success: false,

});
```

# اشتباهات رایج

### استفاده نکردن از Middleware خطا

مدیریت خطا در هر Route باعث تکرار کد و سخت‌تر شدن نگهداری پروژه می‌شود.

---

### نمایش Stack Trace در Production

Stack Trace اطلاعات داخلی برنامه را فاش می‌کند و نباید به کاربران نمایش داده شود.

---

### ارسال Status Code اشتباه

ارسال `200 OK` برای درخواست ناموفق یا استفاده از `500` برای خطاهای اعتبارسنجی باعث سردرگمی Client می‌شود.

---

### فراموش کردن مدیریت Promise Rejection

خطاهای Promise در صورت مدیریت نشدن ممکن است باعث ناپایداری برنامه شوند.

---

### استفاده از پیام‌های نامفهوم

پیام‌هایی مانند:

```text
Something went wrong
```

برای توسعه‌دهنده و کاربر کمکی نمی‌کنند. پیام باید واضح و متناسب با خطا باشد.

---

# نکات حرفه‌ای

* برای تمام APIها از یک قالب ثابت برای پاسخ خطا استفاده کنید.
* یک کلاس اختصاصی مانند `AppError` برای خطاهای برنامه ایجاد کنید.
* از `asyncHandler` برای حذف `try...catch`های تکراری استفاده کنید.
* تمام خطاها را قبل از ارسال پاسخ، Log کنید.
* در محیط Production فقط اطلاعات ضروری را به کاربر نمایش دهید.
* برای هر نوع خطا Status Code مناسب ارسال کنید.
* از Middleware مرکزی برای مدیریت همه خطاها استفاده کنید.

# پاسخ تشریحی

## پاسخ تمرین ۱

```javascript
app.use((err, req, res, next) => {

    res.status(err.statusCode || 500).json({

        success: false,

        message: err.message

    });

});
```

---

## پاسخ تمرین ۲

```javascript
class AppError extends Error {

    constructor(message, statusCode) {

        super(message);

        this.statusCode = statusCode;

    }

}

module.exports = AppError;
```

---

## پاسخ تمرین ۳

```javascript
app.get("/users/:id", (req, res, next) => {

    return next(

        new AppError("User Not Found", 404)

    );

});
```

---

## پاسخ تمرین ۴

```javascript
const asyncHandler = fn =>

(req, res, next) =>

Promise.resolve(

    fn(req, res, next)

).catch(next);
```

استفاده:

```javascript
app.get(

    "/",

    asyncHandler(async (req, res) => {

        res.send("OK");

    })

);
```

---

## پاسخ تمرین ۵

```javascript
app.use((err, req, res, next) => {

    const response = {

        success: false,

        message: err.message

    };

    if (process.env.NODE_ENV === "development") {

        response.stack = err.stack;

    }

    res.status(err.statusCode || 500).json(response);

});
```
