# فصل 73 - انتشار Package در npm

## مقدمه

در فصل‌های قبل یاد گرفتیم چگونه یک Package در Node.js بسازیم.

اما ساختن Package تنها مرحله اول است.

برای اینکه دیگر برنامه‌نویسان بتوانند از Package ما استفاده کنند، باید آن را در Registry اصلی Node.js یعنی:

```text
npm Registry
```

منتشر کنیم.

با انتشار Package در npm:

* میلیون‌ها توسعه‌دهنده می‌توانند از آن استفاده کنند.
* پروژه ما قابل نصب با npm می‌شود.
* می‌توانیم نسخه‌های جدید منتشر کنیم.
* در اکوسیستم Node.js مشارکت کنیم.

فرآیند کلی انتشار:

```text
ساخت Package

↓

تست Package

↓

ساخت حساب npm

↓

Login

↓

npm publish

↓

مدیریت نسخه‌ها
```

---

# 73.1 - npm Registry چیست؟

npm Registry یک مخزن آنلاین برای نگهداری Packageهای Node.js است.

وقتی دستور:

```bash
npm install express
```

را اجرا می‌کنیم، npm از Registry Package را دریافت می‌کند.

---

# 73.2 - پیش‌نیازهای انتشار Package

قبل از انتشار باید:

* Node.js نصب باشد.
* npm نصب باشد.
* حساب npm داشته باشیم.
* Package استاندارد باشد.
* نام Package آزاد باشد.

بررسی نسخه:

```bash
node -v

npm -v
```

# 73.8 - قوانین نام Package

نام Package باید:

* فاصله نداشته باشد.

# 73.9 - بررسی آزاد بودن نام Package


# 73.10 - فایل‌هایی که منتشر می‌شوند

# 73.21 - Scoped Package

```text

```

```bash
npm publish --access public
```

# جمع‌بندی

انتشار Package در npm مرحله‌ای است که یک توسعه‌دهنده Node.js را از مصرف‌کننده کد به تولیدکننده ابزار تبدیل می‌کند.

با یادگیری این فرآیند می‌توانیم:

* کتابخانه‌های شخصی بسازیم.
* ابزارهای حرفه‌ای منتشر کنیم.
* در جامعه Node.js مشارکت کنیم.
* تجربه توسعه خود را با دیگران به اشتراک بگذاریم.

چرخه کامل ساخت Package:

```text
Create

↓

Test

↓

Version

↓

Publish

↓

Maintain
```

یک Package موفق فقط کد نیست؛ بلکه ترکیبی از:

* طراحی خوب
* Documentation
* تست
* مدیریت Version
* انتشار حرفه‌ای

است.
