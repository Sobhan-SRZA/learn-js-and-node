# فصل 68 - package.json

## مقدمه

در هر پروژه حرفه‌ای Node.js، یک فایل بسیار مهم وجود دارد که تقریباً تمام اطلاعات مربوط به پروژه را نگهداری می‌کند:

```text
package.json
```

این فایل مرکز مدیریت پروژه Node.js است.

package.json مشخص می‌کند:

* نام پروژه چیست.
* نسخه پروژه چیست.
* فایل اصلی برنامه کدام است.
* چه Packageهایی نصب شده‌اند.
* چه Scriptهایی قابل اجرا هستند.
* پروژه به چه ابزارهایی نیاز دارد.
* اطلاعات انتشار Package چیست.

تقریباً تمام ابزارهای اکوسیستم Node.js مانند:

* npm
* yarn
* pnpm
* webpack
* eslint
* jest

با package.json کار می‌کنند.

---

# 68.1 - package.json چیست؟

`package.json` یک فایل JSON است که اطلاعات یک پروژه Node.js را ذخیره می‌کند.

مثال ساده:

```json id="6nqj3x"
{
  "name": "my-app",
  "version": "1.0.0",
  "main": "index.js"
}
```

---

# 68.2 - ساخت package.json

روش اول:

```bash id="m4f7qm"
npm init
```

npm سوال‌هایی درباره پروژه می‌پرسد.

---

روش دوم:

```bash id="7cx3ps"
npm init -y
```

بدون سوال فایل ایجاد می‌شود.

---

# 68.3 - ساختار کلی package.json

یک فایل کامل:

```json id="b3m8qv"
{
  "name": "server-app",

  "version": "1.0.0",

  "description": "Node.js server",

  "main": "index.js",

  "scripts": {},

  "dependencies": {},

  "devDependencies": {}
}
```

---

# 68.4 - فیلد name

نام پروژه:

```json id="c3m9xn"
"name":"my-api"
```

قوانین:

* حروف کوچک بهتر است.
* فاصله نباید داشته باشد.
* باید یکتا باشد.

مثال درست:

```json id="7kz4n2"
"name":"user-service"
```

---

# 68.5 - فیلد version

نسخه پروژه:

```json id="r9h6tj"
"version":"1.0.0"
```

معمولاً از Semantic Versioning استفاده می‌شود.

ساختار:

```text id="f4nyw1"
Major.Minor.Patch
```

مثال:

```text id="5v9m3q"
2.4.1
```

یعنی:

* 2 تغییرات بزرگ
* 4 قابلیت جدید
* 1 اصلاح باگ

---

# 68.6 - فیلد description

توضیح پروژه:

```json id="u8m2lh"
"description":
"REST API with Node.js"
```

برای معرفی پروژه استفاده می‌شود.

# 68.8 - فیلد scripts

یکی از مهم‌ترین بخش‌ها.

برای تعریف Commandهای شخصی.

مثال:

```json id="g8p6vb"
{
"scripts":{

"start":
"node index.js"

}
}
```

اجرا:

```bash id="4r6z8v"
npm start
```

---

# 68.9 - Scriptهای رایج

مثال:

```json id="q6n9we"
{
"scripts":{

"start":
"node app.js",

"dev":
"nodemon app.js",

"test":
"jest"

}
}
```

اجرا:

```bash
npm run dev
```

---

# 68.10 - تفاوت npm start و npm run

برای Scriptهای خاص:

```bash id="m8t4rq"
npm run dev
```

اما برای:

```json id="u1a9xk"
"start":"node app.js"
```

می‌توان نوشت:

```bash id="6p8x4d"
npm start
```

# 68.11 - dependencies

Packageهای مورد نیاز اجرای برنامه.

مثال:

```json id="6w7n0a"
"dependencies":{

"express":"5.0.0",

"mongoose":"8.0.0"

}
```

در محیط Production نصب می‌شوند.

---

# 68.12 - devDependencies

Packageهای مخصوص توسعه.

مثال:

```json id="m6k2xq"

"jest":"29.0.0",

"eslint":"8.0.0"

}
```

برای:

* تست
* Lint
* ابزارهای توسعه

استفاده می‌شوند.

# 68.23 - فایل package-lock.json

در کنار package.json ایجاد می‌شود.

وظیفه:

* ذخیره نسخه دقیق Packageها
* نصب یکسان پروژه

---

# 68.24 - تفاوت package.json و package-lock.json

| package.json      | package-lock.json |
| ----------------- | ----------------- |
| اطلاعات کلی پروژه | نسخه دقیق Package |
| قابل ویرایش       | معمولاً خودکار     |
| Dependencyها      | Dependency Tree   |

---

# 68.25 - فیلد optionalDependencies

Dependencyهای اختیاری:

```json id="r7m3qa"
"optionalDependencies":{

"package":"1.0.0"

}
```

اگر نصب نشوند پروژه نباید کاملاً خراب شود.

---

# 68.26 - فیلد peerDependencies

برای Packageهایی که انتظار دارند Package دیگری وجود داشته باشد.

مثال:

```json id="n5v7cx"
"peerDependencies":{

"react":">=18"

}
```

بیشتر در ساخت Library استفاده می‌شود.

---

# 68.27 - Override کردن Dependency

در npm جدید:

```json id="q4z8bh"
"overrides":{

"lodash":"4.17.21"

}
```

برای کنترل نسخه‌های داخلی استفاده می‌شود.

# 68.30 - نکات حرفه‌ای

* package.json را مرتب نگه دار.
* Scriptهای استاندارد تعریف کن.
* نسخه Node پروژه را مشخص کن.
* از `private:true` برای پروژه‌های داخلی استفاده کن.
* Dependencyهای اضافی را حذف کن.
* قبل از انتشار Package اطلاعات کامل اضافه کن.
* از Semantic Versioning استفاده کن.
* package-lock.json را همراه پروژه نگه دار.
* Scriptهای پیچیده را به فایل جدا منتقل کن.

# جمع‌بندی

فایل **package.json** مرکز کنترل پروژه‌های Node.js است.

هر توسعه‌دهنده حرفه‌ای Node.js باید بتواند:

* Dependencyها را مدیریت کند.
* Scriptهای مناسب بسازد.
* نسخه‌ها را کنترل کند.
* Module System را تنظیم کند.
* پروژه را برای محیط Production آماده کند.

تسلط بر package.json یکی از پایه‌های اصلی ساخت پروژه‌های استاندارد و قابل نگهداری در اکوسیستم Node.js است.
