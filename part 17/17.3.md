# بخش ۱۷ - فریمورک‌های Node.js

# فصل 137 - NestJS

## مقدمه

تا اینجا با JavaScript، Node.js، ساخت Web Server، REST API، پایگاه داده، احراز هویت، تست، امنیت، Performance و همچنین فریمورک‌هایی مثل Express.js و Fastify آشنا شده‌ایم.

در این فصل به سراغ **NestJS** می‌رویم.

NestJS یکی از فریمورک‌های مهم اکوسیستم Node.js برای ساخت Backendهای ساختاریافته و قابل توسعه است. این فریمورک روی Node.js ساخته شده و معمولاً از TypeScript استفاده می‌کند.

هدف ما در این فصل این نیست که فقط چند دستور NestJS را یاد بگیریم؛ بلکه قرار است بفهمیم:

* NestJS چیست؟
* چرا باید از آن استفاده کنیم؟
* ساختار یک پروژه NestJS چگونه است؟
* Module چیست؟
* Controller چیست؟
* Service چیست؟
* Dependency Injection چگونه کار می‌کند؟
* Request و Response چگونه مدیریت می‌شوند؟
* Validation چگونه انجام می‌شود؟
* Exceptionها چگونه مدیریت می‌شوند؟
* Middleware، Guard، Pipe، Interceptor و Filter چه هستند؟
* چگونه به Database متصل شویم؟
* Authentication و Authorization را چگونه پیاده کنیم؟
* چگونه API حرفه‌ای بسازیم؟
* چگونه پروژه را تست کنیم؟
* چگونه پروژه NestJS را Deploy کنیم؟
* و در نهایت چگونه یک پروژه واقعی با NestJS بسازیم؟

> در این فصل فرض می‌کنیم خواننده مباحث پایه JavaScript و Node.js فصل‌های قبلی را مطالعه کرده است.

# 1. NestJS چیست؟

NestJS یک فریمورک برای ساخت برنامه‌های سمت سرور با Node.js است.

NestJS امکانات و ساختار مشخصی برای توسعه Backend در اختیار برنامه‌نویس قرار می‌دهد.

در NestJS می‌توان برنامه‌هایی مانند موارد زیر ساخت:

* REST API
* GraphQL API
* Microservice
* WebSocket Server
* سیستم احراز هویت
* فروشگاه اینترنتی
* سیستم مدیریت کاربران
* سیستم پرداخت
* سیستم رزرو
* CMS
* SaaS
* Backend اپلیکیشن موبایل
* سیستم‌های Real-Time

NestJS به صورت پیش‌فرض روی معماری ماژولار و Dependency Injection تأکید زیادی دارد.

# 2. چرا NestJS؟

فرض کنید یک پروژه Node.js ساده با چند هزار خط کد نوشته‌ایم.

اگر ساختار مناسبی نداشته باشیم، به مرور با مشکلاتی مانند موارد زیر مواجه می‌شویم:

```text
Controllerهای بزرگ
Serviceهای شلوغ
وابستگی‌های زیاد
کد تکراری
تست سخت
تغییرات سخت
نگهداری دشوار
```

NestJS تلاش می‌کند ساختار مشخصی برای پروژه ایجاد کند.

برای مثال:

```text
src/
├── users/
│   ├── users.controller.ts
│   ├── users.service.ts
│   └── users.module.ts
│
├── products/
│   ├── products.controller.ts
│   ├── products.service.ts
│   └── products.module.ts
│
└── app.module.ts
```

این ساختار باعث می‌شود بخش‌های مختلف برنامه از یکدیگر تفکیک شوند.

# 3. NestJS و Express.js

NestJS خودش یک HTTP Server مستقل با منطق کاملاً متفاوت از Node.js ایجاد نمی‌کند.

NestJS می‌تواند روی HTTP adapterهایی مانند Express کار کند و امکان استفاده از Fastify را نیز فراهم می‌کند.

بنابراین بهتر است NestJS را جایگزین مفاهیم Node.js ندانیم.

بلکه:

```text
Node.js
   ↓
HTTP Framework / Adapter
   ↓
NestJS
   ↓
Application Architecture
```

یکی از مزیت‌های مهم NestJS این است که بسیاری از مشکلات معماری را در سطح Framework برای ما ساختاریافته می‌کند.

# 12. ساخت Controller

```bash

```


```ts
import { Controller, Get } from '@nestjs/common';

export class UsersController {

    ];
  }
```

# 13. Routing در NestJS

در NestJS Routing با Decoratorها تعریف می‌شود.

مثلاً:

```ts
@Controller('users')
export class UsersController {

  @Get()
  findAll() {
    return [];
  }

  @Get(':id')
  findOne() {
    return {};
  }

  @Post()
  create() {
    return {};
  }

  @Patch(':id')
  update() {
    return {};
  }

  @Delete(':id')
  remove() {
    return {};
  }
}
```

مسیرها:

```text
GET     /users
GET     /users/:id
POST    /users
PATCH   /users/:id
DELETE  /users/:id
```

# 15. Route Parameter

برای دریافت پارامتر URL از `@Param()` استفاده می‌کنیم.

```ts

    id,
  };

```

# 20. Dependency Injection

یکی از مهم‌ترین ویژگی‌های NestJS، **Dependency Injection** است.

مثلاً Controller به UsersService نیاز دارد.

```ts
@Controller('users')
export class UsersController {

  constructor(
    private readonly usersService: UsersService,
  ) {}

}
```

NestJS خودش نمونه `UsersService` را ایجاد و در اختیار Controller قرار می‌دهد.

---

# 21. چرا Dependency Injection مهم است؟

بدون DI ممکن است خودمان وابستگی‌ها را ایجاد کنیم:

```ts
const usersService = new UsersService();
```

اما در معماری بزرگ این کار می‌تواند وابستگی‌ها را پیچیده کند.

با DI:

```text
Controller
     ↓
UsersService
     ↓
Repository
     ↓
Database
```

هر بخش مسئولیت خودش را دارد.

مزایا:

* کاهش Coupling
* تست‌پذیری بهتر
* نگهداری آسان‌تر
* جایگزینی وابستگی‌ها
* معماری تمیزتر

# 22. Providers

در NestJS مفهومی به نام Provider داریم.

Serviceها معمولاً Provider هستند.

مثلاً:

```ts
@Module({
  providers: [UsersService],
})
export class UsersModule {}
```

Provider می‌تواند انواع مختلفی داشته باشد و محدود به Service نیست.

# 23. Module و Dependency Injection

یک Module می‌تواند Providerهای خودش را تعریف کند:

```ts
@Module({
  controllers: [UsersController],
  providers: [UsersService],
})
export class UsersModule {}
```

ساختار:

```text
UsersModule
├── UsersController
└── UsersService
```

---

# 24. Export و Import در Moduleها

اگر Service یک Module را بخواهیم در Module دیگری استفاده کنیم، باید آن را Export کنیم.

```ts
@Module({
  providers: [UsersService],
  exports: [UsersService],
})
export class UsersModule {}
```

سپس:

```ts
@Module({
  imports: [UsersModule],
})
export class OrdersModule {}
```

# 27. Validation

یکی از قابلیت‌های مهم NestJS، امکان استفاده از Validation Pipeline است.

پکیج‌های رایج:

```bash
npm install class-validator class-transformer
```

مثلاً:

```ts
import { IsEmail, IsString, MinLength } from 'class-validator';

export class CreateUserDto {

  @IsString()
  name: string;

  @IsEmail()
  email: string;

  @MinLength(8)
  password: string;
}
```

---

# 28. ValidationPipe

در `main.ts`:

```ts
import { ValidationPipe } from '@nestjs/common';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      transform: true,
    }),
  );

  await app.listen(3000);
}
```

اکنون داده‌های ورودی قبل از رسیدن به منطق اصلی بررسی می‌شوند.

# 31. Exception Handling

در NestJS برای خطاهای HTTP می‌توان از Exceptionهای آماده استفاده کرد.

مثلاً:

```ts
throw new NotFoundException('User not found');
```

یا:

```ts
throw new BadRequestException('Invalid data');
```

نمونه:

```ts
import { NotFoundException } from '@nestjs/common';

findOne(id: number) {
  const user = null;

  if (!user) {
    throw new NotFoundException('User not found');
  }

  return user;
}
```

# 69. نکات حرفه‌ای

### ۱. Controller را کوچک نگه دارید

Controller بهتر است وظیفه HTTP را مدیریت کند و Business Logic در Service یا لایه‌های مناسب قرار بگیرد.

### ۲. DTOهای مشخص بسازید

برای ورودی‌های مختلف DTO جداگانه ایجاد کنید.

### ۳. Validation را Global کنید

Validation یکپارچه باعث کاهش خطا می‌شود.

### ۴. Feature-Based Architecture را جدی بگیرید

به جای یک پوشه بزرگ برای تمام Controllerها و Serviceها، قابلیت‌های مرتبط را کنار هم قرار دهید.

### ۵. Dependency Injection را درست استفاده کنید

DI باید وابستگی‌ها را مدیریت کند، نه اینکه صرفاً برای استفاده از Decoratorها به کار رود.

### ۶. Logging استاندارد داشته باشید

در Production باید بتوان مشکلات را بررسی کرد.

### ۷. Configuration را مدیریت کنید

اطلاعات محیطی را از Source Code جدا کنید.

### ۸. API Documentation داشته باشید

Swagger/OpenAPI برای پروژه‌های API بسیار مفید است.

### ۹. تست خودکار بنویسید

خصوصاً برای Business Logic و Endpointهای مهم.

### ۱۰. از Overengineering دوری کنید

هر پروژه‌ای به Microservice، CQRS یا Clean Architecture پیچیده نیاز ندارد.


### قوانین

* عنوان حداقل طول مشخصی داشته باشد.
* Status فقط مقادیر مجاز را قبول کند.
* Priority فقط مقادیر مجاز را قبول کند.
* خطاها Response استاندارد داشته باشند.
* API با Swagger مستند شود.
* برای بخش‌های مهم تست نوشته شود.
