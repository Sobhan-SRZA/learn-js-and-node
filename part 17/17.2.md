# فصل 136 - Fastify

## مقدمه

در فصل قبل با Express.js آشنا شدیم و یک REST API ساختیم.

در این فصل سراغ یکی دیگر از فریمورک‌های مهم Node.js یعنی **Fastify** می‌رویم.

Fastify یک Web Framework برای Node.js است که با تمرکز بر **Performance، مصرف مناسب منابع، ساختار Plugin-based و Schema-based Validation/Serialization** طراحی شده است.

هدف ما در این فصل فقط یادگیری چند دستور Fastify نیست؛ بلکه می‌خواهیم بفهمیم:

* Fastify چیست؟
* چه تفاوتی با Express دارد؟
* چگونه یک Server بسازیم؟
* Route چگونه تعریف می‌شود؟
* Request و Response چگونه مدیریت می‌شوند؟
* Middleware و Hook چه تفاوتی دارند؟
* Plugin چیست؟
* Validation و Serialization چگونه انجام می‌شوند؟
* چگونه پروژه را ساختاربندی کنیم؟
* چگونه یک REST API واقعی‌تر بسازیم؟

در پایان نیز یک پروژه عملی و یک مینی‌پروژه خواهیم داشت.

---

# 1. Fastify چیست؟

Fastify یک Web Framework برای Node.js است که برای ساخت:

* REST API
* Web Server
* Backend Application
* Microservice
* APIهای High Performance

استفاده می‌شود.

نمونه ساده:

```js
const fastify = require("fastify")({
  logger: true,
});

fastify.get("/", async (request, reply) => {
  return {
    message: "Hello Fastify",
  };
});

fastify.listen({ port: 3000 });
```

در این مثال:

```js
require("fastify")
```

فریمورک Fastify را وارد می‌کند.

سپس:

```js
fastify.get()
```

یک Route ایجاد می‌کند.

و:

```js
fastify.listen()
```

Server را اجرا می‌کند.

---

# 2. چرا Fastify؟

یکی از دلایل اصلی استفاده از Fastify تمرکز آن بر Performance است.

اما Performance تنها ویژگی Fastify نیست.

ویژگی‌های مهم آن عبارت‌اند از:

* Performance بالا
* معماری Plugin-based
* Schema-based Validation
* Serialization
* Logger داخلی
* TypeScript Support
* ساختار مناسب برای پروژه‌های بزرگ
* Lifecycle Hooks
* قابلیت توسعه بالا

به همین دلیل Fastify می‌تواند گزینه مناسبی برای APIهای پرترافیک و سرویس‌های Backend باشد.

# 4. اولین برنامه Fastify

فایل:

```text
app.js
```

ایجاد کنید:

```js
const fastify = require("fastify")({
  logger: true,
});

fastify.get("/", async (request, reply) => {
  return {
    message: "Hello Fastify",
  };
});

const start = async () => {
  try {
    await fastify.listen({
      port: 3000,
    });
  } catch (error) {
    fastify.log.error(error);

    process.exit(1);
  }
};

start();
```

سپس:

```bash
node app.js
```

Server روی:

```text
http://localhost:3000
```

اجرا می‌شود.

در Fastify معمولاً با دو شیء اصلی کار می‌کنیم:


`reply` برای کنترل Response استفاده می‌شود.

# 11. Query String

مثلاً:


# 13. Route با Schema

یکی از تفاوت‌های مهم Fastify با Express استفاده قدرتمند از Schema است.

مثلاً:

```js
fastify.post(
  "/users",
  {
    schema: {
      body: {
        type: "object",
        required: ["name", "age"],
        properties: {
          name: {
            type: "string",
          },
          age: {
            type: "integer",
          },
        },
      },
    },
  },
  async (request, reply) => {
    return reply.code(201).send({
      name: request.body.name,
      age: request.body.age,
    });
  }
);
```

در اینجا Schema مشخص می‌کند Body باید چه ساختاری داشته باشد.

---

# 14. چرا Schema مهم است؟

فرض کنید API انتظار دارد:

```json
{
  "name": "Ali",
  "age": 20
}
```

اما Client ارسال کند:

```json
{
  "name": 123,
  "age": "hello"
}
```

Schema می‌تواند داده نامعتبر را قبل از رسیدن به منطق اصلی برنامه رد کند.

ساختار:

```text
Request
   ↓
Schema Validation
   ↓
Handler
   ↓
Service
   ↓
Response
```

به این ترتیب Validation به شکل منظم‌تری وارد Lifecycle درخواست می‌شود.

---

# 15. Schema برای Response

Schema فقط برای Request نیست.

می‌توانیم Response Schema نیز تعریف کنیم:

```js
fastify.get("/users", {
  schema: {
    response: {
      200: {
        type: "object",
        properties: {
          data: {
            type: "array",
            items: {
              type: "object",
              properties: {
                id: {
                  type: "integer",
                },
                name: {
                  type: "string",
                },
              },
            },
          },
        },
      },
    },
  },
}, async () => {
  return {
    data: [
      {
        id: 1,
        name: "Ali",
      },
    ],
  };
});
```

Response Schema علاوه بر مشخص کردن قرارداد Response می‌تواند به Serialization نیز کمک کند.

# 21. Hook

Fastify مفهوم مهمی به نام Hook دارد.

Hook به ما اجازه می‌دهد در مراحل مختلف Lifecycle درخواست کدی را اجرا کنیم.

مثلاً:

```js
fastify.addHook("onRequest", async (request, reply) => {
  console.log("Request received");
});
```

Hookهای مختلفی برای مراحل مختلف Lifecycle وجود دارند.

* `onRequest`

* `preValidation`
* `preHandler`
* `preSerialization`
* `onSend`
* `onResponse`

هرکدام در بخش متفاوتی از Lifecycle اجرا می‌شوند.

# 23. Middleware در Fastify

در Express مفهوم Middleware بسیار مرکزی است.

در Fastify معماری اصلی بیشتر بر:

Fastify امکان استفاده از Middleware را نیز دارد، اما برای بسیاری از نیازهای داخلی Fastify بهتر است از ابزارهای مخصوص خود Framework مانند Hookها استفاده کنیم.

# 24. Plugin

یکی از مهم‌ترین مفاهیم Fastify Plugin است.

مثلاً:

```js
async function userPlugin(fastify, options) {
  fastify.decorate("users", [
    {
      id: 1,
      name: "Ali",
    },
  ]);
}

module.exports = userPlugin;
```

ثبت:

```js
fastify.register(userPlugin);
```

Pluginها باعث می‌شوند قابلیت‌های مختلف را بتوانیم به صورت ماژولار به Application اضافه کنیم.

---

# 25. Register

برای ثبت Plugin:

```js
fastify.register(plugin);
```

مثلاً:

```js
fastify.register(require("./plugins/users"));
```

این معماری به ساخت پروژه‌های بزرگ کمک می‌کند.

---

# 26. Decorator

Fastify امکان اضافه کردن قابلیت یا Property به Instance را با `decorate` فراهم می‌کند.

مثلاً:

```js
fastify.decorate("appName", "Task API");
```

سپس:

```js
fastify.get("/", async () => {
  return {
    name: fastify.appName,
  };
});
```

---

# 27. Decorate Request

می‌توانیم Request را نیز Decorate کنیم.

مثلاً:

```js
fastify.decorateRequest("user", null);
```

بعداً می‌توانیم اطلاعات User احراز هویت‌شده را روی Request قرار دهیم.

---

# 28. Decorate Reply

مشابه Request می‌توان Reply را نیز توسعه داد.

این قابلیت در Pluginهای پروژه‌های بزرگ کاربرد زیادی دارد.

---

# 29. Encapsulation

یکی از مفاهیم مهم Fastify **Encapsulation** است.

Pluginها می‌توانند Scope جداگانه داشته باشند.

مثلاً:

```js
fastify.register(async function (instance) {
  instance.decorate("name", "Users");
});
```

Decorator مربوط به همان Scope خواهد بود.

این موضوع کمک می‌کند Pluginها وابستگی‌ها و قابلیت‌های خود را به صورت کنترل‌شده مدیریت کنند.

# 36. Custom Error

می‌توانیم Errorهای مخصوص Application ایجاد کنیم:

```js
class AppError extends Error {
  constructor(message, statusCode) {
    super(message);

    this.statusCode = statusCode;
  }
}
```

سپس:

```js
throw new AppError("User not found", 404);
```

و در Error Handler:

```js
fastify.setErrorHandler((error, request, reply) => {
  const statusCode = error.statusCode || 500;

  reply.code(statusCode).send({
    message: error.message,
  });
});
```

# 55. Service

فایل:

```text
src/services/task.service.js
```

```js
const tasks = require("../data/tasks");

const getTasks = ({ search, completed }) => {
  let result = [...tasks];

  if (search) {
    const query = search.toLowerCase();

    result = result.filter((task) =>
      task.title.toLowerCase().includes(query)
    );
  }

  if (completed !== undefined) {
    result = result.filter(
      (task) => task.completed === (completed === "true")
    );
  }

  return result;
};

const getTaskById = (id) => {
  return tasks.find((task) => task.id === id);
};

const createTask = (title) => {
  const task = {
    id: Date.now(),
    title,
    completed: false,
  };

  tasks.push(task);

  return task;
};

const updateTask = (id, data) => {
  const task = getTaskById(id);

  if (!task) {
    return null;
  }

  if (data.title !== undefined) {
    task.title = data.title;
  }

  if (data.completed !== undefined) {
    task.completed = data.completed;
  }

  return task;
};

const deleteTask = (id) => {
  const index = tasks.findIndex((task) => task.id === id);

  if (index === -1) {
    return false;
  }

  tasks.splice(index, 1);

  return true;
};

module.exports = {
  getTasks,
  getTaskById,
  createTask,
  updateTask,
  deleteTask,
};
```

# 56. Controller

فایل:

```text
src/controllers/task.controller.js
```

```js
const taskService = require("../services/task.service");

const getTasks = async (request) => {
  const tasks = taskService.getTasks(request.query);

  return {
    data: tasks,
  };
};

const getTask = async (request, reply) => {
  const id = request.params.id;

  const task = taskService.getTaskById(id);

  if (!task) {
    return reply.code(404).send({
      message: "Task not found",
    });
  }

  return {
    data: task,
  };
};

const createTask = async (request, reply) => {
  const { title } = request.body;

  const task = taskService.createTask(title.trim());

  return reply.code(201).send(task);
};

const updateTask = async (request, reply) => {
  const id = request.params.id;

  const task = taskService.updateTask(id, request.body);

  if (!task) {
    return reply.code(404).send({
      message: "Task not found",
    });
  }

  return task;
};

const deleteTask = async (request, reply) => {
  const id = request.params.id;

  const deleted = taskService.deleteTask(id);

  if (!deleted) {
    return reply.code(404).send({
      message: "Task not found",
    });
  }

  return reply.code(204).send();
};

module.exports = {
  getTasks,
  getTask,
  createTask,
  updateTask,
  deleteTask,
};
```

# 65. مقایسه Express و Fastify

| موضوع         | Express                 | Fastify                    |
| ------------- | ----------------------- | -------------------------- |
| سادگی شروع    | بسیار خوب               | بسیار خوب                  |
| Middleware    | بسیار رایج              | Hooks/Plugins محور         |
| Plugin        | دارد                    | بخش بسیار مهم معماری       |
| Schema        | به شکل داخلی مرکزی نیست | بخش مهم Framework          |
| Validation    | معمولاً با ابزار جانبی   | Schema-based               |
| Serialization | وجود دارد               | تمرکز ویژه                 |
| Logger داخلی  | نیازمند ابزار/تنظیمات   | دارد                       |
| TypeScript    | پشتیبانی می‌شود          | پشتیبانی بسیار خوب         |
| اکوسیستم      | بسیار بزرگ              | در حال رشد                 |
| Performance   | خوب                     | تمرکز ویژه روی Performance |

نباید نتیجه بگیریم که Fastify همیشه بهتر از Express است.

انتخاب Framework باید بر اساس نیاز پروژه انجام شود.

## اشتباه 4: اشتباه گرفتن Hook و Middleware

## اشتباه 5: استفاده بیش از حد از Decorator

داده اولیه:

```js
const products = [
  {
    id: 1,
    name: "Laptop",
    price: 1200,
    category: "electronics",
    stock: 10,
  },
  {
    id: 2,
    name: "Keyboard",

];
```

Service:

```js
const products = require("../data/products");

const getProducts = ({
  search,
  category,
  minPrice,
  maxPrice,
}) => {
  let result = [...products];

  if (search) {
    const query = search.toLowerCase();

    result = result.filter((product) =>
      product.name.toLowerCase().includes(query)
    );
  }

  if (category) {
    result = result.filter(
      (product) => product.category === category
    );
  }

  if (minPrice !== undefined) {
    result = result.filter(
      (product) => product.price >= Number(minPrice)
    );
  }

  if (maxPrice !== undefined) {
    result = result.filter(
      (product) => product.price <= Number(maxPrice)
    );
  }

  return result;
};

const getProductById = (id) => {
  return products.find((product) => product.id === id);
};

const createProduct = (data) => {
  const product = {
    id: Date.now(),
    name: data.name.trim(),
    price: data.price,
    category: data.category.trim(),
    stock: data.stock,
  };

  products.push(product);

  return product;
};

const updateProduct = (id, data) => {
  const product = getProductById(id);

  if (!product) {
    return null;
  }

  if (data.name !== undefined) {
    product.name = data.name.trim();
  }

  if (data.price !== undefined) {
    product.price = data.price;
  }

  if (data.category !== undefined) {
    product.category = data.category.trim();
  }

  if (data.stock !== undefined) {
    product.stock = data.stock;
  }

  return product;
};

const deleteProduct = (id) => {
  const index = products.findIndex(
    (product) => product.id === id
  );

  if (index === -1) {
    return false;
  }

  products.splice(index, 1);

  return true;
};

module.exports = {
  getProducts,
  getProductById,
  createProduct,
  updateProduct,
  deleteProduct,
};
```

Controller:

```js
const productService = require("../services/product.service");

const getProducts = async (request) => {
  const products = productService.getProducts(request.query);

  return {
    data: products,
  };
};

const getProduct = async (request, reply) => {
  const product = productService.getProductById(
    request.params.id
  );

  if (!product) {
    return reply.code(404).send({
      message: "Product not found",
    });
  }

  return {
    data: product,
  };
};

const createProduct = async (request, reply) => {
  const product = productService.createProduct(request.body);

  return reply.code(201).send({
    data: product,
  });
};

const updateProduct = async (request, reply) => {
  const product = productService.updateProduct(
    request.params.id,
    request.body
  );

  if (!product) {
    return reply.code(404).send({
      message: "Product not found",
    });
  }

  return {
    data: product,
  };
};

const deleteProduct = async (request, reply) => {
  const deleted = productService.deleteProduct(
    request.params.id
  );

  if (!deleted) {
    return reply.code(404).send({
      message: "Product not found",
    });
  }

  return reply.code(204).send();
};

module.exports = {
  getProducts,
  getProduct,
  createProduct,
  updateProduct,
  deleteProduct,
};
```

Router:

```js
const controller = require("../controllers/product.controller");

async function productRoutes(fastify) {
  fastify.get("/", controller.getProducts);

  fastify.get("/:id", controller.getProduct);

  fastify.post(
    "/",
    {
      schema: {
        body: {
          type: "object",
          required: [
            "name",
            "price",
            "category",
            "stock",
          ],
          properties: {
            name: {
              type: "string",
              minLength: 1,
            },
            price: {
              type: "number",
              minimum: 0,
            },
            category: {
              type: "string",
            },
            stock: {
              type: "integer",
              minimum: 0,
            },
          },
        },
      },
    },
    controller.createProduct
  );

  fastify.patch("/:id", controller.updateProduct);

  fastify.delete("/:id", controller.deleteProduct);
}

module.exports = productRoutes;
```

# 75. جمع‌بندی

در این فصل با Fastify آشنا شدیم.

مهم‌ترین مفاهیمی که یاد گرفتیم:

```text
Fastify
   ↓
Routes
   ↓
Request / Reply
   ↓
Schema
   ↓
Validation
   ↓
Hooks
   ↓
Plugins
   ↓
Decorators
   ↓
Encapsulation
   ↓
Controllers
   ↓
Services
   ↓
Error Handling
```

همچنین یک Task API و یک مینی‌پروژه Product API ساختیم.

مهم‌ترین تفاوت ذهنی بین Express و Fastify این است که در Express معمولاً Middleware و Routing نقطه شروع معماری هستند، اما در Fastify باید علاوه بر Routeها، مفاهیمی مانند **Schema، Plugin، Hook، Decorator و Encapsulation** را نیز به خوبی درک کنیم.

Fastify را نباید صرفاً به عنوان Frameworkی برای ساخت APIهای سریع‌تر یاد گرفت؛ بلکه باید معماری آن را شناخت و از قابلیت‌های آن برای ساخت Backendهای ماژولار، قابل تست و قابل توسعه استفاده کرد.

در فصل بعد سراغ **NestJS** می‌رویم؛ فریمورکی با معماری ساختاریافته‌تر که مفاهیمی مانند Module، Controller، Service، Dependency Injection، Decorator و معماری سازمان‌یافته را در مرکز توسعه Backend قرار می‌دهد.
