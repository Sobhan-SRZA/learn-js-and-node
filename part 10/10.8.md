# فصل 81 - GraphQL

## GraphQL چیست؟

تا اینجا با **REST API** آشنا شدیم.

در REST برای دریافت اطلاعات معمولاً چندین Endpoint مختلف وجود دارد.

مثلاً:

```text
GET /users

GET /posts

GET /comments
```

اما گاهی اوقات کلاینت فقط به بخشی از اطلاعات نیاز دارد.

فرض کنید فقط نام و ایمیل کاربران را می‌خواهیم.

در REST معمولاً کل اطلاعات کاربر ارسال می‌شود:

```json
{
  "id": 1,
  "name": "Ali",
  "email": "ali@example.com",
  "age": 25,
  "address": "...",
  "phone": "...",
  "createdAt": "...",
  "updatedAt": "..."
}
```

در حالی که شاید فقط این دو فیلد مورد نیاز باشد:

```json
{
  "name": "Ali",
  "email": "ali@example.com"
}
```

اینجاست که **GraphQL** وارد عمل می‌شود.

---

# GraphQL چیست؟

GraphQL یک **زبان پرس‌وجو (Query Language)** برای APIها و همچنین یک **Runtime** برای اجرای این پرس‌وجوها است.

GraphQL توسط Meta (در زمان توسعه با نام Facebook) طراحی شد و در سال ۲۰۱۵ به‌صورت متن‌باز منتشر شد.

در GraphQL، کلاینت مشخص می‌کند دقیقاً چه اطلاعاتی می‌خواهد و سرور همان اطلاعات را بازمی‌گرداند.

---

# REST در مقابل GraphQL

فرض کنید اطلاعات زیر وجود دارد:

* کاربران
* پست‌ها
* نظرات

در REST ممکن است نیاز باشد:

```text
GET /users/1

GET /users/1/posts

GET /posts/12/comments
```

اما در GraphQL تنها یک درخواست کافی است.

---

# معماری GraphQL

```text
Client
     │
 GraphQL Query
     │
GraphQL Server
     │
Database
```

تمام درخواست‌ها معمولاً به یک Endpoint ارسال می‌شوند.

مثلاً:

```text
/graphql
```

---

# Query چیست؟

برای دریافت اطلاعات از Query استفاده می‌شود.

نمونه:

```graphql
query {

  users {

    id
    name
    email

  }

}
```

پاسخ:

```json
{
  "data": {
    "users": [
      {
        "id": 1,
        "name": "Ali",
        "email": "ali@example.com"
      }
    ]
  }
}
```

---

# انتخاب فیلدها

یکی از مهم‌ترین ویژگی‌های GraphQL این است که فقط فیلدهای مورد نیاز دریافت می‌شوند.

مثال:

```graphql
query {

  users {

    name

  }

}
```

پاسخ:

```json
{
  "data": {
    "users": [
      {
        "name": "Ali"
      }
    ]
  }
}
```

---

# دریافت یک کاربر

```graphql
query {

  user(id: 5) {

    id
    name
    email

  }

}
```

---

# Mutation چیست؟

برای تغییر داده‌ها از Mutation استفاده می‌شود.

مثلاً ایجاد کاربر:

```graphql
mutation {

  createUser(

    name: "Sara"

    age: 23

  ) {

    id
    name

  }

}
```

---

# بروزرسانی اطلاعات

```graphql
mutation {

  updateUser(

    id: 5

    age: 30

  ) {

    id
    age

  }

}
```

---

# حذف اطلاعات

```graphql
mutation {

  deleteUser(id: 5) {

    id

  }

}
```

---

# Subscription چیست؟

Subscription برای دریافت اطلاعات لحظه‌ای (Real-Time) استفاده می‌شود.

نمونه:

```graphql
subscription {

  newMessage {

    id
    text
    sender

  }

}
```

در بسیاری از پیاده‌سازی‌ها، Subscription روی WebSocket اجرا می‌شود تا سرور بتواند هنگام وقوع رویداد، اطلاعات جدید را به کلاینت ارسال کند.

---

# Schema

تمام APIهای GraphQL دارای Schema هستند.

Schema مشخص می‌کند:

* چه داده‌هایی وجود دارد.
* چه Queryهایی قابل اجرا هستند.
* چه Mutationهایی وجود دارند.
* نوع هر فیلد چیست.

نمونه:

```graphql
type User {

  id: ID!

  name: String!

  age: Int!

}
```

---

# Type

در GraphQL هر داده یک Type دارد.

نمونه:

```graphql
type Product {

  id: ID!

  title: String!

  price: Float!

}
```

---

# Scalar Typeها

مهم‌ترین Typeهای داخلی:

```text
Int

Float

String

Boolean

ID
```

---

# Non Null

علامت:

```graphql
String!
```

یعنی این مقدار نباید `null` باشد.

---

# List

```graphql
[User]
```

یعنی آرایه‌ای از کاربران.

---

# Resolver

Resolver تابعی است که داده واقعی را برمی‌گرداند.

نمونه:

```javascript
const resolvers = {

  Query: {

    users() {

      return database.users;

    }

  }

};
```

---

# Nested Query

GraphQL از داده‌های تو در تو پشتیبانی می‌کند.

```graphql
query {

  users {

    name

    posts {

      title

    }

  }

}
```

---

# مزایای GraphQL

* دریافت فقط اطلاعات مورد نیاز
* کاهش حجم داده‌های انتقالی
* یک Endpoint واحد
* مناسب برای موبایل
* کاهش تعداد درخواست‌ها
* Schema مشخص
* تایپ‌گذاری قوی
* مستندسازی بهتر

---

# محدودیت‌های GraphQL

* پیچیدگی بیشتر نسبت به REST
* نیاز به طراحی دقیق Schema
* مدیریت کش (Cache) دشوارتر
* امکان اجرای Queryهای بسیار سنگین در صورت عدم محدودسازی
* برای APIهای ساده ممکن است REST گزینه مناسب‌تری باشد.

---

# GraphQL در Node.js

در Node.js می‌توان GraphQL را با کتابخانه‌هایی مانند:

* Apollo Server
* GraphQL.js
* Mercurius (برای Fastify)
* Yoga GraphQL

پیاده‌سازی کرد.

در فصل‌های مربوط به فریمورک‌ها، ساخت یک GraphQL API به‌صورت عملی بررسی خواهد شد.

---

# مقایسه REST و GraphQL

| REST                     | GraphQL                    |
| ------------------------ | -------------------------- |
| چندین Endpoint           | معمولاً یک Endpoint         |
| سرور داده را تعیین می‌کند | کلاینت داده را تعیین می‌کند |
| احتمال Over Fetching     | بسیار کم                   |
| احتمال Under Fetching    | بسیار کم                   |
| مناسب APIهای ساده        | مناسب داده‌های پیچیده       |
| مبتنی بر Resource        | مبتنی بر Query             |

---

# چه زمانی از GraphQL استفاده کنیم؟

GraphQL گزینه مناسبی است اگر:

* روابط بین داده‌ها پیچیده است.
* کلاینت‌های مختلف (وب، موبایل و ...) نیازهای متفاوتی دارند.
* می‌خواهید تعداد درخواست‌ها کاهش یابد.
* پروژه بزرگ و در حال توسعه است.

در پروژه‌های ساده یا سرویس‌هایی با عملیات CRUD محدود، REST معمولاً انتخاب ساده‌تر و کم‌هزینه‌تری است.

---

# اشتباهات رایج

### ۱- استفاده از GraphQL برای هر پروژه

GraphQL همیشه بهترین انتخاب نیست. برای بسیاری از APIهای ساده، REST پیاده‌سازی و نگهداری آسان‌تری دارد.

---

### ۲- طراحی Schema نامناسب

نام‌گذاری نامناسب Typeها یا طراحی غیرمنطقی روابط باعث پیچیدگی API می‌شود.

---

### ۳- نوشتن Resolverهای کند

اگر هر Resolver به‌صورت جداگانه به پایگاه داده مراجعه کند، ممکن است تعداد زیادی Query غیرضروری اجرا شود.

---

### ۴- عدم اعتبارسنجی ورودی‌ها

تمام داده‌های ورودی در Mutationها باید اعتبارسنجی شوند.

---

### ۵- عدم محدود کردن Queryهای سنگین

اجازه اجرای Queryهای بسیار عمیق یا پیچیده می‌تواند باعث کاهش شدید عملکرد سرور شود.

---

# نکات حرفه‌ای

* Schema را ساده، خوانا و قابل توسعه طراحی کنید.
* از Typeهای سفارشی برای ساختاردهی بهتر داده‌ها استفاده کنید.
* Queryها و Mutationها را بر اساس دامنه (Domain) سازمان‌دهی کنید.
* برای جلوگیری از اجرای Queryهای سنگین، محدودیت عمق (Depth Limit) و پیچیدگی Query را اعمال کنید.
* از DataLoader برای کاهش مشکل **N+1 Query** استفاده کنید.
* احراز هویت و مجوزدهی را در Resolverها یا لایه‌های میانی پیاده‌سازی کنید.
* از ابزارهایی مانند GraphQL Playground یا Apollo Sandbox برای تست API استفاده کنید.

# مینی‌پروژه

## طراحی GraphQL API برای فروشگاه اینترنتی

### هدف

طراحی یک GraphQL API برای مدیریت محصولات، کاربران و سفارش‌ها با استفاده از Query، Mutation و Subscription.

### Typeها

* User
* Product
* Category
* Order
* OrderItem

### Queryها

* دریافت تمام محصولات
* دریافت اطلاعات یک محصول
* جستجوی محصولات
* دریافت کاربران
* دریافت سفارش‌های یک کاربر
* دریافت دسته‌بندی‌ها

### Mutationها

* ایجاد محصول
* ویرایش محصول
* حذف محصول
* ثبت کاربر
* ثبت سفارش
* لغو سفارش

### Subscriptionها

* اطلاع از ثبت سفارش جدید
* اطلاع از تغییر موجودی محصول
* اطلاع از ایجاد محصول جدید

### قابلیت‌های تکمیلی

* صفحه‌بندی نتایج
* فیلتر محصولات بر اساس قیمت یا دسته‌بندی
* مرتب‌سازی نتایج
* احراز هویت کاربران با JWT
* اعتبارسنجی داده‌های ورودی
* محدودسازی عمق و پیچیدگی Queryها
* کاهش تعداد درخواست‌های پایگاه داده با DataLoader
* طراحی Schema ماژولار و قابل توسعه برای پروژه‌های بزرگ
