# فصل 79 - WebSocket

## WebSocket چیست؟

تا اینجا با پروتکل HTTP آشنا شدیم. در HTTP، ارتباط به این صورت است که **کلاینت درخواست (Request)** ارسال می‌کند و **سرور پاسخ (Response)** می‌دهد. پس از ارسال پاسخ، ارتباط پایان می‌یابد.

این مدل برای بسیاری از برنامه‌ها مناسب است، اما برای برنامه‌هایی که نیاز به **ارتباط لحظه‌ای (Real-Time)** دارند، مناسب نیست.

برای مثال:

- برنامه‌های چت
- بازی‌های آنلاین
- بازار بورس
- نمایش قیمت ارز و ارز دیجیتال
- سیستم‌های مانیتورینگ
- اعلان‌های لحظه‌ای (Notifications)

در این برنامه‌ها، سرور باید بتواند هر زمان که اطلاعات جدیدی داشت، آن را به کلاینت ارسال کند؛ بدون اینکه کلاینت مدام درخواست جدید بفرستد.

اینجاست که **WebSocket** وارد عمل می‌شود.

---

## مشکل HTTP برای ارتباط لحظه‌ای

فرض کنید یک برنامه چت داریم.

در HTTP روند کار به شکل زیر است:

```
Client ---- Request ----> Server

Client <--- Response ----- Server

Connection Closed
```

اگر پیام جدیدی ارسال شود، کلاینت باید دوباره درخواست بفرستد.

مثلاً هر یک ثانیه:

```
آیا پیام جدیدی وجود دارد؟

آیا پیام جدیدی وجود دارد؟

آیا پیام جدیدی وجود دارد؟
```

به این روش Polling گفته می‌شود که مشکلات زیادی دارد:

- مصرف زیاد پهنای باند
- افزایش بار سرور
- تاخیر بیشتر
- ارسال درخواست‌های بیهوده

---

## WebSocket چگونه کار می‌کند؟

در WebSocket تنها یک بار اتصال برقرار می‌شود.

بعد از آن، هر دو طرف می‌توانند هر زمان که بخواهند اطلاعات ارسال کنند.

```
Client <=================> Server
```

اتصال باز می‌ماند.

به این ارتباط:

> Full Duplex Communication

گفته می‌شود.

---

## ویژگی‌های WebSocket

- ارتباط دائمی
- دوطرفه (Bidirectional)
- سرعت بالا
- تاخیر بسیار کم
- مناسب برای Real-Time
- سربار کمتر نسبت به HTTP Polling

---

## Full Duplex چیست؟

در HTTP فقط کلاینت درخواست ارسال می‌کند.

اما در WebSocket:

- کلاینت می‌تواند پیام بفرستد.
- سرور نیز هر زمان بخواهد پیام ارسال می‌کند.

مانند تماس تلفنی که هر دو نفر هم‌زمان می‌توانند صحبت کنند.

---

## مراحل برقراری اتصال

ابتدا ارتباط از طریق HTTP آغاز می‌شود.

```
Client
   |
HTTP Upgrade Request
   |
Server
```

اگر سرور موافق باشد:

```
101 Switching Protocols
```

ارسال می‌شود.

از این لحظه ارتباط به WebSocket تبدیل می‌شود.

---

## تفاوت HTTP و WebSocket

| HTTP               | WebSocket       |
| ------------------ | --------------- |
| Request / Response | ارتباط دائمی    |
| اتصال کوتاه        | اتصال بلندمدت   |
| Half Duplex        | Full Duplex     |
| مناسب API          | مناسب Real-Time |
| سربار بیشتر        | سربار کمتر      |

## رویداد connection

هر زمان یک کاربر متصل شود:

```javascript
const WebSocket = require("ws");

const server = new WebSocket.Server({
    port: 3000
});

server.on("connection", (socket) => {

    console.log("Client Connected");

});
```

## ارسال پیام

```javascript
socket.send("Hello Client");
```

مثال:

```javascript
server.on("connection", (socket) => {

    socket.send("Welcome");

});
```

---

## دریافت پیام

```javascript
socket.on("message", (message) => {

    console.log(message.toString());

});
```

مثال:

```javascript
server.on("connection", (socket) => {

    socket.on("message", (message) => {

        console.log(message.toString());

    });

});
```

---

## ارسال پاسخ

```javascript
server.on("connection", (socket) => {

    socket.on("message", (message) => {

        socket.send("Message Received");

    });

});
```

---

## رویداد close

وقتی اتصال قطع شود:

```javascript
socket.on("close", () => {

    console.log("Disconnected");

});
```

---

## رویداد error

```javascript
socket.on("error", (err) => {

    console.log(err);

});
```

---

## Broadcast

ارسال پیام برای همه کاربران

```javascript
server.on("connection", (socket) => {

    socket.on("message", (message) => {

        server.clients.forEach(client => {

            if (client.readyState === WebSocket.OPEN) {

                client.send(message.toString());

            }

        });

    });

});
```

---

## ارسال JSON

بهتر است داده‌ها را به صورت JSON ارسال کنیم.

```javascript
socket.send(JSON.stringify({

    type: "message",

    text: "Hello"

}));
```

دریافت:

```javascript
socket.on("message", (message) => {

    const data = JSON.parse(message);

    console.log(data);

});
```

## بررسی وضعیت اتصال

```javascript
socket.readyState
```

مقادیر:

```javascript
WebSocket.CONNECTING

WebSocket.OPEN

WebSocket.CLOSING

WebSocket.CLOSED
```

## Ping و Pong

برای اطمینان از زنده بودن اتصال استفاده می‌شود.

```
Server ---- Ping ---->

Client ---- Pong ---->
```

بسیاری از کتابخانه‌ها از جمله `ws` این مکانیزم را برای تشخیص اتصال‌های قطع‌شده پشتیبانی می‌کنند.

## WebSocket یا REST API؟

هر کدام کاربرد خاص خود را دارند.

REST API:

- دریافت اطلاعات
- ثبت اطلاعات
- عملیات CRUD
- درخواست‌های معمول

WebSocket:

- داده‌های لحظه‌ای
- ارتباط دائمی
- پیام‌رسان
- رویدادهای Real-Time

در بسیاری از پروژه‌ها، هر دو در کنار هم استفاده می‌شوند؛ برای مثال احراز هویت و عملیات CRUD از طریق REST API انجام می‌شود و ارسال پیام‌های لحظه‌ای از طریق WebSocket.

# اشتباهات رایج

### 1- استفاده از WebSocket برای همه چیز

نیازی نیست تمام ارتباطات یک پروژه WebSocket باشند. برای درخواست‌های معمول، HTTP و REST API ساده‌تر و مناسب‌تر هستند.

---

### 2- ارسال متن به جای JSON

کد نامناسب:

```javascript
socket.send("Ali,25,Admin");
```

کد بهتر:

```javascript
socket.send(JSON.stringify({
    name: "Ali",
    age: 25,
    role: "Admin"
}));
```

---

### 3- فراموش کردن مدیریت خطا

```javascript
socket.on("error", console.error);
```

---

### 4- نادیده گرفتن وضعیت اتصال

قبل از ارسال پیام وضعیت اتصال را بررسی کنید.

```javascript
if (socket.readyState === WebSocket.OPEN) {
    socket.send("Hello");
}
```

---

### 5- عدم حذف اتصال‌های قطع‌شده

اتصال‌های بسته‌شده را مدیریت کنید تا از مصرف بیهوده حافظه جلوگیری شود.

---

# نکات حرفه‌ای

- از ساختار پیام استاندارد شامل `type`، `payload` و `timestamp` استفاده کنید.
- برای احراز هویت کاربران، توکن را هنگام برقراری اتصال بررسی کنید.
- اندازه پیام‌ها را محدود کنید تا از سوءاستفاده جلوگیری شود.
- پیام‌های دریافتی را اعتبارسنجی کنید.
- از مکانیزم Heartbeat (Ping/Pong) برای تشخیص اتصال‌های غیرفعال استفاده کنید.
- در صورت نیاز، نرخ ارسال پیام (Rate Limiting) را محدود کنید.
- برای برنامه‌های بزرگ، از سیستم Pub/Sub مانند Redis جهت هماهنگی بین چند سرور WebSocket استفاده کنید.

# مینی‌پروژه

## سیستم چت آنلاین ساده (Simple Chat Server)

### هدف

ساخت یک سرور چت که چندین کاربر بتوانند به آن متصل شوند و پیام‌های خود را به‌صورت لحظه‌ای برای یکدیگر ارسال کنند.

### امکانات

- ایجاد WebSocket Server
- اتصال هم‌زمان چند کاربر
- ارسال پیام خوش‌آمدگویی
- دریافت پیام کاربران
- Broadcast پیام برای همه کاربران متصل
- ثبت اتصال و قطع اتصال کاربران در ترمینال
- مدیریت خطاهای اتصال
- استفاده از پیام‌های JSON با ساختار زیر:

```json
{
  "type": "message",
  "username": "Ali",
  "text": "سلام به همه!",
  "timestamp": "2026-08-04T13:00:00Z"
}
```

### پیشنهاد برای توسعه پروژه

- اضافه کردن نام کاربری
- نمایش زمان ارسال پیام
- ساخت اتاق‌های گفتگو (Rooms)
- ارسال پیام خصوصی
- ذخیره تاریخچه پیام‌ها در پایگاه داده
- احراز هویت کاربران با JWT
- نمایش کاربران آنلاین
- ارسال فایل و تصویر
- نمایش وضعیت «در حال تایپ...» (Typing Indicator)
- پیاده‌سازی اتصال مجدد خودکار (Auto Reconnect) در سمت کلاینت
