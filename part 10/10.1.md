# فصل 74 - HTTP

## مقدمه

یکی از مهم‌ترین مفاهیم در توسعه Backend با Node.js، شناخت پروتکل:

```text
HTTP
```

است.

تمام ارتباطات بین:

* مرورگر و سرور
* اپلیکیشن موبایل و API
* سرویس‌های مختلف Backend

معمولاً از طریق HTTP انجام می‌شود.

وقتی کاربر یک صفحه را باز می‌کند:

```text
Client

↓

HTTP Request

↓

Server

↓

HTTP Response

↓

Client
```

این چرخه پایه اصلی اینترنت مدرن است.

Node.js به دلیل داشتن ماژول داخلی:

```text
http
```

قادر است بدون هیچ Framework خارجی یک Web Server ایجاد کند.

---

# 74.1 - HTTP چیست؟

HTTP مخفف:

```text
HyperText Transfer Protocol
```

است.

یک پروتکل ارتباطی برای انتقال اطلاعات بین Client و Server است.

اطلاعاتی که منتقل می‌شوند:

* HTML
* JSON
* Image
* Video
* File
* Data

---

# 74.2 - Client و Server

## Client

درخواست‌دهنده اطلاعات.

مثال:

* Browser
* Mobile App
* Frontend Application

---

## Server

پردازش‌کننده درخواست.

مثال:

* Node.js Server
* Database Server
* API Server

---

# 74.3 - چرخه Request و Response

هر ارتباط HTTP دو بخش دارد:

## Request

درخواست Client.

مثال:

```text
GET /users
```

---

## Response

پاسخ Server.

مثال:

```json
{
"users":[]
}
```

---

# 74.4 - ساختار HTTP Request

یک Request شامل:

* Method
* URL
* Headers
* Body

است.

مثال:

```http
POST /users HTTP/1.1

Content-Type: application/json

{
"name":"Ali"
}
```

---

# 74.5 - HTTP Method چیست؟

Method مشخص می‌کند چه عملی انجام شود.

مهم‌ترین Methodها:

| Method | کاربرد         |
| ------ | -------------- |
| GET    | دریافت اطلاعات |
| POST   | ساخت اطلاعات   |
| PUT    | بروزرسانی کامل |
| PATCH  | بروزرسانی بخشی |
| DELETE | حذف اطلاعات    |

---

# 74.6 - GET Request

برای دریافت اطلاعات.

مثال:

```http
GET /products
```

نتیجه:

```json
[
 {
  "id":1,
  "name":"Laptop"
 }
]
```

---

# 74.7 - POST Request

برای ساخت داده جدید.

مثال:

```http
POST /users
```

Body:

```json
{
"name":"Sara"
}
```

---

# 74.8 - PUT Request

برای جایگزینی کامل داده.

مثال:

قبل:

```json
{
"name":"Ali",
"age":20
}
```

بعد:

```json
{
"name":"Ali",
"age":21,
"email":"a@test.com"
}
```

---

# 74.9 - PATCH Request

برای تغییر بخشی از داده.

مثال:

فقط سن:

```json
{
"age":21
}
```

---

# 74.10 - DELETE Request

برای حذف داده:

```http
DELETE /users/10
```

---

# 74.11 - HTTP Status Code

Server با Status Code نتیجه درخواست را اعلام می‌کند.

دسته‌بندی:

| محدوده | معنی        |
| ------ | ----------- |
| 1xx    | اطلاعاتی    |
| 2xx    | موفقیت      |
| 3xx    | Redirect    |
| 4xx    | خطای Client |
| 5xx    | خطای Server |

---

# 74.12 - Status Codeهای مهم

## 200 OK

درخواست موفق.

---

## 201 Created

ساخت موفق Resource.

مثال:

ساخت User.

---

## 204 No Content

موفقیت بدون Response.

---

## 400 Bad Request

داده ارسالی اشتباه است.

---

## 401 Unauthorized

کاربر احراز هویت نشده.

---

## 403 Forbidden

دسترسی وجود ندارد.

---

## 404 Not Found

Resource پیدا نشد.

---

## 500 Internal Server Error

خطای داخلی Server.

---

# 74.13 - HTTP Header چیست؟

Header اطلاعات اضافی Request یا Response است.

مثال:

```http
Content-Type: application/json
```

---

Headerهای رایج:

## Content-Type

نوع داده:

```http
application/json
```

---

## Authorization

اطلاعات احراز هویت:

```http
Authorization: Bearer token
```

---

## User-Agent

اطلاعات Client.

---

# 74.14 - HTTP Body چیست؟

Body داده اصلی Request است.

مثال:

```json
{
"username":"admin",
"password":"123456"
}
```

معمولاً در:

* POST
* PUT
* PATCH

استفاده می‌شود.

---

# 74.15 - HTTP در Node.js

Node.js دارای Module داخلی:

```js

```

است.

---

# 74.16 - ساخت HTTP Server ساده

```js
const http = require("http");


const server =
http.createServer(
(req,res)=>{

res.write(
"Hello Node.js"
);

res.end();

});


server.listen(
3000
);
```

---

اجرا:

```bash
node index.js
```

باز کردن:

```text
localhost:3000
```

# 74.29 - اشتباهات رایج

## 1) استفاده اشتباه از Methodها

مثلاً:

حذف اطلاعات با:

```text
GET
```

---

## 2) ارسال JSON بدون Header

اشتباه:

```http
Content-Type
```

قرار نگیرد.

---

## 3) استفاده اشتباه از Status Code

مثلاً:

خطای کاربر:

```text
500
```

برگردانده شود.

---

## 4) ارسال اطلاعات حساس در URL

اشتباه:

```text
/login?password=123
```

---

## 5) فراموش کردن res.end()

باعث باز ماندن Request می‌شود.

---

## 6) نبود مدیریت Error

Server ممکن است Crash کند.

# 74.30 - نکات حرفه‌ای

* برای APIها JSON استاندارد استفاده کن.

* از HTTPS استفاده کن.

* Timeout مشخص کن.

* Response Format ثابت طراحی کن.
* Version برای API تعریف کن.

# جمع‌بندی

HTTP پایه ارتباط در دنیای Backend است.

یک توسعه‌دهنده Node.js باید کاملاً با موارد زیر آشنا باشد:

* Request
* Response
* Methodها
* Headerها
* Status Codeها
* Routing
* JSON
* REST API

Node.js به دلیل داشتن Module داخلی HTTP یکی از بهترین محیط‌ها برای ساخت Serverهای سریع و مقیاس‌پذیر است.

در فصل‌های بعدی، همین مفاهیم را با Frameworkهای حرفه‌ای مانند Express.js توسعه خواهیم داد.
