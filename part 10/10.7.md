# فصل 80 - REST API

## REST API چیست؟

وقتی دو نرم‌افزار بخواهند با یکدیگر ارتباط برقرار کنند، به یک زبان مشترک نیاز دارند.

برای مثال:

* یک وب‌سایت باید اطلاعات کاربران را از سرور دریافت کند.
* یک اپلیکیشن موبایل باید سفارش جدید ثبت کند.
* یک پنل مدیریت باید محصولات را ویرایش کند.

تمام این ارتباط‌ها معمولاً از طریق **API** انجام می‌شوند.

یکی از محبوب‌ترین سبک‌های طراحی API، **REST API** است.

REST مخفف عبارت:

> **Representational State Transfer**

است.

REST یک **پروتکل** یا **زبان برنامه‌نویسی** نیست؛ بلکه مجموعه‌ای از اصول و قوانین برای طراحی API است.

---

# API چیست؟

API مخفف:

> Application Programming Interface

است.

به زبان ساده:

API واسطه‌ای است که دو برنامه را به هم متصل می‌کند.

مثال:

```text
Browser
      │
 HTTP Request
      │
REST API
      │
Database
```

کاربر مستقیماً با پایگاه داده ارتباط برقرار نمی‌کند.

بلکه درخواست ابتدا به API می‌رسد و API تصمیم می‌گیرد چه اطلاعاتی بازگردانده شود.

---

# REST چگونه کار می‌کند؟

در REST همه چیز حول **Resource** می‌چرخد.

Resource یعنی یک منبع یا موجودیت.

مثلاً:

* کاربران
* محصولات
* سفارش‌ها
* دسته‌بندی‌ها
* فایل‌ها

هر Resource یک آدرس (URL) مخصوص دارد.

مثال:

```text
/users
/products
/orders
/categories
```

---

# URL در REST

هر Resource باید URL مشخصی داشته باشد.

مثال:

```text
GET /users
```

تمام کاربران

---

```text
GET /users/5
```

کاربر شماره ۵

---

```text
GET /products
```

تمام محصولات

---

```text
GET /orders/12
```

سفارش شماره ۱۲

---

# HTTP Methodها

REST از متدهای HTTP استفاده می‌کند.

مهم‌ترین آن‌ها:

| Method | کاربرد                    |
| ------ | ------------------------- |
| GET    | دریافت اطلاعات            |
| POST   | ایجاد اطلاعات             |
| PUT    | جایگزینی کامل             |
| PATCH  | بروزرسانی بخشی از اطلاعات |
| DELETE | حذف اطلاعات               |

---

# GET

برای دریافت اطلاعات استفاده می‌شود.

مثال:

```http
GET /users
```

پاسخ:

```json
[
    {
        "id": 1,
        "name": "Ali"
    },
    {
        "id": 2,
        "name": "Sara"
    }
]
```

---

# POST

برای ایجاد Resource جدید استفاده می‌شود.

درخواست:

```http
POST /users
```

Body:

```json
{
    "name": "Reza",
    "age": 25
}
```

---

پاسخ:

```json
{
    "id": 3,
    "name": "Reza",
    "age": 25
}
```

---

# PUT

برای جایگزینی کامل داده استفاده می‌شود.

```http
PUT /users/3
```

Body:

```json
{
    "name": "Reza",
    "age": 30
}
```

تمام اطلاعات قبلی جایگزین می‌شوند.

---

# PATCH

برای تغییر بخشی از اطلاعات است.

```http
PATCH /users/3
```

Body:

```json
{
    "age": 31
}
```

فقط مقدار `age` تغییر می‌کند.

---

# DELETE

حذف اطلاعات

```http
DELETE /users/3
```

---

# Status Codeها

هر پاسخ HTTP دارای Status Code است.

---

## 200 OK

درخواست با موفقیت انجام شد.

---

## 201 Created

Resource جدید ایجاد شد.

---

## 204 No Content

عملیات موفق بود ولی داده‌ای برگردانده نمی‌شود.

---

## 400 Bad Request

درخواست کاربر اشتباه است.

---

## 401 Unauthorized

کاربر احراز هویت نشده است.

---

## 403 Forbidden

کاربر اجازه دسترسی ندارد.

---

## 404 Not Found

Resource پیدا نشد.

---

## 409 Conflict

تداخل در داده‌ها وجود دارد.

---

## 422 Unprocessable Entity

اطلاعات ارسال‌شده معتبر نیستند.

---

## 500 Internal Server Error

خطای سمت سرور.

---

# RESTful API چیست؟

اگر API از قوانین REST پیروی کند، به آن:

> RESTful API

گفته می‌شود.

ویژگی‌های مهم:

* استفاده صحیح از HTTP Methodها
* URLهای خوانا
* Stateless بودن
* استفاده از Status Code مناسب
* استفاده از JSON
* طراحی مبتنی بر Resource

---

# Stateless بودن

یکی از مهم‌ترین ویژگی‌های REST این است که هر درخواست مستقل از درخواست‌های قبلی است.

سرور نباید وضعیت (State) درخواست قبلی را نگه دارد.

برای مثال اگر کاربر برای دسترسی نیاز به احراز هویت دارد، باید اطلاعات احراز هویت (مانند توکن) را در هر درخواست ارسال کند.

---

# Versioning

برای جلوگیری از شکستن نسخه‌های قدیمی API معمولاً از نسخه‌بندی استفاده می‌شود.

```text
/api/v1/users

/api/v2/users
```

---

# مزایای REST API

* یادگیری آسان
* استفاده گسترده
* سازگار با HTTP
* مستقل از زبان برنامه‌نویسی
* مقیاس‌پذیر
* مناسب برای وب و موبایل
* پشتیبانی در اکثر فریمورک‌ها

---

# محدودیت‌های REST

* مناسب نبودن برای ارتباط لحظه‌ای (Real-Time)
* احتمال ارسال داده‌های اضافی (Over Fetching)
* احتمال نیاز به چندین درخواست برای دریافت اطلاعات مرتبط
* عدم پشتیبانی از ارتباط دوطرفه دائمی مانند WebSocket

---

# REST API در Node.js

در Node.js معمولاً REST API با فریمورک‌هایی مانند Express.js، Fastify یا NestJS پیاده‌سازی می‌شود.

در فصل‌های آینده نحوه ساخت یک REST API کامل با Express.js را به‌صورت عملی یاد خواهید گرفت.

---

# اشتباهات رایج

### ۱- استفاده نادرست از Methodها

اشتباه:

```text
GET /deleteUser
```

درست:

```text
DELETE /users/5
```

---

### ۲- استفاده از فعل در URL

اشتباه:

```text
/createUser
```

درست:

```text
POST /users
```

---

### ۳- استفاده نکردن از Status Code مناسب

مثلاً بازگرداندن `200 OK` برای تمام پاسخ‌ها، حتی زمانی که خطا رخ داده است.

---

### ۴- ارسال اطلاعات حساس

اطلاعاتی مانند رمز عبور یا توکن نباید بدون محافظت یا به‌صورت غیرضروری در پاسخ API بازگردانده شوند.

---

### ۵- نداشتن اعتبارسنجی

هرگز داده‌های ورودی را بدون بررسی ذخیره نکنید.

---

### ۶- نام‌گذاری نامناسب Resourceها

بهتر است از اسم‌های جمع استفاده شود.

درست:

```text
/users
/products
/orders
```

---

# نکات حرفه‌ای

* از URLهای ساده، خوانا و قابل پیش‌بینی استفاده کنید.
* برای فیلتر، مرتب‌سازی و صفحه‌بندی از Query Parameterها استفاده کنید.
* پیام‌های خطا را واضح و استاندارد طراحی کنید.
* همیشه پاسخ‌ها را با ساختار مشخص و یکسان برگردانید.
* برای APIهای عمومی نسخه‌بندی (Versioning) را از ابتدا در نظر بگیرید.
* مستندات API را با ابزارهایی مانند OpenAPI (Swagger) تهیه کنید.
* از HTTPS برای محافظت از داده‌های در حال انتقال استفاده کنید.
* برای عملیات حساس از احراز هویت و مجوزدهی مناسب استفاده کنید.

# مینی‌پروژه

## طراحی REST API برای سیستم مدیریت کتابخانه

### هدف

طراحی یک REST API استاندارد برای مدیریت کتاب‌ها و اعضای کتابخانه، بدون نیاز به پیاده‌سازی پایگاه داده.

### Resourceها

* Books
* Members
* Loans

### امکانات

#### مدیریت کتاب‌ها

* دریافت لیست کتاب‌ها
* دریافت اطلاعات یک کتاب
* افزودن کتاب جدید
* ویرایش اطلاعات کتاب
* حذف کتاب

#### مدیریت اعضا

* ثبت عضو جدید
* دریافت لیست اعضا
* ویرایش اطلاعات عضو
* حذف عضو

#### مدیریت امانت

* ثبت امانت کتاب
* ثبت بازگشت کتاب
* مشاهده کتاب‌های امانت‌گرفته‌شده
* مشاهده تاریخچه امانت هر عضو

### قابلیت‌های تکمیلی

* صفحه‌بندی (`page` و `limit`)
* جستجو بر اساس عنوان یا نویسنده
* مرتب‌سازی نتایج
* فیلتر بر اساس وضعیت کتاب (موجود یا امانت‌داده‌شده)
* استفاده از Status Codeهای مناسب
* طراحی پاسخ‌های JSON یکپارچه برای موفقیت و خطا
* نسخه‌بندی API با مسیرهایی مانند `/api/v1`
