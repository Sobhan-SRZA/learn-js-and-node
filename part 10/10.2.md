# فصل 75 - HTTPS

## مقدمه

امنیت یکی از مهم‌ترین بخش‌های توسعه Backend است.

در فصل قبل با HTTP آشنا شدیم؛ پروتکلی که برای ارتباط بین Client و Server استفاده می‌شود.

اما HTTP یک مشکل بزرگ دارد:

اطلاعات را به صورت رمزگذاری نشده منتقل می‌کند.

یعنی اگر فردی بتواند ارتباط بین کاربر و سرور را مشاهده کند، ممکن است بتواند اطلاعاتی مانند:

* رمز عبور
* Token
* اطلاعات شخصی
* داده‌های مالی

را مشاهده کند.

برای حل این مشکل از:

```text id="u8q3mz"
HTTPS
```

استفاده می‌کنیم.

HTTPS نسخه امن HTTP است که با استفاده از:

```text id="p7x4mw"
TLS / SSL
```

اطلاعات را رمزگذاری می‌کند.

---

# 75.1 - HTTPS چیست؟

HTTPS مخفف:

```text id="k3m8qx"
HyperText Transfer Protocol Secure
```

است.

HTTPS همان HTTP است، اما با یک لایه امنیتی اضافه.

ساختار:

```text id="w6p2mz"
HTTP

+

TLS Encryption

=

HTTPS
```

---

# 75.2 - تفاوت HTTP و HTTPS

| HTTP             | HTTPS              |
| ---------------- | ------------------ |
| بدون رمزگذاری    | رمزگذاری شده       |
| پورت 80          | پورت 443           |
| امنیت پایین‌تر    | امنیت بالا         |
| مناسب داده عمومی | مناسب اطلاعات حساس |

---

# 75.3 - چرا HTTPS مهم است؟

HTTPS سه ویژگی اصلی امنیتی ایجاد می‌کند:

---

## 1 - Encryption

رمزگذاری اطلاعات.

مثال:

کاربر ارسال می‌کند:

```text id="q8m4xp"
password=123456
```

در شبکه:

```text id="m7x2qz"
a8F#91kL@2
```

دیده می‌شود.

---

## 2 - Authentication

اطمینان از اینکه به Server واقعی متصل شده‌ایم.

مثال:

کاربر فکر می‌کند وارد:

```text id="x4p8mq"
bank.com
```

شده است.

HTTPS بررسی می‌کند که Server واقعاً همان بانک است.

---

## 3 - Integrity

اطمینان از اینکه داده در مسیر تغییر نکرده است.

---

# 75.4 - SSL و TLS چیست؟

SSL و TLS پروتکل‌های امنیتی هستند.

امروزه بیشتر از:

```text id="m5q9xp"
TLS
```

استفاده می‌شود.

SSL نسخه قدیمی‌تر است.

---

# 75.5 - HTTPS چگونه کار می‌کند؟

فرآیند کلی:

```text id="z8m3qp"
Client

↓

Request Connection

↓

TLS Handshake

↓

Certificate Check

↓

Encrypted Connection

↓

HTTP Data Transfer
```

---

# 75.6 - TLS Handshake

در شروع ارتباط:

1. Client درخواست اتصال امن می‌دهد.
2. Server Certificate ارسال می‌کند.
3. Client Certificate را بررسی می‌کند.
4. کلید رمزگذاری ساخته می‌شود.
5. ارتباط امن شروع می‌شود.

---

# 75.7 - Certificate چیست؟

Certificate یک فایل دیجیتال است که هویت Server را تایید می‌کند.

شامل:

* Domain Name
* Public Key
* Issuer
* Expiration Date

است.

مثال:

```text id="m3q7xp"
example.com

Certificate Valid
```

---

# 75.8 - Certificate Authority چیست؟

Certificate توسط سازمان‌هایی صادر می‌شود که به آن‌ها:

```text id="x7m2qp"
CA
```

می‌گوییم.

مثال:

* Let's Encrypt
* DigiCert
* GlobalSign

---

# 75.9 - Public Key و Private Key

HTTPS از رمزنگاری نامتقارن استفاده می‌کند.

دو کلید وجود دارد:

---

## Public Key

قابل انتشار است.

برای رمزگذاری استفاده می‌شود.

---

## Private Key

محرمانه است.

فقط Server آن را دارد.

---

# 75.10 - نصب Certificate روی Server

برای فعال کردن HTTPS باید:

* Certificate دریافت کنیم.
* Private Key داشته باشیم.
* Server را تنظیم کنیم.

---

# 75.11 - ساخت HTTPS Server در Node.js

Node.js ماژول داخلی:

```js id="v4m8qx"
https
```

دارد.

---

ساخت Server:

```js id="p8x3mw"
const https =
require("https");

const fs =
require("fs");


const options = {

key:
fs.readFileSync(
"private.key"
),

cert:
fs.readFileSync(
"certificate.crt"
)

};


https.createServer(
options,
(req,res)=>{

res.end(
"Secure Server"
);

}
)
.listen(443);
```

---

# 75.12 - ایجاد Certificate برای تست Local

برای محیط توسعه می‌توان از Certificate آزمایشی استفاده کرد.

مثال با OpenSSL:

```bash id="q6m2xp"
openssl req -newkey rsa:2048 -nodes \
-keyout private.key \
-x509 \
-days 365 \
-out certificate.crt
```

# 75.13 - HTTPS در Production

↓

Node.js

Database

# 75.19 - HTTPS و Performance

قبلاً HTTPS کندتر بود.

* مرورگرها HTTPS را بهینه کرده‌اند.

# 75.23 - نکات حرفه‌ای

* همیشه Production را روی HTTPS اجرا کن.
* از TLS نسخه‌های جدید استفاده کن.
* Private Key را امن نگه دار.
* Certificate را قبل از انقضا تمدید کن.
* از HSTS استفاده کن.
* HTTP را به HTTPS Redirect کن.
* از ابزارهای بررسی SSL استفاده کن.
* Cookieهای حساس را Secure کن.
* Secretها را داخل Environment Variable نگه دار.
* TLS Termination را در معماری مناسب انجام بده.

# جمع‌بندی

HTTPS یکی از پایه‌های امنیت Backend است.

یک توسعه‌دهنده حرفه‌ای Node.js باید بداند:

* HTTPS چگونه کار می‌کند.
* TLS چیست.
* Certificate چیست.
* چگونه HTTPS Server بسازد.
* چگونه API امن طراحی کند.

در پروژه‌های واقعی، هر سیستم که با اطلاعات کاربران کار می‌کند باید از HTTPS استفاده کند.

امنیت ارتباط، اولین قدم برای ساخت Backend قابل اعتماد است.
