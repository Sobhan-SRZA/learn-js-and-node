# فصل 96 - SQL

## مقدمه

پایگاه داده یکی از مهم‌ترین بخش‌های هر برنامه Backend است. تقریباً تمام برنامه‌های واقعی نیاز دارند اطلاعات کاربران، محصولات، سفارش‌ها، تراکنش‌ها و داده‌های مختلف را ذخیره، مدیریت و بازیابی کنند.

SQL یکی از اصلی‌ترین زبان‌هایی است که برای کار با پایگاه‌های داده رابطه‌ای (Relational Database) استفاده می‌شود. یادگیری SQL برای هر برنامه‌نویس Node.js که قصد ورود به بازار کار Backend را دارد ضروری است؛ زیرا بسیاری از پروژه‌های واقعی از دیتابیس‌های SQL مانند PostgreSQL و MySQL استفاده می‌کنند.

در این فصل ابتدا با مفهوم دیتابیس‌های رابطه‌ای آشنا می‌شویم، سپس SQL را از پایه یاد می‌گیریم و در ادامه به Query نویسی حرفه‌ای، طراحی جدول، ارتباط بین داده‌ها، بهینه‌سازی Queryها و استفاده از SQL در پروژه‌های Node.js می‌پردازیم.

هدف این فصل این است که بتوانید بدون وابستگی به ابزار خاص، منطق کار با دیتابیس‌های SQL را یاد بگیرید و آماده استفاده از آن در پروژه‌های واقعی Node.js شوید.

# 96.1 - Database چیست؟

## Database چیست؟

در هر نرم‌افزاری که ساخته می‌شود، معمولاً نیاز داریم اطلاعاتی را ذخیره کنیم.

برای مثال:

* اطلاعات کاربران
* محصولات یک فروشگاه
* پیام‌های یک پیام‌رسان
* سفارش‌های مشتریان
* اطلاعات حساب‌های بانکی
* تنظیمات برنامه
* گزارش‌ها و لاگ‌ها

اگر این اطلاعات فقط در حافظه برنامه نگهداری شوند، با بسته شدن برنامه یا خاموش شدن سیستم از بین می‌روند.

برای حل این مشکل از **Database** استفاده می‌کنیم.

Database یا پایگاه داده، سیستمی برای **ذخیره‌سازی، مدیریت، سازمان‌دهی و بازیابی اطلاعات** است.

به زبان ساده:

> Database یک محل ذخیره‌سازی هوشمند است که برنامه‌ها می‌توانند اطلاعات خود را در آن ذخیره کنند و هر زمان لازم بود آن‌ها را دریافت یا تغییر دهند.

---

## چرا به Database نیاز داریم؟

فرض کنید یک فروشگاه اینترنتی داریم.

بدون Database باید اطلاعاتی مانند:

```text
نام کاربر:
Sobhan

ایمیل:
sobhan@example.com

محصول خریداری شده:
Laptop

تاریخ خرید:
2026-08-07
```

را داخل فایل‌ها ذخیره کنیم.

اما زمانی که تعداد کاربران زیاد شود:

* پیدا کردن اطلاعات سخت می‌شود.
* تغییر اطلاعات زمان زیادی می‌گیرد.
* امنیت کاهش پیدا می‌کند.
* مدیریت داده‌ها پیچیده می‌شود.

Database این مشکلات را حل می‌کند.

---

# ذخیره اطلاعات بدون Database

قبل از استفاده گسترده از Database، برنامه‌ها معمولاً اطلاعات را در فایل ذخیره می‌کردند.

مثلاً:

```
users.txt
```

محتوا:

```text
1,Sobhan,sobhan@test.com
2,Ali,ali@test.com
3,Reza,reza@test.com
```

یا:

```
users.json
```

```json
[
  {
    "id":1,
    "name":"Sobhan"
  },
  {
    "id":2,
    "name":"Ali"
  }
]
```

برای پروژه‌های کوچک این روش ممکن است قابل استفاده باشد.

اما در پروژه‌های واقعی مشکلات زیادی ایجاد می‌کند.

---

# مشکلات ذخیره‌سازی سنتی

## 1. سرعت پایین جستجو

برای پیدا کردن یک کاربر باید کل فایل بررسی شود.

Database برای این کار ابزارهای مخصوص دارد.

---

## 2. مشکل همزمانی کاربران

فرض کنید دو کاربر همزمان اطلاعات خود را تغییر دهند.

در ذخیره‌سازی فایل ممکن است اطلاعات یکی از کاربران حذف شود.

Database این مشکل را مدیریت می‌کند.

---

## 3. امنیت پایین

فایل‌های ساده معمولاً:

* کنترل دسترسی ندارند.
* سطح‌بندی کاربران ندارند.
* امکانات امنیتی محدود دارند.

---

## 4. نبود ساختار مناسب

وقتی داده‌ها زیاد شوند، مدیریت فایل‌ها سخت می‌شود.

مثلاً:

```
users.json

products.json

orders.json

payments.json
```

ارتباط بین این فایل‌ها پیچیده خواهد شد.

---

## 5. نبود امکانات حرفه‌ای

Database امکاناتی مانند:

را ارائه می‌دهد.

* ستون‌ها (Column)
* ردیف‌ها (Row)

مثال:

جدول کاربران:

| id  | name | email                                 |
| --- | ---- | ------------------------------------- |
| 1   | Ali  | [ali@test.com](mailto:ali@test.com)   |

---

# تفاوت SQL و NoSQL

| SQL                   | NoSQL                     |
| --------------------- | ------------------------- |
| جدولی                 | سندی یا مدل‌های دیگر       |
| ساختار ثابت           | ساختار انعطاف‌پذیر         |
| SQL Query             | روش‌های مختلف Query        |
| مناسب داده‌های رابطه‌ای | مناسب داده‌های بزرگ و سریع |

---

SQL مناسب است وقتی:

مثال:

* بانک

NoSQL مناسب است وقتی:

* داده‌ها دائماً تغییر می‌کنند.
* سرعت بالا مهم است.
* داده‌ها حجم زیادی دارند.

مثال:

* چت آنلاین
* سیستم لاگ
* تحلیل داده

# بخش ۲ - مفاهیم دیتابیس رابطه‌ای

# 96.4 - Relational Database

## Relational Database چیست؟

قبل از کار با SQL باید با مفهوم **Relational Database** آشنا شویم.

Relational Database یا **پایگاه داده رابطه‌ای** نوعی سیستم ذخیره‌سازی اطلاعات است که داده‌ها را در ساختاری منظم و قابل ارتباط با یکدیگر ذخیره می‌کند.

در این مدل، اطلاعات داخل **Table**ها ذخیره می‌شوند و بین جدول‌ها می‌توان رابطه ایجاد کرد.

برای مثال یک فروشگاه اینترنتی را در نظر بگیرید:

```
Users

+----+---------+----------------+
| id | name    | email          |
+----+---------+----------------+
| 1  | Ali     | ali@test.com   |
| 2  | Sara    | sara@test.com  |
+----+---------+----------------+
```

و جدول سفارش‌ها:

```
Orders

+----+---------+--------+
| id | user_id | price  |
+----+---------+--------+
| 1  | 1       | 500    |
| 2  | 2       | 900    |
+----+---------+--------+
```

اینجا با استفاده از `user_id` می‌توانیم سفارش‌ها را به کاربران متصل کنیم.

---

# مفهوم Relation

در پایگاه داده رابطه‌ای، کلمه **Relation** به ساختار جدولی داده‌ها اشاره دارد.

در SQL معمولا هر Relation یک Table است.

مثلا:

```
Users
```

یک Relation محسوب می‌شود.

این Relation شامل:

* ستون‌ها
* ردیف‌ها
* داده‌ها

است.

---

# Table چیست؟

Table یا جدول، اصلی‌ترین بخش Database رابطه‌ای است.

هر جدول مجموعه‌ای از اطلاعات مرتبط را نگهداری می‌کند.

مثلا:

جدول کاربران:

```
Users

id | username | age
--------------------
1  | ali      | 20
2  | sara     | 25
```

هر جدول معمولا یک موضوع مشخص را مدیریت می‌کند.

مثلا:

```
Users
Products
Orders
Payments
Comments
```

---

# Row چیست؟

Row یا ردیف، یک رکورد کامل از اطلاعات است.

هر Row نشان‌دهنده یک موجودیت واقعی است.

مثلا:

```
Users

id | name | age
----------------
1  | Ali  | 20
```

این یک Row است.

یعنی اطلاعات یک کاربر.

---

# Column چیست؟

Column یا ستون، یک ویژگی از داده‌ها را مشخص می‌کند.

مثلا:

```
Users

id | name | email
------------------
1  | Ali  | a@test.com
```

در این جدول:

```
id
name
email
```

ستون هستند.

هر Column معمولا یک نوع داده مشخص دارد.

مثلا:

```
age → Integer

email → Varchar

created_at → Timestamp
```

---

# Record چیست؟

Record همان یک مجموعه کامل از اطلاعات یک موجودیت است.

در SQL معمولا Record همان Row در نظر گرفته می‌شود.

مثلا:

```
id: 1
name: Ali
email: ali@test.com
```

یک Record است.

---

# Field چیست؟

Field یک مقدار داخل یک Record است.

مثلا:

```
User

id | name | age
----------------
1  | Ali  | 20
```

مقدار:

```
Ali
```

یک Field است.

یا:

```
20
```

یک Field دیگر است.

---

# تفاوت Row، Record و Field

مثال:

```
Users

id | name | age
----------------
1  | Ali  | 20
2  | Sara | 25
```

| مفهوم  | مقدار          |
| ------ | -------------- |
| Table  | Users          |
| Row    | کل اطلاعات Ali |
| Record | کل اطلاعات Ali |
| Column | name           |
| Field  | Ali            |

---

ساختار کلی:

```

 └── Table

      ├── Column
      │
      └── Row
            |
            └── Field
```

مثلا:

```
Database
   |
   └── Users Table
          |
          ├── Columns
          |      ├── id
          |      ├── name
          |      └── email
          |
          └── Rows
                 |
                 └── Record
                        |
                        └── Fields
```

# Data Type

هر Column باید نوع داده مشخصی داشته باشد.

مثلا:

```

```

انتخاب درست Type باعث:

* مصرف کمتر حافظه
* سرعت بیشتر
* جلوگیری از داده اشتباه

می‌شود.

---

# Primary Key

Primary Key یک ستون برای شناسایی یکتا هر Record است.

مثلا:

```
Users

id | name
---------
1  | Ali
2  | Sara
```

ستون:

```
id
```

Primary Key است.

ویژگی‌ها:

* تکراری نیست
* مقدار Null ندارد
* هر Record یک مقدار متفاوت دارد

---

# Unique Value

Unique یعنی مقدار یک ستون نمی‌تواند تکراری باشد.

مثلا:

ایمیل کاربران:

```
ali@test.com
sara@test.com
```

اما:

```
ali@test.com
ali@test.com
```

مجاز نیست.

---

# Default Value

Default یعنی مقدار پیش‌فرض.

مثلا:

```
is_active BOOLEAN DEFAULT true
```

اگر هنگام ساخت کاربر مقدار ارسال نشود:

```
is_active = true
```

قرار می‌گیرد.

---

# Nullable

Nullable مشخص می‌کند یک ستون می‌تواند مقدار خالی داشته باشد یا نه.

مثلا:

شماره تلفن اختیاری:

```
phone NULL
```

اما ایمیل ضروری:

```
email NOT NULL
```

Database اولین بخش از کار با سیستم‌های مدیریت پایگاه داده است. قبل از اینکه بتوانیم Table ایجاد کنیم و اطلاعات ذخیره کنیم، باید یک Database بسازیم.

در این بخش یاد می‌گیریم چگونه:

* یک Database جدید ایجاد کنیم

* Database را حذف کنیم
* تفاوت حذف Database در محیط‌های مختلف را درک کنیم

# CREATE DATABASE

دستور `CREATE DATABASE` برای ساخت یک پایگاه داده جدید استفاده می‌شود.

ساختار کلی:

```sql
CREATE DATABASE database_name;
```

مثال:

```sql
CREATE DATABASE shop;
```

با اجرای این دستور یک Database با نام `shop` ساخته می‌شود.

## نام‌گذاری Database

هنگام انتخاب نام Database باید به قوانین زیر توجه کنیم:

* از کاراکترهای خاص کمتر استفاده شود
* بهتر است از حروف کوچک استفاده شود

نمونه مناسب:


نمونه نام‌های نامناسب:


# 96.12 - حذف داده و جدول

در SQL چند دستور برای حذف وجود دارد که عملکرد متفاوتی دارند:

* DROP
* DELETE
* TRUNCATE

شناخت تفاوت این دستورات بسیار مهم است.

---

# DROP

برای حذف کامل ساختار استفاده می‌شود.

مثال:

```sql
DROP TABLE users;
```

نتیجه:

* Table حذف می‌شود
* داده‌ها حذف می‌شوند
* ساختار Table از بین می‌رود

---

# DELETE

برای حذف رکوردها استفاده می‌شود.

مثال:

```sql
DELETE FROM users;
```

تمام داده‌ها حذف می‌شوند اما Table باقی می‌ماند.

---

حذف شرطی:

```sql
DELETE FROM users
WHERE id = 5;
```

فقط کاربر شماره ۵ حذف می‌شود.

---

# TRUNCATE

برای حذف سریع تمام داده‌های Table:

```sql
TRUNCATE TABLE users;
```

ویژگی‌ها:

* همه رکوردها حذف می‌شوند
* ساختار Table باقی می‌ماند
* سریع‌تر از DELETE است

---

# تفاوت DROP، DELETE و TRUNCATE

| ویژگی      | DROP | DELETE | TRUNCATE |
| ---------- | ---- | ------ | -------- |
| حذف Table  | ✅    | ❌      | ❌        |
| حذف داده   | ✅    | ✅      | ✅        |
| حذف ساختار | ✅    | ❌      | ❌        |
| امکان شرط  | ❌    | ✅      | ❌        |
| سرعت       | زیاد | کمتر   | زیاد     |

---

# اشتباهات رایج

* استفاده از DROP روی Database اصلی
* اجرای DELETE بدون WHERE
* اشتباه گرفتن TRUNCATE و DROP
* حذف اطلاعات بدون Backup

* در پروژه‌های واقعی قبل از حذف داده Backup بگیرید.
* برای حذف چند رکورد مشخص از DELETE استفاده کنید.
* برای خالی کردن کامل Table از TRUNCATE استفاده کنید.

# بخش ۵ - CRUD در SQL

CRUD یکی از مهم‌ترین مفاهیم کار با Database است. تقریباً هر برنامه‌ای که با اطلاعات کاربران، محصولات، سفارش‌ها، پیام‌ها یا هر داده دیگری کار می‌کند، نیاز به چهار عملیات اصلی دارد:

* **Create** → ایجاد داده جدید
* **Read** → خواندن داده‌ها
* **Update** → تغییر داده‌های موجود
* **Delete** → حذف داده‌ها

در این بخش یاد می‌گیریم چگونه با دستورات اصلی SQL داده‌ها را ایجاد، مشاهده، فیلتر، مرتب و بروزرسانی کنیم.

---

# 96.13 - Insert کردن داده

در این بخش یاد می‌گیریم چگونه اطلاعات جدید را داخل Table ذخیره کنیم.

## INSERT INTO چیست؟

دستور `INSERT INTO` برای اضافه کردن رکورد جدید به یک جدول استفاده می‌شود.

ساختار کلی:

```sql
INSERT INTO table_name (column1, column2, column3)
VALUES (value1, value2, value3);
```

مثال:

فرض کنیم یک جدول کاربران داریم:

```sql
CREATE TABLE users (
    id INT,
    name VARCHAR(50),
    email VARCHAR(100)
);
```

اضافه کردن یک کاربر:

```sql
INSERT INTO users (id, name, email)
VALUES (1, 'Ali', 'ali@example.com');
```

---

## Insert چند رکورد

برای اضافه کردن چند داده در یک Query می‌توان چند مقدار ارسال کرد:

```sql
INSERT INTO users (id, name, email)
VALUES
(1, 'Ali', 'ali@example.com'),
(2, 'Sara', 'sara@example.com'),
(3, 'Reza', 'reza@example.com');
```

مزایا:

* سرعت بیشتر
* کاهش تعداد Queryها
* مناسب برای Import کردن داده‌ها

---

## Insert بدون مشخص کردن Column

امکان Insert مستقیم وجود دارد:

```sql
INSERT INTO users
VALUES
(1, 'Ali', 'ali@example.com');
```

اما توصیه نمی‌شود.

دلایل:

* وابستگی به ترتیب Columnها
* احتمال خطا بعد از تغییر ساختار Table
* خوانایی کمتر

---

## Insert با Default Value

اگر Column مقدار پیش‌فرض داشته باشد:

```sql
CREATE TABLE users (
    id INT,
    name VARCHAR(50),
    status VARCHAR(20) DEFAULT 'active'
);
```

می‌توانیم:

```sql
INSERT INTO users (id, name)
VALUES (1, 'Ali');
```

خروجی:

```
id | name | status
------------------
1  | Ali  | active
```

---

## Insert با Select

گاهی نیاز داریم اطلاعات یک Table را داخل Table دیگر کپی کنیم.

ساختار:

```sql
INSERT INTO table2
SELECT column1, column2
FROM table1;
```

مثال:

```sql
INSERT INTO old_users_archive
SELECT *
FROM users;
```

کاربردها:

* Backup داده‌ها
* انتقال اطلاعات
* Archive کردن اطلاعات قدیمی

---

## اشتباهات رایج

### وارد کردن تعداد اشتباه Columnها

## 96.19 - توابع SQL

### مفهوم Function در SQL

* تابع چیست؟
* تفاوت Function و Query
* توابع داخلی SQL
* توابع محاسباتی و آماری
* استفاده از Function در SELECT

---

### COUNT

* شمارش تعداد رکوردها
* COUNT(*)
* COUNT(Column)
* تفاوت COUNT(*) و COUNT(Column)

```sql
SELECT COUNT(*)

```

---

### SUM

* جمع کردن مقادیر عددی
* استفاده روی Columnهای عددی

مثال:

```sql
SELECT SUM(price)

```

---

### AVG

* محاسبه میانگین
* میانگین قیمت
* میانگین امتیاز کاربران
* رفتار AVG با NULL

مثال:

```sql
SELECT AVG(score)
FROM reviews;
```

---

### MIN

* پیدا کردن کمترین مقدار
* کمترین قیمت
* قدیمی‌ترین تاریخ
* کوچک‌ترین مقدار عددی

مثال:

```sql
SELECT MIN(price)
FROM products;
```

---

### MAX

* پیدا کردن بیشترین مقدار
* بیشترین فروش
* جدیدترین تاریخ
* بزرگ‌ترین مقدار عددی

مثال:

```sql
SELECT MAX(price)
FROM products;
```

---

### ترکیب چند Function

* استفاده همزمان از چند تابع
* ساخت گزارش‌های آماری

مثال:

```sql
SELECT

AVG(age) AS average_age,
MAX(age) AS oldest_user
FROM users;
```

### اشتباهات رایج

* استفاده اشتباه از COUNT روی Column دارای NULL
* فراموش کردن GROUP BY هنگام استفاده از Aggregate Function
* استفاده از AVG روی داده‌های غیرعددی
* انجام محاسبات سنگین روی دیتابیس بزرگ بدون بهینه‌سازی

---

### نکات حرفه‌ای

* برای گزارش‌گیری از Aggregate Functionها استفاده کنید
* روی Columnهایی که زیاد محاسبه می‌شوند Index بررسی کنید
* قبل از محاسبات سنگین حجم داده را محدود کنید
* همیشه برای خروجی Functionها Alias مناسب قرار دهید

### تمرین

4. ارزان‌ترین و گران‌ترین محصول را پیدا کنید.

* قبل از Group کردن داده‌ها را با WHERE محدود کنید
* روی Columnهای پرتکرار در Group کردن Index بررسی کنید

# 96.21 - JOIN در SQL

### مفهوم JOIN

* چرا به JOIN نیاز داریم؟
* ارتباط بین چند جدول
* ترکیب اطلاعات چند Table
* تفاوت JOIN و Subquery

مثال:

جدول کاربران:

| id  | name |
| --- | ---- |
| 1   | Ali  |
| 2   | Sara |

جدول سفارش‌ها:

| id  | user_id | price |
| --- | ------- | ----- |
| 1   | 1       | 500   |

برای گرفتن اطلاعات کاربر همراه سفارش نیاز به JOIN داریم.

---

## INNER JOIN

### مفهوم

* فقط رکوردهای مشترک
* حذف داده‌های بدون ارتباط
* پرکاربردترین نوع JOIN

مثال:

```sql
SELECT *
FROM users
INNER JOIN orders
ON users.id = orders.user_id;
```

---

## LEFT JOIN

### مفهوم

* تمام داده‌های جدول سمت چپ
* داده‌های مرتبط از جدول راست
* نمایش کاربران بدون سفارش

مثال:

```sql
SELECT *
FROM users
LEFT JOIN orders
ON users.id = orders.user_id;
```

---

## RIGHT JOIN

### مفهوم

* تمام داده‌های جدول سمت راست
* داده‌های مرتبط از جدول چپ

مثال:

```sql
SELECT *
FROM users
RIGHT JOIN orders
ON users.id = orders.user_id;
```

---

## FULL JOIN

### مفهوم

* تمام داده‌های هر دو جدول
* نمایش رکوردهای مرتبط و غیرمرتبط

مثال:

```sql
SELECT *
FROM users
FULL JOIN orders
ON users.id = orders.user_id;
```

---

### JOIN چند جدول

* اتصال سه یا چند جدول
* Queryهای پیچیده
* طراحی گزارش‌های واقعی

مثال:

```sql
SELECT *
FROM users
JOIN orders
ON users.id = orders.user_id
JOIN payments
ON orders.id = payments.order_id;
```

---

### اشتباهات رایج

* JOIN کردن بدون شرط ON
* ایجاد Cartesian Product
* انتخاب اشتباه نوع JOIN
* JOIN روی Column بدون Index

---

### نکات حرفه‌ای

* همیشه شرط JOIN را واضح بنویسید
* برای جدول‌های بزرگ Index مناسب ایجاد کنید
* فقط Columnهای مورد نیاز را SELECT کنید
* JOIN زیاد ممکن است باعث کاهش Performance شود

---

### تمرین

1. لیست کاربران همراه سفارش‌هایشان را نمایش دهید.

2. تمام کاربران حتی بدون سفارش را نمایش دهید.

3. سفارش‌ها را همراه اطلاعات پرداخت نمایش دهید.

4. سه جدول Users، Orders و Products را به هم متصل کنید.

# 96.22 - ارتباط بین جدول‌ها

## مفهوم Relationship

* طراحی Database حرفه‌ای

## One To One

### مفهوم

```
 |
```

### مفهوم

* یک رکورد با چند رکورد دیگر ارتباط دارد

یک کاربر می‌تواند چند سفارش داشته باشد.

```
id
```

### اشتباهات رایج

* حذف جدول واسط در Many To Many
* طراحی اشتباه Relationship

### نکات حرفه‌ای

* قبل از ساخت Tableها Relationship را طراحی کنید
* از ERD برای طراحی استفاده کنید
* Foreign Keyها را جدی بگیرید
* Normalization را رعایت کنید

---

### تمرین

# 96.23 - Foreign Key

## مفهوم Foreign Key

* کلید خارجی چیست؟
* ارتباط دادن Tableها
* جلوگیری از داده‌های نامعتبر
* حفظ Integrity دیتابیس

مثال:

```sql
CREATE TABLE orders (
id INT PRIMARY KEY,
user_id INT,
FOREIGN KEY(user_id)
REFERENCES users(id)
);
```

---

## Constraint

### مفهوم

* قوانین روی داده‌ها
* جلوگیری از ورود اطلاعات اشتباه

انواع:

* PRIMARY KEY
* FOREIGN KEY
* UNIQUE
* NOT NULL
* CHECK

---

## Cascade

### مفهوم

* تغییر یا حذف خودکار داده‌های وابسته

مثال:

```sql
ON DELETE CASCADE
```

وقتی User حذف شود، سفارش‌های او هم حذف می‌شوند.

---

## Restrict

### مفهوم

* جلوگیری از حذف داده دارای وابستگی

مثال:

```sql
ON DELETE RESTRICT
```

تا زمانی که سفارش وجود دارد، کاربر حذف نمی‌شود.

---

## انواع رفتار Foreign Key

* CASCADE
* RESTRICT
* SET NULL
* NO ACTION

---

### اشتباهات رایج

* حذف Cascade بدون بررسی
* نداشتن Foreign Key در ارتباط‌ها
* ذخیره IDهای نامعتبر
* بی‌توجهی به Integrity

---

### نکات حرفه‌ای

* برای Relationshipهای مهم همیشه Foreign Key استفاده کنید
* قبل از Cascade کردن سناریو را بررسی کنید
* Constraintها باعث سالم ماندن داده‌ها می‌شوند
* طراحی درست Foreign Key باعث کاهش خطاهای برنامه می‌شود

---

### تمرین

1. جدول Users و Orders را با Foreign Key بسازید.

2. هنگام حذف User سفارش‌های مرتبط را مدیریت کنید.

3. رابطه Product و Category را پیاده‌سازی کنید.

4. برای یک سیستم فروشگاه Online Relationship کامل طراحی کنید.

# 96.25 - Transaction

### مفهوم Transaction

* Transaction چیست؟
* چرا Transaction نیاز داریم؟
* عملیات چند مرحله‌ای در Database
* مثال واقعی:

  * انتقال پول بین دو حساب
  * ثبت سفارش فروشگاه
  * پرداخت آنلاین

تمرین

---

### ACID

بررسی چهار ویژگی اصلی Transaction:

## Atomicity

* انجام کامل یا عدم انجام عملیات
* جلوگیری از ذخیره ناقص اطلاعات

---

## Consistency

* حفظ قوانین Database
* جلوگیری از داده‌های نامعتبر

---

## Isolation

* جدا بودن Transactionهای همزمان
* جلوگیری از تداخل عملیات

---

## Durability

* ذخیره دائمی تغییرات
* حفظ اطلاعات بعد از قطع شدن سیستم

تمرین

---

### COMMIT

* ذخیره نهایی تغییرات
* پایان موفق Transaction
* مثال عملی

مثال:

```sql
COMMIT;
```

تمرین

---

### ROLLBACK

* برگشت تغییرات
* لغو Transaction
* استفاده هنگام خطا

مثال:

```sql
ROLLBACK;
```

تمرین

---

### Transaction در پروژه‌های واقعی

* سیستم پرداخت
* بانکداری
* فروشگاه اینترنتی
* سیستم رزرو

# اشتباهات رایج در مفاهیم پیشرفته SQL

* ساخت Index روی تمام Columnها
* استفاده اشتباه از Transaction
* نگه داشتن Transaction برای مدت طولانی
* استفاده بیش از حد از Trigger
* قرار دادن تمام منطق برنامه داخل Database
* نادیده گرفتن Performance Queryها
* استفاده نکردن از Execution Plan

# نکات حرفه‌ای

* همیشه قبل از ساخت Index، Queryهای پرتکرار را بررسی کنید.
* Index زیاد می‌تواند سرعت نوشتن اطلاعات را کاهش دهد.
* Transactionهای کوتاه‌تر عملکرد بهتری دارند.
* Triggerها باید ساده و قابل نگهداری باشند.
* برای منطق اصلی برنامه معمولاً Backend انتخاب بهتری است.
* در پروژه‌های بزرگ Database باید Performance Monitoring داشته باشد.
