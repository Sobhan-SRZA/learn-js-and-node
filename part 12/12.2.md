# فصل 96 - SQL

## مقدمه

در فصل‌های قبل با مفهوم Database و پایگاه داده‌های رابطه‌ای آشنا شدیم. حالا وقت آن است که با **SQL** یاد بگیریم چگونه با یک پایگاه داده رابطه‌ای صحبت کنیم.

SQL مخفف **Structured Query Language** است و زبانی استاندارد برای کار با پایگاه‌های داده رابطه‌ای محسوب می‌شود. با SQL می‌توانیم داده‌ها را ایجاد، ذخیره، جستجو، ویرایش و حذف کنیم و همچنین ارتباط بین داده‌های مختلف را مدیریت کنیم.

در پروژه‌های واقعی Node.js، معمولاً برنامه به یک Database متصل می‌شود و اطلاعاتی مانند کاربران، محصولات، سفارش‌ها، پرداخت‌ها، پیام‌ها و تنظیمات را در آن ذخیره می‌کند.

برای مثال، وقتی در یک API مربوط به فروشگاه اینترنتی درخواست زیر را دریافت می‌کنیم:

```text
GET /products
```

برنامه Node.js باید بتواند محصولات را از Database دریافت کند.

یا وقتی کاربر ثبت‌نام می‌کند:

```text
POST /users
```

اطلاعات کاربر باید در Database ذخیره شود.

در نتیجه، یادگیری SQL یکی از مهارت‌های مهم برای تبدیل شدن به یک **Backend Developer حرفه‌ای با Node.js** است.

در این فصل ابتدا SQL را از پایه یاد می‌گیریم و سپس به تدریج به Queryهای حرفه‌ای‌تر، ارتباط بین جدول‌ها، Index، Transaction و مفاهیم مهم دیگری می‌رسیم.

> نکته: در این فصل تمرکز اصلی روی خود SQL است. در فصل‌های بعدی نحوه استفاده از PostgreSQL، اتصال Node.js به Database و استفاده از ORM و ODM را بررسی خواهیم کرد.

# بخش 1 - آشنایی با Database و SQL

## 96.1 - SQL چیست؟

### SQL چیست؟

SQL یک زبان برای ارتباط با پایگاه‌های داده رابطه‌ای است.

با SQL می‌توانیم به Database بگوییم:

* یک Database ایجاد کن.
* یک Table ایجاد کن.
* داده جدید ذخیره کن.
* داده‌ها را نمایش بده.
* داده‌ها را فیلتر کن.
* داده‌ها را مرتب کن.
* داده‌ها را تغییر بده.
* داده‌ها را حذف کن.
* چند Table را به یکدیگر متصل کن.
* داده‌ها را گروه‌بندی کن.
* اطلاعات آماری استخراج کن.

مثلاً:

```sql
SELECT * FROM users;
```

یعنی:

> تمام اطلاعات جدول `users` را نمایش بده.

---

### SQL در Node.js چه کاربردی دارد؟

Node.js خودش Database نیست.

Node.js وظیفه اجرای برنامه Backend را دارد و SQL می‌تواند برای ارتباط برنامه با Database استفاده شود.

ساختار کلی یک برنامه Backend می‌تواند به این شکل باشد:

```text
Client
   ↓
Node.js
   ↓
SQL Query
   ↓
Database
   ↓
Result
   ↓
Node.js
   ↓
Client
```

مثلاً:

```text
GET /users
      ↓
Node.js
      ↓
SELECT * FROM users
      ↓
PostgreSQL
      ↓
Users
      ↓
Node.js
      ↓
JSON Response
```

---

### SQL و Database یکی نیستند

این دو مفهوم را نباید با یکدیگر اشتباه گرفت.

```text
Database
└── محل ذخیره و مدیریت داده‌ها

SQL
└── زبان ارتباط با Database
```

Databaseهایی مانند:

* PostgreSQL
* MySQL
* MariaDB
* SQLite
* Microsoft SQL Server
* Oracle Database

می‌توانند از SQL یا زبان‌های مبتنی بر SQL استفاده کنند.

---

### SQL Case Sensitivity

در بسیاری از Databaseها، Keywordهای SQL مانند موارد زیر معمولاً نسبت به حروف بزرگ و کوچک حساس نیستند:

```sql
SELECT
select
SeLeCt
```

اما برای خوانایی بهتر معمولاً Keywordها را با حروف بزرگ می‌نویسیم:

```sql
SELECT * FROM users;
```

---

### SQL Statement

هر دستور SQL را می‌توان یک Statement در نظر گرفت.

مثلاً:

```sql
SELECT * FROM users;
```

یا:

```sql
INSERT INTO users (name, email)
VALUES ('Ali', 'ali@example.com');
```

---

### تمرین

1. SQL چیست؟
2. تفاوت SQL و Database چیست؟
3. آیا Node.js خودش Database است؟
4. SQL در یک Backend چه نقشی دارد؟
5. یک Query برای خواندن اطلاعات جدول `users` بنویسید.

# بخش 2 - مفاهیم Database رابطه‌ای

## 96.3 - Table، Row و Column

در Database رابطه‌ای، داده‌ها معمولاً در Table ذخیره می‌شوند.

مثلاً جدول کاربران:

```text
users

| id  | name | email            |
| --- | ---- | ---------------- |
| 1   | Ali  | ali@example.com  |
| 2   | Sara | sara@example.com |
```

### Table

جدول محل نگهداری مجموعه‌ای از داده‌های مرتبط است.

### Row

هر Row نماینده یک رکورد است.

مثلاً:

```text
1 | Ali | ali@example.com
```

یک User را نمایش می‌دهد.

### Column

هر Column یک ویژگی مشخص از داده‌ها را نشان می‌دهد.

مثلاً:

```text
id
name
email
```

---

### تمرین

برای یک فروشگاه اینترنتی جدول‌های زیر را پیشنهاد دهید:

* کاربران
* محصولات
* سفارش‌ها

برای هر Table حداقل 5 Column پیشنهاد کنید.

---

## 96.4 - Primary Key

Primary Key برای شناسایی یکتای هر Row استفاده می‌شود.

مثلاً:

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(255)
);
```

در اینجا:

```text
id
```

Primary Key است.

دو Row نمی‌توانند یک مقدار یکسان برای Primary Key داشته باشند.

---

### ویژگی‌های Primary Key

Primary Key:

* باید Unique باشد.
* نباید `NULL` باشد.
* هر Row را به شکل یکتا مشخص می‌کند.

---

## 96.5 - Foreign Key

Foreign Key برای ایجاد ارتباط بین Tableها استفاده می‌شود.

مثلاً:

```text
users
-----
id
name

orders
------
id
user_id
amount
```

در اینجا:

```text
orders.user_id
```

می‌تواند به:

```text
users.id
```

اشاره کند.

مثلاً:

```sql
CREATE TABLE orders (
    id INTEGER PRIMARY KEY,
    user_id INTEGER,
    amount DECIMAL(10, 2),

    FOREIGN KEY (user_id)
    REFERENCES users(id)
);
```

---

### تمرین

برای سیستم فروشگاه:

```text
users
products
orders
```

یک ارتباط بین User و Order طراحی کنید.

# بخش 4 - دستورات پایه SQL

## 96.9 - ساخت Database

ساخت Database:

```sql
CREATE DATABASE shop;
```

حذف Database:

```sql
DROP DATABASE shop;
```

> اجرای `DROP DATABASE` باعث حذف Database و اطلاعات آن می‌شود؛ بنابراین در محیط واقعی باید با احتیاط استفاده شود.

---

### تمرین

یک Database با نام زیر طراحی کنید:

```text
blog
```

---

## 96.10 - ساخت Table

مثال:

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(255),
    age INTEGER
);
```

---

### Data Type

هر Column باید نوع داده مشخصی داشته باشد.

مثلاً:

```sql
id INTEGER
name VARCHAR(100)
age INTEGER
price DECIMAL(10, 2)
is_active BOOLEAN
```

---

### Constraint

Constraint برای اعمال قوانین روی داده‌ها استفاده می‌شود.

مهم‌ترین موارد:

```text
PRIMARY KEY
FOREIGN KEY
UNIQUE
NOT NULL
DEFAULT
CHECK
```

مثلاً:

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    age INTEGER CHECK (age >= 0),
    is_active BOOLEAN DEFAULT TRUE
);
```

---

## 96.11 - تغییر ساختار Table

### ADD COLUMN

```sql
ALTER TABLE users
ADD COLUMN phone VARCHAR(20);
```

### DROP COLUMN

```sql
ALTER TABLE users
DROP COLUMN phone;
```

### تغییر ساختار Column

نحوه دقیق Syntax در Databaseهای مختلف می‌تواند متفاوت باشد.

بنابراین هنگام کار با PostgreSQL، MySQL یا Database دیگر باید Syntax همان Database را بررسی کنیم.

---

## 96.12 - حذف Table

```sql
DROP TABLE users;
```

همچنین:

```sql
TRUNCATE TABLE users;
```

تفاوت مهم:

```text
DROP
→ ساختار Table را هم حذف می‌کند.

TRUNCATE
→ داده‌ها را حذف می‌کند اما Table باقی می‌ماند.
```

## 96.18 - Update و Delete

### UPDATE

```sql

SET name = 'Ali Reza'
WHERE id = 1;
```



```sql

```

# بخش 6 - Query نویسی حرفه‌ای

## 96.19 - توابع SQL

```sql

```

```sql
SELECT COUNT(*)

```

یا:


## 96.20 - GROUP BY

برای گروه‌بندی داده‌ها:

```sql
SELECT city, COUNT(*)
FROM users

```

---

### HAVING

`WHERE` قبل از گروه‌بندی و `HAVING` برای فیلتر کردن گروه‌ها استفاده می‌شود.

مثلاً:

```sql
SELECT city, COUNT(*)
FROM users

```

---

## 96.21 - JOIN در SQL

یکی از مهم‌ترین مفاهیم SQL، اتصال Tableها است.

فرض کنید:

```text
users
orders
```

و هر Order متعلق به یک User است.

### INNER JOIN

```sql
SELECT
    users.name,
    orders.amount
FROM users
INNER JOIN orders
ON users.id = orders.user_id;
```

---

### LEFT JOIN

```sql
SELECT
    users.name,
    orders.amount
FROM users
LEFT JOIN orders
ON users.id = orders.user_id;
```

---

### RIGHT JOIN

در Databaseهایی که از آن پشتیبانی می‌کنند:

```sql
SELECT
    users.name,
    orders.amount
FROM users
RIGHT JOIN orders
ON users.id = orders.user_id;
```

---

### چند JOIN

در پروژه‌های واقعی ممکن است چند Table به یکدیگر متصل شوند:

```text
users
   ↓
orders
   ↓
order_items
   ↓
products
```

مثلاً:

```sql
SELECT
    users.name,
    products.name,
    order_items.quantity
FROM users
JOIN orders
    ON users.id = orders.user_id
JOIN order_items
    ON orders.id = order_items.order_id
JOIN products
    ON products.id = order_items.product_id;
```

---

## 96.22 - Subquery

گاهی نتیجه یک Query در Query دیگری استفاده می‌شود.

مثلاً:

```sql
SELECT *
FROM products
WHERE price > (
    SELECT AVG(price)
    FROM products
);
```

این Query محصولاتی را پیدا می‌کند که قیمتشان بیشتر از میانگین قیمت محصولات است.

---

## 96.23 - UNION

برای ترکیب نتیجه چند Query:

```sql
SELECT name FROM users
UNION
SELECT name FROM admins;
```

برای حفظ رکوردهای تکراری:

```sql
UNION ALL
```

# بخش 7 - مفاهیم پیشرفته SQL

## 96.24 - Index

Index ساختاری است که می‌تواند جستجو و دسترسی به داده‌ها را سریع‌تر کند.

مثلاً:

```sql
CREATE INDEX idx_users_email
ON users(email);
```

حذف Index:

```sql
DROP INDEX idx_users_email;
```

---

### چرا Index؟

فرض کنید میلیون‌ها User داریم و دائماً با Email جستجو می‌کنیم:

```sql
SELECT *
FROM users
WHERE email = 'ali@example.com';
```

وجود Index مناسب می‌تواند عملکرد چنین Queryهایی را بهبود دهد.

اما Index رایگان نیست و می‌تواند:

* فضای بیشتری مصرف کند.
* عملیات Write را تحت تأثیر قرار دهد.
* نگهداری بیشتری نیاز داشته باشد.

بنابراین نباید روی تمام Columnها بدون دلیل Index ایجاد کرد.

---

## 96.25 - Transaction

Transaction مجموعه‌ای از عملیات است که باید به صورت یک واحد منطقی اجرا شود.

مثلاً انتقال پول:

```text
حساب A
  ↓
کم کردن 100 تومان

حساب B
  ↓
اضافه کردن 100 تومان
```

اگر عملیات اول انجام شود اما عملیات دوم شکست بخورد، وضعیت Database مشکل پیدا می‌کند.

Transaction برای چنین سناریوهایی مهم است.

---

### ACID

چهار ویژگی مهم Transaction:

```text
Atomicity
Consistency
Isolation
Durability
```

---

### COMMIT

ثبت نهایی تغییرات:

```sql
COMMIT;
```

### ROLLBACK

برگرداندن تغییرات:

```sql
ROLLBACK;
```

---

## 96.26 - View

View یک نتیجه Query است که می‌توان مانند یک Table از آن استفاده کرد.

مثلاً:

```sql
CREATE VIEW active_users AS
SELECT id, name, email
FROM users
WHERE is_active = TRUE;
```

سپس:

```sql
SELECT *
FROM active_users;
```

View می‌تواند برای ساده‌تر کردن Queryهای پیچیده و ایجاد abstraction مفید باشد.

```text
   ↓

```

مثلاً درخواست:

```http
GET /users
```

می‌تواند در نهایت به Query زیر تبدیل شود:

```sql
SELECT id, name, email
FROM users;
```

---

## 96.28 - SQL Driver

Node.js برای ارتباط با Database از Driver یا Library مناسب استفاده می‌کند.

برای مثال در PostgreSQL می‌توان از Driverهایی مانند `pg` استفاده کرد.

ایده کلی:

```javascript
const result = await db.query(
  'SELECT * FROM users'
);

console.log(result.rows);
```

در پروژه‌های واقعی باید Connection Pool، مدیریت خطا، Transaction و امنیت Queryها نیز به درستی پیاده‌سازی شوند.

---

## 96.29 - Parameterized Query

یکی از مهم‌ترین نکات هنگام استفاده از SQL در Node.js این است که اطلاعات کاربر را مستقیماً داخل Query قرار ندهیم.

روش نامناسب:

```javascript
const query = `
  SELECT *
  FROM users
  WHERE email = '${email}'
`;
```

به جای آن باید از Parameterized Query استفاده شود.

مثلاً:

```javascript
const result = await db.query(
  'SELECT * FROM users WHERE email = $1',
  [email]
);
```

این موضوع برای جلوگیری از **SQL Injection** بسیار مهم است.

# اشتباهات رایج

## 1. استفاده از SELECT *

در Queryهای واقعی معمولاً بهتر است فقط Columnهای مورد نیاز را دریافت کنیم.

به جای:

```sql
SELECT *
FROM users;
```

در صورت نیاز:

```sql
SELECT id, name, email
FROM users;
```

---

## 2. UPDATE بدون WHERE

اشتباه خطرناک:

```sql
UPDATE users
SET is_active = FALSE;
```

این دستور تمام کاربران را تغییر می‌دهد.

---

## 3. DELETE بدون WHERE

```sql
DELETE FROM users;
```

تمام رکوردها حذف می‌شوند.

---

## 4. قرار دادن مستقیم ورودی کاربر داخل Query

نامناسب:

```javascript
const query = `
  SELECT *
  FROM users
  WHERE name = '${name}'
`;
```

بهتر:

```javascript
const result = await db.query(
  'SELECT * FROM users WHERE name = $1',
  [name]
);
```

---

## 5. استفاده بیش از حد از Index

Index زیاد همیشه بهتر نیست.

Index باید بر اساس Queryهای واقعی و نیازهای سیستم ایجاد شود.

---

## 6. نادیده گرفتن NULL

`NULL` به معنی مقدار صفر یا String خالی نیست.

مثلاً:

```text
NULL
0
''
```

سه مفهوم متفاوت هستند.

برای بررسی NULL معمولاً باید از:

```sql
IS NULL
```

و:

```sql
IS NOT NULL
```

استفاده کرد.

---

## 7. اشتباه گرفتن WHERE و HAVING

```text
WHERE
→ فیلتر کردن Rowها

HAVING
→ فیلتر کردن Groupها
```

---

## 8. JOIN اشتباه

اگر شرط `JOIN` اشتباه نوشته شود ممکن است تعداد زیادی Row غیرمنتظره ایجاد شود.

همیشه باید رابطه بین Tableها را به خوبی درک کرد.

---

## 9. استفاده نکردن از Transaction در عملیات وابسته

اگر چند عملیات Database باید با هم موفق یا شکست بخورند، استفاده از Transaction اهمیت زیادی دارد.

---

## 10. فرض کردن اینکه همه Databaseها دقیقاً یک Syntax دارند

SQL استاندارد است، اما Databaseهای مختلف قابلیت‌ها و Syntaxهای اختصاصی خودشان را نیز دارند.

برای همین باید تفاوت PostgreSQL، MySQL و سایر Databaseها را نیز بشناسیم.

# نکات حرفه‌ای

## 1. Query را بر اساس نیاز بنویسید

همیشه لازم نیست تمام داده‌های یک Table را دریافت کنیم.

```sql
SELECT id, name
FROM users;
```

می‌تواند بهتر از:

```sql
SELECT *
FROM users;
```

باشد.

---

## 2. Index را بر اساس Queryهای واقعی ایجاد کنید

قبل از ایجاد Index باید بدانیم:

* چه Queryهایی زیاد اجرا می‌شوند؟
* چه Columnهایی در `WHERE` استفاده می‌شوند؟
* چه Columnهایی در `JOIN` استفاده می‌شوند؟
* چه Queryهایی کند هستند؟

---

## 3. Queryهای پیچیده را بررسی کنید

در پروژه‌های واقعی فقط نوشتن Query مهم نیست؛ باید عملکرد آن را نیز بررسی کرد.

مفاهیمی مانند:

```text
Execution Plan
Query Optimization
Index
Full Table Scan
```

در بهینه‌سازی SQL اهمیت زیادی دارند.

---

## 4. از Transaction درست استفاده کنید

Transaction را فقط برای عملیات ساده استفاده نمی‌کنیم؛ عملیات‌های وابسته مانند:

```text
Payment
Order
Inventory
Bank Transfer
```

معمولاً نیازمند طراحی دقیق Transaction هستند.

---

## 5. SQL Injection را جدی بگیرید

در Node.js از:

* Parameterized Query
* Prepared Statement
* Libraryهای معتبر
* Validation

استفاده کنید.

---

## 6. ساختار Database را قبل از Query نویسی طراحی کنید

یک Backend خوب فقط مجموعه‌ای از Queryها نیست.

ابتدا باید رابطه بین داده‌ها مشخص شود:

```text
User
 ↓
Order
 ↓
OrderItem
 ↓
Product
```

سپس Queryهای مناسب طراحی شوند.

---

## 7. Pagination را برای داده‌های زیاد در نظر بگیرید

در APIهایی که ممکن است هزاران یا میلیون‌ها رکورد داشته باشند، نباید تمام داده‌ها را یک‌باره برگردانیم.

```text
?page=1&limit=20
```

می‌تواند بخشی از داده‌ها را دریافت کند.

# مینی‌پروژه - سیستم مدیریت فروشگاه با SQL

## امکانات

سیستم باید بتواند:

* کاربران را ذخیره کند.
* محصولات را ذخیره کند.
* سفارش ایجاد کند.
* سفارش‌های کاربران را نمایش دهد.
* قیمت محصولات را مدیریت کند.
* تعداد محصولات را محاسبه کند.
* گزارش فروش ایجاد کند.
* Queryهای مختلف روی اطلاعات اجرا کند.
