# فصل 95 - Database

تا اینجا تقریباً تمام بخش‌های مهم توسعه Backend را یاد گرفتیم.

اما هنوز یک مشکل بزرگ وجود دارد.

فرض کنید برنامه‌ای می‌نویسیم که کاربران بتوانند ثبت‌نام کنند.

اگر اطلاعات کاربران را داخل یک متغیر ذخیره کنیم:

```javascript
const users = [];
```

بعد از خاموش شدن سرور چه اتفاقی می‌افتد؟

تمام اطلاعات از بین می‌رود.

بنابراین برای نگهداری دائمی اطلاعات به **Database (پایگاه داده)** نیاز داریم.

تقریباً تمام نرم‌افزارهای امروزی از پایگاه داده استفاده می‌کنند.

مثلاً:

* اینستاگرام
* تلگرام
* دیجی‌کالا
* اسنپ
* یوتیوب
* گوگل
* فیسبوک

همگی میلیاردها رکورد را داخل پایگاه داده ذخیره می‌کنند.

در این فصل با مفهوم Database، انواع آن، اصطلاحات رایج و نحوه ارتباط Node.js با پایگاه داده آشنا می‌شویم.

---

# Database چیست؟

Database یا پایگاه داده، محلی برای ذخیره، مدیریت و بازیابی اطلاعات است.

به کمک پایگاه داده می‌توان اطلاعات را:

* ذخیره کرد.
* جستجو کرد.
* ویرایش کرد.
* حذف کرد.
* مرتب کرد.
* فیلتر کرد.

---

# چرا Database لازم است؟

فرض کنید اطلاعات کاربران را داخل حافظه ذخیره کنیم.

```javascript
const users = [
    {
        id: 1,
        name: "Ali"
    }
];
```

بعد از Restart شدن برنامه:

```text
users = []
```

همه اطلاعات حذف می‌شوند.

اما Database اطلاعات را روی دیسک ذخیره می‌کند.

---

# SQL Database

# NoSQL Database

# SQL یا NoSQL؟

هر دو کاربردهای خاص خود را دارند.

SQL مناسب است برای:

* سیستم مالی
* بانک
* حسابداری
* فروشگاه
* ERP

---

NoSQL مناسب است برای:

* شبکه اجتماعی
* چت
* سیستم‌های Real-Time
* داده‌های انعطاف‌پذیر
* پروژه‌های Big Data

# اشتباهات رایج

### ذخیره اطلاعات داخل متغیرها

نگهداری اطلاعات در حافظه برنامه باعث از بین رفتن آن‌ها پس از Restart شدن سرور می‌شود.

---

### انتخاب Database نامناسب

هر پروژه نیازهای متفاوتی دارد؛ همیشه قبل از انتخاب SQL یا NoSQL نیازهای پروژه را بررسی کنید.

---

### نداشتن Backup

از دست رفتن اطلاعات بدون داشتن نسخه پشتیبان می‌تواند خسارت جبران‌ناپذیری ایجاد کند.

---

### استفاده نکردن از Index

جستجو روی داده‌های زیاد بدون Index می‌تواند عملکرد برنامه را به‌شدت کاهش دهد.

---

### باز نگذاشتن Connectionهای بلااستفاده

مدیریت نادرست Connectionها باعث مصرف بیش از حد منابع و کاهش کارایی سرور می‌شود.

---

# نکات حرفه‌ای

* قبل از انتخاب Database، نوع داده‌ها و نیازهای پروژه را تحلیل کنید.
* همیشه از Connection Pool استفاده کنید.
* برای ستون‌های پرتکرار در جستجو، Index ایجاد کنید.
* از Backupهای منظم و خودکار استفاده کنید.
* اطلاعات حساس مانند رمز عبور را به‌صورت هش‌شده ذخیره کنید.
* برای پروژه‌های بزرگ، مانیتورینگ عملکرد پایگاه داده را فراموش نکنید.
* طراحی صحیح ساختار داده‌ها از همان ابتدای پروژه، هزینه توسعه آینده را کاهش می‌دهد.

# پاسخ تشریحی

## پاسخ تمرین ۱

SQL داده‌ها را در جدول‌های ساخت‌یافته ذخیره می‌کند و برای پروژه‌هایی با روابط پیچیده و تراکنش‌های دقیق مناسب است. NoSQL داده‌ها را به‌صورت منعطف‌تر (مانند Document یا Key-Value) ذخیره می‌کند و برای پروژه‌هایی با ساختار داده متغیر یا حجم بسیار زیاد مناسب است.

---

## پاسخ تمرین ۲

* **Create:** ثبت کاربر جدید
* **Read:** نمایش اطلاعات کاربر
* **Update:** تغییر ایمیل کاربر
* **Delete:** حذف حساب کاربری

---

## پاسخ تمرین ۳

در SQL داده‌ها داخل **Table** ذخیره می‌شوند، اما در MongoDB داده‌ها داخل **Collection** قرار می‌گیرند که شامل مجموعه‌ای از Documentها است.

---

## پاسخ تمرین ۴

Index ساختاری برای دسترسی سریع‌تر به داده‌ها است. به جای بررسی تمام رکوردها، Database از Index برای پیدا کردن سریع داده استفاده می‌کند و زمان جستجو را کاهش می‌دهد.

---
