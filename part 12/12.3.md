# فصل 97 - PostgreSQL

## مقدمه

در فصل قبل با SQL آشنا شدیم و یاد گرفتیم چگونه با Databaseهای رابطه‌ای کار کنیم.

اما SQL به‌تنهایی یک Database نیست.

برای اجرای Queryهای SQL به یک **Database Management System** یا DBMS نیاز داریم. یکی از قدرتمندترین و محبوب‌ترین گزینه‌ها برای Backend، **PostgreSQL** است.

PostgreSQL یک Database رابطه‌ای قدرتمند، متن‌باز و مناسب پروژه‌های کوچک تا سیستم‌های بزرگ است و قابلیت‌های پیشرفته‌ای مانند:

* Transaction
* Foreign Key
* Index
* Constraint
* JSON
* Array
* Full-Text Search
* View
* Function
* Trigger
* Extension

را در اختیار برنامه‌نویس قرار می‌دهد.

در پروژه‌های Node.js، PostgreSQL یکی از انتخاب‌های بسیار مناسب برای ذخیره و مدیریت داده‌های Backend است.

در این فصل ابتدا PostgreSQL را نصب و راه‌اندازی می‌کنیم، سپس با ساخت Database و Table، اجرای Query، کاربران و Permissionها، Backup و Restore و در نهایت اتصال PostgreSQL به Node.js آشنا می‌شویم.

هدف این فصل این است که در پایان بتوانیم یک PostgreSQL Database واقعی را برای یک پروژه Node.js طراحی و مدیریت کنیم.

# بخش 1 - آشنایی با PostgreSQL

## 97.1 - PostgreSQL چیست؟

PostgreSQL یک **Object-Relational Database Management System** یا ORDBMS است.

به زبان ساده:

```text
PostgreSQL
    ↓
Database Management System
    ↓
ذخیره و مدیریت داده‌ها
    ↓
اجرای SQL Query
```

PostgreSQL از SQL پشتیبانی می‌کند و علاوه بر امکانات استاندارد SQL، قابلیت‌های اختصاصی زیادی نیز دارد.

---

## 97.2 - ویژگی‌های PostgreSQL

مهم‌ترین ویژگی‌های PostgreSQL:

* Open Source
* رایگان
* پایدار
* قابل توسعه
* پشتیبانی قدرتمند از SQL
* پشتیبانی از Transaction
* پشتیبانی از Foreign Key
* پشتیبانی از Index
* پشتیبانی از JSON و JSONB
* پشتیبانی از Array
* پشتیبانی از Full-Text Search
* پشتیبانی از View
* پشتیبانی از Function
* پشتیبانی از Trigger
* پشتیبانی از Extension
* مناسب برای پروژه‌های Backend
* مناسب برای پروژه‌های بزرگ

## 97.3 - PostgreSQL در Node.js

یک Backend واقعی می‌تواند ساختار زیر را داشته باشد:

```text
Client
   ↓
HTTP Request
   ↓
Node.js
   ↓
Application Logic
   ↓
PostgreSQL
   ↓
Data
```

مثلاً:

```text
POST /users
       ↓
Node.js
       ↓
INSERT INTO users
       ↓
PostgreSQL
       ↓
User Created
```

یا:

```text
GET /products
       ↓
Node.js
       ↓
SELECT * FROM products
       ↓
PostgreSQL
       ↓
JSON Response
```

## 97.27 - JSON و JSONB

یکی از قابلیت‌های قدرتمند PostgreSQL پشتیبانی از JSON است.

مثلاً:

```sql

    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    metadata JSONB
);
```

```sql

    'Laptop',
    '{"brand": "Lenovo", "ram": 16}'
);
```

سپس:

```sql
SELECT metadata->>'brand'
FROM products;
```

`JSONB` برای سناریوهایی که داده ساختاریافته JSON داریم بسیار کاربردی است.

# بخش 8 - Identity و تولید ID

## 97.35 - Identity Column

در PostgreSQL می‌توان از Identity برای تولید خودکار ID استفاده کرد.

مثلاً:

```sql
id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY
```

در این حالت هنگام Insert نیازی نیست مقدار `id` را ارسال کنیم:

```sql
INSERT INTO users (name, email)
VALUES ('Ali', 'ali@example.com');
```

PostgreSQL مقدار ID را تولید می‌کند.

---

## 97.36 - GENERATED ALWAYS و BY DEFAULT

دو حالت رایج:

```sql
GENERATED ALWAYS AS IDENTITY
```

و:

```sql
GENERATED BY DEFAULT AS IDENTITY
```

`ALWAYS` محدودیت بیشتری برای وارد کردن دستی مقدار دارد، در حالی که `BY DEFAULT` انعطاف بیشتری دارد.

## 97.40 - RETURNING

یکی از قابلیت‌های بسیار کاربردی PostgreSQL، `RETURNING` است.

مثلاً:

```sql

VALUES ('Ali', 'ali@example.com')
```

```sql

SET name = 'Ali Reza'
```

بعد از Delete:

```sql

WHERE id = 1
RETURNING id, name;
```

این قابلیت در Node.js بسیار کاربردی است؛ زیرا می‌توان نتیجه رکورد تغییرکرده را مستقیماً از همان Query دریافت کرد.

```sql

    users.name,
    orders.id
FROM users

    ON users.id = orders.user_id;
```

---

## 97.42 - LEFT JOIN

```sql
SELECT
    users.name,
    orders.id
FROM users
LEFT JOIN orders
    ON users.id = orders.user_id;
```

---

## 97.43 - چند Table

مثلاً:

```text
users
  ↓
orders
  ↓
order_items
  ↓
products
```

Query:

```sql
SELECT
    users.name AS user_name,
    products.name AS product_name,
    order_items.quantity
FROM users
JOIN orders
    ON users.id = orders.user_id
JOIN order_items
    ON orders.id = order_items.order_id
JOIN products
    ON products.id = order_items.product_id;
```

## 97.47 - بررسی Query

PostgreSQL ابزارهایی برای بررسی نحوه اجرای Query دارد.

مثلاً:

```sql
EXPLAIN
SELECT *
FROM users
WHERE email = 'ali@example.com';
```

برای اجرای Query و مشاهده اطلاعات اجرای آن:

```sql
EXPLAIN ANALYZE
SELECT *
FROM users
WHERE email = 'ali@example.com';
```

`EXPLAIN ANALYZE` واقعاً Query را اجرا می‌کند؛ بنابراین باید هنگام استفاده از آن روی Queryهای `INSERT`، `UPDATE` یا `DELETE` دقت بیشتری داشته باشیم.

## 97.66 - اتصال ساده

مثال:

```javascript
import pg from 'pg';

const { Client } = pg;

const client = new Client({
  host: 'localhost',
  port: 5432,
  user: 'postgres',
  password: process.env.DB_PASSWORD,
  database: 'shop'
```

## 97.67 - Connection Pool

در یک Backend واقعی معمولاً بهتر است به جای ایجاد Connection جدید برای هر Request از Connection Pool استفاده کنیم.

مثلاً:

```javascript
import pg from 'pg';

const { Pool } = pg;

const pool = new Pool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME
});
```

سپس:

```javascript
const result = await pool.query(
  'SELECT id, name FROM users'
);

console.log(result.rows);
```

Pool به مدیریت Connectionهای Database کمک می‌کند.

---

## 97.68 - Parameterized Query

نباید اطلاعات کاربر را مستقیم داخل SQL قرار دهیم.

نامناسب:

```javascript
const query = `
  SELECT *
  FROM users
  WHERE email = '${email}'
`;
```

روش مناسب:

```javascript
const result = await pool.query(
  'SELECT * FROM users WHERE email = $1',
  [email]
);
```

## 97.69 - INSERT و RETURNING در Node.js

```javascript
const result = await pool.query(
  `
  INSERT INTO users (name, email)
  VALUES ($1, $2)
  RETURNING id, name, email
  `,
  [name, email]
);

console.log(result.rows[0]);
```

## 97.70 - Transaction در Node.js

برای Transaction چند Query باید از یک Connection مشترک استفاده کنیم.

الگوی کلی:

```javascript
const client = await pool.connect();

try {
  await client.query('BEGIN');

  await client.query(
    `
    UPDATE accounts
    SET balance = balance - $1
    WHERE id = $2
    `,
    [100, 1]
  );

  await client.query(
    `
    UPDATE accounts
    SET balance = balance + $1
    WHERE id = $2
    `,
    [100, 2]
  );

  await client.query('COMMIT');
} catch (error) {
  await client.query('ROLLBACK');
  throw error;
} finally {
  client.release();
}
```

نکته مهم این است که تمام Queryهای Transaction باید از همان Connection اجرا شوند.

## مرحله 14 - ثبت Order با Transaction

پروژه باید:

* PostgreSQL داشته باشد.

* Queryها Parameterized باشند.
* Constraint داشته باشد.
* Foreign Key داشته باشد.
* Index مناسب داشته باشد.
* Transaction برای ایجاد Order داشته باشد.
* Environment Variable داشته باشد.
* خطاهای Database را مدیریت کند.
* از `RETURNING` در عملیات مناسب استفاده کند.
* ساختار پروژه مرتب داشته باشد.
