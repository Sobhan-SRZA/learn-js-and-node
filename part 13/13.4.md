# فصل 105 - Jest

## مقدمه

در فصل‌های قبل با مفهوم **Testing**، تفاوت Unit Test و Integration Test و نحوه تست کردن بخش‌های مختلف یک برنامه Node.js آشنا شدیم.

حالا وقت آن است که با یکی از معروف‌ترین ابزارهای Testing در اکوسیستم JavaScript و Node.js آشنا شویم:

**Jest**

Jest یک Test Framework است که امکانات مختلفی برای نوشتن و اجرای Test در اختیار ما قرار می‌دهد.

با Jest می‌توانیم:

* Unit Test بنویسیم.
* Integration Test بنویسیم.
* Functionها را تست کنیم.
* Moduleها را Mock کنیم.
* Function Callها را بررسی کنیم.
* Exceptionها را تست کنیم.
* Async Code را تست کنیم.
* Promiseها را تست کنیم.
* Timerها را کنترل کنیم.
* Testها را Group کنیم.
* Testها را Filter کنیم.
* Coverage بگیریم.
* قبل و بعد از Testها Setup و Cleanup انجام دهیم.

ساختار کلی کار با Jest:

```text
Write Test
   ↓
Run Jest
   ↓
Execute Code
   ↓
Assertion
   ↓
PASS / FAIL
```

در این فصل Jest را از پایه شروع می‌کنیم و قدم‌به‌قدم به استفاده حرفه‌ای از آن در پروژه‌های Node.js می‌رسیم.

# بخش 1 - آشنایی با Jest

## 105.1 - Jest چیست؟

Jest یک ابزار Testing برای JavaScript است که توسط Meta توسعه داده شده و در پروژه‌های JavaScript و Node.js استفاده می‌شود.

Jest امکانات مختلف Testing را در یک ابزار ارائه می‌کند.

به جای اینکه برای هر بخش از Testing ابزار جداگانه‌ای نصب کنیم، Jest بسیاری از قابلیت‌های مورد نیاز را در اختیارمان قرار می‌دهد.

---

## 105.2 - چرا Jest؟

برخی از ویژگی‌های مهم Jest:

* Syntax ساده
* اجرای سریع Testها
* Assertion داخلی
* Mocking
* Snapshot Testing
* Code Coverage
* Test Isolation
* پشتیبانی از Async Code
* Watch Mode
* قابلیت Configuration
* اکوسیستم گسترده

---

## 105.3 - Jest در پروژه Node.js

Jest می‌تواند برای تست بخش‌های مختلف یک Backend استفاده شود:

```text
Node.js Application
│
├── Controllers
├── Services
├── Repositories
├── Utilities
├── Validators
├── Authentication
└── API
```

برای هرکدام می‌توان Test مناسب نوشت.

# بخش 18 - Testing Service

فرض کنید:

```javascript
class UserService {
  constructor(repository) {
    this.repository = repository;
  }

  async getUser(id) {
    return this.repository.findById(id);
  }
}
```

Test:

```javascript
test("gets user", async () => {
  const repository = {
    findById: jest.fn()
  };

  repository.findById.mockResolvedValue({
    id: 1,
    name: "Ali"
  });

  const service = new UserService(repository);

  const user = await service.getUser(1);

  expect(user).toEqual({
    id: 1,
    name: "Ali"
  });

  expect(repository.findById)
    .toHaveBeenCalledWith(1);
});
```

این یک نمونه مناسب از Unit Test با Jest است.

# جمع‌بندی فصل

در این فصل با Jest به عنوان یکی از ابزارهای مهم Testing در JavaScript و Node.js آشنا شدیم.

یاد گرفتیم چگونه:

```text
Test
↓
Expect
↓
Assertion
```

بنویسیم و با Matcherهای مختلف نتیجه را بررسی کنیم.

همچنین با:

```text
describe
beforeEach
afterEach
beforeAll
afterAll
```

برای مدیریت ساختار و Lifecycle Testها آشنا شدیم.

در ادامه Mocking را یاد گرفتیم:

```text
jest.fn()
jest.mock()
jest.spyOn()
```

و دیدیم چگونه Dependencyها را برای Unit Test شبیه‌سازی کنیم.

همچنین یاد گرفتیم چگونه:

```text
Promise
Async/Await
Error
HTTP API
Database Layer
```

را در Testهای مختلف بررسی کنیم.

در نهایت با Coverage، Watch Mode، Configuration، Parameterized Test و اجرای Jest در پروژه‌های Node.js آشنا شدیم.

ساختار کلی Testing در پروژه ما اکنون می‌تواند به شکل زیر باشد:

```text
Node.js Application
│
├── Unit Test
│   └── Jest
│
├── Integration Test
│   ├── Jest
│   └── Supertest
│
└── E2E Test
```

Jest ابزار اصلی اجرای بسیاری از Testهای Unit و Integration ما خواهد بود و در فصل‌های بعدی می‌توانیم از آن در کنار ابزارهای تخصصی‌تر برای Testing بخش‌های مختلف یک Backend واقعی استفاده کنیم.
