# فصل 128 - ESLint

## مقدمه

در فصل‌های قبل یاد گرفتیم چگونه با Git و GitHub پروژه‌های خود را مدیریت کنیم. اما یک سؤال مهم باقی می‌ماند:

**چطور مطمئن شویم کدی که می‌نویسیم از نظر کیفیت، یکدستی و برخی خطاهای رایج وضعیت مناسبی دارد؟**

فرض کنید در یک پروژه Node.js چندین فایل JavaScript داشته باشیم و برنامه‌نویسان مختلف روی آن کار کنند.

ممکن است یک نفر این‌گونه بنویسد:

```js
const userName = "Sobhan";
```

و شخص دیگری:

```js
const user_name = "Sobhan";
```

یا ممکن است برنامه‌نویسی متغیری تعریف کند که هیچ‌وقت استفاده نمی‌شود:

```js
const userName = "Sobhan";

console.log("Hello");
```

یا به‌صورت ناخواسته خطاهایی در کد ایجاد کند که در زمان اجرا متوجه آن‌ها شویم.

در پروژه‌های کوچک ممکن است این مشکلات چندان جدی به نظر نرسند؛ اما در پروژه‌های بزرگ Node.js، تعداد زیاد فایل‌ها، توابع و اعضای تیم باعث می‌شود کنترل کیفیت کد سخت‌تر شود.

اینجاست که **ESLint** وارد می‌شود.

ESLint یک ابزار **Static Code Analysis** برای JavaScript است که کد را بدون اجرای برنامه بررسی می‌کند و می‌تواند بسیاری از مشکلات، خطاهای احتمالی و ناهماهنگی‌های مربوط به Style را شناسایی کند.

در این فصل یاد می‌گیریم:

* ESLint چیست؟
* Static Analysis چیست؟
* چرا ESLint در Node.js مهم است؟
* چگونه ESLint را نصب کنیم؟
* چگونه ESLint را در پروژه Node.js راه‌اندازی کنیم؟
* Configuration چیست؟
* Rule چیست؟
* Error و Warning چه تفاوتی دارند؟
* چگونه Ruleها را فعال یا غیرفعال کنیم؟
* چگونه کد را با ESLint بررسی کنیم؟
* Auto Fix چیست؟
* چگونه ESLint را با VS Code استفاده کنیم؟
* چگونه ESLint را در پروژه تیمی استفاده کنیم؟
* چگونه ESLint را در Git و GitHub وارد Workflow کنیم؟
* چگونه ESLint را در CI/CD اجرا کنیم؟

---

# 128.1 - ESLint چیست؟

ESLint یک ابزار برای **Lint کردن کد JavaScript** است.

Lint به فرآیند بررسی کد برای پیدا کردن مشکلات احتمالی، خطاهای رایج و ناهماهنگی‌های کدنویسی گفته می‌شود.

برای مثال:

```js
const name = "Ali";

console.log(name);
```

کد بالا مشکلی ندارد.

اما:

```js
const name = "Ali";

console.log("Hello");
```

ممکن است ESLint بتواند تشخیص دهد که `name` تعریف شده ولی استفاده نشده است.

---

# 128.2 - Linter چیست؟

Linter برنامه‌ای است که Source Code را بررسی می‌کند و مشکلات مشخصی را گزارش می‌دهد.

به‌صورت ساده:

```text
JavaScript Code
      ↓
    ESLint
      ↓
Code Analysis
      ↓
Problems
Warnings
Errors
Suggestions
```

---

# 128.3 - Static Analysis چیست؟

Static Analysis یعنی بررسی کد **بدون اجرای برنامه**.

برای مثال:

```js
const userName = "Ali";

console.log(user);
```

در این کد متغیر `user` تعریف نشده است.

ابزارهای تحلیل استاتیک می‌توانند برخی مشکلات این‌چنینی را قبل از اجرای برنامه شناسایی کنند.

این ویژگی باعث می‌شود بسیاری از مشکلات زودتر پیدا شوند.

---

# 128.4 - چرا ESLint برای Node.js مهم است؟

در پروژه‌های Node.js معمولاً تعداد زیادی فایل JavaScript داریم:

```text
src/
├── controllers/
├── services/
├── routes/
├── models/
├── middlewares/
└── utils/
```

اگر هیچ قانون مشخصی برای کدنویسی نداشته باشیم، ممکن است کد پروژه به مرور نامنظم شود.

ESLint کمک می‌کند برخی قوانین به‌صورت خودکار بررسی شوند.

برای مثال:

* متغیر بدون استفاده
* برخی خطاهای رایج
* الگوهای نامناسب
* قوانین مربوط به Style
* برخی مشکلات مربوط به JavaScript

---

# 128.5 - ESLint کد را اجرا نمی‌کند

یک نکته مهم:

ESLint جایگزین اجرای برنامه و تست نیست.

مثلاً اگر برنامه از نظر Syntax درست باشد ولی منطق اشتباهی داشته باشد:

```js
function calculatePrice(price, discount) {
  return price + discount;
}
```

ممکن است ESLint نتواند تشخیص دهد که منطق تجاری اشتباه است.

بنابراین:

```text
ESLint
+
Tests
+
Code Review
+
Runtime Validation
```

در کنار هم کیفیت کد را بهتر می‌کنند.

# 128.6 - نصب ESLint

در پروژه Node.js ابتدا پروژه را ایجاد می‌کنیم:

```bash
mkdir eslint-node-app
cd eslint-node-app
npm init -y
```

سپس ESLint را به‌عنوان Development Dependency نصب می‌کنیم:

```bash
npm install --save-dev eslint
```

یا:

```bash
npm i -D eslint
```

# 128.7 - چرا ESLint را به صورت devDependency نصب می‌کنیم؟

ESLint معمولاً ابزار توسعه است.

یعنی برای اجرای برنامه در Production به خود ESLint نیاز نداریم.

به همین دلیل معمولاً در:

```json
{
  "devDependencies": {
    "eslint": "..."
  }
}
```

قرار می‌گیرد.

# 128.8 - اجرای ESLint

پس از نصب، می‌توانیم فایل‌های پروژه را بررسی کنیم.

مثلاً:

```bash
npx eslint .
```

نقطه (`.`) یعنی مسیر فعلی پروژه.

یا می‌توانیم مسیر مشخصی بدهیم:

```bash
npx eslint src/
```

---

# 128.9 - Configuration چیست؟

ESLint برای اینکه بداند چه قوانینی باید بررسی شوند، نیاز به Configuration دارد.

در نسخه‌های جدید ESLint، یکی از روش‌های اصلی تنظیمات استفاده از:

```text
eslint.config.js
```

است.

برای مثال:

```js
export default [];
```

این فایل می‌تواند قوانین و تنظیمات ESLint پروژه را مشخص کند.

---

# 128.10 - Rule چیست؟

Rule یا قانون مشخص می‌کند ESLint باید چه چیزی را بررسی کند.

مثلاً می‌توانیم قانونی داشته باشیم که متغیرهای بدون استفاده را گزارش کند.

ساختار مفهومی:

```text
ESLint
 │
 ├── Rule A
 ├── Rule B
 ├── Rule C
 └── Rule D
```

هر Rule می‌تواند:

```text
off
warn
error
```

باشد.

---

# 128.11 - سطح Ruleها

سه سطح رایج برای Ruleها:

### off

Rule غیرفعال است.

```text
0
```

### warn

مشکل به‌عنوان Warning گزارش می‌شود.

```text
1
```

### error

مشکل به‌عنوان Error گزارش می‌شود.

```text
2
```

مثلاً:

```js
rules: {
  "no-unused-vars": "warn"
}
```

یا:

```js
rules: {
  "no-unused-vars": "error"
}
```

---

# 128.12 - no-unused-vars

یکی از Ruleهای مهم:

```text
no-unused-vars
```

است.

مثلاً:

```js
const userName = "Ali";

console.log("Hello");
```

متغیر `userName` استفاده نشده است.

ESLint می‌تواند چنین مشکلی را گزارش کند.

---

# 128.13 - نمونه Configuration

یک Configuration ساده می‌تواند شامل Ruleهایی مانند:

```js
export default [
  {
    rules: {
      "no-unused-vars": "error"
    }
  }
];
```

باشد.

اکنون ESLint متغیرهای بدون استفاده را به‌عنوان Error گزارش می‌کند.

---

# 128.14 - بررسی یک فایل مشخص

فرض کنید فایل زیر را داریم:

```text
src/app.js
```

می‌توانیم اجرا کنیم:

```bash
npx eslint src/app.js
```

اگر مشکلی وجود داشته باشد، ESLint آن را گزارش می‌کند.

---

# 128.15 - Auto Fix چیست؟

برخی مشکلات قابل اصلاح خودکار هستند.

برای استفاده از Auto Fix:

```bash
npx eslint . --fix
```

ESLint در مواردی که امکان اصلاح خودکار وجود داشته باشد، کد را تغییر می‌دهد.

اما نباید تصور کنیم تمام مشکلات با `--fix` حل می‌شوند.

برخی مشکلات نیاز به تصمیم برنامه‌نویس دارند.

---

# 128.16 - مثال Auto Fix

فرض کنید یک Rule مربوط به Formatting فعال باشد و کد با آن Rule هماهنگ نباشد.

می‌توانیم:

```bash
npx eslint . --fix
```

را اجرا کنیم.

ESLint تلاش می‌کند مشکلات قابل اصلاح را برطرف کند.

پس از آن بهتر است دوباره:

```bash
npx eslint .
```

را اجرا کنیم.

---

# 128.17 - ESLint و Formatting

ESLint می‌تواند برخی قوانین Style را نیز بررسی کند، اما باید تفاوت دو مفهوم را بدانیم:

```text
Linting
```

و:

```text
Formatting
```

Linting بیشتر روی مشکلات و قوانین کد تمرکز دارد.

Formatting بیشتر مربوط به شکل ظاهری و قالب‌بندی کد است.

برای Formatting معمولاً ابزارهایی مانند **Prettier** استفاده می‌شوند که در فصل بعد با آن آشنا خواهیم شد.

---

# 128.18 - ESLint و Node.js

در پروژه Node.js باید Configuration را متناسب با محیط پروژه تنظیم کنیم.

مثلاً پروژه ما ممکن است از:

```text
Node.js
CommonJS
```

یا:

```text
Node.js
ES Modules
```

استفاده کند.

همچنین ممکن است پروژه از قابلیت‌های جدید JavaScript استفاده کند.

پس ESLint باید Context پروژه را به‌درستی بشناسد.

---

# 128.19 - ESLint و ES Modules

اگر پروژه از ES Modules استفاده کند:

```js
import fs from "node:fs";
```

و:

```js
export function readFile() {
  // ...
}
```

باید Configuration پروژه نیز متناسب با این ساختار باشد.

در پروژه‌های جدید Node.js، استفاده از ES Modules موضوع مهمی است.

---

# 128.20 - ESLint و CommonJS

در CommonJS ممکن است کد به این شکل باشد:

```js
const fs = require("node:fs");

module.exports = {
  readFile
};
```

ESLint باید بر اساس محیط و Syntax پروژه تنظیم شود.

---

# 128.21 - استفاده از Presetها و Configهای آماده

نوشتن تمام Ruleها از ابتدا معمولاً مناسب نیست.

ESLint و اکوسیستم آن امکان استفاده از Configurationهای آماده و Pluginهای مختلف را فراهم می‌کنند.

این کار باعث می‌شود بتوانیم مجموعه‌ای از قوانین استاندارد را سریع‌تر به پروژه اضافه کنیم.

---

# 128.22 - Plugin چیست؟

Plugin قابلیتی است که قوانین یا امکانات بیشتری به ESLint اضافه می‌کند.

به‌صورت مفهومی:

```text
ESLint
   +
Plugin
   ↓
Additional Rules
```

Pluginها می‌توانند برای نیازهای مختلف استفاده شوند.

برای مثال در اکوسیستم JavaScript Pluginهایی برای:

* Frameworkها
* Libraryها
* Testing
* Importها
* Security
* Documentation

وجود دارند.

---

# 128.23 - ESLint Configuration در پروژه تیمی

در پروژه تیمی نباید هر برنامه‌نویس قوانین متفاوتی داشته باشد.

مثلاً اگر شخص اول:

```text
no-unused-vars = error
```

داشته باشد و شخص دوم این Rule را نداشته باشد، ممکن است کیفیت کد یکسان نباشد.

Configuration باید در Repository پروژه قرار داشته باشد تا همه اعضای تیم از قوانین یکسان استفاده کنند.

# 128.24 - ESLint و package.json

بهتر است دستور اجرای ESLint را در `package.json` قرار دهیم.

مثلاً:

```json
{
  "scripts": {
    "lint": "eslint ."
  }
}
```

حالا به‌جای:

```bash
npx eslint .
```

می‌توانیم بنویسیم:

```bash
npm run lint
```

# 128.25 - Script مربوط به Fix

می‌توانیم Script جداگانه برای اصلاح خودکار داشته باشیم:

```json
{
  "scripts": {
    "lint": "eslint .",
    "lint:fix": "eslint . --fix"
  }
}
```

حالا:

```bash
npm run lint
```

برای بررسی و:

```bash
npm run lint:fix
```

برای اصلاح خودکار استفاده می‌شود.

# 128.27 - مزیت استفاده از ESLint در Editor

```text
   ↓

   ↓
```

```text
   ↓
Fix
```

مشکلات می‌توانند خیلی زودتر دیده شوند.

# 128.37 - تنظیم ESLint برای پروژه Node.js

یک پروژه ساده:

```text
eslint-node-app/
├── eslint.config.js
├── package.json
├── package-lock.json
├── .gitignore
└── src/
    └── app.js
```

نمونه Configuration:

```js
export default [
  {
    rules: {
      "no-unused-vars": "error"
    }
  }
];
```

و `package.json`:

```json
{
  "scripts": {
```

## مرحله 5 - ایجاد کد

فایل `src/tasks.js`:

```js
const tasks = [];

function addTask(title) {
  tasks.push({
    id: tasks.length + 1,
    title,
    completed: false
  });
}

export {
  tasks,
  addTask
};
```

فایل `src/utils.js`:

```js
function formatTask(task) {
  return `${task.id}: ${task.title}`;
}

export {
  formatTask
};
```

فایل `src/app.js`:

```js
import { addTask, tasks } from "./tasks.js";
import { formatTask } from "./utils.js";

const unusedValue = 123;

addTask("Learn ESLint");

for (const task of tasks) {
  console.log(formatTask(task));
}
```

در اینجا:

```js
const unusedValue = 123;
```

استفاده نشده است.
