# فصل 131 - Nodemon

## مقدمه

در پروژه‌های Node.js معمولاً در زمان توسعه، مرتباً فایل‌های مختلف را تغییر می‌دهیم.

فرض کنید یک Server ساده داریم:

```js
const http = require('node:http');

const server = http.createServer((req, res) => {
  res.end('Hello Node.js');
});

server.listen(3000, () => {
  console.log('Server is running on port 3000');
});
```

برای اجرای آن:

```bash
node server.js
```

حالا اگر فایل `server.js` را تغییر دهیم، Node.js به‌صورت خودکار متوجه تغییر فایل نمی‌شود و Server را Restart نمی‌کند.

در نتیجه باید:

```text
تغییر کد
   ↓
متوقف کردن Server
   ↓
اجرای دوباره node
   ↓
بررسی نتیجه
```

را بارها انجام دهیم.

در پروژه‌های واقعی این کار بسیار خسته‌کننده می‌شود.

**Nodemon** ابزاری برای محیط توسعه است که فایل‌های پروژه را زیر نظر می‌گیرد و وقتی تغییری مشاهده کند، برنامه Node.js را به‌صورت خودکار Restart می‌کند.

در این فصل یاد می‌گیریم:

* Nodemon چیست؟
* چرا به Nodemon نیاز داریم؟
* چگونه Nodemon را نصب کنیم؟
* چگونه برنامه را با Nodemon اجرا کنیم؟
* تفاوت `node` و `nodemon` چیست؟
* چگونه Nodemon را در `package.json` قرار دهیم؟
* چگونه فایل‌ها و پوشه‌های خاص را Watch کنیم؟
* چگونه فایل‌ها را Ignore کنیم؟
* چگونه Nodemon را برای پروژه‌های مختلف Node.js تنظیم کنیم؟
* `nodemon.json` چیست؟
* چگونه Nodemon را با Environment Variables استفاده کنیم؟
* چگونه Nodemon را با پروژه‌های API و Server استفاده کنیم؟
* تفاوت Development و Production در این زمینه چیست؟
* اشتباهات رایج Nodemon چیست؟
* چگونه یک Workflow حرفه‌ای برای توسعه Node.js ایجاد کنیم؟

---

# 131.1 - Nodemon چیست؟

**Nodemon** ابزاری برای توسعه برنامه‌های Node.js است که می‌تواند فایل‌های پروژه را زیر نظر بگیرد.

اگر فایلی که برنامه به آن وابسته است تغییر کند، Nodemon برنامه را Restart می‌کند.

به‌صورت ساده:

```text
Node.js Application
       ↑
    Nodemon
       ↑
File Changes
```

مثلاً:

```text
server.js
   ↓
nodemon
   ↓
Node.js Server
```

اگر `server.js` تغییر کند:

```text
server.js تغییر کرد
       ↓
Nodemon متوجه تغییر می‌شود
       ↓
Process متوقف می‌شود
       ↓
Process دوباره اجرا می‌شود
```

---

# 131.2 - مشکل اجرای معمولی Node.js

وقتی برنامه را با:

```bash
node server.js
```

اجرا می‌کنیم، Node.js برنامه را اجرا می‌کند.

اگر فایل را تغییر دهیم:

```text
server.js
   ↓
Change
   ↓
Node.js
   ↓
بدون Restart خودکار
```

بنابراین برای دیدن تغییرات باید Server را Restart کنیم.

---

# 131.3 - راه‌حل Nodemon

با Nodemon:

```bash
nodemon server.js
```

برنامه اجرا می‌شود.

سپس:

```text
Edit server.js
      ↓
Save
      ↓
Nodemon detects change
      ↓
Restart application
```

در نتیجه دیگر لازم نیست بعد از هر تغییر، برنامه را دستی Restart کنیم.

---

# 131.4 - نصب Nodemon

از آنجا که Nodemon ابزار مخصوص توسعه است، معمولاً آن را به‌عنوان `devDependency` نصب می‌کنیم:

```bash
npm install --save-dev nodemon
```

یا:

```bash
npm install -D nodemon
```

بعد از نصب، در `package.json` قرار می‌گیرد:

```json
{
  "devDependencies": {
    "nodemon": "..."
  }
}
```

---

# 131.5 - چرا Nodemon در `devDependencies`؟

Nodemon معمولاً برای اجرای برنامه در محیط Development استفاده می‌شود.

در Production معمولاً نمی‌خواهیم برنامه صرفاً به‌خاطر تغییر فایل‌ها Restart شود.

بنابراین:

```text
Development
    ↓
Nodemon
    ↓
Automatic Restart
```

اما:

```text
Production
    ↓
Normal Process Management
```

رویکرد مناسب‌تری است.

---

# 131.6 - اجرای برنامه با Nodemon

فرض کنید فایل زیر را داریم:

```text
server.js
```

به‌جای:

```bash
node server.js
```

می‌توانیم بنویسیم:

```bash
npx nodemon server.js
```

اکنون Nodemon برنامه را اجرا می‌کند و تغییرات فایل‌ها را زیر نظر می‌گیرد.

---

# 131.7 - تفاوت `node` و `nodemon`

### Node.js

```bash
node server.js
```

برنامه را اجرا می‌کند.

### Nodemon

```bash
npx nodemon server.js
```

برنامه را اجرا می‌کند و تغییرات را نیز زیر نظر می‌گیرد.

پس:

```text
node
 ↓
Run

nodemon
 ↓
Run + Watch + Restart
```

---

# 131.8 - استفاده از Script در `package.json`

بهتر است به‌جای اینکه هر بار بنویسیم:

```bash
npx nodemon server.js
```

یک Script ایجاد کنیم.

مثلاً:

```json
{
  "scripts": {
    "dev": "nodemon server.js"
  }
}
```

حالا:

```bash
npm run dev
```

برنامه را با Nodemon اجرا می‌کند.

---

# 131.9 - تفاوت `npm start` و `npm run dev`

می‌توانیم Scriptهای مختلفی داشته باشیم:

```json
{
  "scripts": {
    "start": "node server.js",
    "dev": "nodemon server.js"
  }
}
```

حالا:

```bash
npm start
```

برنامه را با Node.js اجرا می‌کند.

و:

```bash
npm run dev
```

برنامه را با Nodemon اجرا می‌کند.

این تفکیک بسیار مفید است:

```text
Development
    ↓
npm run dev
    ↓
nodemon

Production
    ↓
npm start
    ↓
node
```

# 131.10 - اجرای Nodemon در یک پروژه Node.js

فرض کنید ساختار پروژه این باشد:

```text
my-app/
├── package.json
├── package-lock.json
└── src/
    └── server.js
```

در این صورت می‌توانیم Script را این‌گونه تعریف کنیم:

```json
{
  "scripts": {
    "dev": "nodemon src/server.js"
  }
}
```

سپس:

```bash
npm run dev
```

# 131.11 - مشاهده Restart شدن برنامه

فرض کنید:

```js
console.log('Server started');
```

در برنامه داشته باشیم.

وقتی برنامه را اجرا می‌کنیم:

```bash
npm run dev
```

Nodemon برنامه را اجرا می‌کند.

اگر فایل را تغییر دهیم و Save کنیم، Nodemon برنامه را Restart می‌کند.

در نتیجه دوباره پیام:

```text
Server started
```

را مشاهده خواهیم کرد.

---

# 131.12 - Nodemon چه چیزی را Watch می‌کند؟

Nodemon به‌صورت پیش‌فرض فایل‌های پروژه را برای تشخیص تغییرات زیر نظر می‌گیرد.

این تغییرات می‌توانند شامل مواردی مانند:

* تغییر فایل
* ایجاد فایل
* حذف فایل

باشند.

وقتی تغییر مرتبطی تشخیص داده شود، Process برنامه Restart می‌شود.

---

# 131.13 - Watch کردن یک پوشه خاص

می‌توانیم مشخص کنیم Nodemon فقط یک پوشه خاص را زیر نظر بگیرد.

مثلاً:

```bash
nodemon --watch src server.js
```

در این حالت تغییرات داخل `src` باعث Restart برنامه می‌شوند.

---

# 131.14 - Watch کردن چند مسیر

می‌توان چند مسیر را مشخص کرد:

```bash
nodemon --watch src --watch config server.js
```

اکنون تغییرات در:

```text
src/
config/
```

می‌توانند باعث Restart شوند.

---

# 131.15 - Ignore کردن فایل‌ها

گاهی نمی‌خواهیم تغییر بعضی فایل‌ها باعث Restart شوند.

مثلاً:

```text
logs/
```

را می‌توان Ignore کرد:

```bash
nodemon --ignore logs server.js
```

---

# 131.16 - استفاده از `nodemon.json`

برای پروژه‌های بزرگ بهتر است تنظیمات Nodemon را در یک فایل Configuration قرار دهیم.

فایل:

```text
nodemon.json
```

می‌تواند در Root پروژه قرار بگیرد.

مثلاً:

```json
{
  "watch": ["src"],
  "ignore": ["logs", "uploads"],
  "ext": "js,json"
}
```

---

# 131.17 - گزینه `watch`

مثلاً:

```json
{
  "watch": ["src"]
}
```

یعنی Nodemon تغییرات موجود در `src` را زیر نظر بگیرد.

ساختار:

```text
project/
├── nodemon.json
├── src/
│   ├── server.js
│   └── routes.js
└── package.json
```

---

# 131.18 - گزینه `ignore`

مثلاً:

```json
{
  "ignore": ["logs", "uploads"]
}
```

یعنی تغییرات این مسیرها باعث Restart نشوند.

این قابلیت در پروژه‌هایی که فایل‌های زیادی تولید می‌کنند بسیار مفید است.

---

# 131.19 - گزینه `ext`

می‌توان مشخص کرد چه Extensionهایی زیر نظر گرفته شوند:

```json

  "ext": "js,json"
}
```

یعنی تغییر فایل‌های:

```text
.js
.json
```

برای Nodemon مهم باشند.

# 131.21 - Nodemon و Environment Variables

می‌توانیم برنامه را همراه با Environment Variables اجرا کنیم.

مثلاً:

```bash
PORT=3000 nodemon src/server.js
```

در برنامه:

```js
const port = process.env.PORT || 3000;

console.log(`Server running on port ${port}`);
```

در پروژه‌های واقعی بهتر است مدیریت Environment Variables را با روش مناسب پروژه انجام دهیم.

---

# 131.22 - Nodemon و فایل `.env`

اگر پروژه از `.env` استفاده کند، تغییر `.env` ممکن است نیاز به Restart برنامه داشته باشد.

برای پروژه‌هایی که `.env` را Watch می‌کنند، باید با دقت Configuration مربوط به Watch و امنیت فایل‌های Environment را تنظیم کنیم.

همچنین:

```text
.env
```

نباید به Repository عمومی Commit شود.

در `.gitignore` معمولاً:

```text
.env
```

قرار می‌گیرد.

---

# 131.23 - Nodemon در API Server

Nodemon در توسعه APIهای Node.js بسیار کاربردی است.

مثلاً:

```js
const http = require('node:http');

const server = http.createServer((req, res) => {
  res.end('Hello API');
});

server.listen(3000, () => {
  console.log('API running on port 3000');
});
```

با:

```bash
npm run dev
```

Server اجرا می‌شود.

حالا هر بار که Route یا Logic مربوط به API را تغییر دهیم، Nodemon Server را Restart می‌کند.

# 131.24 - Nodemon و Express

در پروژه‌های Express نیز می‌توان از Nodemon استفاده کرد.

مثلاً:

```js
const express = require('express');

const app = express();

app.get('/', (req, res) => {
  res.json({
    message: 'Hello Node.js',
  });
});

app.listen(3000, () => {
  console.log('Server started');
});
```

در `package.json`:

```json
{
  "scripts": {
    "dev": "nodemon src/server.js"
  }
}
```

اکنون:

```bash
npm run dev
```

برای توسعه مناسب است.

# 131.25 - Nodemon و TypeScript

اگر در آینده با TypeScript کار کنیم، Workflow کمی متفاوت خواهد شد؛ زیرا فایل TypeScript ابتدا باید به JavaScript تبدیل شود.

یک معماری رایج:

```text
TypeScript
   ↓
Compiler
   ↓
JavaScript
   ↓
Node.js
```

در چنین پروژه‌هایی ابزارهایی مانند `tsx` نیز می‌توانند برای Development بسیار مناسب باشند.

بنابراین Nodemon تنها ابزار ممکن برای Hot Reload در اکوسیستم Node.js نیست.

# 131.26 - Nodemon و Debugging

Nodemon را می‌توان در Workflow مربوط به Debugging نیز استفاده کرد.

مثلاً:

```text
Code
 ↓
Nodemon
 ↓
Node.js
 ↓
Debugger
```

هدف این است که بعد از تغییر کد، Process دوباره اجرا شود تا بتوانیم تغییرات را سریع‌تر بررسی کنیم.

# 131.27 - توقف Nodemon

# 131.28 - Restart دستی

Nodemon امکان Restart دستی را نیز فراهم می‌کند.

در محیط اجرای Nodemon می‌توان با دستور مناسب Restart را درخواست کرد.

همچنین هر زمان فایل‌های Watch شده تغییر کنند، Restart به‌صورت خودکار انجام می‌شود.

---

# 131.29 - Nodemon و فرآیند توسعه

یکی از مهم‌ترین مزایای Nodemon، کوتاه کردن چرخه توسعه است.

بدون Nodemon:

```text
Write
 ↓
Save
 ↓
Stop
 ↓
Run
 ↓
Test
 ↓
Write Again
```

با Nodemon:

```text
Write
 ↓
Save
 ↓
Automatic Restart
 ↓
Test
 ↓
Write Again
```

این تفاوت در پروژه‌های بزرگ بسیار مهم می‌شود.

---

# 131.30 - Nodemon برای Production نیست

یکی از نکات بسیار مهم این است که Nodemon را نباید صرفاً به‌عنوان Process Manager مخصوص Production در نظر بگیریم.

Nodemon برای **Development** طراحی شده است.

در Production معمولاً از ابزارهای مناسب مدیریت Process و زیرساخت استفاده می‌شود.

بنابراین:

```text
Development
→ Nodemon

Production
→ Production Process Manager / Container / Platform
```

---

# 131.31 - Nodemon و Docker

اگر برنامه Node.js داخل Docker اجرا شود، مسئله File Watching و نحوه Mount شدن فایل‌ها اهمیت بیشتری پیدا می‌کند.

در Development ممکن است Source Code از Host به Container Mount شود:

```text
Host
 ↓
Volume
 ↓
Container
 ↓
Node.js
```

در چنین شرایطی باید تنظیمات File Watching با محیط Container هماهنگ باشد.

# 131.32 - Nodemon و پروژه‌های بزرگ

در پروژه‌های بزرگ بهتر است Nodemon همه فایل‌های موجود در پروژه را بدون دلیل Watch نکند.

مثلاً:

```text
node_modules/
uploads/
logs/
coverage/
dist/
```

معمولاً گزینه‌های مناسبی برای Watch کردن نیستند.

بهتر است فقط مسیرهای موردنیاز را مشخص کنیم:

```json
{
  "watch": ["src"]
}
```

اگر برنامه هنگام اجرا فایلی را تغییر دهد و همان فایل Watch شود، ممکن است Restartهای مکرر اتفاق بیفتد.

مثلاً:

```text
Application
 ↓
Writes File
 ↓
Nodemon detects
 ↓
Restart
 ↓
Application writes File
 ↓
...
```

برای جلوگیری از این مشکل باید مسیرهای Generated را Ignore کنیم.

---

## اشتباه 7 - تصور اینکه Nodemon خطاهای برنامه را حل می‌کند

Nodemon فقط برنامه را اجرا و Restart می‌کند.

اگر برنامه Bug داشته باشد، Nodemon Bug را برطرف نمی‌کند.

---

## اشتباه 8 - Restart شدن برنامه و تصور رفع شدن Error

Restart شدن Process به معنی رفع مشکل نیست.

اگر Error همچنان در کد وجود داشته باشد، بعد از Restart دوباره رخ خواهد داد.

---

## اشتباه 9 - Watch کردن کل پروژه بدون نیاز

بهتر است مسیرهای مشخصی مانند:

```text
src/
```

را Watch کنیم.

---

## اشتباه 10 - Commit کردن `node_modules`

Nodemon نیز مانند سایر Packageهای npm باید از طریق `package.json` و Lock File مدیریت شود.

پوشه:

```text
node_modules/
```

نباید وارد Git شود.

## مرحله 5 - فایل `routes.js`

```js
const users = require('./data');

function handleRequest(req, res) {
  if (req.url === '/users' && req.method === 'GET') {
    res.writeHead(200, {
      'Content-Type': 'application/json',
    });

    res.end(JSON.stringify(users));
    return;
  }

  res.writeHead(404, {
    'Content-Type': 'application/json',
  });

  res.end(
    JSON.stringify({
      message: 'Route not found',
    }),
  );
}

module.exports = handleRequest;
```

```js
const http = require('node:http');
const handleRequest = require('./routes');

const PORT = 3000;

const server = http.createServer(handleRequest);

  console.log(`Server running on port ${PORT}`);
});
```

# جمع‌بندی فصل

Nodemon یکی از ابزارهای بسیار کاربردی برای **توسعه برنامه‌های Node.js** است.

مهم‌ترین کاری که Nodemon انجام می‌دهد:

```text
Watch Files
    ↓
Detect Changes
    ↓
Restart Node.js Process
```

نصب:

```bash
npm install -D nodemon
```

اجرای مستقیم:

```bash
npx nodemon src/server.js
```

Script پیشنهادی:

```json
{
  "scripts": {
    "dev": "nodemon src/server.js",
    "start": "node src/server.js"
  }
}
```

Configuration:

```json
{
  "watch": ["src"],
  "ignore": ["logs", "uploads", "dist"],
  "ext": "js,json"
}
```

و مهم‌تر از همه، باید تفاوت محیط Development و Production را درک کنیم:

```text
Development
    ↓
Nodemon
    ↓
Automatic Restart
```

در حالی که Nodemon را نباید صرفاً به‌عنوان راهکار مدیریت Process در Production در نظر گرفت.

اکنون Workflow ابزارهای توسعه‌ای که تا اینجا یاد گرفته‌ایم، می‌تواند به شکل زیر باشد:

```text
Developer
    ↓
Prettier
    ↓
ESLint
    ↓
Nodemon
    ↓
Node.js Application
    ↓
Git
    ↓
GitHub
```

در این ساختار، هر ابزار وظیفه مشخصی دارد و در کنار یکدیگر تجربه توسعه یک پروژه واقعی Node.js را بسیار سریع‌تر و منظم‌تر می‌کنند.
