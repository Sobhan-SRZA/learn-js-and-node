# فصل 129 - Prettier

## مقدمه

در فصل قبل با **ESLint** آشنا شدیم. ESLint به ما کمک می‌کند مشکلات مختلف کد را شناسایی کنیم و قوانینی برای کیفیت و استاندارد کد پروژه تعریف کنیم.

اما یک موضوع دیگر وجود دارد:

**چطور ظاهر و Formatting کد را در کل پروژه یکسان کنیم؟**

فرض کنید دو برنامه‌نویس روی یک پروژه کار می‌کنند. یکی کد را این‌گونه می‌نویسد:

```js
const user = { name: "Ali", age: 20 };
```

و دیگری:

```js
const user = {
  name: "Ali",
  age: 20
};
```

یا ممکن است در پروژه‌ای هر شخص از تعداد متفاوتی Space، Tab، Line Break و روش‌های مختلف Formatting استفاده کند.

از نظر عملکرد، ممکن است این کدها تفاوتی نداشته باشند؛ اما در یک پروژه تیمی باعث می‌شوند:

* کدها ظاهر یکسانی نداشته باشند.
* Code Review سخت‌تر شود.
* Diffهای Git بزرگ‌تر و شلوغ‌تر شوند.
* زمان زیادی صرف بحث درباره Formatting شود.
* خوانایی پروژه کاهش پیدا کند.

برای حل این مشکل می‌توانیم از **Prettier** استفاده کنیم.

Prettier یک **Code Formatter** است که کد را طبق قوانین مشخصی به‌شکل خودکار قالب‌بندی می‌کند.

در این فصل یاد می‌گیریم:

* Prettier چیست؟
* Formatter چیست؟
* تفاوت Prettier و ESLint چیست؟
* چگونه Prettier را نصب کنیم؟
* چگونه آن را در پروژه Node.js تنظیم کنیم؟
* چگونه کد را Format کنیم؟
* `.prettierrc` چیست؟
* `.prettierignore` چیست؟
* چگونه Prettier را با VS Code استفاده کنیم؟
* چگونه Prettier و ESLint را کنار هم استفاده کنیم؟
* چگونه Formatting را در Git و GitHub وارد Workflow کنیم؟
* چگونه Prettier را در CI اجرا کنیم؟
* چگونه مشکلات Formatting را قبل از Merge شناسایی کنیم؟

---

# 129.1 - Prettier چیست؟

**Prettier** یک ابزار برای Formatting خودکار کد است.

یعنی کد را دریافت می‌کند و آن را به یک شکل استاندارد و قابل خواندن تبدیل می‌کند.

مثلاً:

```js
const user={name:"Ali",age:20};
```

می‌تواند به:

```js
const user = { name: "Ali", age: 20 };
```

تبدیل شود.

Prettier تلاش می‌کند ظاهر کد در کل پروژه یکدست باشد.

---

# 129.2 - Formatter چیست؟

Formatter ابزاری است که شکل ظاهری کد را تنظیم می‌کند.

مواردی مانند:

* فاصله‌ها
* Indentation
* Line Break
* Quotation
* Trailing Comma
* طول خطوط
* قالب‌بندی Objectها
* قالب‌بندی Arrayها

می‌توانند توسط Formatter مدیریت شوند.

به‌صورت ساده:

```text
Code
 ↓
Formatter
 ↓
Formatted Code
```

---

# 129.3 - چرا Formatting مهم است؟

ممکن است Formatting روی منطق برنامه تأثیری نداشته باشد، اما روی تجربه توسعه‌دهندگان تأثیر زیادی دارد.

مثلاً:

```js
function getUser(id){
const user=findUser(id);
return user;
}
```

خوانایی کمتری نسبت به:

```js
function getUser(id) {
  const user = findUser(id);
  return user;
}
```

دارد.

Prettier می‌تواند چنین Formattingهایی را به‌صورت خودکار انجام دهد.

# 129.4 - Prettier و Node.js

Prettier به خود Node.js محدود نیست و می‌تواند برای فایل‌ها و زبان‌های مختلف استفاده شود.

اما در این آموزش تمرکز ما روی پروژه‌های JavaScript و Node.js است.

مثلاً:

```text
Node.js Project
│
├── src/
│   ├── app.js
│   ├── server.js
│   └── utils.js
│
├── package.json
└── prettier config
```

Prettier می‌تواند فایل‌های JavaScript پروژه را Format کند.

# 129.7 - نصب Prettier

Prettier را بهتر است در پروژه به‌عنوان Development Dependency نصب کنیم:

```bash
npm install --save-dev prettier
```

یا:

```bash
npm install -D prettier
```

پس از نصب، در `package.json` قرار می‌گیرد:

```json
{
  "devDependencies": {
    "prettier": "..."
  }
}
```

---

# 129.8 - چرا Prettier در devDependencies؟

Prettier معمولاً در زمان توسعه و CI استفاده می‌شود و جزء Runtime برنامه نیست.

مثلاً وقتی برنامه Node.js را در Production اجرا می‌کنیم:

```bash
node app.js
```

برای اجرای خود برنامه به Prettier نیاز نداریم.

بنابراین معمولاً:

```json
{
  "devDependencies": {
    "prettier": "..."
  }
}
```

مناسب است.

# 129.9 - اولین اجرای Prettier

فرض کنید فایل زیر را داریم:

```js

```

می‌توانیم Prettier را روی فایل اجرا کنیم:

```bash
npx prettier app.js --write
```

گزینه:

```text
--write
```

یعنی فایل را Format کن و تغییرات را روی خود فایل ذخیره کن.

# 129.10 - بررسی Formatting بدون تغییر فایل

می‌توانیم فقط بررسی کنیم که فایل با Formatting موردنظر Prettier هماهنگ است یا خیر:

```bash
npx prettier app.js --check
```

در این حالت Prettier فایل را تغییر نمی‌دهد.

این قابلیت برای CI بسیار مهم است.

# 129.11 - تفاوت `--write` و `--check`

### `--write`

فایل را تغییر می‌دهد:

```bash
npx prettier . --write
```

### `--check`

فقط بررسی می‌کند:

```bash
npx prettier . --check
```

به‌صورت ساده:

```text
--write
   ↓
Format + Save

--check
   ↓
Check Only
```

# 129.12 - Format کردن کل پروژه

برای Format کردن فایل‌های پروژه:

```bash
npx prettier . --write
```

اما در پروژه واقعی بهتر است مشخص کنیم چه فایل‌هایی باید توسط Prettier بررسی شوند.

برای مثال:

```bash
npx prettier "src/**/*.{js,json,md}" --write
```

# 129.13 - Configuration چیست؟

Prettier برای بسیاری از پروژه‌ها با تنظیمات پیش‌فرض نیز قابل استفاده است.

اما ممکن است بخواهیم تنظیمات خاصی داشته باشیم.

مثلاً:

* طول خط
* نوع Quote
* استفاده از Semicolon
* Trailing Comma

برای این کار Configuration ایجاد می‌کنیم.

---

# 129.14 - فایل `.prettierrc`

یکی از روش‌های رایج تنظیم Prettier استفاده از:

```text
.prettierrc
```

است.

مثلاً:

```json
{
  "semi": true,
  "singleQuote": true,
  "trailingComma": "all"
}
```

اکنون Formatting پروژه بر اساس این تنظیمات انجام می‌شود.

---

# 129.15 - گزینه `semi`

این گزینه مشخص می‌کند Prettier در انتهای Statementها Semicolon قرار دهد یا خیر.

مثلاً:

```json
{
  "semi": true
}
```

نتیجه:

```js
const name = 'Ali';
```

در مقابل:

```json
{
  "semi": false
}
```

می‌تواند نتیجه‌ای مانند:

```js
const name = 'Ali'
```

داشته باشد.

---

# 129.16 - گزینه `singleQuote`

با:

```json
{
  "singleQuote": true
}
```

Prettier برای Stringهای JavaScript معمولاً Single Quote را ترجیح می‌دهد:

```js
const name = 'Ali';
```

در حالت پیش‌فرض می‌تواند از Double Quote استفاده کند:

```js
const name = "Ali";
```

---

# 129.17 - گزینه `trailingComma`

Trailing Comma یعنی قرار دادن Comma بعد از آخرین عضو در ساختارهایی که از آن پشتیبانی می‌کنند.

مثلاً:

```js
const user = {
  name: 'Ali',
  age: 20,
};
```

می‌توان آن را با تنظیمات Prettier کنترل کرد.

---

# 129.18 - گزینه `printWidth`

یکی از تنظیمات مهم:

```json
{
  "printWidth": 80
}
```

است.

این گزینه طول ترجیحی خطوط را مشخص می‌کند.

نکته مهم:

`printWidth` به معنی این نیست که Prettier در همه شرایط هیچ خطی بیشتر از این مقدار ایجاد نمی‌کند؛ بلکه یک عرض ترجیحی برای Formatting است.

# 129.31 - Prettier و `package.json`

بهتر است Scriptهای مربوط به Prettier را در `package.json` قرار دهیم.

مثلاً:

```json
{
  "scripts": {
    "format": "prettier . --write",
    "format:check": "prettier . --check"
  }
}
```

حالا:

```bash
npm run format
```

برای Formatting و:

```bash
npm run format:check
```

برای بررسی استفاده می‌شود.

# 129.41 - Line Ending

سیستم‌عامل‌های مختلف ممکن است Line Ending متفاوتی داشته باشند.
