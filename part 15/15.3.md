# فصل 121 - Redis

## مقدمه

در فصل قبل با مفهوم **Cache** آشنا شدیم و دیدیم که Cache می‌تواند با نگه‌داشتن داده‌های پرمصرف در حافظه، زمان پاسخ‌گویی برنامه را کاهش دهد و فشار روی Database را کم کند.

اما در آن فصل Cache را با `Map` داخل خود برنامه Node.js پیاده‌سازی کردیم.

این روش برای یادگیری و پروژه‌های کوچک مناسب است، اما در پروژه‌های واقعی محدودیت‌هایی دارد.

فرض کنید برنامه ما روی چند Server اجرا شود:

```text
                    Load Balancer
                   /      |      \
                  /       |       \
             Node.js   Node.js   Node.js
                A         B         C
                ↓         ↓         ↓
             Memory     Memory     Memory
             Cache A    Cache B    Cache C
```

هر Process حافظه خودش را دارد.

در نتیجه ممکن است:

```text
Cache A ≠ Cache B ≠ Cache C
```

باشد.

اینجاست که **Redis** اهمیت پیدا می‌کند.

Redis یک سیستم ذخیره‌سازی داده در حافظه است که می‌تواند به‌عنوان Cache، Session Store، Message Broker و برای کاربردهای مختلف دیگری در Backend استفاده شود.

در معماری معمول:

```text
                    ┌──────────────┐
                    │   Node.js    │
                    └──────┬───────┘
                           │
                           ▼
                    ┌──────────────┐
                    │    Redis     │
                    └──────┬───────┘
                           │
                           ▼
                    ┌──────────────┐
                    │   Database   │
                    └──────────────┘
```

در این فصل Redis را از پایه یاد می‌گیریم و سپس آن را در یک پروژه Node.js استفاده می‌کنیم.

---

# 121.1 - Redis چیست؟

Redis یک سیستم ذخیره‌سازی داده بسیار سریع و عمدتاً مبتنی بر حافظه است.

نام Redis از:

```text
REmote DIctionary Server
```

گرفته شده است.

Redis برخلاف Databaseهای رابطه‌ای مانند PostgreSQL، داده‌ها را به شکل Table و Row ذخیره نمی‌کند.

در ساده‌ترین حالت می‌توان آن را به شکل:

```text
Key → Value
```

در نظر گرفت.

مثلاً:

```text
user:1 → Ali
user:2 → Reza
```

---

# 121.2 - چرا Redis سریع است؟

یکی از دلایل اصلی سرعت Redis این است که داده‌ها را در Memory نگهداری می‌کند.

مقایسه ساده:

```text
Application
    ↓
RAM
    ↓
Redis
```

در مقابل:

```text
Application
    ↓
Database
    ↓
Disk
```

دسترسی به Memory معمولاً بسیار سریع‌تر از دسترسی به Storage است.

البته Redis فقط یک Cache ساده نیست و امکانات بیشتری دارد.

---

# 121.3 - Redis در معماری Node.js

یکی از معماری‌های رایج:

```text
Client
   ↓
Node.js API
   ↓
Redis
   ↓
Database
```

درخواست ابتدا Redis را بررسی می‌کند.

اگر داده موجود باشد:

```text
Redis Hit
   ↓
Response
```

اگر داده موجود نباشد:

```text
Redis Miss
   ↓
Database
   ↓
Redis
   ↓
Response
```

این همان الگوی Cache-Aside است که در فصل قبل با آن آشنا شدیم.

---

# 121.4 - Redis چه کاربردهایی دارد؟

Redis کاربردهای بسیار متنوعی دارد.

از جمله:

* Cache
* Session Storage
* Rate Limiting
* Queue
* Pub/Sub
* Distributed Lock
* Counter
* Leaderboard
* Temporary Data
* Token Storage
* Real-Time Applications

در این فصل تمرکز اصلی ما روی استفاده از Redis در Node.js است.

# 121.5 - Redis Server و Redis Client

برای استفاده از Redis دو بخش اصلی داریم:

```text
Node.js Application
       ↓
Redis Client
       ↓
Redis Server
```

**Redis Server** داده‌ها را نگهداری می‌کند.

**Redis Client** به Node.js اجازه می‌دهد با Redis ارتباط برقرار کند.

در Node.js می‌توان از کتابخانه‌هایی مانند:

```text
redis
```

یا:

```text
ioredis
```

استفاده کرد.

در این آموزش برای مثال‌ها از پکیج `redis` استفاده می‌کنیم.

# 121.9 - اتصال Node.js به Redis

یک Client ایجاد می‌کنیم:

```js
import { createClient } from "redis";

const client = createClient({
  url: "redis://localhost:6379",
});

await client.connect();

console.log("Connected to Redis");
```

اکنون Node.js به Redis متصل شده است.

---

# 121.10 - مدیریت خطای Connection

بهتر است Errorهای Redis را نیز مدیریت کنیم:

```js
import { createClient } from "redis";

const client = createClient({
  url: "redis://localhost:6379",
});

client.on("error", (error) => {
  console.error("Redis Error:", error);
});

await client.connect();
```

این کار برای Debug و Monitoring بسیار مهم است.

# 121.20 - ذخیره JSON

Redis می‌تواند JSON را به صورت String ذخیره کند.

مثلاً:

```js

  id: 1,
  name: "Ali",
  age: 20,
};

await client.set(
  "user:1",
  JSON.stringify(user)

```

دریافت:

```js
const data = await client.get("user:1");

const user = JSON.parse(data);

console.log(user);
```

# 121.21 - Cache کردن Object

این الگو برای Cache کردن نتیجه Database بسیار کاربردی است:

```js
const key = `user:${userId}`;

const cached = await client.get(key);

if (cached) {
  return JSON.parse(cached);
}

const user = await database.getUser(userId);

await client.set(
  key,
  JSON.stringify(user),

    EX: 60,
  }

```

# 121.24 - دریافت Hash

```js
const name = await client.hGet(

```

```js

```

---

# 121.25 - Hash یا JSON؟

هر دو روش کاربرد دارند.

JSON:

```text
user:1 → "{...}"
```

Hash:

```text
user:1
 ├── name
 ├── age
 └── city
```

اگر بخواهیم کل Object را یکجا ذخیره و دریافت کنیم، JSON ساده است.

اگر بخواهیم Fieldهای مشخص را جداگانه تغییر دهیم، Hash می‌تواند مناسب‌تر باشد.

انتخاب به نیاز پروژه بستگی دارد.

# 121.37 - Rate Limiting با Redis

یکی از کاربردهای مهم Redis:

```text
Rate Limiting
```

است.

مثلاً می‌خواهیم هر IP در یک دقیقه فقط 100 درخواست ارسال کند.

می‌توانیم Counter ذخیره کنیم:

```text
rate-limit:IP
```

و آن را افزایش دهیم.

مثلاً:

```js
const key = `rate-limit:${ip}`;

const count = await client.incr(key);

if (count === 1) {
  await client.expire(key, 60);
}
```

سپس:

```js
if (count > 100) {
  // Reject
}
```

# 121.38 - Session با Redis

Redis می‌تواند Sessionهای کاربران را نیز ذخیره کند.

مثلاً:

```text
session:abc123
```

مقدار:

```json
{
  "userId": 42,
  "role": "user"
}
```

با TTL مشخص.

ساختار:

```text
Client
  ↓
Node.js
  ↓
Redis Session
```

این روش مخصوصاً در معماری چند Instance مفید است.

فرض کنید:

```text
            /             \

            \             /
             \           /
                Redis
```

هر دو Instance به Redis مشترک دسترسی دارند.

در نتیجه Session یا Cache بین آن‌ها مشترک خواهد بود.

# 121.40 - Pub/Sub

Redis قابلیت:

```text
Pub/Sub
```

نیز دارد.

Pub/Sub یعنی:

```text
Publisher
    ↓
 Channel
    ↓
Subscribers
```

Publisher پیام منتشر می‌کند.

Subscriber پیام را دریافت می‌کند.

---

# 121.41 - Channel

مثلاً:

```text
notifications
```

یک Channel است.

Publisher:

```js
await publisher.publish(
  "notifications",
  "New notification"
);
```

Subscriber:

```js
await subscriber.subscribe(
  "notifications",
  (message) => {
    console.log(message);
  }
);
```

---

# 121.42 - کاربرد Pub/Sub

Pub/Sub برای مواردی مانند:

* Notification
* Real-Time Events
* Communication بین Serviceها
* Event Broadcasting

کاربرد دارد.

برای سیستم‌های پیچیده‌تر باید نیازهای Reliability و Delivery را نیز بررسی کنیم؛ Pub/Sub ساده Redis الزاماً جایگزین Queueهای پایدار نیست.

---

# 121.43 - Redis و Cache-Aside

یک الگوی بسیار مهم:

```text
Request
   ↓
Redis
   ↓
Hit ───────→ Return
   │
   Miss
   ↓
Database
   ↓
Redis
   ↓
Return
```

پیاده‌سازی:

```js
async function getUser(id) {
  const key = `user:${id}`;

  const cached = await client.get(key);

  if (cached) {
    return JSON.parse(cached);
  }

  const user = await database.getUser(id);

  await client.set(
    key,
    JSON.stringify(user),
    {
      EX: 60,
    }
  );

  return user;
}
```

# 121.44 - Invalidation با Redis

هنگام Update:

```js
await database.updateUser(id, data);

await client.del(`user:${id}`);
```

درخواست بعدی:

```text
Redis Miss
   ↓
Database
   ↓
New Data
   ↓
Redis
```

# 121.47 - Redis و Environment Variables

اطلاعات Connection را بهتر است داخل Environment Variables قرار دهیم.

مثلاً:

```env
REDIS_URL=redis://localhost:6379
```

و در Node.js:

```js
const client = createClient({
  url: process.env.REDIS_URL,
});
```

اطلاعات حساس مانند Password نباید مستقیماً داخل Source Code قرار گیرد.

---

# 121.48 - Redis Authentication

اگر Redis در محیطی قرار دارد که نیاز به Authentication دارد، Connection باید با Credentials مناسب پیکربندی شود.

مثلاً:

```env
REDIS_URL=redis://:password@localhost:6379
```

در Production باید Secretها را از طریق روش امن مدیریت Secrets در اختیار Application قرار داد.

---

# 121.49 - Redis Persistence

اگرچه Redis عمدتاً Memory-based است، اما قابلیت‌های Persistence نیز دارد.

دو مفهوم مهم:

```text
RDB
AOF
```

هستند.

---

# 121.50 - RDB

RDB Snapshotهایی از داده‌ها ایجاد می‌کند.

یعنی در زمان‌های مشخص وضعیت Redis ذخیره می‌شود.

مزایا:

* فایل Snapshot نسبتاً مناسب
* Recovery ساده‌تر
* مناسب برای Backupهای دوره‌ای

اما ممکن است آخرین تغییرات بین Snapshotها از دست بروند.

---

# 121.51 - AOF

AOF مخفف:

```text
Append Only File
```

است.

در این روش عملیات تغییر داده‌ها ثبت می‌شوند.

AOF می‌تواند برای نیازهایی که Persistence بیشتری می‌خواهند مناسب باشد، اما هزینه I/O و حجم ذخیره‌سازی باید در نظر گرفته شود.

---

# 121.52 - آیا Redis جایگزین Database است؟

در حالت معمول:

**خیر.**

Redis و Database نقش یکسانی ندارند.

معماری رایج:

```text
Application
    ↓
Redis
    ↓
PostgreSQL / MongoDB
```

Redis می‌تواند لایه سریع و موقت یا اشتراکی باشد و Database منبع اصلی داده باقی بماند.

البته Redis قابلیت‌های Persistence و کاربردهای مستقل خودش را دارد، اما نباید صرفاً به دلیل سرعت بالا آن را جایگزین خودکار Database اصلی در نظر گرفت.

# 121.53 - Redis و Memory

# 121.54 - Eviction Policy

اگر Redis به محدودیت Memory برسد، بسته به Configuration می‌تواند طبق Eviction Policy داده‌هایی را حذف کند.

یکی از معروف‌ترین Policyها:

در این حالت Keyهایی که کمتر اخیراً استفاده شده‌اند، کاندید حذف هستند.

Policy مناسب باید بر اساس نوع Workload انتخاب شود.

# 121.60 - Redis و Distributed Lock

Redis می‌تواند در برخی معماری‌ها برای پیاده‌سازی Distributed Lock استفاده شود.

ایده کلی:

```text
Process A
   ↓
Acquire Lock
   ↓
Critical Section
   ↓
Release Lock
```

در حالی که:

```text
Process B
   ↓
Cannot Acquire Lock
```

است.

پیاده‌سازی Lock توزیع‌شده نیازمند دقت زیاد است و نباید با یک `SET` ساده بدون توجه به Timeout، Ownership و Failure Mode در Production پیاده‌سازی شود.

# مرحله 5 - Cache Service

فایل:

```text
src/cache.js
```

```js
import client from "./redis.js";

let hits = 0;
let misses = 0;

export async function getCache(key) {
  const data = await client.get(key);

  if (data) {
    hits++;
    return JSON.parse(data);
  }

  misses++;

  return null;
}

export async function setCache(
  key,
  value,
  ttl = 60
) {
  await client.set(
    key,
    JSON.stringify(value),
    {
      EX: ttl,
    }
  );
}

export async function deleteCache(key) {
  await client.del(key);
}

export function getStats() {
  const total = hits + misses;

  return {
    hits,
    misses,
    hitRate:
      total === 0
        ? 0
        : Number(
            ((hits / total) * 100).toFixed(2)
          ),
  };
}
```

# مرحله 6 - Product Service

فایل:

```text
src/product.service.js
```

```js
import client from "./redis.js";

import {
  getProducts,
  getProductById,
  updateProduct,
} from "./database.js";

import {
  getCache,
  setCache,
  deleteCache,
} from "./cache.js";

export async function findProducts() {
  const key = "products:all";

  const cached = await getCache(key);

  if (cached) {
    return cached;
  }

  const products = await getProducts();

  await setCache(
    key,
    products,
    60
  );

  return products;
}

export async function findProduct(id) {
  const key = `product:${id}`;

  const cached = await getCache(key);

  if (cached) {
    return cached;
  }

  const product =
    await getProductById(id);

  if (!product) {
    return null;
  }

  await setCache(
    key,
    product,
    60
  );

  return product;
}

export async function editProduct(
  id,
  data
) {
  const product =
    await updateProduct(id, data);

  if (!product) {
    return null;
  }

  await deleteCache(
    `product:${id}`
  );

  await deleteCache(
    "products:all"
  );

  return product;
}
```

```js
import "dotenv/config";

import express from "express";

import {
  findProducts,
  findProduct,
  editProduct,
} from "./product.service.js";

import {
  getStats,
} from "./cache.js";

const app = express();

app.use(express.json());

app.get("/products", async (req, res) => {
  const products = await findProducts();

  res.json(products);
});

app.get(
  "/products/:id",
  async (req, res) => {
    const product =
      await findProduct(
        req.params.id
      );

    if (!product) {
      return res
        .status(404)
        .json({
          message: "Product not found",
        });
    }

    res.json(product);
  }
);

app.put(
  "/products/:id",
  async (req, res) => {
    const product =
      await editProduct(
        req.params.id,
        req.body
      );

    if (!product) {
      return res
        .status(404)
        .json({
          message: "Product not found",
        });
    }

    res.json(product);
  }
);

app.get(
  "/cache/stats",
  (req, res) => {
    res.json(getStats());
  }
);

app.listen(
  process.env.PORT,
  () => {
    console.log(
      `Server running on port ${process.env.PORT}`
    );
  }
);
```

# جمع‌بندی

در این فصل Redis را به‌عنوان یکی از مهم‌ترین ابزارهای اکوسیستم Backend یاد گرفتیم.

مهم‌ترین نکته این فصل:

> **Redis فقط یک Cache نیست؛ یک ابزار سریع و چندمنظوره برای نگهداری داده در Memory، مدیریت State موقت، Counter، Session، Rate Limiting، Pub/Sub و بسیاری از نیازهای Backend است.**

در معماری‌های واقعی Node.js، Redis معمولاً در کنار Database استفاده می‌شود، نه اینکه بدون دلیل جای آن را بگیرد.

همچنین در فهرست دوره، Redis به‌درستی بعد از **Performance Optimization** و **Cache** قرار گرفته است و بعد از آن نیز فصل‌های **Compression، Cluster، Load Balancing و Profiling** آمده‌اند؛ بنابراین این فصل نقش پل بین Cache ساده و مباحث Performance و معماری مقیاس‌پذیرتر را دارد.
