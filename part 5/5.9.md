# مقدمه فصل

در برنامه‌نویسی همیشه با داده‌های متنی سروکار داریم.

نام کاربران، ایمیل‌ها، شماره تلفن‌ها، رمزهای عبور، آدرس‌ها، فایل‌ها، لاگ‌های سرور و بسیاری از اطلاعات دیگر همگی به شکل متن ذخیره می‌شوند.

اما گاهی نیاز داریم روی این متن‌ها عملیات خاصی انجام دهیم:

* پیدا کردن یک الگوی خاص در متن
* بررسی معتبر بودن اطلاعات ورودی
* استخراج بخش‌هایی از یک متن
* جایگزین کردن قسمت‌هایی از متن
* حذف کاراکترهای اضافی
* جستجوی پیشرفته در فایل‌ها و داده‌ها

برای انجام این کارها در جاوااسکریپت از **RegExp** یا **Regular Expression** استفاده می‌کنیم.

RegExp یک ابزار قدرتمند برای تعریف الگوهای متنی است.

برای مثال:

می‌توانیم الگویی بسازیم که بررسی کند:

* آیا یک ایمیل معتبر است؟
* آیا رمز عبور شرایط لازم را دارد؟
* آیا شماره تلفن فرمت درستی دارد؟
* آیا یک متن شامل کلمه خاصی است؟
* تمام لینک‌های موجود در یک متن را پیدا کند.
* تمام اعداد داخل یک فایل را استخراج کند.

در Node.js نیز RegExp کاربرد بسیار زیادی دارد.

موارد استفاده در پروژه‌های واقعی:

* اعتبارسنجی اطلاعات کاربران
* پاک‌سازی داده‌ها (Data Cleaning)
* پردازش فایل‌های متنی
* تحلیل لاگ‌های سرور
* ساخت Middlewareهای اعتبارسنجی
* فیلتر کردن محتوا
* پردازش ورودی‌های API

در این فصل از پایه‌ترین مفاهیم RegExp شروع می‌کنیم و قدم‌به‌قدم به کاربردهای حرفه‌ای آن در پروژه‌های Node.js می‌رسیم.

# بخش ۱ - آشنایی با RegExp و مفاهیم پایه

## RegExp چیست؟

`RegExp` کوتاه‌شده‌ی عبارت:

```
Regular Expression
```

است.

Regular Expression یک روش برای تعریف الگوهای متنی است.

به جای اینکه فقط دنبال یک متن مشخص بگردیم، می‌توانیم یک قانون تعریف کنیم.

مثلاً:

به جای اینکه بگوییم:

```
دنبال کلمه Ali بگرد
```

می‌توانیم بگوییم:

```
هر متنی که با حرف A شروع می‌شود و بعد از آن سه حرف دارد را پیدا کن
```

این قدرت اصلی Regex است.

---

## مثال ساده

فرض کنید یک متن داریم:

```javascript
const text = "Hello Node.js";
```

می‌خواهیم بررسی کنیم آیا کلمه Node در متن وجود دارد یا نه.

بدون Regex:

```javascript
console.log(text.includes("Node"));
```

خروجی:

```text
true
```

اما با Regex:

```javascript
const regex = /Node/;

console.log(regex.test(text));
```

خروجی:

```text
true
```

Regex انتخاب مناسب‌تری است.

## ۳۰.۸ - Character Classes

### مفهوم Character Class

گاهی نمی‌خواهیم فقط یک کاراکتر خاص را پیدا کنیم، بلکه می‌خواهیم یکی از چند کاراکتر مشخص را بررسی کنیم.

برای این کار از **Character Class** استفاده می‌کنیم.

Character Class داخل براکت‌ها نوشته می‌شود:

```regex
[]
```

مثلاً:

```javascript id="c8v1tn"
const regex = /[abc]/;

console.log(regex.test("apple"));
```

در این مثال، اگر متن شامل یکی از حروف `a`، `b` یا `c` باشد، نتیجه `true` می‌شود.

خروجی:

```text
true
```

---

### براکت‌ها `[]`

وقتی از براکت استفاده می‌کنیم، یعنی فقط یکی از کاراکترهای داخل آن قابل قبول است.

مثال:

```javascript id="q9jvkp"

console.log(regex.test("hello x"));
```

خروجی:

```text
true
```

اگر متن هیچ‌کدام از این کاراکترها را نداشته باشد:

```javascript id="s7m1na"
console.log(regex.test("hello"));
```

خروجی:

```text
false
```

### محدوده کاراکترها

## ۳۰.۱۲ - Greedy و Lazy Matching

### مفهوم Greedy

Regex به صورت پیش‌فرض **Greedy** است؛ یعنی تا جایی که بتواند بیشترین بخش ممکن را match می‌کند.

مثال:

```javascript id="c1t9af"
const text = "<b>hello</b><b>world</b>";
const regex = /<b>.*<\/b>/;

console.log(text.match(regex));
```

در این حالت ممکن است از اولین `<b>` تا آخرین `</b>` را بگیرد، نه فقط یک بخش کوچک.

---

### مشکل Matching زیاد

مثلاً در متن HTML، اگر از `.*` استفاده کنیم، ممکن است بیشتر از مقدار موردنظر match شود.

---

### استفاده از Lazy Quantifier

برای Lazy کردن quantifier از `?` بعد از آن استفاده می‌کنیم.

مثال:

```javascript id="l3q7dx"
const text = "<b>hello</b><b>world</b>";
const regex = /<b>.*?<\/b>/g;

console.log(text.match(regex));
```

خروجی:

```text
[ '<b>hello</b>', '<b>world</b>' ]
```

---

### تفاوت Greedy و Lazy

| حالت   | رفتار              |
| ------ | ------------------ |
| Greedy | بیشترین match ممکن |
| Lazy   | کمترین match ممکن  |

## ۳۰.۱۳ - Group ها

### ساخت گروه

گروه‌ها با پرانتز ساخته می‌شوند:

```regex
()
```

گروه‌ها برای:

* دسته‌بندی الگوها
* تکرار روی کل گروه
* استخراج بخش‌های مختلف متن

استفاده می‌شوند.

---

### مثال ساده

```javascript id="v8m4sy"
const regex = /(abc)/;

console.log(regex.test("123abc456"));
```

خروجی:

```text
true
```

---

### Capturing Groups

وقتی از `()` استفاده می‌کنیم، آن بخش capture می‌شود و می‌توانیم بعداً به آن دسترسی داشته باشیم.

مثال:

```javascript id="q2j6kl"

```

```text

  'My name is Ali',
  'Ali',
  index: 0,

]
```

### استخراج داده از گروه‌ها

```javascript id="s5p7dn"

const result = text.match(regex);

console.log(result[1]);
console.log(result[2]);
```

خروجی:

```text
Reza
23
```

---

### Nested Groups

گروه‌ها می‌توانند داخل هم قرار بگیرند.

```javascript id="a7d1qx"

```

این نوع ساختار برای استخراج تاریخ، شماره‌ها و الگوهای پیچیده مفید است.

### مثال کاربردی

```javascript id="p1m8zc"

```

### مفهوم


# مقایسه متدهای مهم String

# جمع‌بندی بخش ۳

در این بخش با مهم‌ترین متدهای String که از Regular Expression پشتیبانی می‌کنند آشنا شدیم.

مفاهیم یادگرفته‌شده:

* استفاده از `match()` برای پیدا کردن Matchها
* استفاده از `matchAll()` برای دریافت اطلاعات کامل تمام Matchها
* جایگزینی متن با `replace()`
* جایگزینی همه موارد با `replaceAll()`
* پیدا کردن محل اولین Match با `search()`
* تقسیم رشته‌ها با `split()`

در بخش بعدی از فصل RegExp، این مفاهیم را در پروژه‌های واقعی Node.js به کار خواهیم گرفت و الگوهای کاربردی برای اعتبارسنجی ایمیل، شماره تلفن، رمز عبور، URL، IP و پردازش فایل‌های Log را پیاده‌سازی خواهیم کرد.

# بخش ۴ - RegExp در پروژه‌های واقعی Node.js

تا اینجا تقریباً تمام ابزارهای موردنیاز برای نوشتن Regular Expression را یاد گرفتیم.

اما ارزش واقعی RegExp زمانی مشخص می‌شود که آن را در پروژه‌های واقعی استفاده کنیم.

در این بخش یاد می‌گیریم چگونه با استفاده از Regex:

* اطلاعات کاربران را اعتبارسنجی کنیم.
* داده‌ها را استخراج کنیم.
* متن‌ها را پاک‌سازی کنیم.
* فایل‌های Log را تحلیل کنیم.
* ورودی‌های API را بررسی کنیم.

تقریباً تمام پروژه‌های Node.js در یکی از بخش‌های زیر از RegExp استفاده می‌کنند.

# ۳۰.۲۲ - اعتبارسنجی ایمیل (Email Validation)

یکی از رایج‌ترین کاربردهای Regular Expression بررسی معتبر بودن آدرس ایمیل است.

فرض کنید کاربر در فرم ثبت‌نام ایمیل خود را وارد کرده است.

قبل از ذخیره اطلاعات باید بررسی کنیم که فرمت ایمیل صحیح باشد.

---

## ساختار کلی یک ایمیل

یک ایمیل معمولاً از سه بخش تشکیل می‌شود.

```text id="f7h0bq"
username@example.com
```

| بخش      | توضیح     |
| -------- | --------- |
| username | نام کاربر |
| @        | جداکننده  |
| domain   | دامنه     |

---

## ساده‌ترین Regex

```regex id="m2z0gi"
.+@.+\..+
```

این Regex فقط بررسی می‌کند که:

* قبل از @ متن وجود داشته باشد.
* بعد از @ متن وجود داشته باشد.
* یک نقطه وجود داشته باشد.

---

## مثال

```javascript id="d9mq4s"
const regex = /.+@.+\..+/;

console.log(regex.test("ali@gmail.com"));
```

خروجی:

```text id="j6hskf"
true
```

---

## Regex بهتر

```regex id="w0p3mu"
^[^\s@]+@[^\s@]+\.[^\s@]+$
```

این Regex:

* فاصله را قبول نمی‌کند.
* فقط یک @ را می‌پذیرد.
* ابتدا و انتهای رشته را بررسی می‌کند.

---

### مثال

```javascript id="r7a8hy"
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

console.log(emailRegex.test("user@gmail.com"));
console.log(emailRegex.test("wrong email"));
```

خروجی:

```text id="lzv7gn"
true
false
```

---

## ساخت تابع اعتبارسنجی

```javascript id="w1c6nt"
function validateEmail(email) {

    const regex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

    return regex.test(email);

}

console.log(validateEmail("admin@example.com"));
console.log(validateEmail("admin.example.com"));
```

---

## محدودیت‌های Email Validation

یکی از اشتباهات رایج این است که تصور کنیم Regex می‌تواند معتبر بودن ایمیل را به طور کامل بررسی کند.

در واقع Regex فقط **فرمت** را بررسی می‌کند.

مثلاً:

```text id="g8m8gp"
hello@not-exist-domain.com
```

از نظر Regex معتبر است، اما ممکن است چنین دامنه‌ای اصلاً وجود نداشته باشد.

---

برای بررسی واقعی باید:

* ایمیل تأیید (Verification Email) ارسال شود.
* یا دامنه بررسی شود.
* یا سرویس‌های اعتبارسنجی استفاده شوند.

> **نکته امنیتی:** حذف چند کاراکتر با Regex برای جلوگیری از حملاتی مانند XSS کافی نیست. در پروژه‌های واقعی باید از کتابخانه‌های معتبر برای اعتبارسنجی، Escape کردن و پاک‌سازی ورودی‌ها استفاده کنید.

# جمع‌بندی بخش ۴

در این بخش یاد گرفتیم که چگونه از Regular Expression در پروژه‌های واقعی Node.js استفاده کنیم.

# بخش ۵ - مباحث پیشرفته RegExp

تا اینجا تقریباً تمام ابزارهای اصلی Regular Expression را یاد گرفته‌ایم.

اما RegExp امکانات پیشرفته‌ای نیز دارد که در پروژه‌های بزرگ، موتورهای جستجو، پردازش متن، تحلیل فایل‌های Log، اعتبارسنجی داده‌ها و حتی کامپایلرها استفاده می‌شوند.

در این بخش با مباحث پیشرفته زیر آشنا می‌شویم:

* Lookahead
* Lookbehind
* Backreference
* Unicode
* Performance و بهینه‌سازی Regex

این مباحث شاید در پروژه‌های ساده زیاد استفاده نشوند، اما دانستن آن‌ها باعث می‌شود Regexهای حرفه‌ای‌تر و دقیق‌تری بنویسید.

---

# ۳۰.۲۹ - Lookahead

گاهی می‌خواهیم بررسی کنیم که بعد از یک قسمت از متن، الگوی خاصی وجود دارد یا خیر، اما نمی‌خواهیم آن قسمت وارد نتیجه Match شود.

برای این کار از **Lookahead** استفاده می‌کنیم.

Lookahead فقط بررسی می‌کند و چیزی از متن را مصرف (Consume) نمی‌کند.

---

## Positive Lookahead

ساختار:

```regex id="jv83hf"
(?=...)
```

معنی:

> بعد از این قسمت باید الگوی مشخص‌شده وجود داشته باشد.

---

## مثال

فرض کنید متن زیر را داریم:

```text id="mtm1u0"
100$
```

می‌خواهیم فقط عدد را پیدا کنیم، اما فقط زمانی که بعد از آن علامت دلار وجود داشته باشد.

Regex:

```regex id="o1e8vu"
\d+(?=\$)
```

---

### مثال عملی

```javascript id="g2x5nt"
const text = "100$";

console.log(
    text.match(/\d+(?=\$)/)
);
```

خروجی:

```text id="r1nbot"
[
    '100'
]
```

علامت `$` در خروجی وجود ندارد.

---

## مثال دیگر

```javascript id="p8v3mw"
const text = "Version: 18.0";

console.log(
    text.match(/\d+(?=\.)/)
);
```

خروجی:

```text id="jlwm01"
18
```

---

## کاربرد

فرض کنید فقط قیمت‌ها را می‌خواهیم.

```text id="jlwm02"
120$
50€
300$
```

Regex:

```regex id="jlwm03"
\d+(?=\$)
```

خروجی:

```text id="jlwm04"
120
300
```

---

# Negative Lookahead

ساختار:

```regex id="jlwm05"
(?!...)
```

معنی:

بعد از این قسمت نباید الگوی مشخص‌شده وجود داشته باشد.

---

## مثال

```javascript id="jlwm06"
const text = "100€";

console.log(
    text.match(/\d+(?!\$)/)
);
```

خروجی:

```text id="jlwm07"
100
```

چون بعد از عدد، دلار وجود ندارد.

---

## مثال دیگر

```javascript id="jlwm08"
const text = "cat catalog";

console.log(
    text.match(/cat(?!alog)/g)
);
```

خروجی:

```text id="jlwm09"
[
    'cat'
]
```

کلمه‌ی `catalog` انتخاب نمی‌شود.

---

## کاربرد در Node.js

فرض کنید فایل‌هایی را می‌خواهیم که پسوند `.js` داشته باشند ولی `.test.js` نباشند.

```javascript id="jlwm44"
const regex = /\.js$(?<!\.test\.js$)/;
```

هرچند برای این مثال معمولاً از Lookbehind استفاده می‌شود، اما مفهوم بررسی شرط بدون مصرف متن همین است.

---

# تفاوت Lookahead

| نوع       | معنی                  |
| --------- | --------------------- |
| `(?=...)` | باید وجود داشته باشد  |
| `(?!...)` | نباید وجود داشته باشد |

---

# ۳۰.۳۰ - Lookbehind

Lookbehind دقیقاً برعکس Lookahead است.

به جای بررسی کاراکترهای بعدی، کاراکترهای قبل را بررسی می‌کند.

---

# Positive Lookbehind

ساختار:

```regex id="jlwm10"
(?<=...)
```

معنی:

قبل از این قسمت باید الگوی مشخصی وجود داشته باشد.

---

## مثال

```text id="jlwm11"
$250
```

Regex:

```regex id="jlwm12"
(?<=\$)\d+
```

---

### مثال عملی

```javascript id="jlwm13"
const text = "$250";

console.log(
    text.match(/(?<=\$)\d+/)
);
```

خروجی:

```text id="jlwm14"
250
```

---

## مثال دیگر

```javascript id="jlwm15"
const text = "ID-145";

console.log(
    text.match(/(?<=ID-)\d+/)
);
```

خروجی:

```text id="jlwm16"
145
```

---

# Negative Lookbehind

ساختار:

```regex id="jlwm17"
(?<!...)
```

معنی:

قبل از این قسمت نباید الگوی مشخصی وجود داشته باشد.

---

## مثال

```javascript id="jlwm18"
const text = "$200 300";

console.log(
    text.match(/(?<!\$)\d+/g)
);
```

خروجی:

```text id="jlwm19"
[
    '300'
]
```

---

# کاربرد

فرض کنید فقط اعدادی را می‌خواهیم که قیمت نیستند.

```text id="jlwm20"
$500
300
```

Regex:

```regex id="jlwm21"
(?<!\$)\d+
```

خروجی:

```text id="jlwm22"
300
```

---

# تفاوت Lookbehind

| نوع        | معنی                               |
| ---------- | ---------------------------------- |
| `(?<=...)` | قبل از Match باید وجود داشته باشد  |
| `(?<!...)` | قبل از Match نباید وجود داشته باشد |

---

# ۳۰.۳۱ - Backreference

گاهی می‌خواهیم دوباره از مقداری که قبلاً Match شده استفاده کنیم.

برای این کار از **Backreference** استفاده می‌شود.

---

## مفهوم

فرض کنید گروه اول را Capture کرده‌ایم.

```regex id="jlwm23"
(\w+)
```

برای استفاده دوباره از آن می‌نویسیم:

```regex id="jlwm24"
\1
```

---

## مثال

```javascript id="jlwm25"
const regex = /(\w+)\s\1/;

console.log(
    regex.test("hello hello")
);
```

خروجی:

```text id="jlwm26"
true
```

---

اما:

```javascript id="jlwm27"
console.log(
    regex.test("hello world")
);
```

خروجی:

```text id="jlwm28"
false
```

---

# مثال

```javascript id="jlwm29"
const regex = /(\d{4})-\1/;

console.log(
    regex.test("2026-2026")
);
```

خروجی:

```text id="jlwm30"
true
```

---

# حذف کلمات تکراری

```javascript id="jlwm31"
const text =
"hello hello world";

console.log(
    text.match(/\b(\w+)\s+\1\b/)
);
```

---

# Backreference در replace

```javascript id="jlwm32"
const text =
"Ali Ahmadi";

console.log(
    text.replace(
        /(\w+)\s(\w+)/,
        "$2, $1"
    )
);
```

خروجی:

```text id="jlwm33"
Ahmadi, Ali
```

مثلاً تغییر ترتیب نام و نام خانوادگی کاربران.

# ۳۰.۳۲ - Unicode در RegExp

در گذشته بسیاری از Regexها فقط برای حروف انگلیسی طراحی شده بودند.

اما امروزه برنامه‌ها از زبان‌های مختلف پشتیبانی می‌کنند.

برای همین RegExp نیز قابلیت Unicode را اضافه کرده است.

---

# Flag u

```regex id="jlwm34"
/pattern/u
```

این Flag باعث می‌شود Regex متن را بر اساس استاندارد Unicode پردازش کند.

---

## مثال

```javascript id="jlwm35"
const regex = /😊/u;

console.log(
    regex.test("😊")
);
```

خروجی:

```text id="jlwm36"
true
```

---

# کار با زبان فارسی

```javascript id="jlwm37"
const regex = /سلام/u;

console.log(
    regex.test("سلام دنیا")
);
```

---

# بررسی حروف فارسی

می‌توان از محدوده Unicode استفاده کرد.

```javascript id="jlwm38"
const regex = /[\u0600-\u06FF]+/u;

console.log(
    regex.test("سلام")
);
```

خروجی:

```text id="jlwm39"
true
```

---

# استخراج متن فارسی

```javascript id="jlwm40"
const text =
"Node.js سلام JavaScript";

console.log(
    text.match(/[\u0600-\u06FF]+/gu)
);
```

خروجی:

```text id="jlwm41"
[
    'سلام'
]
```

---

# Emoji

```javascript id="jlwm42"
const text =
"😀 😁 😂";

console.log(
    text.match(/./gu)
);
```

بدون Flag `u` ممکن است برخی کاراکترهای Unicode مانند Emoji به‌درستی پردازش نشوند.

# کاربرد در Node.js

* پردازش متن فارسی
* جستجوی عربی
* پشتیبانی از Emoji
* سیستم‌های چندزبانه

# ۳۰.۳۳ - Performance در Regex

همه Regexها سرعت یکسانی ندارند.

بعضی Regexها بسیار سریع هستند.

بعضی دیگر می‌توانند برنامه را برای چند ثانیه یا حتی چند دقیقه متوقف کنند.

---

# Regexهای سنگین

مثال:

```regex id="jlwm43"
(a+)+
```

این Regex روی بعضی ورودی‌ها بسیار کند اجرا می‌شود.

---

# Catastrophic Backtracking

یکی از معروف‌ترین مشکلات Regex همین است.

مثال:

```regex id="jlwm45"
(a+)+$
```

اگر ورودی طولانی باشد:

```text id="jlwm46"
aaaaaaaaaaaaaaaaaaaaaaaaaaaaab
```

موتور Regex میلیون‌ها حالت مختلف را امتحان می‌کند تا در نهایت شکست بخورد.

به این اتفاق:

```text id="jlwm47"
Catastrophic Backtracking
```

گفته می‌شود.

---

# مثال بهتر

به جای:

```regex id="jlwm48"
(a+)+
```

از الگوهای ساده‌تر استفاده کنید.

---

# از .* بی‌دلیل استفاده نکنید

اشتباه:

```regex id="jlwm49"
.*password.*
```

بهتر:

```regex id="jlwm50"
password
```

یا:

```regex id="jlwm51"
\bpassword\b
```

---

# Regexهای کوتاه‌تر

هرچه Regex ساده‌تر باشد:

* خواناتر است.
* سریع‌تر اجرا می‌شود.
* نگهداری آن آسان‌تر است.

---

# Compile کردن Regex

اگر قرار است یک Regex بارها استفاده شود:

اشتباه:

```javascript id="jlwm52"
for (const item of items) {

    if (/admin/.test(item)) {

    }

}
```

---

بهتر:

```javascript id="jlwm53"
const regex = /admin/;

for (const item of items) {

    if (regex.test(item)) {

    }

}
```

در این حالت Regex فقط یک بار ساخته می‌شود.

---

# از Groupهای غیرضروری استفاده نکنید

اشتباه:

```regex id="jlwm54"
(cat)
```

اگر Capture لازم نیست:

```regex id="jlwm55"
(?:cat)
```

---

# Regex مناسب انتخاب کنید

گاهی استفاده از Regex بهترین انتخاب نیست.

مثلاً:

```javascript id="jlwm56"
text.includes("node");
```

از:

```javascript id="jlwm57"
/node/.test(text);
```

ساده‌تر و خواناتر است.

اگر فقط می‌خواهید وجود یک رشته ثابت را بررسی کنید، معمولاً متدهای `includes()`، `startsWith()` یا `endsWith()` انتخاب مناسب‌تری هستند.

---

# نکات مهم برای Performance

* Regex را تا حد امکان ساده نگه دارید.
* از `.*` فقط در صورت نیاز استفاده کنید.
* از Nested Quantifierها (`(a+)+`) پرهیز کنید.
* Regexهای پرتکرار را یک بار ایجاد کنید.
* از Non Capturing Group در صورت عدم نیاز به Capture استفاده کنید.
* قبل از نوشتن Regexهای پیچیده، بررسی کنید که آیا متدهای معمولی String نیاز شما را برطرف می‌کنند یا خیر.

---

# جمع‌بندی بخش ۵

در این بخش با پیشرفته‌ترین قابلیت‌های Regular Expression آشنا شدیم.

مفاهیم این بخش عبارت بودند از:

* Positive Lookahead
* Negative Lookahead
* Positive Lookbehind
* Negative Lookbehind
* Backreference
* Unicode و پشتیبانی از زبان‌های مختلف
* بهینه‌سازی عملکرد Regex
* آشنایی با Catastrophic Backtracking

با یادگیری این مباحث اکنون تقریباً تمام قابلیت‌های مهم RegExp در جاوااسکریپت و Node.js را می‌شناسید و می‌توانید Regexهای حرفه‌ای، خوانا و بهینه برای پروژه‌های واقعی طراحی کنید.

# بخش ۶ - اشتباهات رایج

یکی از دلایلی که بسیاری از برنامه‌نویسان از Regular Expression فراری هستند، اشتباهات رایجی است که هنگام نوشتن Regex رخ می‌دهد.

در بسیاری از موارد، مشکل از خود RegExp نیست؛ بلکه از نوشتن الگوهای نادرست، پیچیده یا نامناسب است.

در این بخش با رایج‌ترین اشتباهاتی آشنا می‌شویم که تقریباً همه برنامه‌نویسان، به‌خصوص افراد تازه‌کار، حداقل یک بار با آن‌ها روبه‌رو می‌شوند.

---

# ۳۰.۳۴ - اشتباهات رایج در RegExp

---

## اشتباه اول: استفاده نادرست از Flagها

یکی از رایج‌ترین اشتباهات، انتخاب نکردن Flag مناسب است.

مثلاً:

```javascript
const text = "cat dog cat";

console.log(
    text.match(/cat/)
);
```

خروجی:

```text
[
  'cat',
  index: 0,
  input: 'cat dog cat'
]
```

برنامه‌نویس انتظار دارد هر دو `cat` پیدا شوند، اما فقط اولین مورد برگردانده می‌شود.

دلیل:

Flag `g` استفاده نشده است.

راه‌حل:

```javascript
console.log(
    text.match(/cat/g)
);
```

خروجی:

```text
[
    'cat',
    'cat'
]
```

---

## فراموش کردن Flag `i`

```javascript
const regex = /node/;

console.log(regex.test("Node"));
```

خروجی:

```text
false
```

دلیل:

Regex به حروف بزرگ و کوچک حساس است.

راه‌حل:

```javascript
const regex = /node/i;
```

---

## استفاده اشتباه از Flag `m`

برخی تصور می‌کنند Flag `m` باعث جستجو در چند خط می‌شود.

در واقع:

`m` فقط رفتار `^` و `$` را تغییر می‌دهد.

مثال:

```javascript
const text = `A
B
C`;

console.log(
    text.match(/^B/m)
);
```

---

## استفاده بی‌دلیل از Flag `g`

گاهی فقط می‌خواهیم بررسی کنیم رشته وجود دارد یا خیر.

اشتباه:

```javascript
/hello/g.test(text)
```

در این حالت وجود `g` هیچ مزیتی ندارد و حتی هنگام استفاده مکرر از همان شیء `RegExp` می‌تواند باعث نتایج غیرمنتظره شود، زیرا ویژگی `lastIndex` تغییر می‌کند.

بهتر:

```javascript
/hello/.test(text)
```

# اشتباه دوم: فراموش کردن Escape کردن کاراکترها

بعضی کاراکترها در Regex معنی ویژه دارند.

مثل:

```text
.
*
+
?
(
)
[
]
{
}
$
^
|
\
```

اگر بخواهیم خود این کاراکترها را جستجو کنیم باید آن‌ها را Escape کنیم.

---

اشتباه:

```javascript
const regex = /.com/;
```

این Regex:

هر کاراکتری قبل از `com` را قبول می‌کند.

---

در حالی که هدف معمولاً این است:

```text
.com
```

راه‌حل:

```javascript
const regex = /\.com/;
```

---

مثال دیگر:

اشتباه:

```javascript
const regex = /$/;
```

این Regex پایان رشته را بررسی می‌کند، نه علامت دلار.

راه‌حل:

```javascript
const regex = /\$/;
```

---

## Escape کردن Backslash

در رشته‌های جاوااسکریپت باید Backslash نیز Escape شود.

مثال:

```javascript
const regex = new RegExp("\\d+");
```

اما اگر از Literal استفاده کنیم:

```javascript
const regex = /\d+/;
```

نیازی به Escape اضافی نیست.

---

# اشتباه سوم: نوشتن Regexهای بیش از حد پیچیده

گاهی یک Regex آن‌قدر پیچیده می‌شود که حتی نویسنده آن نیز بعد از چند روز دیگر آن را متوجه نمی‌شود.

مثال:

```regex
^(?=.*[A-Z])(?=.*[a-z])(?=.*\d)(?=.*[@#$]).{8,32}$
```

اگر چنین Regexهایی لازم هستند، بهتر است آن‌ها را مستندسازی کنید.

مثلاً:

```javascript
const passwordRegex =
/^(?=.*[A-Z])(?=.*[a-z])(?=.*\d)(?=.*[@#$]).{8,32}$/;
```

همراه با توضیح:

```javascript
// Password:
// - Uppercase
// - Lowercase
// - Number
// - Special Character
// - Minimum 8 Characters
```

خوانایی همیشه مهم‌تر از کوتاه بودن کد است.

---

# اشتباه چهارم: استفاده اشتباه از `*` و `+`

بسیاری از افراد تفاوت این دو را فراموش می‌کنند.

---

`*`

یعنی:

```text
صفر بار یا بیشتر
```

---

`+`

یعنی:

```text
یک بار یا بیشتر
```

---

مثال:

```regex
ab*
```

موارد زیر را Match می‌کند:

```text
a
ab
abb
abbb
```

---

اما:

```regex
ab+
```

فقط:

```text
ab
abb
abbb
```

را Match می‌کند.

---

اشتباه رایج:

استفاده از `*` زمانی که وجود حداقل یک کاراکتر الزامی است.

---

# اشتباه پنجم: استفاده بیش از حد از `.*`

بعضی افراد تقریباً در تمام Regexها از `.*` استفاده می‌کنند.

مثلاً:

```regex
.*gmail.*
```

در حالی که:

```regex
gmail
```

کاملاً کافی است.

---

استفاده زیاد از `.*`

* سرعت را کاهش می‌دهد.
* خوانایی را کم می‌کند.
* احتمال Match اشتباه را افزایش می‌دهد.

---

# اشتباه ششم: فراموش کردن Anchorها

اگر هدف بررسی کل رشته باشد باید از:

```regex
^
$
```

استفاده شود.

---

مثال:

اشتباه:

```regex
\d+
```

این Regex:

```text
abc123xyz
```

را نیز معتبر می‌داند.

---

اگر فقط عدد می‌خواهیم:

```regex
^\d+$
```

---

# اشتباه هفتم: مشکل در کاراکترهای فارسی

بسیاری از Regexها فقط برای زبان انگلیسی نوشته شده‌اند.

مثلاً:

```regex
\w+
```

بعضی افراد انتظار دارند این Regex متن فارسی را نیز پیدا کند.

اما:

```text
سلام
```

ممکن است Match نشود یا رفتار آن مطابق انتظار نباشد.

---

برای زبان فارسی بهتر است از محدوده Unicode استفاده کنید.

مثال:

```regex
[\u0600-\u06FF]+
```

یا از ویژگی‌های Unicode همراه با Flag `u` (در محیط‌های مدرن) استفاده کنید.

---

# اشتباه هشتم: اعتماد بیش از حد به Regex

Regex ابزار بسیار قدرتمندی است.

اما همه مشکلات را حل نمی‌کند.

مثلاً:

این Regex:

```regex
^[^\s@]+@[^\s@]+\.[^\s@]+$
```

فقط فرمت ایمیل را بررسی می‌کند.

اما:

```text
hello@not-real-domain.com
```

را نیز معتبر می‌داند.

---

همچنین برای بررسی قدرت رمز عبور، صحت شماره تلفن، وجود فایل، یا اعتبار دامنه، معمولاً به منطق برنامه یا سرویس‌های دیگر نیز نیاز دارید.

Regex فقط یکی از ابزارهای اعتبارسنجی است، نه کل فرآیند اعتبارسنجی.

---

# اشتباه نهم: استفاده از Regex برای هر مسئله

گاهی استفاده از متدهای معمولی String بسیار ساده‌تر و خواناتر است.

مثلاً:

اشتباه:

```javascript
/node/.test(text);
```

در حالی که:

```javascript
text.includes("node");
```

کاملاً کافی است.

---

یا:

```javascript
/^admin/.test(text);
```

را می‌توان با:

```javascript
text.startsWith("admin");
```

جایگزین کرد.

---

# اشتباه دهم: تست نکردن Regex

قبل از استفاده از یک Regex در پروژه واقعی، آن را با ورودی‌های مختلف آزمایش کنید.

ورودی‌های پیشنهادی:

* مقدار صحیح
* مقدار اشتباه
* رشته خالی
* مقدار `null` یا `undefined` (در صورت امکان)
* رشته بسیار طولانی
* کاراکترهای فارسی
* فاصله‌ها
* Emoji
* کاراکترهای خاص

هرچه Regex روی ورودی‌های بیشتری آزمایش شود، احتمال بروز خطا در محیط واقعی کمتر خواهد بود.

---

# چک‌لیست قبل از استفاده از RegExp

قبل از نهایی کردن یک Regex این سؤال‌ها را از خود بپرسید:

* آیا Regex تا حد امکان ساده است؟
* آیا از Anchorهای مناسب استفاده کرده‌ام؟
* آیا کاراکترهای خاص را Escape کرده‌ام؟
* آیا Flag مناسب را انتخاب کرده‌ام؟
* آیا Regex روی داده‌های واقعی آزمایش شده است؟
* آیا استفاده از Regex واقعاً بهترین انتخاب است یا یک متد ساده String کافی است؟
* آیا این Regex برای سایر اعضای تیم نیز قابل فهم است؟

# جمع‌بندی بخش ۶

در این بخش با رایج‌ترین اشتباهات هنگام کار با Regular Expression آشنا شدیم.

مهم‌ترین آن‌ها عبارت بودند از:

* استفاده نادرست از Flagها
* فراموش کردن Escape کردن کاراکترهای خاص
* نوشتن Regexهای بیش از حد پیچیده
* استفاده اشتباه از `*` و `+`
* استفاده بی‌دلیل از `.*`
* فراموش کردن `^` و `$`
* مشکلات مربوط به متن‌های فارسی و Unicode
* اعتماد بیش از حد به Regex برای اعتبارسنجی
* استفاده از Regex در مسائلی که متدهای ساده String مناسب‌تر هستند
* تست نکردن Regex قبل از استفاده در پروژه

با رعایت این نکات، Regexهای شما خواناتر، سریع‌تر، قابل نگهداری‌تر و قابل اعتمادتر خواهند بود.

# بخش ۷ - نکات حرفه‌ای

نوشتن یک Regular Expression که فقط کار کند کافی نیست.

یک برنامه‌نویس حرفه‌ای Regexهایی می‌نویسد که:

* خوانا باشند.
* قابل نگهداری باشند.
* سریع اجرا شوند.
* سایر اعضای تیم نیز بتوانند آن‌ها را درک کنند.

در این بخش با مجموعه‌ای از نکات و تجربه‌های عملی آشنا می‌شویم که در پروژه‌های واقعی Node.js بسیار ارزشمند هستند.

---

# ۳۰.۳۵ - نکات حرفه‌ای کار با RegExp

---

## ۱- ابتدا ساده‌ترین راه را انتخاب کنید

قبل از نوشتن Regex از خودتان بپرسید:

> آیا واقعاً به Regular Expression نیاز دارم؟

گاهی یک متد ساده از String همان کار را انجام می‌دهد.

مثال:

```javascript
const email = "admin@gmail.com";

console.log(email.includes("@"));
```

یا:

```javascript
const file = "photo.png";

console.log(file.endsWith(".png"));
```

استفاده از Regex فقط زمانی مناسب است که واقعاً به الگوهای پیچیده نیاز داشته باشید.

---

## ۲- Regex را تا حد امکان کوتاه نگه دارید

اشتباه:

```regex
.*node.*
```

بهتر:

```regex
node
```

هرچه Regex کوتاه‌تر باشد:

* خواناتر است.
* سریع‌تر اجرا می‌شود.
* نگهداری آن آسان‌تر است.

---

## ۳- از Anchorها استفاده کنید

اگر قرار است کل رشته بررسی شود، همیشه از:

```regex
^
$
```

استفاده کنید.

اشتباه:

```regex
\d+
```

بهتر:

```regex
^\d+$
```

---

## ۴- نام مناسب برای Regex انتخاب کنید

اشتباه:

```javascript
const regex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
```

بهتر:

```javascript
const emailRegex =
/^[^\s@]+@[^\s@]+\.[^\s@]+$/;
```

یا:

```javascript
const phoneRegex =
/^09\d{9}$/;
```

نام مناسب باعث خوانایی بیشتر کد می‌شود.

---

## ۵- Regexهای پرتکرار را یک بار ایجاد کنید

اشتباه:

```javascript
for (const user of users) {

    if (/^\d+$/.test(user.id)) {

    }

}
```

در هر بار اجرای حلقه یک شیء جدید ساخته می‌شود.

بهتر:

```javascript
const numberRegex = /^\d+$/;

for (const user of users) {

    if (numberRegex.test(user.id)) {

    }

}
```

---

## ۶- از Non Capturing Group استفاده کنید

اگر مقدار گروه را نیاز ندارید:

اشتباه:

```regex
(cat|dog)
```

بهتر:

```regex
(?:cat|dog)
```

این کار هم خوانایی را افزایش می‌دهد و هم از ایجاد گروه‌های غیرضروری جلوگیری می‌کند.

---

## ۷- Regexهای بزرگ را تقسیم کنید

گاهی یک Regex بسیار طولانی نوشته می‌شود.

مثلاً:

```regex
^(?=.*[A-Z])(?=.*[a-z])(?=.*\d)(?=.*[@#$]).{8,32}$
```

در پروژه‌های واقعی بهتر است منطق را به چند بخش تقسیم کنید.

مثال:

```javascript
const hasUpperCase = /[A-Z]/;
const hasLowerCase = /[a-z]/;
const hasNumber = /\d/;
const hasSpecial = /[!@#$%^&*]/;
const hasMinLength = /^.{8,}$/;

function validatePassword(password) {
    return (
        hasUpperCase.test(password) &&
        hasLowerCase.test(password) &&
        hasNumber.test(password) &&
        hasSpecial.test(password) &&
        hasMinLength.test(password)
    );
}
```

مزایا:

* خواناتر
* قابل تست
* قابل توسعه
* نگهداری آسان‌تر

---

## ۸- Regexهای پیچیده را مستندسازی کنید

اگر Regex پیچیده‌ای نوشته‌اید، برای آن توضیح بنویسید.

مثال:

```javascript
// Password:
// Minimum 8 characters
// At least one uppercase letter
// At least one lowercase letter
// At least one digit
// At least one special character

const passwordRegex =
/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[!@#$%^&*]).{8,}$/;
```

چند خط توضیح می‌تواند ساعت‌ها زمان اعضای تیم را ذخیره کند.

---

## ۹- Regex را روی داده‌های واقعی تست کنید

قبل از استفاده در پروژه، Regex را با ورودی‌های مختلف بررسی کنید.

مثال:

```javascript
const regex = /^\d+$/;

console.log(regex.test("123"));
console.log(regex.test("12a"));
console.log(regex.test(""));
console.log(regex.test("0001"));
console.log(regex.test("123456789"));
```

هرچه سناریوهای بیشتری آزمایش شوند، احتمال خطا کمتر خواهد بود.

---

## ۱۰- از ابزارهای تست Regex استفاده کنید

در زمان توسعه می‌توانید از ابزارهای آنلاین برای آزمایش Regex استفاده کنید.

این ابزارها معمولاً امکانات زیر را ارائه می‌دهند:

* نمایش بخش‌های Match شده
* بررسی گروه‌ها
* تست روی چندین ورودی
* نمایش خطاهای احتمالی
* توضیح ساختار Regex

این ابزارها برای یادگیری و اشکال‌زدایی بسیار مفید هستند.

---

## ۱۱- به Performance توجه کنید

همیشه ساده‌ترین Regex ممکن را انتخاب کنید.

مثال:

اشتباه:

```regex
(a+)+
```

بهتر:

```regex
a+
```

Regexهای ساده‌تر سریع‌تر اجرا می‌شوند و احتمال بروز Catastrophic Backtracking در آن‌ها کمتر است.

---

## ۱۲- از Flag مناسب استفاده کنید

هر Flag هدف مشخصی دارد.

| Flag | کاربرد                          |
| ---- | ------------------------------- |
| `g`  | جستجوی همه Matchها              |
| `i`  | نادیده گرفتن بزرگی و کوچکی حروف |
| `m`  | بررسی چندخطی برای `^` و `$`     |
| `s`  | تطبیق `.` با کاراکتر خط جدید    |
| `u`  | پشتیبانی از Unicode             |

از اضافه کردن Flagهای غیرضروری خودداری کنید.

---

## ۱۳- متن فارسی و Unicode را فراموش نکنید

اگر برنامه شما چندزبانه است، Regex را فقط روی متن انگلیسی آزمایش نکنید.

مثال:

```text
سلام
Node.js
۱۲۳۴۵
😊
```

Regex باید روی تمام داده‌های واقعی پروژه به‌درستی عمل کند.

---

## ۱۴- از Regex برای تجزیه HTML استفاده نکنید

یکی از معروف‌ترین توصیه‌ها در دنیای برنامه‌نویسی این است:

> HTML یک زبان ساختاریافته است، نه یک متن ساده.

بنابراین برای خواندن یا تحلیل HTML از Parserهای مناسب استفاده کنید، نه Regex.

مثال اشتباه:

```regex
<div>.*</div>
```

این الگو در بسیاری از ساختارهای واقعی HTML نتیجه درستی نخواهد داشت.

---

## ۱۵- اعتبارسنجی را فقط به Regex محدود نکنید

Regex فقط فرمت داده را بررسی می‌کند.

مثال:

```text
admin@example.com
```

ممکن است از نظر Regex معتبر باشد، اما:

* دامنه وجود نداشته باشد.
* ایمیل متعلق به کاربر نباشد.
* صندوق پستی غیرفعال باشد.

در پروژه‌های واقعی علاوه بر Regex از اعتبارسنجی‌های دیگر نیز استفاده می‌شود.

---

## ۱۶- برای اعتبارسنجی‌های رایج از کتابخانه‌های معتبر استفاده کنید

در بسیاری از پروژه‌های Node.js، برای اعتبارسنجی اطلاعاتی مانند:

* ایمیل
* URL
* IP
* UUID
* شماره کارت
* تاریخ

به‌جای نوشتن Regex از ابتدا، از کتابخانه‌های معتبر و آزمایش‌شده استفاده می‌شود.

این کار احتمال خطا را کاهش می‌دهد و نگهداری پروژه را آسان‌تر می‌کند.

---

## ۱۷- بین خوانایی و کوتاهی تعادل برقرار کنید

گاهی می‌توان یک Regex را کوتاه‌تر نوشت، اما در عوض فهم آن بسیار سخت می‌شود.

در پروژه‌های تیمی معمولاً خوانایی از کوتاه بودن مهم‌تر است.

کدی که همه اعضای تیم آن را بفهمند، ارزش بیشتری نسبت به کدی دارد که فقط نویسنده آن متوجهش شود.

---

## ۱۸- Regex را آخرین گزینه ندانید، اما اولین گزینه هم قرار ندهید

Regex یک ابزار بسیار قدرتمند است، اما همیشه بهترین ابزار نیست.

قبل از استفاده از آن بررسی کنید:

* آیا `includes()` کافی است؟
* آیا `startsWith()` مناسب‌تر است؟
* آیا `endsWith()` نیاز شما را برطرف می‌کند؟
* آیا `split()` یا `replace()` بدون Regex قابل استفاده هستند؟

اگر پاسخ مثبت است، معمولاً همان روش ساده‌تر را انتخاب کنید.

---

# چک‌لیست حرفه‌ای قبل از نوشتن Regex

قبل از نهایی کردن یک Regex این موارد را بررسی کنید:

* آیا Regex تا حد امکان ساده است؟
* آیا نام مناسبی برای آن انتخاب کرده‌ام؟
* آیا از Anchorهای مناسب استفاده کرده‌ام؟
* آیا Flagهای اضافی حذف شده‌اند؟
* آیا Regex روی داده‌های واقعی تست شده است؟
* آیا گروه‌های غیرضروری حذف شده‌اند؟
* آیا برای سایر اعضای تیم قابل فهم است؟
* آیا برای این مسئله واقعاً به Regex نیاز دارم؟

# جمع‌بندی بخش ۷

در این بخش با مجموعه‌ای از نکات حرفه‌ای برای استفاده از Regular Expression آشنا شدیم.

مهم‌ترین توصیه‌ها عبارت بودند از:

* همیشه ساده‌ترین راه‌حل را انتخاب کنید.
* Regexهای خوانا و قابل نگهداری بنویسید.
* از نام‌گذاری مناسب و مستندسازی استفاده کنید.
* Regexهای پیچیده را به بخش‌های کوچک‌تر تقسیم کنید.
* Regex را روی داده‌های واقعی آزمایش کنید.
* به Performance توجه داشته باشید.
* برای اعتبارسنجی‌های حساس فقط به Regex تکیه نکنید.
* هر زمان که متدهای ساده String کافی هستند، از آن‌ها استفاده کنید.

رعایت این نکات باعث می‌شود کدهای شما حرفه‌ای‌تر، سریع‌تر، قابل اعتمادتر و برای سایر توسعه‌دهندگان نیز قابل فهم باشند.

# جمع‌بندی بخش ۸

در این بخش، مجموعه‌ای از تمرین‌های کاربردی برای تثبیت مفاهیم RegExp ارائه شد.

اگر بتوانید تمام تمرین‌های این بخش را بدون مراجعه به پاسخ‌ها حل کنید، تسلط بسیار خوبی بر Regular Expression در JavaScript و Node.js خواهید داشت.

| بخش                | وظیفه                |
| ------------------ | -------------------- |

| `(?=.*[!@#$%^&*])` | حداقل یک کاراکتر خاص |
| `.{8,}`            | حداقل ۸ کاراکتر      |

# ۳۰.۴۱ - مینی پروژه ۲

# Password Strength Checker

## هدف پروژه

بررسی قدرت رمز عبور کاربران.

---

## قوانین

رمز عبور باید:

* حداقل ۸ کاراکتر باشد.
* حداقل یک حرف بزرگ داشته باشد.
* حداقل یک حرف کوچک داشته باشد.
* حداقل یک عدد داشته باشد.
* حداقل یک کاراکتر خاص داشته باشد.

---

## Regex

```javascript
const passwordRegex =
/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[!@#$%^&*]).{8,}$/;
```

---

## تابع بررسی

```javascript
function validatePassword(password) {

    return passwordRegex.test(password);

}
```

```javascript
const passwords = [

    "Node123",

    "Node123!",

    "PASSWORD123!",

    "node123!"

];

    console.log(

        password,

        validatePassword(password)

    );

}
```

## خروجی

```text
node123! false
```

---

## توسعه پروژه

