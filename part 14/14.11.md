فصل 118 - Environment Variables

مقدمه

در پروژه‌های واقعی Node.js، برنامه فقط از کد تشکیل نشده است. معمولاً بخشی از اطلاعات موردنیاز برنامه باید خارج از Source Code نگهداری شود.

برای مثال:

Database URL
API Key
JWT Secret
Application Port
Environment
Third-party Credentials

قرار دادن چنین اطلاعاتی مستقیماً داخل کد، هم مدیریت پروژه را سخت می‌کند و هم می‌تواند یک مشکل امنیتی جدی ایجاد کند.

برای همین در Node.js از مفهومی به نام:

Environment Variables

یا متغیرهای محیطی استفاده می‌کنیم.

در این فصل یاد می‌گیریم Environment Variable چیست، چگونه در Node.js به آن دسترسی پیدا کنیم، چگونه فایل .env بسازیم، چگونه Configuration پروژه را مدیریت کنیم و چگونه از قرار گرفتن اطلاعات حساس در Git جلوگیری کنیم.


---

118.1 - Environment Variable چیست؟

Environment Variable متغیری است که خارج از Source Code برنامه قرار می‌گیرد و در زمان اجرای Application در اختیار آن قرار داده می‌شود.

مثلاً:

PORT=3000

یا:

DATABASE_URL=mongodb://localhost:27017/myapp

برنامه می‌تواند این مقدار را در زمان اجرا دریافت کند.


---

118.2 - چرا به Environment Variables نیاز داریم؟

فرض کنید Port برنامه را مستقیماً داخل کد نوشته‌ایم:

const PORT = 3000;

در محیط Development ممکن است بخواهیم:

3000

استفاده کنیم.

اما در Production شاید:

8080

مناسب باشد.

اگر مقدار داخل کد باشد، برای تغییر Configuration باید Source Code را تغییر دهیم.

اما با Environment Variable:

Development
PORT=3000

Production
PORT=8080

کد برنامه می‌تواند بدون تغییر باقی بماند.


---

118.3 - Configuration چیست؟

Configuration به تنظیماتی گفته می‌شود که رفتار Application را مشخص می‌کنند.

مثلاً:

PORT
NODE_ENV
DATABASE_URL
JWT_SECRET
LOG_LEVEL
API_URL

این اطلاعات معمولاً بخشی از Business Logic نیستند.

بهتر است Configuration از کد Application جدا باشد.


---

118.4 - Environmentهای مختلف

یک پروژه معمولاً در محیط‌های مختلف اجرا می‌شود:

Development
Testing
Staging
Production

ممکن است Configuration هر محیط متفاوت باشد.

مثلاً:

Development
DATABASE_URL=localhost

Production
DATABASE_URL=production-database

اما کد Node.js می‌تواند همان کد باقی بماند.


---

118.5 - متغیر process.env

در Node.js برای دسترسی به Environment Variables از:

process.env

استفاده می‌کنیم.

مثلاً:

console.log(process.env.PORT);

اگر متغیر زیر تعریف شده باشد:

PORT=3000

خروجی:

3000

خواهد بود.


---

118.6 - یک نکته مهم درباره Type

مقادیر موجود در:

process.env

به‌صورت String در اختیار برنامه قرار می‌گیرند.

مثلاً:

PORT=3000

را داریم.

اما:

process.env.PORT

یک String است.

بنابراین:

console.log(typeof process.env.PORT);

معمولاً نتیجه:

string

است.


---

118.7 - تبدیل Environment Variable به Number

اگر Port را می‌خواهیم به‌عنوان Number استفاده کنیم:

const PORT = Number(process.env.PORT);

یا:

const PORT = parseInt(process.env.PORT, 10);

سپس می‌توانیم:

app.listen(PORT);

استفاده کنیم.


---

118.8 - مقدار پیش‌فرض

گاهی ممکن است Environment Variable تعریف نشده باشد.

می‌توانیم مقدار پیش‌فرض تعیین کنیم:

const PORT = Number(process.env.PORT || 3000);

یا:

const PORT = Number(process.env.PORT ?? 3000);

در این حالت اگر PORT وجود نداشته باشد، برنامه از 3000 استفاده می‌کند.


---

118.9 - تفاوت || و ??

در Configuration این تفاوت مهم است.

مثلاً:

const value = process.env.VALUE || "default";

اگر مقدار Empty String باشد، مقدار Default استفاده می‌شود.

اما:

const value = process.env.VALUE ?? "default";

فقط زمانی Default استفاده می‌شود که مقدار:

null
undefined

باشد.


---

118.10 - ساخت فایل .env

یکی از روش‌های رایج برای نگهداری Environment Variables در Development استفاده از فایل:

.env

است.

مثلاً:

PORT=3000
NODE_ENV=development
DATABASE_URL=mongodb://localhost:27017/myapp
JWT_SECRET=my-super-secret


---

118.11 - ساختار .env

هر Variable معمولاً به شکل زیر نوشته می‌شود:

KEY=VALUE

مثلاً:

PORT=3000
APP_NAME=my-app
NODE_ENV=development


---

118.12 - استفاده از Comment

می‌توان برای مرتب‌تر کردن فایل .env از Comment استفاده کرد:

# Server
PORT=3000

# Database
DATABASE_URL=mongodb://localhost:27017/myapp

# Authentication
JWT_SECRET=change-this-secret

118.13 - استفاده از dotenv

یکی از Packageهای معروف برای خواندن فایل .env:

dotenv

است.

نصب:

npm install dotenv

118.14 - Load کردن .env

در حالت CommonJS:

require("dotenv").config();

و در ES Modules:

import "dotenv/config";

بعد:

console.log(process.env.PORT);

قابل استفاده است.

118.15 - مثال کامل

فایل:

PORT=3000
NODE_ENV=development

کد:

import "dotenv/config";

const PORT = Number(process.env.PORT);

console.log(PORT);
console.log(process.env.NODE_ENV);

خروجی:

3000
development


---

118.16 - چرا .env نباید وارد Git شود؟

فایل .env ممکن است شامل اطلاعات حساسی باشد:

Database Password
API Key
JWT Secret
Private Credentials

اگر این فایل وارد Git شود، ممکن است اطلاعات حساس در Repository قرار بگیرد.

بنابراین معمولاً .env را در:

.gitignore

قرار می‌دهیم.


---

118.17 - فایل .gitignore

مثلاً:

node_modules/
.env

به این ترتیب Git فایل .env را Track نمی‌کند.


---

118.18 - فایل .env.example

اگر .env را Commit نمی‌کنیم، اعضای دیگر تیم چگونه متوجه شوند چه Variableهایی نیاز است؟

برای این کار معمولاً از:

.env.example

استفاده می‌کنیم.

مثلاً:

PORT=
NODE_ENV=
DATABASE_URL=
JWT_SECRET=

این فایل شامل Secret واقعی نیست و فقط ساختار Configuration را نشان می‌دهد.


---

118.19 - تفاوت .env و .env.example

.env

مقادیر واقعی:

PORT=3000
DATABASE_URL=mongodb://localhost:27017/app
JWT_SECRET=real-secret

.env.example

Template:

PORT=
DATABASE_URL=
JWT_SECRET=

معمولاً:

.env

نباید Commit شود.

اما:

.env.example

می‌تواند در Repository قرار بگیرد.


---

118.20 - Secret چیست؟

Secret به اطلاعاتی گفته می‌شود که نباید عمومی شوند.

مثلاً:

JWT_SECRET
API_KEY
DATABASE_PASSWORD
PRIVATE_KEY

Secret را نباید در کد Hard-Code کنیم:

const JWT_SECRET = "123456";

این روش مناسبی نیست.


---

118.21 - Hard-Coded Secret

کد زیر مشکل دارد:

const API_KEY = "abc123-secret";

چون Secret بخشی از Source Code شده است.

اگر Repository عمومی شود یا دسترسی افراد زیادی به آن وجود داشته باشد، Secret ممکن است افشا شود.


---

118.22 - استفاده از Environment Variable برای Secret

بهتر:

API_KEY=abc123-secret

و:

const API_KEY = process.env.API_KEY;

البته این به معنی آن نیست که فایل .env را می‌توان بدون محدودیت در اختیار دیگران قرار داد.


---

118.23 - Environment Variable فقط برای Secret نیست

یکی از اشتباهات رایج این است که تصور کنیم Environment Variable فقط برای Password و API Key است.

در واقع می‌توان برای Configurationهای مختلف استفاده کرد:

PORT=3000
NODE_ENV=development
LOG_LEVEL=debug
API_URL=https://example.com


---

118.24 - NODE_ENV

یکی از Variableهای معروف در اکوسیستم Node.js:

NODE_ENV

است.

مثلاً:

NODE_ENV=development

یا:

NODE_ENV=production

در کد:

if (process.env.NODE_ENV === "production") {
  console.log("Production mode");
}


---

118.25 - Development و Production

ممکن است در Development:

NODE_ENV=development

و در Production:

NODE_ENV=production

داشته باشیم.

برنامه می‌تواند بر اساس Environment رفتار متفاوتی داشته باشد.

مثلاً Logging بیشتر در Development:

if (process.env.NODE_ENV === "development") {
  console.log("Debug information");
}


---

118.26 - Environment Variable در Command Line

لازم نیست حتماً از .env استفاده کنیم.

می‌توان Variable را هنگام اجرای برنامه تعریف کرد.

در Linux/macOS:

PORT=4000 node src/server.js

سپس:

console.log(process.env.PORT);

مقدار:

4000

خواهد بود.


---

118.27 - Environment Variable در npm Script

می‌توان Configuration را هنگام اجرای Script نیز تعیین کرد.

مثلاً:

{
  "scripts": {
    "start": "node src/server.js"
  }
}

در محیط اجرای برنامه می‌توان Environment Variable را تنظیم کرد.


---

118.28 - Environment Variable در Docker

در پروژه‌های واقعی ممکن است Node.js داخل Docker اجرا شود.

Environment Variable می‌تواند از خارج Container به Application داده شود.

مثلاً:

PORT
DATABASE_URL
NODE_ENV

این یکی از دلایل مهم جدا نگه داشتن Configuration از Source Code است.


---

118.29 - Environment Variable در Deployment

در سرویس‌های Deployment و Cloud معمولاً می‌توان Environment Variableها را در تنظیمات محیط اجرا تعریف کرد.

در این حالت:

Source Code
     +
Environment Configuration
     ↓
Running Application

داریم.

بنابراین لازم نیست Secretهای Production را داخل Repository قرار دهیم.


---

118.30 - Centralized Configuration

در پروژه‌های کوچک ممکن است مستقیماً بنویسیم:

process.env.PORT

اما در پروژه‌های بزرگ بهتر است Configuration را متمرکز کنیم.

مثلاً:

src/
├── config/
│   └── env.js
├── routes/
├── controllers/
└── server.js


---

118.31 - فایل Configuration

مثلاً:

export const config = {
  port: Number(process.env.PORT ?? 3000),

  nodeEnv:
    process.env.NODE_ENV ?? "development",

  databaseUrl:
    process.env.DATABASE_URL
};

سپس در Application:

import { config } from "./config/env.js";

console.log(config.port);

این روش باعث می‌شود Application به‌جای دسترسی پراکنده به process.env از یک Configuration مرکزی استفاده کند.


---

118.32 - Validation کردن Environment Variables

یکی از مهم‌ترین نکات حرفه‌ای این است که Environment Variableها نیز باید Validate شوند.

مثلاً اگر:

PORT=abc

باشد:

const PORT = Number(process.env.PORT);

نتیجه مناسبی نخواهد داشت.

بنابراین باید Configuration را بررسی کنیم.


---

118.33 - Validation با Zod

می‌توانیم از Zod استفاده کنیم:

import { z } from "zod";

const envSchema = z.object({
  PORT: z.coerce.number().int().positive(),
  NODE_ENV: z.enum([
    "development",
    "test",
    "production"
  ]),
  DATABASE_URL: z.string().min(1),
  JWT_SECRET: z.string().min(32)
});

const env = envSchema.parse(process.env);

حالا:

env.PORT
env.NODE_ENV
env.DATABASE_URL
env.JWT_SECRET

مقادیر Validate شده هستند.


---

118.34 - Fail Fast

اگر Configuration ضروری وجود ندارد، بهتر است Application هنگام Startup متوقف شود.

مثلاً:

if (!process.env.DATABASE_URL) {
  throw new Error(
    "DATABASE_URL is required"
  );
}

بهتر است Application خیلی زود متوجه Configuration اشتباه شود، نه اینکه بعداً در زمان اجرای یک Request خراب شود.


---

118.35 - Required Environment Variables

برخی Variableها ممکن است ضروری باشند:

DATABASE_URL
JWT_SECRET

برخی دیگر می‌توانند Optional باشند:

LOG_LEVEL
PORT

البته این موضوع به Architecture پروژه بستگی دارد.


---

118.36 - Optional و Required

مثلاً:

const PORT =
  Number(process.env.PORT ?? 3000);

اینجا PORT می‌تواند Default داشته باشد.

اما:

const DATABASE_URL =
  process.env.DATABASE_URL;

if (!DATABASE_URL) {
  throw new Error(
    "DATABASE_URL is required"
  );
}

در اینجا Database URL ضروری است.


---

118.37 - Environment Variableهای Boolean

یک نکته مهم:

DEBUG=false

به معنی Boolean false نیست.

مقدار:

process.env.DEBUG

یک String است:

"false"

بنابراین:

Boolean(process.env.DEBUG)

اشتباه است، چون "false" یک String غیرخالی است و به Boolean true تبدیل می‌شود.


---

118.38 - تبدیل صحیح Boolean

می‌توانیم صریحاً بررسی کنیم:

const DEBUG =
  process.env.DEBUG === "true";

در این صورت:

DEBUG=true

تبدیل به:

true

و:

DEBUG=false

تبدیل به:

false

می‌شود.


---

118.39 - Array در Environment Variable

Environment Variable ذاتاً String است.

اگر بخواهیم چند مقدار داشته باشیم:

ALLOWED_ORIGINS=https://a.com,https://b.com

می‌توانیم آن را تبدیل کنیم:

const allowedOrigins =
  process.env.ALLOWED_ORIGINS
    ?.split(",")
    .map(value => value.trim())
    .filter(Boolean);


---

118.40 - Environment Variables و Security

Environment Variable ابزار مدیریت Configuration است، نه یک سیستم جادویی برای امنیت.

مثلاً:

JWT_SECRET=secret

بهتر از Hard-Code کردن Secret است.

اما اگر Environment Variable در:

Logs
Error Messages
Client Response
Monitoring

نمایش داده شود، همچنان Secret افشا شده است.

118.41 - Secret را Log نکنید

اشتباه:

console.log(process.env);

این کار می‌تواند تمام Environment Variables را در Log قرار دهد.

به‌خصوص در Production خطرناک است.

118.42 - فقط مقدارهای غیرحساس را Log کنید

مثلاً:

console.log({
  nodeEnv: process.env.NODE_ENV,
  port: process.env.PORT
});

اما مواردی مانند:

JWT_SECRET
DATABASE_PASSWORD
API_KEY

نباید Log شوند.

118.43 - Secret Rotation

در پروژه‌های حرفه‌ای ممکن است Secretها نیاز به تغییر داشته باشند.

مثلاً:

JWT Secret

Database Credential

نباید برای همیشه ثابت باقی بمانند.

به تغییر دوره‌ای یا در شرایط خاص به:

نیاز داریم.

118.44 - مدیریت Secret در Production

در محیط Production بهتر است Secretهای حساس توسط سیستم مدیریت Secret یا Configuration خود محیط اجرا مدیریت شوند.

مثلاً:

Application
    ↓
Environment / Secret Manager
    ↓
Secrets

هدف این است که Secretها وارد Source Code و Repository نشوند.

118.45 - تفاوت Configuration و User Data

Environment Variable برای Configuration برنامه مناسب است:

PORT
DATABASE_URL
NODE_ENV
JWT_SECRET

اما برای اطلاعات Dynamic کاربران مناسب نیست.

مثلاً اطلاعاتی مانند:

username
email
address

باید در Database یا Storage مناسب نگهداری شوند.

118.46 - ترتیب بارگذاری Configuration

بهتر است Environment Variableها در ابتدای اجرای Application Load شوند.

مثلاً:

import "dotenv/config";

import express from "express";
import { config } from "./config/env.js";

تا Moduleهای دیگر بتوانند Configuration موردنیاز را دریافت کنند.

118.47 - Configuration Object

یک ساختار تمیز:

export const config = {
  server: {
    port: Number(process.env.PORT ?? 3000)
  },

  database: {
    url: process.env.DATABASE_URL
  },

  auth: {
    jwtSecret: process.env.JWT_SECRET
  },

  app: {
    environment:
      process.env.NODE_ENV ?? "development"
  }
};

حالا ساختار Configuration مشخص است.

import "dotenv/config";

import { z } from "zod";

const envSchema = z.object({
  PORT: z.coerce
    .number()
    .int()
    .positive()
    .default(3000),

  NODE_ENV: z.enum([
    "development",
    "test",
    "production"
  ]).default("development"),

  DATABASE_URL: z.string().min(1),

  JWT_SECRET: z.string().min(32)
});

const env = envSchema.parse(
  process.env
);

export const config = {
  server: {
    port: env.PORT
  },

  app: {
    environment: env.NODE_ENV
  },

  database: {
    url: env.DATABASE_URL
  },

  auth: {
    jwtSecret: env.JWT_SECRET
  }
};

جمع‌بندی

Environment Variables یکی از پایه‌ای‌ترین مفاهیم برای ساخت Applicationهای واقعی Node.js هستند.

با آن‌ها می‌توانیم Configuration را از Source Code جدا کنیم:

Source Code
      +
Environment
      ↓
Application

به‌جای:

Source Code
   ↓
Hard-Coded Configuration

مهم‌ترین نکات این فصل:

process.env
.env
.env.example
.gitignore
dotenv
Configuration
Validation
Required Variables
Default Values
Secrets
NODE_ENV
Development
Production
Fail Fast
Secret Management

و مهم‌تر از همه، باید به خاطر داشته باشیم:

> Environment Variable بودن یک مقدار به‌تنهایی آن را امن نمی‌کند.



اگر Secret را داخل process.env قرار دهیم ولی آن را در Log چاپ کنیم، در Error Response ارسال کنیم یا به اشتباه در Repository قرار دهیم، همچنان Secret افشا خواهد شد.

الگوی مناسب:

Environment
     ↓
Load
     ↓
Validate
     ↓
Normalize / Transform
     ↓
Centralized Config
     ↓
Application

است.
