# فصل 118 - Environment Variables

## مقدمه

در پروژه‌های واقعی Node.js، اطلاعات مختلفی وجود دارند که نباید مستقیماً داخل کد برنامه نوشته شوند.

برای مثال:

* رمز عبور Database
* نام کاربری Database
* کلید API سرویس‌های خارجی
* Secret مربوط به JWT
* اطلاعات اتصال به Redis
* Port برنامه
* آدرس سرویس‌های مختلف
* تنظیمات مربوط به محیط Development و Production

اگر این اطلاعات را مستقیماً داخل کد قرار دهیم، هم مدیریت پروژه سخت‌تر می‌شود و هم ممکن است اطلاعات حساس به‌صورت ناخواسته وارد Git و GitHub شوند.

برای حل این مشکل از **Environment Variables** یا **متغیرهای محیطی** استفاده می‌کنیم.

Environment Variable مقداری است که خارج از کد برنامه تعریف می‌شود و برنامه Node.js می‌تواند هنگام اجرا آن را دریافت کند.

در این فصل یاد می‌گیریم چگونه Environment Variableها را در Node.js تعریف، دریافت، مدیریت و در پروژه‌های واقعی استفاده کنیم.

---

# 118.1 - Environment Variable چیست؟

Environment Variable یک مقدار نام‌گذاری‌شده است که در محیط اجرای برنامه قرار می‌گیرد.

برای مثال:

```text
PORT=3000
```

در اینجا:

```text
PORT
```

نام متغیر و:

```text
3000
```

مقدار آن است.

برنامه Node.js می‌تواند این مقدار را دریافت کند.

مثلاً:

```js
console.log(process.env.PORT);
```

اگر `PORT` برابر `3000` باشد، خروجی:

```text
3000
```

خواهد بود.

---

# 118.2 - چرا از Environment Variables استفاده می‌کنیم؟

یکی از مهم‌ترین دلایل استفاده از Environment Variableها جدا کردن **Configuration** از **Source Code** است.

فرض کنید برنامه ما به Database متصل می‌شود.

روش نامناسب:

```js
const password = "my-secret-password";
```

این رمز داخل Source Code قرار گرفته است.

روش بهتر:

```js
const password = process.env.DB_PASSWORD;
```

حالا رمز عبور خارج از کد قرار دارد.

این کار چند مزیت دارد:

* افزایش امنیت
* امکان استفاده از تنظیمات متفاوت در محیط‌های مختلف
* جلوگیری از تغییر Source Code برای تغییر Configuration
* مناسب بودن برای Deployment
* مناسب بودن برای Docker
* مناسب بودن برای CI/CD
* جلوگیری از قرار گرفتن Secretها در Git

---

# 118.3 - process.env

در Node.js برای دسترسی به Environment Variableها از:

```js
process.env
```

استفاده می‌کنیم.

مثلاً:

```js
console.log(process.env.NODE_ENV);
```

یا:

```js
console.log(process.env.PORT);
```

یا:

```js
console.log(process.env.DB_HOST);
```

ساختار کلی:

```js
process.env.NAME
```

است.

# 118.4 - ساخت Environment Variable در سیستم‌عامل

Environment Variable را می‌توان مستقیماً در سیستم‌عامل تعریف کرد.

در Linux و macOS:

```bash
export PORT=3000
```

سپس:

```bash
node app.js
```

در برنامه:

```js
console.log(process.env.PORT);
```

خروجی:

```text
3000
```

# 118.5 - تعریف متغیر هنگام اجرای برنامه

می‌توان Environment Variable را فقط برای همان اجرای برنامه تعریف کرد.

مثلاً در Linux و macOS:

```bash
PORT=5000 node app.js
```

سپس:

```js
console.log(process.env.PORT);
```

خروجی:

```text
5000
```

این روش برای تست و اجرای سریع بسیار کاربردی است.

# 118.6 - Environment Variables در Windows

در Windows Command Prompt می‌توان از:

```cmd
set PORT=3000
node app.js
```

استفاده کرد.

در PowerShell:

```powershell
$env:PORT="3000"
node app.js
```

بعد در Node.js:

```js
console.log(process.env.PORT);
```

# 118.8 - چرا فایل .env محبوب است؟

فایل `.env` باعث می‌شود Configuration پروژه در یک محل مشخص قرار بگیرد.

مثلاً:

```text
.env
```

می‌تواند شامل:

```env
PORT=3000
JWT_SECRET=super-secret
DATABASE_URL=postgresql://...
```

باشد.

در نتیجه کد برنامه فقط به این مقادیر ارجاع می‌دهد:

```js
const port = process.env.PORT;
const jwtSecret = process.env.JWT_SECRET;
```

# 118.9 - dotenv

یکی از Packageهای شناخته‌شده برای مدیریت فایل `.env` در پروژه‌های Node.js، پکیج `dotenv` است.

نصب:

```bash
npm install dotenv
```

سپس در برنامه:

```js
require("dotenv").config();
```

حالا متغیرهای موجود در `.env` از طریق:

```js
process.env
```

قابل دسترسی هستند.

مثلاً:

```env
PORT=3000
```

و:

```js
require("dotenv").config();

console.log(process.env.PORT);
```

---

# 118.10 - استفاده از import

اگر پروژه از ES Modules استفاده کند، می‌توان `dotenv` را به شکل زیر استفاده کرد:

```js
import dotenv from "dotenv";

dotenv.config();

console.log(process.env.PORT);
```

یا در نسخه‌های جدید Node.js می‌توان از قابلیت‌های داخلی مربوط به `.env` نیز استفاده کرد.

نکته مهم این است که باید بدانیم مدیریت Environment Variable فقط به `dotenv` محدود نیست و Node.js در نسخه‌های جدید امکانات داخلی بیشتری برای کار با فایل‌های `.env` ارائه کرده است.

# 118.16 - NODE_ENV

یکی از Environment Variableهای رایج:

```text
NODE_ENV
```

است.

مقادیر رایج:

```text
development

```

مثلاً:

```env
NODE_ENV=development
```

و در Node.js:

```js
console.log(process.env.NODE_ENV);
```

# 118.17 - Environment Variableها همیشه String هستند

یکی از نکات بسیار مهم:

مقادیر `process.env` به‌صورت String در اختیار برنامه قرار می‌گیرند.

مثلاً:

```env
PORT=3000
```

وقتی دریافت شود:

```js
const port = process.env.PORT;
```

مقدار `port` یک String است.

بنابراین:

```js
console.log(typeof port);
```

خروجی:

```text
string
```

است.

---

# 118.18 - تبدیل Environment Variable به Number

اگر به Number نیاز داریم، باید تبدیل نوع انجام دهیم:

```js
const port = Number(process.env.PORT);
```

یا:

```js
const port = parseInt(process.env.PORT, 10);
```

مثلاً:

```js
const port = Number(process.env.PORT);

console.log(typeof port);
```

خروجی:

```text
number
```

---

# 118.19 - مشکل Boolean

فرض کنید:

```env
DEBUG=false
```

ممکن است تصور کنیم:

```js
const debug = process.env.DEBUG;
```

یک Boolean است.

اما:

```js
typeof debug
```

برابر:

```text
string
```

است.

حتی:

```js
if (process.env.DEBUG) {
  console.log("Debug enabled");
}
```

می‌تواند مشکل ایجاد کند، چون String `"false"` مقدار Truthy دارد.

روش صحیح:

```js
const debug = process.env.DEBUG === "true";
```

حالا:

```js
if (debug) {
  console.log("Debug enabled");
}
```

# 118.20 - مقدار پیش‌فرض

ممکن است Environment Variable تعریف نشده باشد.

مثلاً:

```js
const port = process.env.PORT;
```

اگر `PORT` وجود نداشته باشد:

```js
port === undefined
```

خواهد بود.

می‌توانیم مقدار پیش‌فرض تعیین کنیم:

```js
const port = process.env.PORT || 3000;
```

یا:

```js
const port = process.env.PORT ?? 3000;
```

برای مثال:

```js
const port = Number(process.env.PORT ?? 3000);
```

---

# 118.21 - تفاوت || و ??

این تفاوت در Configurationها مهم است.

با:

```js
process.env.PORT || 3000
```

مقادیر Falsy می‌توانند باعث استفاده از مقدار پیش‌فرض شوند.

با:

```js
process.env.PORT ?? 3000
```

فقط `null` و `undefined` باعث استفاده از مقدار پیش‌فرض می‌شوند.

در Environment Variableها معمولاً مقدار دریافت‌شده String یا `undefined` است، بنابراین باید متناسب با نیاز برنامه تصمیم بگیریم.

# 118.22 - اعتبارسنجی Environment Variables

نباید تصور کنیم چون Environment Variable وجود دارد، پس حتماً معتبر است.

مثلاً:

```env
PORT=hello
```

وجود دارد، اما Port معتبر نیست.

یا:

```env
NODE_ENV=something
```

ممکن است مقدار مورد انتظار نباشد.

بنابراین در پروژه‌های حرفه‌ای باید Configuration را Validate کنیم.

مثلاً:

```js
const port = Number(process.env.PORT);

if (!Number.isInteger(port)) {
  throw new Error("PORT must be a valid number");
}
```

# 118.23 - جلوگیری از اجرای برنامه با Configuration ناقص

فرض کنید:

```env
DATABASE_URL=
JWT_SECRET=
```

وجود ندارند.

اجرای برنامه در چنین شرایطی ممکن است باعث خطاهای پیچیده و نامفهوم شود.

بهتر است برنامه در ابتدای اجرا Configuration را بررسی کند:

```js
if (!process.env.DATABASE_URL) {
  throw new Error("DATABASE_URL is required");
}

if (!process.env.JWT_SECRET) {
  throw new Error("JWT_SECRET is required");
}
```

در نتیجه خطا سریع و واضح مشخص می‌شود.

# 118.24 - ساخت Configuration مرکزی

در پروژه‌های بزرگ بهتر است در همه جای پروژه مستقیماً از:

```js
process.env
```

استفاده نکنیم.

به جای آن یک Configuration مرکزی بسازیم.

مثلاً:

```text
src/
├── config/
│   └── env.js
├── controllers/
├── services/
└── server.js
```

در:

```js
// config/env.js
```

می‌توانیم بنویسیم:

```js
export const env = {
  port: Number(process.env.PORT ?? 3000),
  nodeEnv: process.env.NODE_ENV ?? "development",
  databaseUrl: process.env.DATABASE_URL,
  jwtSecret: process.env.JWT_SECRET,
};
```

حالا سایر قسمت‌های برنامه می‌توانند از:

```js
import { env } from "./config/env.js";
```

استفاده کنند.

# 118.26 - Secret چیست؟

Secret به اطلاعات حساسی گفته می‌شود که نباید در اختیار افراد غیرمجاز قرار گیرد.

مثلاً:

```text
JWT Secret
API Key
Database Password
Private Key
Cloud Credentials
Webhook Secret
```

مثلاً:

```env
JWT_SECRET=very-secret-value
```

این مقدار نباید در Source Code قرار گیرد.

# 118.27 - Environment Variable جایگزین کامل Secret Manager نیست

استفاده از `.env` برای پروژه‌های آموزشی و بسیاری از پروژه‌های کوچک مناسب است.

اما در سیستم‌های بزرگ ممکن است از Secret Management Service استفاده شود.

مثلاً Secretها می‌توانند توسط زیرساخت Deployment یا سرویس‌های مدیریت Secret در اختیار برنامه قرار بگیرند.

بنابراین مفهوم مهم این است:

> Secret نباید به Source Code وابسته باشد.

# 118.28 - Environment Variables در Docker

Environment Variableها در Docker نیز بسیار مهم هستند.

مثلاً:

```bash
docker run -e PORT=3000 my-app
```

برنامه Node.js می‌تواند آن را دریافت کند:

```js
console.log(process.env.PORT);
```

همچنین می‌توان Configuration را در Docker Compose مدیریت کرد.

این موضوع در فصل Docker و Deployment با جزئیات بیشتری بررسی خواهد شد.

# 118.29 - Environment Variables در CI/CD

در Pipelineهای CI/CD نیز معمولاً Secretها و Configurationها به‌صورت Environment Variable در اختیار برنامه قرار می‌گیرند.

مثلاً:

```text
DATABASE_URL
NPM_TOKEN
JWT_SECRET
API_KEY
```

در این حالت لازم نیست Secretها را داخل Repository قرار دهیم.

## 4. فرض کردن اینکه Environment Variable عدد است

اشتباه:

```js
const port = process.env.PORT;
```

و فرض کنیم `port` Number است.

بهتر:

```js
const port = Number(process.env.PORT);
```

---

## 5. اشتباه گرفتن `"false"` با `false`

اشتباه:

```js
if (process.env.DEBUG) {
}
```

اگر مقدار:

```env
DEBUG=false
```

باشد، همچنان String `"false"` دریافت می‌شود.

بهتر:

```js
const debug = process.env.DEBUG === "true";
```

---

## 6. استفاده مستقیم و پراکنده از process.env

اگر در ده‌ها فایل بنویسیم:

```js
process.env.SOMETHING
```

مدیریت Configuration سخت می‌شود.

بهتر است Configuration مرکزی داشته باشیم.

---

## 7. نداشتن Validation

ممکن است برنامه با:

```env
PORT=abc
```

اجرا شود و خیلی دیرتر با خطای نامفهوم مواجه شویم.

Configuration را در ابتدای اجرای برنامه Validate کنید.

---

## 8. قرار دادن Secret واقعی در `.env.example`

اشتباه:

```env
JWT_SECRET=real-production-secret
```

در `.env.example`.

بهتر:

```env
JWT_SECRET=
```

---

## 9. تصور اینکه حذف `.env` از پروژه کافی است

اگر Secret قبلاً Commit شده باشد، حذف فایل لزوماً به معنی حذف Secret از Git History نیست.

در چنین شرایطی باید Secret افشاشده را تعویض کرد.

# نکات حرفه‌ای

## 1. Configuration را متمرکز کنید

به جای استفاده پراکنده از:

```js
process.env
```

یک Configuration Layer ایجاد کنید.

---

## 2. Configuration را Validate کنید

برای متغیرهای مهم فقط وجود مقدار کافی نیست.

نوع، فرمت و محدوده مقدار را نیز بررسی کنید.

---

## 3. برای Secretها Default نسازید

برای مثال:

```js
const jwtSecret = process.env.JWT_SECRET || "secret";
```

برای Production خطرناک است.

اگر Secret ضروری است، بهتر است برنامه بدون آن اجرا نشود:

```js
if (!process.env.JWT_SECRET) {
  throw new Error("JWT_SECRET is required");
}
```

---

## 4. Secretها را Log نکنید

اشتباه:

```js
console.log(process.env);
```

یا:

```js
console.log(process.env.JWT_SECRET);
```

چنین کاری می‌تواند Secret را وارد Logها کند.

---

## 5. Environmentهای مختلف را جدی بگیرید

Configuration مناسب برای:

```text
development
test
staging
production
```

ممکن است متفاوت باشد.

---

## 6. نام‌گذاری استاندارد داشته باشید

مثلاً:

```env
DATABASE_URL=
JWT_SECRET=
REDIS_URL=
PORT=
NODE_ENV=
```

نام‌های واضح باعث خوانایی بهتر می‌شوند.

---

## 7. Configuration را در Startup بررسی کنید

بهتر است برنامه در ابتدای Startup بفهمد Configuration مشکل دارد، نه بعد از دریافت اولین Request.

---

## 8. Secretها را Rotate کنید

اگر احتمال دادید Secretی افشا شده است، فقط حذف آن از کد کافی نیست.

باید Secret جدید ایجاد و Secret قبلی بی‌اعتبار شود.

---

## 9. `.env` را با Production یکی فرض نکنید

در Production ممکن است Environment Variableها توسط:

* Docker
* CI/CD
* Cloud Platform
* Container Orchestrator
* Secret Manager

در اختیار برنامه قرار بگیرند.

---

## 10. Configuration را بخشی از Architecture بدانید

در پروژه‌های بزرگ Environment Variables فقط چند خط Configuration نیستند.

Configuration باید:

```text
Load
Parse
Validate
Normalize
Expose
```

شود.

# مینی‌پروژه - Configuration Manager برای Node.js

در این مینی‌پروژه یک سیستم کوچک برای مدیریت Configuration یک برنامه Node.js می‌سازیم.

```js
dotenv.config();

const port = Number(process.env.PORT ?? 3000);

if (!Number.isInteger(port) || port < 1 || port > 65535) {
  throw new Error("PORT must be an integer between 1 and 65535");
}

const requiredVariables = [
  "DATABASE_URL",
  "JWT_SECRET",
];

for (const variable of requiredVariables) {
  if (!process.env[variable]) {
    throw new Error(`${variable} is required`);
  }
}

  nodeEnv: process.env.NODE_ENV ?? "development",
  port,
  appName: process.env.APP_NAME ?? "Node App",
  databaseUrl: process.env.DATABASE_URL,
  jwtSecret: process.env.JWT_SECRET,
};
```

# جمع‌بندی

Environment Variables یکی از مفاهیم مهم در توسعه برنامه‌های واقعی Node.js است.

در این فصل یاد گرفتیم که:

* Environment Variable چیست.
* `process.env` چگونه کار می‌کند.
* چگونه Environment Variable تعریف کنیم.
* فایل `.env` چیست.
* `dotenv` چگونه استفاده می‌شود.
* چرا `.env` نباید Commit شود.
* `.env.example` چه کاربردی دارد.
* Environmentهای مختلف چه تفاوتی دارند.
* `NODE_ENV` چیست.
* چرا مقادیر `process.env` را باید Type Convert کنیم.
* چگونه Boolean را از Environment Variable دریافت کنیم.
* چگونه مقدار پیش‌فرض تعیین کنیم.
* چگونه Configuration را Validate کنیم.
* چگونه Configuration مرکزی بسازیم.
* Secret چیست.
* چرا نباید Secret را داخل Source Code قرار دهیم.
* Environment Variables چه نقشی در Docker و CI/CD دارند.
* چگونه یک Configuration Manager ساده برای Node.js طراحی کنیم.

در پروژه‌های واقعی، Environment Variables پل ارتباطی بین **Source Code** و **محیط اجرای برنامه** هستند و یکی از پایه‌های مهم برای ساخت برنامه‌های قابل‌انتقال، امن و قابل‌استقرار محسوب می‌شوند.
