# فصل 45 - Inheritance

در فصل‌های قبل با **Class**، **Constructor** و **Prototype** آشنا شدیم.

اما اگر چندین Class داشته باشیم که ویژگی‌های مشترکی دارند، چه باید کرد؟

مثلاً:

* User
* Admin
* Customer
* Teacher
* Student

همه آن‌ها:

* نام دارند.
* سن دارند.
* ایمیل دارند.
* می‌توانند اطلاعات خود را نمایش دهند.

آیا باید این کدها را در تمام کلاس‌ها تکرار کنیم؟

قطعاً خیر.

برای حل این مشکل از **Inheritance** یا **وراثت** استفاده می‌کنیم.

---

# Inheritance چیست؟

Inheritance یعنی یک Class بتواند ویژگی‌ها و رفتارهای Class دیگری را به ارث ببرد.

به Class اصلی گفته می‌شود:

* Parent Class
* Base Class
* Super Class

و به Class جدید گفته می‌شود:

* Child Class
* Derived Class
* Sub Class

---

# مزایای Inheritance

استفاده از Inheritance باعث می‌شود:

* از تکرار کد جلوگیری شود.
* نگهداری پروژه آسان‌تر شود.
* توسعه پروژه سریع‌تر انجام شود.
* ساختار پروژه منظم‌تر باشد.
* کد خواناتر شود.

---

# اولین مثال

```js id="p1k9tr"
class Animal {

    eat() {
        console.log("Eating...");
    }

}

class Dog extends Animal {

}

const dog = new Dog();

dog.eat();
```

خروجی:

```txt id="j2m4qs"
Eating...
```

کلاس `Dog` متد `eat` را از `Animal` به ارث برده است.

# super

در کلاس فرزند، برای اجرای Constructor کلاس والد از `super()` استفاده می‌کنیم.

```js id="m4n8yb"
class Person {

    constructor(name) {
        this.name = name;
    }

}

class Teacher extends Person {

    constructor(name, lesson) {

        super(name);

        this.lesson = lesson;

    }

}

const teacher = new Teacher(
    "Sara",
    "Node.js"
);

console.log(teacher.name);
console.log(teacher.lesson);
```

---

# چرا super ضروری است؟

در کلاس فرزند، قبل از استفاده از `this` باید Constructor والد اجرا شود.

اشتباه:

```js id="f7q3dj"
class Person {

    constructor(name) {
        this.name = name;
    }

}

class Student extends Person {

    constructor(name) {

        this.name = name;

    }

}
```

این کد خطا ایجاد می‌کند.

روش صحیح:

```js id="n6w8tp"
class Student extends Person {

    constructor(name) {

        super(name);

    }

}
```

# ارث‌بری و Private Field

```js id="q4x7cb"
class Person {

    #name;

    constructor(name) {
        this.#name = name;
    }

    getName() {
        return this.#name;
    }

}

class Student extends Person {}

const student = new Student("Ali");

console.log(student.getName());
```

Private Field مستقیماً از بیرون یا کلاس فرزند قابل دسترسی نیست و باید از طریق متدهای عمومی (مانند Getter) استفاده شود.

# چه زمانی از Inheritance استفاده کنیم؟

مناسب:

* User ← Admin
* Animal ← Dog
* Vehicle ← Car
* Shape ← Circle

زیرا رابطه **"یک نوع از"** (is-a) وجود دارد.

مثلاً:

* Dog یک نوع Animal است.
* Car یک نوع Vehicle است.

---

# چه زمانی استفاده نکنیم؟

مثلاً:

```txt id="p9m1xf"
Car
Engine
```

خودرو **Engine نیست**.

بلکه:

```txt id="o6w4bn"
Car has Engine
```

در اینجا بهتر است از **Composition** استفاده شود، نه Inheritance.

---

# Composition چیست؟

در Composition به جای ارث‌بری، یک Object را داخل Object دیگر قرار می‌دهیم.

```js id="c8t2hy"
class Engine {

    start() {
        console.log("Engine Started");
    }

}

class Car {

    constructor() {
        this.engine = new Engine();
    }

    start() {
        this.engine.start();
    }

}

const car = new Car();

car.start();
```

گاهی Composition نسبت به Inheritance انعطاف‌پذیرتر است.

---

# تفاوت Inheritance و Composition

| Inheritance          | Composition          |
| -------------------- | -------------------- |
| رابطه is-a           | رابطه has-a          |
| استفاده از extends   | استفاده از Objectها  |
| مناسب ویژگی‌های مشترک | مناسب ترکیب قابلیت‌ها |
| وابستگی بیشتر        | انعطاف‌پذیری بیشتر    |

---

# اشتباهات رایج

## 1. استفاده از ارث‌بری بدون رابطه منطقی

اگر رابطه واقعی بین دو کلاس وجود ندارد، از `extends` استفاده نکنید.

---

## 2. فراموش کردن super()

در کلاس‌های فرزند، قبل از استفاده از `this` باید `super()` فراخوانی شود.

---

## 3. ایجاد زنجیره‌های بسیار طولانی

اشتباه:

```txt id="h3f7ra"
A

↓

B

↓

C

↓

D

↓

E

↓

F
```

هرچه زنجیره طولانی‌تر باشد، نگهداری کد سخت‌تر می‌شود.

---

## 4. Override کردن بدون دلیل

اگر رفتار والد مناسب است، نیازی به بازنویسی متد نیست.

---

## 5. شکستن اصل مسئولیت واحد

هر کلاس باید مسئولیت مشخصی داشته باشد، حتی اگر از کلاس دیگری ارث ببرد.

---

## 6. وابستگی بیش از حد به کلاس والد

اگر کلاس فرزند برای انجام هر کاری به جزئیات کلاس والد وابسته باشد، تغییر کلاس والد ممکن است باعث شکستن کدهای فرزند شود.

---

# نکات حرفه‌ای

* فقط زمانی از Inheritance استفاده کنید که رابطه "یک نوع از" وجود داشته باشد.
* برای اشتراک رفتارهای عمومی از کلاس والد استفاده کنید.
* کلاس‌های پایه را ساده و عمومی طراحی کنید.
* در صورت نیاز به ترکیب قابلیت‌ها، Composition را ترجیح دهید.
* از Override فقط زمانی استفاده کنید که واقعاً رفتار متفاوتی نیاز دارید.
* از زنجیره‌های عمیق ارث‌بری پرهیز کنید.
* قبل از طراحی کلاس‌ها، مسئولیت هر کلاس را مشخص کنید.
* در پروژه‌های بزرگ، کلاس‌های پایه مانند `BaseController` یا `BaseService` می‌توانند کدهای مشترک را در خود نگه دارند.

# جمع‌بندی

در این فصل یاد گرفتیم:

* Inheritance چیست.
* چگونه با `extends` از کلاس‌های دیگر ارث‌بری کنیم.
* از `super()` برای فراخوانی Constructor و متدهای کلاس والد استفاده کنیم.
* متدهای کلاس والد را Override کنیم.
* با `instanceof` رابطه بین Object و Class را بررسی کنیم.
* تفاوت Inheritance و Composition را بشناسیم.
* از Inheritance در پروژه‌های واقعی Node.js برای ساخت کلاس‌های پایه مانند Service، Controller و Repository استفاده کنیم.

وراثت یکی از مهم‌ترین مفاهیم برنامه‌نویسی شیءگرا است، اما باید با دقت از آن استفاده شود. هر زمان رابطه منطقی «یک نوع از» وجود داشت، Inheritance انتخاب مناسبی است؛ در غیر این صورت، Composition معمولاً انعطاف‌پذیری و نگهداری بهتری برای پروژه فراهم می‌کند.
