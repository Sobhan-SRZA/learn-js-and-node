# فصل 41 - Object Oriented Programming

در این فصل با یکی از مهم‌ترین شیوه‌های برنامه‌نویسی یعنی **برنامه‌نویسی شیءگرا** یا **OOP** آشنا می‌شویم.

در جاوااسکریپت و مخصوصاً در Node.js، OOP به ما کمک می‌کند کد را:

* منظم‌تر بنویسیم
* قابل‌استفاده‌مجدد کنیم
* بهتر نگهداری کنیم
* برای پروژه‌های واقعی حرفه‌ای‌تر طراحی کنیم

وقتی پروژه بزرگ می‌شود، نوشتن همه چیز به‌صورت تابعی و پراکنده می‌تواند کد را سخت‌خوان و شلوغ کند.
اما با OOP می‌توانیم داده‌ها و رفتارها را کنار هم قرار دهیم.

---

# OOP چیست؟

OOP یعنی **Data + Behavior**.

یعنی هر چیز را به شکل یک **شیء** در نظر می‌گیریم که:

* **ویژگی** دارد
* **رفتار** دارد

مثلاً یک کاربر در سایت:

* نام دارد
* ایمیل دارد
* رمز عبور دارد
* می‌تواند ثبت‌نام کند
* می‌تواند لاگین کند

پس کاربر را می‌توان به شکل یک Object مدل کرد.

---

# چرا OOP مهم است؟

OOP در پروژه‌های Node.js بسیار کاربردی است، چون:

* ساختار پروژه را بهتر می‌کند
* منطق برنامه را تمیزتر می‌کند
* برای مدل‌سازی Entityها عالی است
* توسعه پروژه را راحت‌تر می‌کند
* تیمی کار کردن را آسان‌تر می‌کند

مثال‌هایی از جاهایی که OOP زیاد استفاده می‌شود:

* User
* Product
* Cart
* Order
* Database Connection
* Logger
* Service Classes

---

# مفاهیم اصلی OOP

OOP معمولاً چهار مفهوم اصلی دارد:

1. **Encapsulation** — کپسوله‌سازی
2. **Abstraction** — انتزاع
3. **Inheritance** — وراثت
4. **Polymorphism** — چندریختی

در ادامه هرکدام را ساده و کاربردی یاد می‌گیریم.

---

# Object چیست؟

Object یک ساختار داده‌ای است که چندین property و method را کنار هم نگه می‌دارد.

مثال:

```js id="8b2a1f"
const user = {
    name: "Ali",
    age: 20,
    login() {
        console.log("User logged in");
    }
};

console.log(user.name);
user.login();
```

خروجی:

```txt id="2b19af"
Ali
User logged in
```

---

# Class چیست؟

در جاوااسکریپت، `class` قالبی است برای ساخت Objectهای مشابه.

یعنی به جای اینکه هر بار Object را دستی بنویسیم، یک الگو می‌سازیم و از روی آن شیء تولید می‌کنیم.

مثال:

```js id="0d91ae"
class User {
    constructor(name, age) {
        this.name = name;
        this.age = age;
    }

    login() {
        console.log(`${this.name} logged in`);
    }
}

const user1 = new User("Ali", 20);
const user2 = new User("Sara", 22);

console.log(user1.name);
user1.login();
```

خروجی:

```txt id="4d2b44"
Ali
Ali logged in
```

---

# constructor

`constructor` متدی است که هنگام ساخت شیء جدید از روی کلاس اجرا می‌شود.

کار آن مقداردهی اولیه است.

```js id="7d3ce9"
class Product {
    constructor(name, price) {
        this.name = name;
        this.price = price;
    }
}

const p1 = new Product("Laptop", 50000);

console.log(p1.name);
console.log(p1.price);
```

خروجی:

```txt id="f61c6a"
Laptop
50000
```

# this

`this` به شیء فعلی اشاره می‌کند.

در کلاس‌ها، `this` برای دسترسی به ویژگی‌ها و متدهای همان شیء استفاده می‌شود.

```js id="6f4a4a"
class Person {
    constructor(name) {
        this.name = name;
    }

    sayHello() {
        console.log(`Hello, ${this.name}`);
    }
}

const p = new Person("Reza");
p.sayHello();
```

خروجی:

```txt id="ce5d1b"
Hello, Reza
```

class Car {

    }

const car1 = new Car("BMW", "X5");

# Method چیست؟

Method یعنی تابعی که داخل class یا object قرار دارد.

```js id="f08b7b"
class MathTool {
    sum(a, b) {
        return a + b;
    }

const tool = new MathTool();

console.log(tool.sum(3, 5));
```

خروجی:

```txt id="2ef4f6"

```

# Encapsulation

Encapsulation یعنی داده‌ها و رفتارهای مرتبط را در یک واحد نگه داریم و دسترسی را کنترل کنیم.

در جاوااسکریپت می‌توانیم از ویژگی‌های private استفاده کنیم.

---

# Private Field

با `#` می‌توانیم فیلد خصوصی بسازیم.

```js id="d4d1b0"
class BankAccount {
    #balance;

    constructor(balance) {
        this.#balance = balance;
    }

    getBalance() {
        return this.#balance;
    }
}

const account = new BankAccount(1000);

console.log(account.getBalance());
```

خروجی:

```txt id="6d8e33"
1000
```

---

اگر بخواهیم مستقیم به آن دسترسی پیدا کنیم:

```js id="cdd9c8"
console.log(account.#balance);
```

این کار خطا می‌دهد، چون فیلد private است.

---

# Abstraction

Abstraction یعنی فقط بخش‌های مهم را نشان بدهیم و جزئیات غیرضروری را پنهان کنیم.

مثلاً کاربر با ماشین حساب کار می‌کند:

* عدد می‌دهد
* نتیجه می‌گیرد

اما لازم نیست بداند داخل آن چه اتفاقی می‌افتد.

در OOP این مفهوم کمک می‌کند کلاس‌ها تمیزتر و ساده‌تر باشند.

---

# Inheritance

Inheritance یعنی یک کلاس از کلاس دیگر ویژگی‌ها و رفتارها را به ارث ببرد.

این باعث کاهش تکرار کد می‌شود.

مثال:

```js id="76f52b"
class Animal {
    constructor(name) {
        this.name = name;
    }

    eat() {
        console.log(`${this.name} is eating`);
    }
}

class Dog extends Animal {
    bark() {
        console.log(`${this.name} is barking`);
    }
}

const dog = new Dog("Buddy");

dog.eat();
dog.bark();
```

خروجی:

```txt id="8c7f4f"
Buddy is eating
Buddy is barking
```

---

# super

وقتی کلاس فرزند می‌خواهد constructor کلاس والد را اجرا کند، از `super()` استفاده می‌کند.

```js id="4edb3b"
class Animal {
    constructor(name) {
        this.name = name;
    }
}

class Cat extends Animal {
    constructor(name, color) {
        super(name);
        this.color = color;
    }
}

const cat = new Cat("Kitty", "white");

console.log(cat.name);
console.log(cat.color);
```

خروجی:

```txt id="b5fbc2"
Kitty
white
```

---

# Overriding

وقتی کلاس فرزند متدی را با همان نام بازنویسی کند، به آن overriding می‌گوییم.

```js id="daebd2"
class Animal {
    sound() {
        console.log("Some sound");
    }
}

class Dog extends Animal {
    sound() {
        console.log("Bark");
    }
}

const dog = new Dog();
dog.sound();
```

خروجی:

```txt id="6fa37c"
Bark
```

# Polymorphism

Polymorphism یعنی یک متد یا رفتار در اشیای مختلف، خروجی متفاوتی داشته باشد.

مثال:

```js id="7f94a1"
class Bird {
    move() {
        console.log("Bird is flying");
    }
}

class Fish {
    move() {
        console.log("Fish is swimming");
    }
}

const bird = new Bird();
const fish = new Fish();

bird.move();
fish.move();
```

خروجی:

```txt id="1ea1f8"
Bird is flying
Fish is swimming
```

# Getter

Getter برای خواندن مقدار به شکل کنترل‌شده استفاده می‌شود.

```js id="b4b8d9"
class User {
    constructor(name) {
        this.name = name;
    }

    get upperName() {
        return this.name.toUpperCase();
    }
}

const user = new User("ali");

console.log(user.upperName);
```

خروجی:

```txt id="83df2b"
ALI
```

---

# Setter

Setter برای تنظیم مقدار به شکل کنترل‌شده استفاده می‌شود.

```js id="a91c7e"
class User {
    constructor(name) {
        this.name = name;
    }

    set updateName(newName) {
        this.name = newName;
    }
}

const user = new User("Ali");

user.updateName = "Reza";
console.log(user.name);
```

خروجی:

```txt id="0c6e42"
Reza
```

# Static Method

متدهای static متعلق به خود کلاس هستند، نه به شیء ساخته‌شده از آن.

```js id="e7f6f8"
class MathTool {
    static sum(a, b) {
        return a + b;
    }
}

console.log(MathTool.sum(2, 3));
```

خروجی:

```txt id="29c2c4"
5
```

# تفاوت Static و Non-Static

# OOP در Node.js چه کاربردی دارد؟

در پروژه‌های Node.js از OOP زیاد استفاده می‌شود برای:

* ساخت Serviceها
* مدل‌سازی User و Product
* ساخت Logger
* ساخت Class برای اتصال دیتابیس
* مدیریت Authentication
* طراحی معماری تمیز

مثلاً:

```js id="e4d4f9"
class UserService {
    createUser(name, email) {
        return {
            name,
            email
        };
    }
}

const service = new UserService();

console.log(service.createUser("Ali", "ali@test.com"));
```

---

# مثال کاربردی در Node.js

```js id="2f7ae1"
class Logger {
    log(message) {
        console.log(`[LOG] ${message}`);
    }

    error(message) {
        console.log(`[ERROR] ${message}`);
    }
}

const logger = new Logger();

logger.log("Server started");
logger.error("Something went wrong");
```

# ساختار کلاس در پروژه واقعی

```js id="f5c0ab"
class User {
    constructor(name, email) {
        this.name = name;
        this.email = email;
    }

    validate() {
        return this.email.includes("@");
    }
}
```

این کلاس می‌تواند در پروژه‌های واقعی برای اعتبارسنجی و مدیریت داده استفاده شود.

---

# اشتباهات رایج

## 1. استفاده بی‌دلیل از class

همه چیز نباید class باشد.
اگر یک تابع ساده کافی است، class اضافه ممکن است کد را پیچیده کند.

---

## 2. قرار دادن منطق زیاد داخل constructor

constructor باید فقط برای مقداردهی اولیه باشد، نه انجام کارهای سنگین.

---

## 3. استفاده اشتباه از this

اگر `this` را اشتباه استفاده کنید، به شیء موردنظر اشاره نمی‌کند.

---

## 4. ارث‌بری بدون نیاز

گاهی inheritance باعث پیچیدگی می‌شود.
اگر رابطه واقعی بین دو کلاس وجود ندارد، بهتر است از composition استفاده شود.

---

## 5. نادیده گرفتن encapsulation

اگر همه چیز public باشد، کنترل روی داده‌ها سخت‌تر می‌شود.

---

## 6. over-engineering

برای یک مسئله کوچک، ساختن چندین کلاس و لایه غیرضروری است.

---

# نکات حرفه‌ای

* همیشه قبل از نوشتن class فکر کنید آیا واقعاً OOP لازم است یا نه.
* برای Entityهای اصلی پروژه از class استفاده کنید.
* از encapsulation برای جلوگیری از دستکاری مستقیم داده‌ها استفاده کنید.
* متدهای مشترک را در class والد قرار دهید.
* برای رفتارهای ساده، تابع معمولی هم می‌تواند کافی باشد.
* در پروژه‌های Node.js، OOP را همراه با Module System استفاده کنید.
* کلاس‌ها را کوچک و مسئولیت‌محور نگه دارید.
* برای منطق‌های بزرگ، هر کلاس فقط یک وظیفه داشته باشد.
