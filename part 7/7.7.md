## فصل 47 - Encapsulation

### مقدمه

یکی از مهم‌ترین اصول برنامه‌نویسی شی‌گرا، **Encapsulation** یا **کپسوله‌سازی** است.
کپسوله‌سازی یعنی داده‌ها و رفتارهای مرتبط با آن‌ها را داخل یک واحد مشخص قرار دهیم و دسترسی مستقیم و بی‌نظم به آن‌ها را محدود کنیم.

در دنیای **JavaScript** و مخصوصاً در **Node.js**، کپسوله‌سازی فقط یک مفهوم تئوری نیست؛ بلکه در ساخت کلاس‌ها، ماژول‌ها، سرویس‌ها، مدل‌ها و ساختارهای تمیز و قابل‌نگهداری نقش خیلی مهمی دارد.
اگر بخواهیم نرم‌افزاری بنویسیم که:

* خطای کمتری داشته باشد
* نگهداری آن ساده‌تر باشد
* تغییر در آن دردسر کمتری ایجاد کند
* امنیت و کنترل بیشتری روی داده‌ها داشته باشیم

باید کپسوله‌سازی را درست یاد بگیریم و در پروژه‌هایمان به‌کار ببریم.

---

## 47.1 - Encapsulation چیست؟

کپسوله‌سازی یعنی:

* داده‌های یک آبجکت یا کلاس را از بیرون پنهان کنیم
* فقط از راه‌های مشخص و کنترل‌شده به آن داده‌ها دسترسی بدهیم
* منطق تغییر داده‌ها را داخل همان کلاس نگه داریم

به زبان ساده:

> به‌جای اینکه هر بخش از برنامه مستقیم به داده‌ها دست بزند، یک درگاه امن و مشخص برای کار با آن داده‌ها می‌سازیم.

### مثال ساده

فرض کن یک حساب بانکی داریم.
اگر موجودی حساب را هر جایی از برنامه بتوانیم مستقیم تغییر بدهیم، احتمال خطا خیلی بالا می‌رود:

```js
const account = {
  balance: 1000
};

account.balance = -500;
```

این کار از نظر منطقی اشتباه است، چون موجودی نمی‌تواند منفی شود.
پس بهتر است موجودی را مستقیم در دسترس نگذاریم و فقط از طریق متدهای کنترل‌شده مثل `deposit` و `withdraw` تغییرش دهیم.

---

## 47.2 - چرا Encapsulation مهم است؟

کپسوله‌سازی چند مزیت مهم دارد:

### 1) جلوگیری از تغییرات اشتباه

وقتی داده‌ها مستقیم در دسترس نباشند، احتمال خراب شدن وضعیت داخلی شیء کمتر می‌شود.

### 2) کنترل روی ورودی‌ها

می‌توانیم قبل از تغییر داده، اعتبارسنجی انجام دهیم.

### 3) ساده‌تر شدن نگهداری کد

اگر منطق تغییر داده‌ها فقط یک‌جا باشد، در آینده اصلاح آن راحت‌تر می‌شود.

### 4) کاهش وابستگی

بخش‌های مختلف برنامه کمتر به جزئیات داخلی هم وابسته می‌شوند.

### 5) خوانایی بهتر

از بیرون فقط رفتارهای مهم دیده می‌شوند، نه تمام جزئیات پیاده‌سازی.

## 47.3 - کپسوله‌سازی در JavaScript

در JavaScript، کپسوله‌سازی را می‌توان با روش‌های مختلفی پیاده کرد:

* استفاده از **Closure**
* استفاده از **Private Fields** در کلاس‌ها
* استفاده از **Symbol**
* استفاده از **ماژول‌ها** و مخفی کردن جزئیات داخلی
* استفاده از **getter** و **setter**

در Node.js، این مفهوم خیلی کاربردی است؛ چون معمولاً با سرویس‌ها، مدل‌ها و ماژول‌هایی کار می‌کنیم که نباید همه چیزشان مستقیم از بیرون تغییر کند.

---

## 47.4 - Encapsulation با کلاس‌ها

### مثال اول: بدون کپسوله‌سازی

```js
class BankAccount {
  constructor(owner, balance) {
    this.owner = owner;
    this.balance = balance;
  }
}

const account = new BankAccount("Ali", 1000);
account.balance = -9999;
console.log(account.balance); // -9999
```

در این مثال، هر کسی می‌تواند موجودی را مستقیم تغییر بدهد.
این خطرناک است.

---

### مثال دوم: با کپسوله‌سازی

```js
class BankAccount {
  constructor(owner, balance) {
    this.owner = owner;
    this._balance = balance;
  }

  deposit(amount) {
    if (amount <= 0) {
      throw new Error("مبلغ واریز باید بیشتر از صفر باشد.");
    }
    this._balance += amount;
  }

  withdraw(amount) {
    if (amount <= 0) {
      throw new Error("مبلغ برداشت باید بیشتر از صفر باشد.");
    }

    if (amount > this._balance) {
      throw new Error("موجودی کافی نیست.");
    }

    this._balance -= amount;
  }

  getBalance() {
    return this._balance;
  }
}

const account = new BankAccount("Ali", 1000);

account.deposit(500);
account.withdraw(200);

console.log(account.getBalance()); // 1300
```

در اینجا موجودی فقط از طریق متدهای مشخص تغییر می‌کند.
این یعنی کنترل بیشتر و خطای کمتر.

## 47.5 - Private Fields در JavaScript

در نسخه‌های جدید JavaScript، می‌توان از فیلدهای خصوصی استفاده کرد.
این فیلدها با `#` شروع می‌شوند و از بیرون کلاس قابل دسترسی نیستند.

### مثال

```js
class BankAccount {
  #balance;

  constructor(owner, balance) {
    this.owner = owner;
    this.#balance = balance;
  }

  deposit(amount) {
    if (amount <= 0) {
      throw new Error("مبلغ واریز باید بیشتر از صفر باشد.");
    }
    this.#balance += amount;
  }

  withdraw(amount) {
    if (amount <= 0) {
      throw new Error("مبلغ برداشت باید بیشتر از صفر باشد.");
    }

    if (amount > this.#balance) {
      throw new Error("موجودی کافی نیست.");
    }

    this.#balance -= amount;
  }

  getBalance() {
    return this.#balance;
  }
}

const account = new BankAccount("Sara", 2000);
console.log(account.getBalance()); // 2000
```

### نکته

این خط خطا می‌دهد:

```js
console.log(account.#balance);
```

چون `#balance` خصوصی است و فقط داخل همان کلاس قابل استفاده است.

## 47.6 - Getter و Setter

گاهی لازم است مقدار یک property از بیرون خوانده شود، اما تغییر آن تحت کنترل باشد.
در این حالت از `getter` و `setter` استفاده می‌کنیم.

### مثال

```js
class Product {
  constructor(name, price) {
    this.name = name;
    this._price = price;
  }

  get price() {
    return this._price;
  }

  set price(value) {
    if (value <= 0) {
      throw new Error("قیمت باید بیشتر از صفر باشد.");
    }
    this._price = value;
  }
}

const p = new Product("Laptop", 3000);

console.log(p.price); // 3000
p.price = 3500;
console.log(p.price); // 3500
```

اینجا خواندن قیمت ساده است، اما تغییر قیمت کنترل‌شده انجام می‌شود.

## 47.7 - Encapsulation در پروژه‌های Node.js

در Node.js معمولاً این مفهوم را در جاهای مختلف می‌بینیم:

### 1) مدل‌ها

مثلاً در یک پروژه فروشگاهی، اطلاعات محصول نباید بدون کنترل تغییر کند.

### 2) سرویس‌ها

منطق کسب‌وکار بهتر است داخل سرویس‌ها مخفی شود و فقط متدهای مشخص در اختیار بقیه بخش‌ها قرار بگیرد.

### 3) ماژول‌ها

در Node.js هر فایل می‌تواند یک بخش مستقل از برنامه باشد.
این خودش نوعی جداسازی و کپسوله‌سازی در سطح ماژول است.

### 4) کلاس‌های کمکی

مثلاً کلاس مربوط به اعتبارسنجی، محاسبه مالیات، یا مدیریت فایل.

## 47.8 - Encapsulation با ماژول‌ها

در Node.js، ماژول‌ها کمک می‌کنند جزئیات داخلی را مخفی کنیم.

### مثال

**mathService.js**

```js
function add(a, b) {
  return a + b;
}

function multiply(a, b) {
  return a * b;
}

module.exports = {
  add,
  multiply
};
```

**app.js**

```js
const mathService = require("./mathService");

console.log(mathService.add(2, 3)); // 5
```

در این حالت فقط چیزهایی که export شده‌اند از بیرون قابل استفاده‌اند.
توابع داخلی و جزئیات غیرضروری مخفی می‌مانند.

## 47.9 - Encapsulation و اصول طراحی تمیز

کپسوله‌سازی فقط برای پنهان کردن data نیست؛ بلکه کمک می‌کند طراحی کد تمیزتر باشد.

### چند اصل مهم:

* هر کلاس فقط یک مسئولیت مشخص داشته باشد
* داده‌ها مستقیم از بیرون تغییر نکنند
* منطق تغییر وضعیت در همان کلاس باقی بماند
* رابط عمومی کلاس کوچک و واضح باشد

## 47.10 - مثال کاربردی در Node.js

فرض کن می‌خواهیم یک سیستم ساده مدیریت کاربر بسازیم.

```js
class User {
  #password;

  constructor(username, password) {
    this.username = username;
    this.#password = password;
  }

  changePassword(oldPassword, newPassword) {
    if (oldPassword !== this.#password) {
      throw new Error("رمز عبور فعلی اشتباه است.");
    }

    if (newPassword.length < 8) {
      throw new Error("رمز عبور جدید باید حداقل 8 کاراکتر باشد.");
    }

    this.#password = newPassword;
  }

  checkPassword(password) {
    return password === this.#password;
  }
}

const user = new User("sobhan", "12345678");

console.log(user.checkPassword("12345678")); // true
user.changePassword("12345678", "newPass123");
```

در اینجا رمز عبور مستقیم در دسترس نیست و تغییر آن فقط با قوانین مشخص انجام می‌شود.

## 47.11 - اشتباهات رایج

### 1) استفاده مستقیم از propertyها

خیلی‌ها همه چیز را public می‌گذارند و بعداً درگیر خطاهای غیرمنتظره می‌شوند.

### 2) استفاده اشتباه از underscore

قرار دادن `_balance` به‌تنهایی خصوصی واقعی نیست؛ فقط یک قرارداد است.

### 3) نداشتن validation

اگر ورودی‌ها را بررسی نکنیم، کلاس به‌راحتی خراب می‌شود.

### 4) مخفی‌سازی بیش از حد

اگر همه چیز را پنهان کنیم و هیچ API واضحی ندهیم، استفاده از کلاس سخت می‌شود.

### 5) گذاشتن منطق زیاد در بیرون از کلاس

اگر تغییر وضعیت در جاهای مختلف برنامه پخش شود، کنترل سیستم از دست می‌رود.

## 47.12 - نکات حرفه‌ای

### 1) از private field برای داده‌های حساس استفاده کن

مثل رمز عبور، موجودی، توکن، یا وضعیت داخلی مهم.

### 2) برای تغییر داده‌ها متدهای مشخص بساز

مثل `deposit`، `withdraw`، `changePassword`.

### 3) API کلاس را کوچک نگه دار

هرچه رابط عمومی ساده‌تر باشد، استفاده از آن بهتر است.

### 4) وضعیت داخلی را با منطق اعتبارسنجی محافظت کن

قبل از هر تغییر، ورودی را بررسی کن.

### 5) در Node.js منطق کسب‌وکار را از routeها جدا کن

route فقط درخواست را دریافت کند، اما تصمیم اصلی داخل سرویس یا کلاس باشد.

### 6) از getter و setter فقط وقتی استفاده کن که لازم است

استفاده بی‌دلیل از setterها می‌تواند کد را پیچیده کند.

## 47.14 - پاسخ تشریحی

### پاسخ تمرین 1

```js
class Student {
  #grade;

  constructor(name, grade) {
    this.name = name;
    this.#grade = grade;
  }

  increaseGrade(amount) {
    if (amount < 0) {
      throw new Error("مقدار افزایش نمی‌تواند منفی باشد.");
    }
    this.#grade += amount;
  }

  getGrade() {
    return this.#grade;
  }
}

const student = new Student("Ali", 15);
student.increaseGrade(3);
console.log(student.getGrade()); // 18
```

**توضیح:**
نمره داخل فیلد خصوصی نگهداری شده و فقط از طریق متد کنترل‌شده تغییر می‌کند.

---

### پاسخ تمرین 2

```js
class ShoppingCart {
  #items;

  constructor() {
    this.#items = [];
  }

  addItem(name, price) {
    if (price <= 0) {
      throw new Error("قیمت باید بیشتر از صفر باشد.");
    }
    this.#items.push({ name, price });
  }

  removeItem(name) {
    this.#items = this.#items.filter(item => item.name !== name);
  }

  getTotalPrice() {
    return this.#items.reduce((total, item) => total + item.price, 0);
  }

  getItems() {
    return [...this.#items];
  }
}

const cart = new ShoppingCart();
cart.addItem("Book", 100);
cart.addItem("Pen", 20);
console.log(cart.getTotalPrice()); // 120
```

**توضیح:**
آرایه آیتم‌ها خصوصی است و از بیرون مستقیم تغییر داده نمی‌شود.
تابع `getItems` هم یک کپی برمی‌گرداند تا آرایه اصلی آسیب نبیند.

---

### پاسخ تمرین 3

```js
class Counter {
  #value;

  constructor(initialValue = 0) {
    this.#value = initialValue;
  }

  increment() {
    this.#value++;
  }

  decrement() {
    if (this.#value === 0) {
      throw new Error("مقدار نمی‌تواند کمتر از صفر شود.");
    }
    this.#value--;
  }

  getValue() {
    return this.#value;
  }
}

const counter = new Counter();
counter.increment();
counter.increment();
console.log(counter.getValue()); // 2
```

**توضیح:**
مقدار فقط از راه متدهای کلاس تغییر می‌کند و هیچ تغییری مستقیم روی آن انجام نمی‌شود.

### پاسخ تمرین 4

```js
class PasswordManager {
  #password;

  constructor(password) {
    if (password.length < 8) {
      throw new Error("رمز عبور باید حداقل 8 کاراکتر باشد.");
    }
    this.#password = password;
  }

  changePassword(oldPassword, newPassword) {
    if (oldPassword !== this.#password) {
      throw new Error("رمز فعلی اشتباه است.");
    }

    if (newPassword.length < 8) {
      throw new Error("رمز جدید باید حداقل 8 کاراکتر باشد.");
    }

    this.#password = newPassword;
  }

  verifyPassword(password) {
    return password === this.#password;
  }
}

const manager = new PasswordManager("12345678");
console.log(manager.verifyPassword("12345678")); // true
manager.changePassword("12345678", "newPassword123");
```

**توضیح:**
رمز عبور نه‌تنها خصوصی است، بلکه تغییر آن هم با اعتبارسنجی انجام می‌شود.

## 47.15 - مینی‌پروژه

### Mini Project: User Account Manager

در این مینی‌پروژه یک سیستم ساده مدیریت حساب کاربری می‌سازیم که در آن:

* نام کاربر ذخیره می‌شود
* رمز عبور خصوصی است
* امکان تغییر رمز وجود دارد
* امکان فعال/غیرفعال کردن حساب وجود دارد
* وضعیت حساب از بیرون مستقیم تغییر نمی‌کند

### نمونه پیاده‌سازی

```js
class UserAccount {
  #password;
  #isActive;

  constructor(username, password) {
    if (password.length < 8) {
      throw new Error("رمز عبور باید حداقل 8 کاراکتر باشد.");
    }

    this.username = username;
    this.#password = password;
    this.#isActive = true;
  }

  changePassword(oldPassword, newPassword) {
    if (!this.#isActive) {
      throw new Error("حساب غیرفعال است.");
    }

    if (oldPassword !== this.#password) {
      throw new Error("رمز فعلی اشتباه است.");
    }

    if (newPassword.length < 8) {
      throw new Error("رمز جدید باید حداقل 8 کاراکتر باشد.");
    }

    this.#password = newPassword;
  }

  deactivate() {
    this.#isActive = false;
  }

  activate() {
    this.#isActive = true;
  }

  checkPassword(password) {
    return this.#isActive && password === this.#password;
  }

  getStatus() {
    return this.#isActive ? "active" : "inactive";
  }
}

const user = new UserAccount("sobhan", "12345678");

console.log(user.getStatus()); // active
console.log(user.checkPassword("12345678")); // true

user.changePassword("12345678", "newPass123");
user.deactivate();

console.log(user.getStatus()); // inactive
```

### هدف این پروژه

این پروژه به تو یاد می‌دهد چگونه:

* داده‌های حساس را مخفی کنی
* وضعیت داخلی را کنترل کنی
* منطق مهم را داخل کلاس نگه داری
* از تغییرات مستقیم و خطرناک جلوگیری کنی

### ایده برای توسعه بیشتر

* اضافه کردن `login`
* اضافه کردن `logout`
* ثبت تاریخچه تغییر رمز
* محدود کردن تعداد تلاش برای ورود
* ذخیره‌سازی اطلاعات در فایل یا دیتابیس

* قابل‌فهم‌تر باشد
* قابل‌توسعه‌تر باشد
* و در پروژه‌های واقعی کمتر دچار خطا شود

در فصل‌های بعدی، این مفهوم را در کنار سایر اصول شی‌گرایی و معماری تمیز بیشتر به‌کار خواهیم برد.
