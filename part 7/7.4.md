# فصل 44 - Constructor

در فصل قبل با **Class** آشنا شدیم و دیدیم که چگونه می‌توان از روی یک کلاس، Objectهای مختلف ایجاد کرد.

اما یک سؤال مهم وجود دارد:

**وقتی با `new` یک Object می‌سازیم، چگونه مقدارهای اولیه به آن اختصاص داده می‌شوند؟**

پاسخ این سؤال **Constructor** است.

Constructor یکی از مهم‌ترین بخش‌های برنامه‌نویسی شیءگرا در جاوااسکریپت است و تقریباً در تمام پروژه‌های Node.js از آن استفاده می‌شود.

---

# Constructor چیست؟

Constructor یک متد ویژه است که هنگام ساخت یک Object جدید، به صورت خودکار اجرا می‌شود.

کار اصلی آن:

* مقداردهی اولیه Propertyها
* آماده‌سازی Object
* انجام تنظیمات اولیه

---

# اولین Constructor

```js id="k8a2pm"
class User {

    constructor() {
        console.log("User Created");
    }

}

const user = new User();
```

خروجی:

```txt id="q1z8ec"
User Created
```

به محض ساخت Object، Constructor اجرا شد.

---

# مقداردهی اولیه

```js id="x4c9jt"
class User {

    constructor(name, age) {

        this.name = name;
        this.age = age;

    }

}

const user = new User("Ali", 20);

console.log(user);
```

خروجی:

```txt id="n7b3la"
User { name: 'Ali', age: 20 }
```

# Constructor در Inheritance


# Constructor و تولید شناسه

```js id="l2f7mv"
class User {

    constructor(name) {

        this.id = Date.now();
        this.name = name;

    }

}

const user = new User("Ali");

console.log(user.id);
```

> **نکته:** `Date.now()` فقط برای آموزش مناسب است. در پروژه‌های واقعی معمولاً از شناسه‌های یکتا مانند UUID یا شناسه‌های تولیدشده توسط پایگاه داده استفاده می‌شود.

# Constructor Function

قبل از معرفی Classها، از Constructor Function استفاده می‌شد.

```js id="s1k9qb"
function User(name) {

    this.name = name;

}

const user = new User("Ali");

console.log(user.name);
```

در پشت صحنه، Class نیز از همین مفهوم استفاده می‌کند.

# Constructor در پروژه‌های Node.js

در پروژه‌های واقعی معمولاً Constructor برای:

* مقداردهی Serviceها
* اتصال به Database
* دریافت تنظیمات
* ذخیره وابستگی‌ها
* مقداردهی Logger

استفاده می‌شود.

مثال:

```js id="c5m2ne"
class UserService {

    constructor(database) {

        this.database = database;

    }

}
```

---

# Dependency Injection ساده

```js id="d7x9qa"
class Logger {

    info(message) {
        console.log(message);
    }

}

class UserService {

    constructor(logger) {

        this.logger = logger;

    }

    createUser() {
        this.logger.info("User Created");
    }

}

const logger = new Logger();

const service = new UserService(logger);

service.createUser();
```

این روش باعث می‌شود کلاس‌ها وابستگی‌های خود را از بیرون دریافت کنند و تست‌پذیرتر باشند.

# اشتباهات رایج

## 1. فراموش کردن new

```js id="j4h8cp"
const user = User("Ali");
```

برای Class همیشه باید از `new` استفاده شود.

---

## 2. استفاده از this قبل از super

در کلاس‌های فرزند ابتدا باید `super()` فراخوانی شود.

---

## 3. انجام عملیات سنگین داخل Constructor

Constructor باید سریع اجرا شود.

عملیات سنگین مانند:

* خواندن فایل
* درخواست HTTP
* Query پایگاه داده

بهتر است داخل متدهای جداگانه انجام شوند.

---

## 4. قرار دادن منطق زیاد داخل Constructor

Constructor فقط برای مقداردهی اولیه است.

---

## 5. نداشتن اعتبارسنجی

اگر ورودی‌ها بررسی نشوند، Objectهای نامعتبر ساخته می‌شوند.

---

## 6. استفاده از پارامترهای زیاد

اگر Constructor بیش از ۵ یا ۶ پارامتر دارد، بهتر است از یک Object به عنوان ورودی استفاده کنید.

---

# نکات حرفه‌ای

* Constructor را کوتاه و ساده نگه دارید.
* برای ورودی‌های زیاد از Destructuring استفاده کنید.
* اعتبارسنجی داده‌ها را فراموش نکنید.
* عملیات Async را داخل Constructor انجام ندهید.
* وابستگی‌ها را از بیرون دریافت کنید (Dependency Injection).
* برای مقدارهای اختیاری از Default Parameter استفاده کنید.
* فقط داده‌های ضروری را داخل Constructor مقداردهی کنید.
* اگر کلاس پیچیده شد، مسئولیت آن را به چند کلاس کوچک‌تر تقسیم کنید.
