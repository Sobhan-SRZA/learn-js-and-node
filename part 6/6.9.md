# فصل 39 - Error Handling

تا اینجا یاد گرفتیم که چگونه برنامه بنویسیم، توابع ایجاد کنیم، با فایل‌ها کار کنیم و عملیات Async انجام دهیم.

اما یک سوال مهم وجود دارد:

**اگر برنامه با خطا مواجه شود چه اتفاقی می‌افتد؟**

اگر خطا را مدیریت نکنیم، ممکن است:

* برنامه به طور کامل متوقف شود.
* اطلاعات ناقص ذخیره شوند.
* کاربر پیام مناسبی دریافت نکند.
* سرور Crash کند.

به همین دلیل جاوااسکریپت مکانیزمی به نام **Error Handling** یا **مدیریت خطا** دارد.

---

## چرا Error Handling مهم است؟

فرض کنید می‌خواهید یک فایل را بخوانید.

```js
const fs = require("fs");

const data = fs.readFileSync("users.json");
```

اگر فایل وجود نداشته باشد:

```
Error: ENOENT: no such file or directory
```

و برنامه متوقف می‌شود.

اما اگر خطا را مدیریت کنیم:

```js
try {
    const data = fs.readFileSync("users.json");
} catch (err) {
    console.log("فایل پیدا نشد.");
}
```

برنامه متوقف نمی‌شود.

---

# انواع خطاها

به طور کلی خطاها به دو دسته تقسیم می‌شوند.

## Syntax Error

اشتباه در نوشتن کد

```js
console.log("Hello"
```

```
SyntaxError
```

---

## Runtime Error

کد درست نوشته شده اما هنگام اجرا خطا رخ داده است.

```js
const user = null;

console.log(user.name);
```

```
TypeError
```

---

## Logical Error

برنامه اجرا می‌شود ولی نتیجه اشتباه است.

```js
function sum(a, b) {
    return a - b;
}
```

هیچ خطایی رخ نمی‌دهد اما منطق اشتباه است.

---

# try

کدهایی که احتمال خطا دارند داخل try قرار می‌گیرند.

ساختار:

```js
try {

}
```

مثال:

```js
try {
    console.log("شروع");

    const user = null;

    console.log(user.name);

    console.log("پایان");
}
```

خروجی:

```
شروع
```

بعد از خطا اجرای try متوقف می‌شود.

---

# catch

اگر داخل try خطایی رخ دهد، کنترل برنامه وارد catch می‌شود.

ساختار:

```js
try {

} catch (error) {

}
```

مثال:

```js
try {
    const user = null;

    console.log(user.name);

} catch (error) {
    console.log("خطایی رخ داد.");
}
```

خروجی:

```
خطایی رخ داد.
```

# finally

کد داخل finally چه خطا رخ دهد و چه رخ ندهد همیشه اجرا می‌شود.

ساختار:

```js

}
```

مثال:


# throw

گاهی خودمان می‌خواهیم خطا ایجاد کنیم.

برای این کار از throw استفاده می‌کنیم.

```js
throw "Error";
```

اما بهتر است Error واقعی پرتاب کنیم.

```js
throw new Error("Something went wrong");
```

---

مثال:

```js
const age = -5;

if (age < 0) {
    throw new Error("Age cannot be negative");
}
```

خروجی:

```
Error: Age cannot be negative
```

---

# مدیریت throw

```js
try {

    const age = -5;

    if (age < 0) {
        throw new Error("سن معتبر نیست.");
    }

} catch (error) {
    console.log(error.message);
}
```

خروجی:

```
سن معتبر نیست.
```

# اعتبارسنجی ورودی

```js
function divide(a, b) {

    if (b === 0) {
        throw new Error("تقسیم بر صفر مجاز نیست.");
    }

    return a / b;
}

try {

    console.log(divide(10, 2));

    console.log(divide(10, 0));

} catch (error) {
    console.log(error.message);
}
```

```

تقسیم بر صفر مجاز نیست.
```

# Re-throw

گاهی می‌خواهیم بعد از انجام کاری، دوباره خطا را به لایه بالاتر منتقل کنیم.

```js
try {

    throw new Error("Database Error");

} catch (error) {

    console.log("Log:", error.message);

    throw error;
}
```

مناسب برای:

# چه زمانی استفاده نکنیم؟

اشتباه:

```js
try {

    const result = 5 + 10;

} catch {}
```

عملیات ساده معمولاً نیازی به `try...catch` ندارند و استفاده بی‌مورد از آن باعث کاهش خوانایی کد می‌شود.

---

# بهترین روش مدیریت خطا

```js
function login(username) {

    if (!username) {
        throw new Error("Username Required");
    }

    return true;
}

try {

    login("");

} catch (error) {

    console.error(error.message);
}
```

---

# اشتباهات رایج

## 1. خالی گذاشتن catch

```js
try {
    riskyOperation();
} catch {}
```

این کار باعث می‌شود خطاها مخفی شوند و پیدا کردن علت مشکل بسیار سخت شود.

---

## 2. استفاده از throw برای رشته

```js
throw "Error";
```

بهتر است همیشه از شیء `Error` استفاده کنید.

```js
throw new Error("Error");
```

---

## 3. قرار دادن کل برنامه داخل یک try

```js
try {
    // هزاران خط کد
} catch (error) {}
```

بهتر است فقط بخش‌هایی که احتمال خطا دارند داخل `try` قرار بگیرند.

---

## 4. نادیده گرفتن finally

اگر منابعی مانند فایل، اتصال دیتابیس یا Socket باز کرده‌اید، از `finally` برای آزادسازی آن‌ها استفاده کنید.

---

## 5. نمایش مستقیم خطا به کاربر

```js
console.log(error.stack);
```

در محیط Production بهتر است جزئیات فنی خطا به کاربر نمایش داده نشود و فقط پیام مناسبی نمایش داده شود.

---

# نکات حرفه‌ای

* همیشه از `throw new Error(...)` به جای `throw "..."` استفاده کنید.
* پیام خطا باید واضح، کوتاه و قابل فهم باشد.
* برای اعتبارسنجی ورودی‌ها از `throw` استفاده کنید.
* در برنامه‌های Node.js خطاها را لاگ کنید تا بعداً قابل بررسی باشند.
* برای عملیات Async از `try...catch` همراه `await` استفاده کنید.
* از `finally` برای آزادسازی منابع استفاده کنید.
* تا حد امکان خطاها را در نزدیک‌ترین محل ممکن مدیریت کنید.
* در پروژه‌های بزرگ، ایجاد کلاس‌های خطای سفارشی (Custom Error) باعث خوانایی بهتر کد می‌شود.

# مینی‌پروژه

## مینی‌پروژه ۱: Safe Calculator

یک ماشین‌حساب ساده بسازید که:

* جمع
* تفریق
* ضرب
* تقسیم

را انجام دهد و هنگام تقسیم بر صفر با `throw` خطا ایجاد کرده و با `try...catch` آن را مدیریت کند.

---

## مینی‌پروژه ۲: JSON Validator

برنامه‌ای بنویسید که:

* یک رشته JSON دریافت کند.
* با `JSON.parse` آن را بررسی کند.
* در صورت معتبر بودن، داده را نمایش دهد.
* در غیر این صورت پیام مناسبی چاپ کند.

---

## مینی‌پروژه ۳: User Registration Validator

برنامه‌ای بنویسید که اطلاعات کاربر را بررسی کند.

شرایط:

* نام کاربری خالی نباشد.
* رمز عبور حداقل ۸ کاراکتر باشد.
* سن منفی نباشد.
* ایمیل شامل `@` باشد.

در صورت نقض هر شرط، با `throw new Error()` خطای مناسب ایجاد کنید و با `try...catch` آن را مدیریت کنید.

---

## مینی‌پروژه ۴: File Reader Wrapper (Node.js)

تابعی بنویسید که یک فایل را بخواند و:

* اگر فایل وجود داشت، محتوای آن را نمایش دهد.
* اگر فایل پیدا نشد، پیام خطای مناسبی چاپ کند.
* در `finally` پیامی مانند `"پایان عملیات خواندن فایل"` را نمایش دهد.

---

## جمع‌بندی

در این فصل با مهم‌ترین ابزارهای مدیریت خطا در جاوااسکریپت آشنا شدید:

* `try` برای اجرای امن کدهای حساس
* `catch` برای دریافت و مدیریت خطاها
* `finally` برای اجرای کدهای پاک‌سازی، چه خطا رخ دهد و چه ندهد
* `throw` برای ایجاد و پرتاب خطاهای سفارشی

مدیریت صحیح خطا یکی از مهم‌ترین مهارت‌ها در توسعه نرم‌افزار است. استفاده درست از این مفاهیم باعث می‌شود برنامه‌های Node.js پایدارتر، قابل نگهداری‌تر و حرفه‌ای‌تر باشند.
