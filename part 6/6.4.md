# فصل ۳۴ - Garbage Collection (مدیریت خودکار حافظه)

## مقدمه

یکی از ویژگی‌های مهم جاوااسکریپت این است که **برنامه‌نویس معمولاً نیازی ندارد حافظه را به صورت دستی آزاد کند.**

در زبان‌هایی مانند ++C یا C، برنامه‌نویس باید خودش حافظه را مدیریت کند و در صورت فراموشی، برنامه با مشکل **Memory Leak** مواجه می‌شود.

اما در جاوااسکریپت و Node.js این مسئولیت بر عهده موتور جاوااسکریپت است.

بخشی از موتور که این کار را انجام می‌دهد **Garbage Collector (GC)** نام دارد.

وظیفه Garbage Collector این است که:

* حافظه‌های بلااستفاده را پیدا کند.
* آن‌ها را از حافظه حذف کند.
* فضای آزاد را دوباره در اختیار برنامه قرار دهد.
* از مصرف بی‌دلیل حافظه جلوگیری کند.

در این فصل یاد می‌گیریم Garbage Collection چگونه کار می‌کند، چه زمانی حافظه آزاد می‌شود و چگونه از ایجاد Memory Leak جلوگیری کنیم.

---

# ۳۴.۱ - Garbage Collection چیست؟

Garbage Collection فرآیندی است که طی آن موتور جاوااسکریپت اشیاء و داده‌هایی را که دیگر مورد استفاده برنامه نیستند، از حافظه حذف می‌کند.

به این داده‌های بلااستفاده **Garbage** گفته می‌شود.

هدف اصلی:

* کاهش مصرف حافظه
* جلوگیری از Memory Leak
* افزایش پایداری برنامه

---

# ۳۴.۲ - چرا به Garbage Collector نیاز داریم؟

فرض کنید برنامه‌ای هزاران Object ایجاد می‌کند.

```js
const user = {
  name: "Ali"
};
```

اگر این Objectها هیچ‌وقت حذف نشوند:

* حافظه پر می‌شود.
* سرعت برنامه کاهش پیدا می‌کند.
* احتمال Crash شدن برنامه افزایش می‌یابد.

Garbage Collector این مشکل را برطرف می‌کند.

---

# ۳۴.۳ - Garbage چیست؟

Garbage یعنی داده‌ای که دیگر هیچ بخشی از برنامه به آن نیاز ندارد.

مثال:

```js
let user = {
  name: "Sara"
};

user = null;
```

بعد از اجرای خط دوم:

شیء قبلی دیگر هیچ Reference فعالی ندارد.

پس به یک Garbage تبدیل شده است.

---

# ۳۴.۴ - مفهوم Reachability

مهم‌ترین اصل Garbage Collection مفهوم **Reachability** یا «قابل دسترس بودن» است.

یک شیء زمانی زنده محسوب می‌شود که بتوان از طریق یکی از مسیرهای زیر به آن رسید:

* متغیرهای سراسری
* متغیرهای محلی
* پارامترهای توابع
* Closureها
* زنجیره Referenceها

اگر هیچ راهی برای رسیدن به یک شیء وجود نداشته باشد، آن شیء Garbage محسوب می‌شود.

---

# ۳۴.۵ - Root Objects

Garbage Collector بررسی را از مجموعه‌ای از اشیاء به نام **Root Objects** شروع می‌کند.

نمونه‌هایی از Rootها:

* Global Object
* متغیرهای فعال
* پارامترهای توابع
* Execution Contextهای موجود در Call Stack

اگر بتوان از Rootها به یک شیء رسید، آن شیء حذف نخواهد شد.

---

# ۳۴.۶ - Mark and Sweep

تقریباً تمام موتورهای مدرن جاوااسکریپت از الگوریتمی بر پایه **Mark and Sweep** استفاده می‌کنند.

این الگوریتم دو مرحله اصلی دارد.

---

## مرحله اول: Mark

Garbage Collector از Rootها شروع می‌کند.

هر شیء قابل دسترس را علامت‌گذاری (Mark) می‌کند.

---

## مرحله دوم: Sweep

تمام اشیائی که علامت نخورده‌اند، دیگر قابل دسترس نیستند.

بنابراین از حافظه حذف می‌شوند.

---

# ۳۴.۷ - مثال Mark and Sweep

```js
let user = {
  profile: {
    age: 20
  }
};
```

اگر بنویسیم:

```js
user = null;
```

دیگر هیچ Referenceای به:

```text
{
  profile: {
    age: 20
  }
}
```

وجود ندارد.

Garbage Collector در اجرای بعدی، هم شیء اصلی و هم شیء `profile` را حذف خواهد کرد.

---

# ۳۴.۸ - Referenceهای زنجیره‌ای

```js
const a = {};
const b = {
  ref: a
};
```

اگر:

```js
a = null;
```

(در عمل باید `let` باشد تا امکان انتساب مجدد وجود داشته باشد.)

اما همچنان `b.ref` به شیء اشاره کند، شیء حذف نخواهد شد.

زیرا هنوز قابل دسترس است.

---

# ۳۴.۹ - Circular Reference

گاهی دو شیء به یکدیگر اشاره می‌کنند.

```js
const user = {};
const profile = {};

user.profile = profile;
profile.user = user;
```

وجود Reference حلقه‌ای به تنهایی باعث Memory Leak نمی‌شود.

اگر هیچ Reference خارجی به این دو شیء وجود نداشته باشد، Garbage Collector می‌تواند هر دو را حذف کند.

---

# ۳۴.۱۰ - چه زمانی Garbage Collector اجرا می‌شود؟

زمان اجرای Garbage Collector مشخص نیست.

این موضوع به موتور جاوااسکریپت بستگی دارد.

معمولاً وقتی:

* حافظه زیاد مصرف شود.
* سیستم احساس نیاز کند.
* زمان مناسبی برای پاک‌سازی وجود داشته باشد.

عملیات GC انجام می‌شود.

---

# ۳۴.۱۱ - آیا می‌توان GC را دستی اجرا کرد؟

در برنامه‌های معمولی خیر.

Garbage Collection به صورت خودکار انجام می‌شود.

در برخی شرایط خاص و هنگام اجرای Node.js با تنظیمات ویژه (مانند فعال‌سازی قابلیت‌های مخصوص توسعه و دیباگ)، امکان درخواست اجرای GC وجود دارد، اما این کار در برنامه‌های عادی توصیه نمی‌شود.

---

# ۳۴.۱۲ - Memory Leak چیست؟

Memory Leak زمانی اتفاق می‌افتد که:

* داده دیگر استفاده نمی‌شود.
* اما همچنان Reference آن باقی مانده است.

در نتیجه Garbage Collector نمی‌تواند حافظه را آزاد کند.

---

# ۳۴.۱۳ - مثال Memory Leak

```js
const cache = [];

function save(data) {
  cache.push(data);
}
```

اگر:

* `save()` هزاران بار اجرا شود.
* `cache` هیچ‌وقت پاک نشود.

مصرف حافظه دائماً افزایش پیدا خواهد کرد.

---

# ۳۴.۱۴ - Closure و Garbage Collection

```js
function createCounter() {
  let count = 0;

  return function () {
    count++;
    return count;
  };
}
```

تا زمانی که تابع بازگشتی وجود دارد، متغیر `count` نیز در حافظه باقی خواهد ماند.

این رفتار کاملاً طبیعی است و Memory Leak محسوب نمی‌شود.

---

# ۳۴.۱۵ - Event Listener و Memory Leak

در محیط مرورگر، اگر Event Listenerها حذف نشوند، ممکن است باعث Memory Leak شوند.

در Node.js نیز نگه داشتن Listenerهای غیرضروری روی EventEmitterها می‌تواند باعث افزایش مصرف حافظه شود.

بنابراین پس از پایان نیاز، Listenerها را حذف کنید.

---

# ۳۴.۱۶ - Timerها

نمونه:

```js
const timer = setInterval(() => {
  console.log("Running...");
}, 1000);
```

اگر دیگر به Timer نیازی نداریم:

```js
clearInterval(timer);
```

در غیر این صورت، Callback همچنان در حافظه باقی خواهد ماند.

---

# ۳۴.۱۷ - Buffer و Garbage Collection

در Node.js، Bufferها نیز توسط Garbage Collector مدیریت می‌شوند.

اما اگر Reference آن‌ها را نگه داریم:

```js
const buffers = [];

buffers.push(Buffer.alloc(1024 * 1024));
```

مصرف حافظه به مرور افزایش پیدا می‌کند.

---

# ۳۴.۱۸ - مشاهده مصرف حافظه

```js
console.log(process.memoryUsage());
```

اطلاعاتی مانند:

* rss
* heapTotal
* heapUsed
* external
* arrayBuffers

نمایش داده می‌شود.

این اطلاعات برای بررسی وضعیت حافظه بسیار مفید هستند.

---

# ۳۴.۱۹ - بهترین روش جلوگیری از Memory Leak

* حذف Referenceهای غیرضروری
* پاک کردن Cacheهای قدیمی
* حذف Listenerهای بلااستفاده
* متوقف کردن Timerها
* مدیریت اندازه آرایه‌ها و Mapها
* استفاده صحیح از Closureها
* بررسی دوره‌ای مصرف حافظه

---

# ۳۴.۲۰ - Garbage Collection در V8

Node.js از موتور **V8** استفاده می‌کند.

V8 یکی از پیشرفته‌ترین Garbage Collectorهای دنیا را دارد.

این موتور از تکنیک‌هایی مانند:

* Generational Garbage Collection
* Incremental Marking
* Concurrent Marking
* Parallel Sweeping

استفاده می‌کند تا زمان توقف برنامه را تا حد امکان کاهش دهد.

جزئیات این الگوریتم‌ها پیچیده هستند و برای استفاده روزمره از Node.js دانستن مفاهیم پایه‌ای این فصل کافی است.

---

# اشتباهات رایج

## ۱) تصور اینکه `delete` حافظه را آزاد می‌کند

عملگر `delete` فقط یک ویژگی (Property) را از یک شیء حذف می‌کند و به‌تنهایی باعث آزاد شدن حافظه نمی‌شود.

---

## ۲) نگه داشتن Referenceهای غیرضروری

اگر Reference باقی بماند، Garbage Collector نمی‌تواند شیء را حذف کند.

---

## ۳) استفاده از Cache بدون محدودیت

Cacheهای بدون محدودیت یکی از رایج‌ترین دلایل Memory Leak هستند.

---

## ۴) فراموش کردن Timerها

`setInterval()` و برخی Timerهای دیگر تا زمانی که متوقف نشوند، به اجرای خود ادامه می‌دهند.

---

## ۵) نادیده گرفتن مصرف حافظه

در پروژه‌های Node.js بهتر است مصرف حافظه را به صورت دوره‌ای بررسی کنید.

---

# نکات حرفه‌ای

* همیشه طول عمر داده‌ها را تا حد ممکن کوتاه نگه دارید.
* از نگهداری داده‌های بزرگ در متغیرهای Global خودداری کنید.
* برای Cacheها از محدودیت حجم یا زمان انقضا (TTL) استفاده کنید.
* در EventEmitterها Listenerهای اضافه را حذف کنید.
* در سرویس‌های طولانی‌مدت، مصرف حافظه را با `process.memoryUsage()` پایش کنید.
* هنگام بررسی مشکلات حافظه از Heap Snapshot و ابزارهای پروفایلینگ استفاده کنید.
* از ایجاد Objectهای بزرگ در حلقه‌ها، بدون نیاز واقعی، خودداری کنید.

---

# پاسخ تشریحی

## پاسخ ۱

Garbage Collector اشیاء و داده‌هایی را که دیگر قابل دسترس نیستند شناسایی کرده و حافظه آن‌ها را آزاد می‌کند.

---

## پاسخ ۲

شیئی که قبلاً در متغیر `user` قرار داشت، چون دیگر هیچ Reference فعالی به آن وجود ندارد، Garbage محسوب می‌شود.

---

## پاسخ ۳

خیر.

اگر هیچ Reference قابل دسترسی از Rootها به آن اشیاء وجود نداشته باشد، Garbage Collector می‌تواند آن‌ها را حذف کند؛ حتی اگر به یکدیگر اشاره کنند.

---

## پاسخ ۴

آرایه `cache` به‌طور مداوم بزرگ‌تر می‌شود و هیچ داده‌ای از آن حذف نمی‌شود. این موضوع می‌تواند باعث افزایش مصرف حافظه و در نهایت Memory Leak شود.

---

## پاسخ ۵

نمونه پاسخ:

* حذف Referenceهای غیرضروری
* متوقف کردن Timerها
* حذف Listenerهای بلااستفاده
* محدود کردن اندازه Cache
* بررسی دوره‌ای مصرف حافظه

# مینی‌پروژه

## پروژه: Memory Leak Detector

برنامه‌ای بنویسید که مصرف حافظه را هر پنج ثانیه نمایش دهد و در صورت افزایش غیرعادی، هشدار چاپ کند.

### مرحله اول

هر پنج ثانیه اطلاعات حافظه را نمایش دهید.

```js
setInterval(() => {
  const memory = process.memoryUsage();

  console.log({
    heapUsed: memory.heapUsed,
    heapTotal: memory.heapTotal
  });
}, 5000);
```

### مرحله دوم

یک آرایه به عنوان Cache ایجاد کنید و هر ثانیه یک Object جدید به آن اضافه کنید.

تغییرات `heapUsed` را مشاهده کنید.

### مرحله سوم

کد را طوری تغییر دهید که:

* اندازه Cache بیشتر از ۱۰۰۰ عنصر نشود.
* داده‌های قدیمی حذف شوند.
* افزایش مصرف حافظه کنترل شود.

### اهداف پروژه

* آشنایی عملی با Garbage Collection
* مشاهده تأثیر Referenceها بر حافظه
* درک نحوه ایجاد Memory Leak
* تمرین مدیریت Cache در Node.js
* تحلیل خروجی `process.memoryUsage()`

---

# جمع‌بندی

Garbage Collection یکی از مهم‌ترین قابلیت‌های جاوااسکریپت و Node.js است که مدیریت حافظه را تا حد زیادی خودکار می‌کند. با این حال، عملکرد صحیح آن به نحوه نوشتن کد نیز وابسته است. اگر Referenceهای غیرضروری را نگه دارید، Cacheهای بدون محدودیت ایجاد کنید یا منابعی مانند Timerها و Listenerها را آزاد نکنید، Garbage Collector نیز نمی‌تواند حافظه را بازیابی کند. شناخت نحوه کار GC و رعایت اصول مدیریت حافظه، نقش مهمی در ساخت برنامه‌های سریع، پایدار و مقیاس‌پذیر دارد.
