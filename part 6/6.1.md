# فصل ۳۱ - Execution Context

## مقدمه

در این فصل با یکی از مهم‌ترین مفاهیم پایه‌ای جاوااسکریپت در نود جی‌اس آشنا می‌شویم: **Execution Context** یا «بافت اجرایی».

اگر بخواهیم ساده بگوییم، هر بار که کد اجرا می‌شود، جاوااسکریپت باید بداند:

* کدام متغیرها و توابع الان در دسترس هستند
* `this` به چه چیزی اشاره می‌کند
* کد از کجا شروع شده و با چه ترتیبی اجرا می‌شود
* چه چیزی وارد حافظه شده و چه چیزی هنوز فقط در مرحله آماده‌سازی است

درک Execution Context کمک می‌کند بهتر بفهمیم چرا بعضی متغیرها قبل از تعریف شدن قابل دسترسی هستند، چرا بعضی توابع بدون خطا اجرا می‌شوند، و چرا در نود جی‌اس رفتار `this` در فایل‌ها و ماژول‌ها گاهی با چیزی که انتظار داریم فرق دارد.

---

## ۳۱.۱ - Execution Context چیست؟

Execution Context محیطی است که کد جاوااسکریپت در آن اجرا می‌شود.

هر بار که کد اجرا می‌شود، یک Execution Context ساخته می‌شود. این بافت اجرایی اطلاعات زیر را نگه می‌دارد:

* متغیرهای آن بخش از کد
* توابع تعریف‌شده
* مقدار `this`
* ارتباط با بافت‌های دیگر
* مسیر اجرای کد

به زبان خیلی ساده، Execution Context مثل «اتاق کار» جاوااسکریپت برای اجرای کد است.

---

## ۳۱.۲ - سه نوع Execution Context

در جاوااسکریپت معمولاً سه نوع Execution Context را می‌شناسیم:

### ۱) Global Execution Context

اولین بافت اجرایی که هنگام شروع برنامه ساخته می‌شود.

### ۲) Function Execution Context

هر بار که یک تابع اجرا می‌شود، برای آن یک بافت اجرایی جدید ساخته می‌شود.

### ۳) Eval Execution Context

وقتی از `eval()` استفاده شود، یک بافت اجرایی جداگانه ساخته می‌شود.
در آموزش‌های عملی نود جی‌اس معمولاً با این نوع کمتر کار می‌کنیم.

---

## ۳۱.۳ - Global Execution Context در نود جی‌اس

در مرورگر، سطح بالای برنامه معمولاً به `window` وصل است.
اما در نود جی‌اس، محیط اجرای کد با مرورگر فرق دارد.

نکته مهم در نود جی‌اس این است که هر فایل معمولاً مثل یک **ماژول** اجرا می‌شود، نه مثل یک اسکریپت کاملاً آزاد.

یعنی کد شما در نود جی‌اس داخل یک ساختار ماژولی اجرا می‌شود و این باعث می‌شود بعضی رفتارها با مرورگر متفاوت باشد.

مثلاً:

```js
console.log(this);
```

در فایل‌های CommonJS نود جی‌اس، مقدار `this` در سطح فایل معمولاً به `module.exports` نزدیک است، نه به `window` مثل مرورگر.

---

## ۳۱.۴ - Execution Context چه بخش‌هایی دارد؟

هر Execution Context را می‌توان به سه بخش اصلی تقسیم کرد:

### ۱) Memory Creation Phase

در این مرحله، جاوااسکریپت فقط فضا آماده می‌کند:

* متغیرها را ثبت می‌کند
* توابع را به خاطر می‌سپارد
* مقداردهی اولیه را انجام می‌دهد

### ۲) Code Execution Phase

در این مرحله، خطوط کد یکی‌یکی اجرا می‌شوند.

### ۳) Environment / Scope Chain

جاوااسکریپت بررسی می‌کند هر متغیر یا تابع از کجا قابل دسترسی است.

---

## ۳۱.۵ - مراحل اجرای کد

وقتی کد اجرا می‌شود، این اتفاق‌ها می‌افتد:

1. Global Execution Context ساخته می‌شود
2. Memory Creation Phase انجام می‌شود
3. توابع و متغیرها آماده می‌شوند
4. اجرای واقعی کد از بالا به پایین شروع می‌شود
5. هر بار که تابعی صدا زده می‌شود، یک Function Execution Context جدید ساخته می‌شود
6. بعد از پایان تابع، آن بافت اجرایی از بین می‌رود

---

## ۳۱.۶ - Call Stack چیست؟

**Call Stack** یا پشته فراخوانی، ساختاری است که جاوااسکریپت با آن مدیریت می‌کند کدام تابع الان در حال اجراست.

قانون آن ساده است:

* تابع جدید وارد Stack می‌شود
* وقتی اجرا تمام شد، از Stack خارج می‌شود

مثال:

```js
function first() {
  second();
}

function second() {
  third();
}

function third() {
  console.log("Hello");
}

first();
```

ترتیب اتفاق‌ها:

* `first()` وارد Stack می‌شود
* داخل `first`، تابع `second()` اجرا می‌شود
* `second()` وارد Stack می‌شود
* داخل `second`، تابع `third()` اجرا می‌شود
* `third()` وارد Stack می‌شود
* بعد از پایان `third`، از Stack خارج می‌شود
* سپس `second`
* سپس `first`

---

## ۳۱.۷ - Hoisting و رابطه آن با Execution Context

یکی از مهم‌ترین دلایل یادگیری Execution Context، فهمیدن **Hoisting** است.

Hoisting یعنی جاوااسکریپت در مرحله ساختن حافظه، بعضی اعلان‌ها را جلوتر از اجرای واقعی کد در نظر می‌گیرد.

### مثال با `var`

```js
console.log(name);
var name = "Node";
```

خروجی:

```js
undefined
```

چرا؟
چون `var` در مرحله Memory Creation به حافظه اضافه می‌شود، اما مقدارش هنوز تنظیم نشده است.

### مثال با `let` و `const`

```js
console.log(age);
let age = 20;
```

اینجا خطا می‌گیریم، چون `let` و `const` تا قبل از مقداردهی اولیه وارد **Temporal Dead Zone** می‌شوند.

---

## ۳۱.۸ - نقش Scope در Execution Context

Scope مشخص می‌کند یک متغیر از کجا قابل دسترسی است.

Execution Context و Scope خیلی به هم نزدیک هستند، اما یکی نیستند:

* **Execution Context** مربوط به اجرای کد است
* **Scope** مربوط به دسترسی به متغیرهاست

مثال:

```js
function test() {
  let x = 10;
  console.log(x);
}

test();
console.log(x);
```

`x` فقط داخل `test` قابل دسترسی است.

---

## ۳۱.۹ - Lexical Environment چیست؟

Lexical Environment ساختاری است که جاوااسکریپت برای نگهداری متغیرها و ارتباط آن‌ها با Scope استفاده می‌کند.

هر Execution Context یک Lexical Environment دارد.

به زبان ساده:

* متغیرهای محلی
* توابع داخلی
* ارتباط با Scope والد

همه در این ساختار دیده می‌شوند.

---

## ۳۱.۱۰ - Scope Chain چیست؟

وقتی جاوااسکریپت یک متغیر را پیدا نمی‌کند، به سراغ Scope بالاتر می‌رود.

این مسیر جست‌وجو را **Scope Chain** می‌گویند.

مثال:

```js
const a = 1;

function outer() {
  const b = 2;

  function inner() {
    const c = 3;
    console.log(a, b, c);
  }

  inner();
}

outer();
```

`inner` به `c`، `b` و `a` دسترسی دارد چون Scope Chain از داخل به بیرون بررسی می‌شود.

---

## ۳۱.۱۱ - Execution Context در توابع

هر بار که یک تابع اجرا می‌شود، یک Execution Context تازه ساخته می‌شود.

مثال:

```js
function greet(name) {
  const message = "Hello " + name;
  console.log(message);
}

greet("Sobhan");
greet("Ali");
```

هر بار اجرای `greet` یک بافت اجرایی مستقل دارد.
یعنی متغیر `message` در هر بار اجرا جداگانه ساخته می‌شود.

---

## ۳۱.۱۲ - Execution Context در نود جی‌اس و ماژول‌ها

در نود جی‌اس، هر فایل معمولاً به شکل یک ماژول اجرا می‌شود.
این یعنی:

* متغیرهای یک فایل مستقیم به فایل دیگر نمی‌روند
* هر فایل Scope مخصوص خودش را دارد
* باید از `require` یا `import` برای ارتباط بین فایل‌ها استفاده کنیم

مثال در CommonJS:

```js
// math.js
function sum(a, b) {
  return a + b;
}

module.exports = sum;
```

```js
// app.js
const sum = require("./math");
console.log(sum(2, 3));
```

این جداسازی بخشی از مدیریت اجرای کد در نود جی‌اس است.

---

## ۳۱.۱۳ - چرخه کلی اجرای یک فایل در نود جی‌اس

وقتی یک فایل را اجرا می‌کنی، معمولاً این مسیر را طی می‌کند:

1. نود فایل را می‌خواند
2. ماژول را می‌سازد
3. Global/Module Context را آماده می‌کند
4. کد را خط به خط اجرا می‌کند
5. توابع و وابستگی‌ها را در صورت نیاز صدا می‌زند
6. نتیجه را برمی‌گرداند یا در حافظه نگه می‌دارد

---

## ۳۱.۱۴ - مثال مفهومی کامل

```js
let x = 10;

function outer() {
  let y = 20;

  function inner() {
    let z = 30;
    console.log(x, y, z);
  }

  inner();
}

outer();
```

### تحلیل:

* `x` در Global Execution Context ساخته شده
* `outer` یک Function Execution Context می‌سازد
* `y` داخل `outer` است
* `inner` یک Execution Context دیگر می‌سازد
* `inner` به `x` و `y` از طریق Scope Chain دسترسی دارد
* `z` فقط داخل `inner` است

---

## ۳۱.۱۵ - چرا این مبحث مهم است؟

اگر Execution Context را خوب بفهمی، این موضوع‌ها را راحت‌تر یاد می‌گیری:

* Hoisting
* Scope
* Closure
* `this`
* Call Stack
* رفتار توابع
* تفاوت `var`، `let` و `const`
* رفتار ماژول‌ها در نود جی‌اس

این فصل در واقع یکی از پایه‌های اصلی برای فهم عمیق جاوااسکریپت و نود جی‌اس است.

---

## اشتباهات رایج

### ۱) فکر کردن اینکه همه چیز مثل مرورگر است

در نود جی‌اس محیط اجرا با مرورگر فرق دارد.
نباید `window` را در نود جی‌اس فرض کنیم.

### ۲) اشتباه گرفتن Execution Context با Scope

Execution Context محیط اجراست، Scope محدوده دسترسی است.
این دو به هم مرتبط‌اند ولی یکسان نیستند.

### ۳) نادیده گرفتن Hoisting

بسیاری از خطاها به خاطر این است که فکر می‌کنیم همه چیز دقیقاً در همان خطی که نوشته شده اجرا می‌شود.

### ۴) درک نکردن Call Stack

وقتی توابع تو در تو زیاد می‌شوند، بدون فهم Stack سردرگم می‌شویم.

### ۵) استفاده از `var` بدون شناخت رفتار آن

`var` در سطح مفهومی با `let` و `const` متفاوت است و ممکن است باعث باگ شود.

### ۶) توجه نکردن به ماژول بودن فایل در نود جی‌اس

هر فایل در نود جی‌اس مثل یک محدوده مستقل رفتار می‌کند.

---

## نکات حرفه‌ای

### ۱) همیشه اجرای کد را ذهنی دنبال کن

قبل از اجرای برنامه، سعی کن حدس بزنی:

* چه متغیری زودتر ساخته می‌شود
* چه تابعی وارد Stack می‌شود
* خروجی نهایی چه خواهد بود

### ۲) برای فهم عمیق، از مثال‌های تو در تو استفاده کن

توابع تو در تو بهترین ابزار برای فهم Execution Context و Scope Chain هستند.

### ۳) از `let` و `const` به‌جای `var` استفاده کن

در پروژه‌های نود جی‌اس، این کار خوانایی و امنیت کد را بهتر می‌کند.

### ۴) تفاوت فایل و تابع را جدی بگیر

در نود جی‌اس، فایل خودش یک مرز مهم در اجراست.

### ۵) برای هر تابع یک مسئولیت مشخص تعریف کن

تابع‌های کوچک و ساده، فهم Call Stack و Execution Context را آسان‌تر می‌کنند.

---

## تمرین

### تمرین ۱

خروجی کد زیر را حدس بزن:

```js
console.log(a);
var a = 5;
console.log(a);
```

### تمرین ۲

خروجی کد زیر را حدس بزن:

```js
let name = "Ali";

function show() {
  console.log(name);
  let name = "Reza";
}

show();
```

### تمرین ۳

خروجی کد زیر را بنویس و دلیل آن را توضیح بده:

```js
function a() {
  console.log("A");
}

function b() {
  a();
  console.log("B");
}

b();
```

### تمرین ۴

مشخص کن هر متغیر در کدام Execution Context ساخته می‌شود:

```js
let x = 1;

function outer() {
  let y = 2;

  function inner() {
    let z = 3;
    console.log(x, y, z);
  }

  inner();
}
```

### تمرین ۵

در نود جی‌اس، چرا نباید انتظار داشته باشیم `window` در دسترس باشد؟

---

## پاسخ تشریحی

### پاسخ ۱

```js
undefined
5
```

**توضیح:**
`a` با `var` در مرحله آماده‌سازی وارد حافظه می‌شود، اما مقدار آن هنوز `undefined` است. بعداً مقدار `5` به آن اختصاص داده می‌شود.

---

### پاسخ ۲

این کد خطا می‌دهد.

**توضیح:**
داخل تابع `show`، متغیر `name` با `let` تعریف شده و در Temporal Dead Zone قرار دارد تا وقتی که خط تعریفش اجرا شود.
پس `console.log(name)` نمی‌تواند به متغیر بیرونی دسترسی پیدا کند، چون نام همان متغیر داخلی را پیدا می‌کند و قبل از مقداردهی استفاده شده است.

---

### پاسخ ۳

خروجی:

```js
A
B
```

**توضیح:**
تابع `b` اجرا می‌شود، داخل آن تابع `a` صدا زده می‌شود، پس اول `A` چاپ می‌شود. بعد از بازگشت از `a`، خط بعدی `console.log("B")` اجرا می‌شود.

---

### پاسخ ۴

* `x` در Global Execution Context ساخته می‌شود
* `y` در Execution Context تابع `outer` ساخته می‌شود
* `z` در Execution Context تابع `inner` ساخته می‌شود

**توضیح:**
`inner` به `x` و `y` هم دسترسی دارد، چون از طریق Scope Chain به بیرون نگاه می‌کند.

---

### پاسخ ۵

چون نود جی‌اس محیطی متفاوت از مرورگر است.
`window` متعلق به مرورگر است و در نود جی‌اس به طور پیش‌فرض وجود ندارد.

---

## مینی‌پروژه

### پروژه: تحلیل‌گر ترتیب اجرا

یک اسکریپت نود جی‌اس بنویس که چند تابع تو در تو داشته باشد و ترتیب اجرای آن‌ها را با `console.log` نشان دهد.

### هدف پروژه

* درک Call Stack
* درک ترتیب اجرای تابع‌ها
* درک اینکه هر تابع یک Execution Context جدا می‌سازد

### نمونه شروع پروژه

```js
function level1() {
  console.log("Entered level1");

  function level2() {
    console.log("Entered level2");

    function level3() {
      console.log("Entered level3");
    }

    level3();
  }

  level2();
  console.log("Exit level1");
}

level1();
```

### وظیفه

خروجی را حدس بزن، سپس کد را اجرا کن و نتیجه را با پیش‌بینی خودت مقایسه کن.

### نسخه کامل‌تر پروژه

می‌توانی این پروژه را گسترش بدهی و برای هر تابع:

* زمان ورود
* زمان خروج
* نام تابع
* سطح تو در تو بودن

را ثبت کنی.

## جمع‌بندی

Execution Context پایه‌ای‌ترین مفهومی است که کمک می‌کند رفتار واقعی جاوااسکریپت و نود جی‌اس را بفهمیم.
اگر این فصل را خوب یاد بگیری، یادگیری فصل‌های بعدی مثل Scope، Hoisting، Closure و `this` بسیار ساده‌تر می‌شود.

در فصل بعدی می‌توانیم وارد یکی از موضوع‌های نزدیک و مهم این مبحث شویم، مثل **Scope Chain** یا **Hoisting**.
