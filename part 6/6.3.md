# فصل ۳۳ - Memory (حافظه در جاوااسکریپت و Node.js)

## مقدمه

هر برنامه‌ای که می‌نویسیم، برای نگهداری اطلاعات به حافظه (Memory) نیاز دارد.

وقتی یک متغیر تعریف می‌کنیم، یک آرایه می‌سازیم، یک شیء ایجاد می‌کنیم یا تابعی را اجرا می‌کنیم، جاوااسکریپت باید همه این اطلاعات را در جایی از حافظه ذخیره کند.

اما این حافظه چگونه مدیریت می‌شود؟

* متغیرها کجا ذخیره می‌شوند؟
* آرایه‌ها و آبجکت‌ها در کجا قرار می‌گیرند؟
* چرا بعضی داده‌ها کپی می‌شوند و بعضی فقط آدرسشان منتقل می‌شود؟
* چرا حافظه گاهی پر می‌شود؟
* Garbage Collector چیست و چگونه حافظه را آزاد می‌کند؟

در این فصل با نحوه مدیریت حافظه در موتور جاوااسکریپت و محیط Node.js آشنا می‌شویم.

---

# ۳۳.۱ - Memory چیست؟

Memory یا حافظه، محلی است که برنامه هنگام اجرا اطلاعات موردنیاز خود را در آن نگهداری می‌کند.

این اطلاعات می‌توانند شامل موارد زیر باشند:

* متغیرها
* توابع
* آرایه‌ها
* اشیاء (Objects)
* رشته‌ها (Strings)
* اعداد
* کلاس‌ها
* Promiseها
* بافرها (Buffer)
* ساختارهای داخلی موتور جاوااسکریپت

---

# ۳۳.۲ - انواع حافظه در جاوااسکریپت

به صورت مفهومی حافظه را به دو بخش تقسیم می‌کنیم:

## Stack Memory

محل نگهداری:

* Execution Context
* Primitive Valueها
* Referenceها

---

## Heap Memory

محل نگهداری:

* Object
* Array
* Function
* Date
* Map
* Set
* Buffer
* سایر داده‌های پیچیده

Heap معمولاً فضای بسیار بزرگ‌تری نسبت به Stack دارد.

---

# ۳۳.۳ - Stack Memory چیست؟

Stack حافظه‌ای سریع است که اطلاعات موقتی را نگهداری می‌کند.

مثال:

```js
let age = 20;
let score = 95;
let active = true;
```

در این مثال مقادیر Primitive مستقیماً در Stack نگهداری می‌شوند.

---

# ۳۳.۴ - Heap Memory چیست؟

Heap حافظه‌ای است که داده‌های پیچیده در آن ذخیره می‌شوند.

مثال:

```js
const user = {
  name: "Sobhan",
  age: 22
};
```

در اینجا:

* خود شیء داخل Heap قرار می‌گیرد.
* متغیر `user` فقط آدرس آن شیء را در Stack نگه می‌دارد.

---

# ۳۳.۵ - Primitive و Reference

Primitiveها:

* Number
* String
* Boolean
* Null
* Undefined
* Symbol
* BigInt

Referenceها:

* Object
* Array
* Function
* Date
* RegExp
* Map
* Set
* Buffer

Primitiveها مقدار را نگه می‌دارند.

Referenceها آدرس حافظه را نگه می‌دارند.

---

# ۳۳.۶ - کپی شدن Primitiveها

```js
let a = 10;

let b = a;

b = 20;

console.log(a);
console.log(b);
```

خروجی:

```text
10
20
```

چرا؟

زیرا مقدار `10` کپی شده است.

---

# ۳۳.۷ - کپی شدن Objectها

```js
const person1 = {
  name: "Ali"
};

const person2 = person1;

person2.name = "Reza";

console.log(person1.name);
```

خروجی:

```text
Reza
```

دلیل:

کپی انجام نشده است.

فقط آدرس حافظه منتقل شده است.

---

# ۳۳.۸ - نمایش مفهومی حافظه

فرض کنید داریم:

```js
const user = {
  name: "Sara"
};
```

Stack:

```text
user ───────┐
            │
```

Heap:

```text
{
  name: "Sara"
}
```

متغیر `user` فقط محل شیء را می‌شناسد.

---

# ۳۳.۹ - حذف Reference

```js
let obj = {
  value: 10
};

obj = null;
```

بعد از این خط:

هیچ Referenceای به آن شیء وجود ندارد.

در آینده Garbage Collector آن را حذف خواهد کرد.

---

# ۳۳.۱۰ - Garbage Collector چیست؟

Garbage Collector بخشی از موتور جاوااسکریپت است که حافظه‌های بلااستفاده را آزاد می‌کند.

اگر شیئی دیگر Reference نداشته باشد، موتور می‌تواند آن را حذف کند.

این کار باعث جلوگیری از پر شدن حافظه می‌شود.

---

# ۳۳.۱۱ - Reachability

مهم‌ترین معیار Garbage Collector:

**Reachability**

اگر بتوان از طریق متغیرها یا سایر Referenceها به یک شیء رسید، آن شیء زنده است.

اگر هیچ راهی برای رسیدن به آن وجود نداشته باشد، آن شیء Garbage محسوب می‌شود.

---

# ۳۳.۱۲ - مثال Reachability

```js
let user = {
  name: "Ali"
};

user = null;
```

بعد از این خط:

شیء دیگر قابل دسترسی نیست.

بنابراین بعداً حذف خواهد شد.

---

# ۳۳.۱۳ - Referenceهای متعدد

```js
let a = {
  x: 1
};

let b = a;

a = null;
```

آیا شیء حذف می‌شود؟

خیر.

زیرا هنوز `b` به آن اشاره می‌کند.

---

# ۳۳.۱۴ - Memory Leak چیست؟

Memory Leak زمانی اتفاق می‌افتد که حافظه‌ای دیگر استفاده نمی‌شود، اما همچنان Reference آن باقی مانده است.

در نتیجه Garbage Collector نمی‌تواند آن را آزاد کند.

در پروژه‌های بزرگ Node.js این موضوع بسیار مهم است.

---

# ۳۳.۱۵ - نمونه Memory Leak

```js
const users = [];

function saveUser(user) {
  users.push(user);
}
```

اگر آرایه `users` همیشه بزرگ‌تر شود و هیچ‌وقت پاک نشود، حافظه به مرور مصرف خواهد شد.

---

# ۳۳.۱۶ - Closure و حافظه

گاهی Closure باعث می‌شود بعضی متغیرها مدت بیشتری در حافظه باقی بمانند.

مثال:

```js
function counter() {
  let count = 0;

  return function () {
    count++;
    return count;
  };
}

const increment = counter();
```

متغیر `count` حتی بعد از پایان اجرای `counter` همچنان در حافظه باقی می‌ماند، زیرا تابع بازگشتی هنوز به آن نیاز دارد.

---

# ۳۳.۱۷ - حافظه در Node.js

در Node.js علاوه بر Objectها، داده‌های زیر نیز در Heap قرار می‌گیرند:

* Buffer
* Stream
* Promise
* EventEmitter
* کلاس‌ها
* ماژول‌ها

مدیریت صحیح این داده‌ها در پروژه‌های واقعی اهمیت زیادی دارد.

---

# ۳۳.۱۸ - Buffer و حافظه

```js
const buffer = Buffer.alloc(1024);
```

در این مثال یک بافر ۱ کیلوبایتی در حافظه ایجاد می‌شود.

اگر تعداد زیادی Buffer ایجاد کنیم و آن‌ها را آزاد نکنیم، مصرف حافظه افزایش پیدا می‌کند.

---

# ۳۳.۱۹ - مشاهده مصرف حافظه

در Node.js می‌توان اطلاعاتی از حافظه را مشاهده کرد.

```js
console.log(process.memoryUsage());
```

خروجی مشابه:

```text
{
  rss: ...,
  heapTotal: ...,
  heapUsed: ...,
  external: ...
}
```

این اطلاعات برای بررسی مصرف حافظه برنامه بسیار کاربردی هستند.

---

# ۳۳.۲۰ - چه زمانی حافظه آزاد می‌شود؟

زمان دقیق آزاد شدن حافظه قابل پیش‌بینی نیست.

Garbage Collector هر زمان که لازم بداند عملیات پاک‌سازی را انجام می‌دهد.

به همین دلیل نباید انتظار داشته باشیم بلافاصله بعد از حذف یک متغیر، حافظه آزاد شود.

---

# اشتباهات رایج

## ۱) تصور اینکه حذف متغیر یعنی حذف فوری حافظه

خیر.

حذف واقعی توسط Garbage Collector انجام می‌شود.

---

## ۲) اشتباه گرفتن Stack و Heap

Stack محل اجرای توابع و نگهداری داده‌های ساده است.

Heap محل نگهداری داده‌های پیچیده است.

---

## ۳) تصور اینکه Objectها هنگام انتساب کپی می‌شوند

Objectها کپی نمی‌شوند.

فقط Reference آن‌ها منتقل می‌شود.

---

## ۴) نگهداری Referenceهای غیرضروری

اگر Referenceها باقی بمانند، حافظه آزاد نخواهد شد.

---

## ۵) نادیده گرفتن Memory Leak

در پروژه‌های کوچک شاید دیده نشود، اما در سرورهای Node.js که ساعت‌ها یا روزها در حال اجرا هستند، Memory Leak می‌تواند باعث افزایش مصرف حافظه، کاهش کارایی و حتی از کار افتادن برنامه شود.

---

# نکات حرفه‌ای

* از ساخت Objectهای غیرضروری خودداری کنید.
* Referenceهایی که دیگر نیاز ندارید را حذف کنید.
* آرایه‌ها و Mapهای بسیار بزرگ را مدیریت کنید.
* هنگام استفاده از Cache، محدودیت حجم یا زمان انقضا (TTL) در نظر بگیرید.
* با `process.memoryUsage()` مصرف حافظه برنامه را بررسی کنید.
* برای تحلیل دقیق‌تر حافظه در پروژه‌های بزرگ از ابزارهای Profiler و Heap Snapshot استفاده کنید.
* مراقب Closureهایی باشید که ناخواسته داده‌های زیادی را در حافظه نگه می‌دارند.

# مینی‌پروژه

## پروژه: Memory Usage Monitor

برنامه‌ای بنویسید که هر پنج ثانیه میزان مصرف حافظه Node.js را نمایش دهد.

### نمونه شروع

```js
setInterval(() => {
  const memory = process.memoryUsage();

  console.log("RSS:", memory.rss);
  console.log("Heap Total:", memory.heapTotal);
  console.log("Heap Used:", memory.heapUsed);
  console.log("External:", memory.external);

  console.log("----------------------");
}, 5000);
```

### اهداف پروژه

* آشنایی با `process.memoryUsage()`
* مشاهده تغییرات مصرف حافظه در زمان اجرا
* درک تفاوت بین `heapTotal` و `heapUsed`
* بررسی تأثیر ایجاد Objectها و Arrayهای بزرگ بر مصرف حافظه

### تمرین تکمیلی

برنامه را توسعه دهید تا:

* میزان مصرف حافظه را بر حسب مگابایت نمایش دهد.
* بیشترین مقدار `heapUsed` را ذخیره کند.
* در صورت عبور مصرف حافظه از یک حد مشخص، هشداری در کنسول نمایش دهد.
* گزارشی از مصرف حافظه را در یک فایل متنی ذخیره کند.

# جمع‌بندی

مدیریت حافظه یکی از مهم‌ترین مفاهیم در جاوااسکریپت و به‌ویژه Node.js است. شناخت تفاوت بین **Stack** و **Heap**، درک نحوه کار **Reference**ها، آشنایی با **Garbage Collector** و تشخیص **Memory Leak** به شما کمک می‌کند برنامه‌هایی سریع‌تر، پایدارتر و کم‌مصرف‌تر بنویسید. این مفاهیم در پروژه‌های واقعی و سرورهای Node.js که مدت طولانی در حال اجرا هستند، نقش بسیار مهمی در حفظ عملکرد و پایداری برنامه دارند.
