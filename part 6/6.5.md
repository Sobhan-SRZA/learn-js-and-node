# فصل ۳۵ - Event Loop (حلقه رویداد)

## مقدمه

یکی از مهم‌ترین و در عین حال گیج‌کننده‌ترین مفاهیم جاوااسکریپت، **Event Loop** یا «حلقه رویداد» است.

تقریباً تمام برنامه‌های Node.js بر پایه Event Loop اجرا می‌شوند.

اگر Event Loop را به خوبی یاد بگیرید، درک موضوعات زیر بسیار ساده‌تر خواهد شد:

* عملیات ناهمزمان (Asynchronous)
* Promise
* Async/Await
* Timerها
* File System
* شبکه (Network)
* Stream
* EventEmitter

و مهم‌تر از همه، خواهید فهمید که:

**چگونه جاوااسکریپت با وجود Single Thread بودن، هزاران درخواست را مدیریت می‌کند؟**

---

# ۳۵.۱ - Event Loop چیست؟

Event Loop مکانیزمی است که وظیفه هماهنگی اجرای کدهای همزمان و ناهمزمان را بر عهده دارد.

به زبان ساده:

Event Loop همیشه بررسی می‌کند:

* آیا Call Stack خالی شده است؟
* آیا Callback آماده اجرا وجود دارد؟
* آیا Promise آماده اجرا وجود دارد؟
* اگر بله، آن را وارد Call Stack می‌کند.

---

# ۳۵.۲ - چرا به Event Loop نیاز داریم؟

جاوااسکریپت فقط یک Call Stack دارد.

اگر اجرای یک عملیات طولانی تمام برنامه را متوقف کند، هیچ کار دیگری انجام نخواهد شد.

مثلاً:

```js
console.log("Start");

while (true) {}

console.log("End");
```

در این مثال:

* برنامه هیچ‌وقت به `End` نمی‌رسد.
* Event Loop نیز فرصتی برای اجرای Callbackها پیدا نمی‌کند.

---

# ۳۵.۳ - اجزای اصلی Event Loop

در Node.js، اجرای کد به کمک بخش‌های مختلفی انجام می‌شود:

* Call Stack
* Web APIs (در مرورگر) یا Node.js APIs
* Callback Queue
* Microtask Queue
* Event Loop

در Node.js به جای Web APIs، امکاناتی مانند:

* Timer
* File System
* Network
* DNS
* Crypto

توسط خود Node.js فراهم می‌شوند.

---

# ۳۵.۴ - روند اجرای برنامه

فرض کنید:

```js
console.log("A");

setTimeout(() => {
  console.log("B");
}, 0);

console.log("C");
```

ترتیب اجرا:

```
A
C
B
```

چرا؟

زیرا:

۱. `A` اجرا می‌شود.

۲. Timer ثبت می‌شود.

۳. `C` اجرا می‌شود.

۴. Stack خالی می‌شود.

۵. Event Loop، Callback مربوط به Timer را وارد Stack می‌کند.

---

# ۳۵.۵ - Timerها

```js
setTimeout(() => {
  console.log("Hello");
}, 1000);
```

این کد به معنی:

> «حداقل یک ثانیه بعد، اگر Stack خالی بود، این Callback را اجرا کن.»

دقت کنید:

`1000` میلی‌ثانیه تضمین نمی‌کند دقیقاً بعد از یک ثانیه اجرا شود.

اگر Stack مشغول باشد، اجرای Callback به تأخیر می‌افتد.

---

# ۳۵.۶ - مثال تأخیر

```js
setTimeout(() => {
  console.log("Timer");
}, 0);

for (let i = 0; i < 1_000_000_000; i++) {}

console.log("Done");
```

خروجی:

```
Done
Timer
```

زیرا حلقه `for` ابتدا باید تمام شود.

---

# ۳۵.۷ - Callback Queue

وقتی Callback آماده اجرا شود، مستقیماً وارد Stack نمی‌شود.

ابتدا وارد:

**Callback Queue**

می‌شود.

Event Loop زمانی آن را به Stack منتقل می‌کند که Stack خالی باشد.

---

# ۳۵.۸ - Microtask Queue

Promiseها و برخی عملیات دیگر داخل:

**Microtask Queue**

قرار می‌گیرند.

Microtaskها نسبت به Callback Queue اولویت بیشتری دارند.

---

# ۳۵.۹ - Promise و Event Loop

```js
console.log("A");

Promise.resolve().then(() => {
  console.log("Promise");
});

console.log("B");
```

خروجی:

```
A
B
Promise
```

زیرا Callback مربوط به Promise وارد Microtask Queue می‌شود.

---

# ۳۵.۱۰ - Promise و Timer

```js
console.log("Start");

setTimeout(() => {
  console.log("Timer");
}, 0);

Promise.resolve().then(() => {
  console.log("Promise");
});

console.log("End");
```

خروجی:

```
Start
End
Promise
Timer
```

زیرا Microtask Queue همیشه قبل از Callback Queue پردازش می‌شود.

---

# ۳۵.۱۱ - ترتیب اولویت

به صورت ساده:

```
Call Stack

↓

Microtask Queue

↓

Callback Queue
```

بنابراین Promiseها معمولاً قبل از Timerها اجرا می‌شوند.

---

# ۳۵.۱۲ - Event Loop در Node.js

در Node.js، Event Loop توسط کتابخانه **libuv** مدیریت می‌شود.

libuv مسئول مدیریت موارد زیر است:

* Timerها
* File System
* Network
* Thread Pool
* Event Loop

به همین دلیل Node.js می‌تواند هزاران اتصال همزمان را مدیریت کند.

---

# ۳۵.۱۳ - فازهای Event Loop در Node.js

Event Loop در Node.js چند مرحله (Phase) اصلی دارد:

1. Timers
2. Pending Callbacks
3. Idle / Prepare
4. Poll
5. Check
6. Close Callbacks

هر مرحله وظایف مشخصی دارد.

برای شروع یادگیری Node.js، دانستن نام و ترتیب این فازها کافی است. در ادامه مسیر، هنگام کار با APIهای مختلف، با نقش هر فاز بیشتر آشنا خواهید شد.

---

# ۳۵.۱۴ - Poll Phase

بخش Poll مهم‌ترین قسمت Event Loop است.

در این مرحله:

* عملیات File System
* عملیات شبکه
* بسیاری از Callbackها

منتظر اجرا هستند.

---

# ۳۵.۱۵ - Check Phase

در این مرحله Callbackهای مربوط به:

```js
setImmediate()
```

اجرا می‌شوند.

---

# ۳۵.۱۶ - setImmediate

```js
setImmediate(() => {
  console.log("Immediate");
});
```

این تابع مخصوص Node.js است و Callback آن در فاز **Check** اجرا می‌شود.

---

# ۳۵.۱۷ - process.nextTick

Node.js تابع ویژه‌ای دارد:

```js
process.nextTick(() => {
  console.log("Tick");
});
```

Callback مربوط به `process.nextTick()` حتی قبل از Microtaskهای معمولی Promise پردازش می‌شود.

به همین دلیل استفاده بیش از حد از آن می‌تواند باعث به تأخیر افتادن سایر عملیات شود.

---

# ۳۵.۱۸ - مقایسه ترتیب اجرا

```js
console.log("Start");

process.nextTick(() => {
  console.log("nextTick");
});

Promise.resolve().then(() => {
  console.log("Promise");
});

setTimeout(() => {
  console.log("Timeout");
}, 0);

setImmediate(() => {
  console.log("Immediate");
});

console.log("End");
```

خروجی معمول:

```
Start
End
nextTick
Promise
Timeout
Immediate
```

> **نکته:** ترتیب `setTimeout(..., 0)` و `setImmediate()` همیشه در همه شرایط یکسان نیست. در سطح بالای یک فایل، ممکن است بسته به شرایط اجرا و نسخه Node.js، یکی قبل از دیگری اجرا شود. اما اگر هر دو را داخل Callback مربوط به عملیات I/O (مانند `fs.readFile`) فراخوانی کنید، معمولاً `setImmediate()` زودتر اجرا می‌شود.

---

# ۳۵.۱۹ - Event Loop و عملیات I/O

مثال:

```js
const fs = require("fs");

fs.readFile("data.txt", () => {
  console.log("File Loaded");
});

console.log("Running...");
```

خروجی:

```
Running...
File Loaded
```

در این مثال:

* خواندن فایل به Node.js سپرده می‌شود.
* اجرای برنامه ادامه پیدا می‌کند.
* بعد از آماده شدن نتیجه، Callback وارد Event Loop می‌شود.

---

# ۳۵.۲۰ - چرا Event Loop مهم است؟

اگر Event Loop نبود:

* هر عملیات شبکه برنامه را متوقف می‌کرد.
* خواندن فایل باعث قفل شدن برنامه می‌شد.
* اجرای هزاران درخواست همزمان ممکن نبود.

تقریباً تمام قدرت Node.js در برنامه‌های سمت سرور به Event Loop و libuv وابسته است.

---

# اشتباهات رایج

## ۱) تصور اینکه `setTimeout(..., 0)` فوراً اجرا می‌شود

خیر.

فقط **حداقل زمان انتظار** صفر است؛ اجرای واقعی به خالی بودن Call Stack و وضعیت Event Loop بستگی دارد.

---

## ۲) اشتباه گرفتن Promise با Timer

Promiseها وارد Microtask Queue می‌شوند.

Timerها وارد Callback Queue یا فاز Timers می‌شوند.

---

## ۳) استفاده بیش از حد از `process.nextTick()`

این کار می‌تواند باعث شود Event Loop فرصت رسیدگی به سایر صف‌ها را پیدا نکند.

---

## ۴) نوشتن کدهای سنگین روی Thread اصلی

حلقه‌های بسیار بزرگ یا پردازش‌های CPU-محور می‌توانند Event Loop را مسدود کنند.

---

## ۵) تصور اینکه Node.js چندین Thread برای اجرای کد جاوااسکریپت دارد

کد جاوااسکریپت معمولاً روی یک Thread اجرا می‌شود. برخی عملیات مانند File System یا Crypto ممکن است از Thread Pool داخلی libuv استفاده کنند، اما اجرای کد جاوااسکریپت همچنان روی Thread اصلی انجام می‌شود.

---

# نکات حرفه‌ای

* عملیات CPU-محور سنگین را از Thread اصلی دور نگه دارید.
* برای پردازش‌های سنگین از **Worker Threads** یا پردازش‌های جداگانه استفاده کنید.
* تفاوت بین `setTimeout()`، `setImmediate()` و `process.nextTick()` را به‌خوبی بشناسید.
* هنگام دیباگ کردن، همیشه وضعیت Call Stack و صف‌های مختلف را در ذهن تجسم کنید.
* برای جلوگیری از مسدود شدن Event Loop، کارهای طولانی را به بخش‌های کوچک‌تر تقسیم کنید.
* در پروژه‌های واقعی، زمان پاسخ‌گویی Event Loop را پایش کنید تا گلوگاه‌های عملکرد را پیدا کنید.

# پاسخ تشریحی

## پاسخ ۱

خروجی:

```
A
C
B
```

زیرا Callback مربوط به `setTimeout()` بعد از خالی شدن Call Stack اجرا می‌شود.

---

## پاسخ ۲

خروجی:

```
Start
End
Promise
```

Promise وارد Microtask Queue می‌شود و بعد از پایان اجرای کدهای همزمان پردازش خواهد شد.

---

## پاسخ ۳

* **Microtask Queue** برای Promiseها و برخی Callbackهای ویژه استفاده می‌شود و اولویت بالاتری دارد.
* **Callback Queue** برای Callbackهای معمولی مانند Timerها استفاده می‌شود و پس از خالی شدن Microtask Queue پردازش خواهد شد.

---

## پاسخ ۴

زیرا حلقه بی‌نهایت هیچ‌گاه پایان پیدا نمی‌کند و Thread اصلی را اشغال می‌کند. در نتیجه Event Loop نمی‌تواند Callbackهای آماده را اجرا کند.

---

## پاسخ ۵

`setImmediate()` تابعی مخصوص Node.js است که Callback آن در فاز **Check** از Event Loop اجرا می‌شود و معمولاً برای زمان‌بندی اجرای کد پس از پایان فاز Poll استفاده می‌شود.

# مینی‌پروژه

## پروژه: شبیه‌سازی Event Loop

برنامه‌ای بنویسید که ترتیب اجرای انواع مختلف عملیات را نمایش دهد.

### مرحله اول

کد زیر را اجرا کنید و قبل از اجرا، خروجی آن را پیش‌بینی کنید.

```js
console.log("1");

setTimeout(() => {
  console.log("2");
}, 0);

Promise.resolve().then(() => {
  console.log("3");
});

process.nextTick(() => {
  console.log("4");
});

setImmediate(() => {
  console.log("5");
});

console.log("6");
```

### مرحله دوم

کد را تغییر دهید و داخل Callback مربوط به `fs.readFile()` نیز از `setTimeout()` و `setImmediate()` استفاده کنید.

### مرحله سوم

ترتیب اجرای هر بخش را روی کاغذ رسم کنید و توضیح دهید که چرا هر Callback در آن زمان اجرا شده است.

### اهداف پروژه

* درک عملی Event Loop
* شناخت تفاوت Call Stack، Microtask Queue و Callback Queue
* آشنایی با `process.nextTick()`
* آشنایی با `setImmediate()`
* تحلیل ترتیب اجرای عملیات ناهمزمان در Node.js

---

# جمع‌بندی

Event Loop قلب تپنده Node.js است. این مکانیزم باعث می‌شود جاوااسکریپت، با وجود اجرای کد روی یک Thread اصلی، بتواند عملیات ناهمزمان مانند خواندن فایل‌ها، درخواست‌های شبکه، Timerها و Promiseها را به شکلی کارآمد مدیریت کند. درک دقیق Event Loop، Call Stack، صف‌های مختلف و فازهای اجرای Node.js یکی از مهم‌ترین مهارت‌هایی است که برای نوشتن برنامه‌های سریع، مقیاس‌پذیر و بدون باگ به آن نیاز خواهید داشت. این فصل پایه‌ای برای یادگیری مباحث پیشرفته‌تری مانند **Async/Await**، **Streams**، **Worker Threads** و معماری داخلی Node.js است.
