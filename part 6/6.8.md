# فصل ۳۸ - Async / Await (مدیریت کدهای ناهمزمان)

## مقدمه

در فصل قبل با **Promise** آشنا شدیم و دیدیم که چگونه می‌توان عملیات ناهمزمان را با `then()` و `catch()` مدیریت کرد.

اما با بزرگ‌تر شدن برنامه، زنجیره‌های طولانی Promise نیز ممکن است خوانایی کد را کاهش دهند.

برای حل این مشکل، جاوااسکریپت در نسخه **ES2017 (ES8)** قابلیت **Async / Await** را معرفی کرد.

با استفاده از Async / Await می‌توان کدهای ناهمزمان را تقریباً مانند کدهای همزمان نوشت؛ در حالی که در پشت صحنه همچنان از Promise استفاده می‌شود.

امروزه تقریباً تمام پروژه‌های جدید Node.js از Async / Await استفاده می‌کنند.

---

# ۳۸.۱ - Async / Await چیست؟

Async / Await مجموعه‌ای از کلمات کلیدی جاوااسکریپت است که کار با Promiseها را ساده‌تر می‌کند.

نکته مهم:

> Async / Await جایگزین Promise نیست.

بلکه **یک روش ساده‌تر برای کار با Promiseهاست.**

---

# ۳۸.۲ - کلمه کلیدی async

اگر قبل از یک تابع کلمه `async` قرار دهیم:

```js id="u0kz92"
async function hello() {
  return "Hello";
}
```

این تابع همیشه یک Promise برمی‌گرداند.

مثلاً:

```js id="ch8s5v"
hello().then(console.log);
```

خروجی:

```text id="txbqj0"
Hello
```

---

# ۳۸.۳ - مقدار بازگشتی async

```js id="53vth5"
async function sum() {
  return 10;
}
```

معادل:

```js id="vy5n2o"
function sum() {
  return Promise.resolve(10);
}
```

---

# ۳۸.۴ - کلمه کلیدی await

کلمه `await` باعث می‌شود اجرای تابع `async` تا تعیین تکلیف Promise متوقف شود.

مثال:

```js id="5t4m8n"
function getUser() {
  return Promise.resolve("Ali");
}

async function main() {
  const user = await getUser();

  console.log(user);
}

main();
```

---

# ۳۸.۵ - تبدیل Promise به Async / Await

نسخه Promise:

```js id="5h6y4h"
getUser()
  .then((user) => {
    console.log(user);
  });
```

نسخه Async / Await:

```js id="x4x0hg"
async function main() {
  const user = await getUser();

  console.log(user);
}

main();
```

کد دوم معمولاً خواناتر است.

---

# ۳۸.۶ - استفاده از چند await

```js id="a8q0q8"
async function main() {
  const user = await getUser();

  const posts = await getPosts(user);

  console.log(posts);
}
```

کد مانند برنامه‌های همزمان خوانده می‌شود.

---

# ۳۸.۷ - مدیریت خطا

اگر Promise رد (Rejected) شود، `await` یک استثنا (Exception) ایجاد می‌کند.

بنابراین باید از `try...catch` استفاده کنیم.

```js id="4o8gf4"
async function main() {
  try {
    const user = await getUser();

    console.log(user);
  } catch (error) {
    console.error(error.message);
  }
}
```

---

# ۳۸.۸ - استفاده از finally

همانند Promise می‌توان از `finally` در ساختار `try...catch` استفاده کرد.

```js id="1ewv6m"
async function main() {
  try {
    console.log("Working...");
  } catch (error) {
    console.error(error);
  } finally {
    console.log("Finished");
  }
}
```

---

# ۳۸.۹ - await فقط داخل async

اشتباه:

```js id="x76rxb"
const result = await getUser();
```

این کد در بیشتر شرایط معتبر نیست.

درست:

```js id="8xwvzc"
async function main() {
  const result = await getUser();
}
```

> **نکته:** در برخی محیط‌ها و فایل‌های ES Module امکان استفاده از **Top-Level Await** وجود دارد که در ادامه همین فصل با آن آشنا می‌شویم.

---

# ۳۸.۱۰ - اجرای متوالی

```js id="zrnkmg"
const a = await getA();
const b = await getB();
const c = await getC();
```

در این حالت:

* ابتدا `getA`
* سپس `getB`
* سپس `getC`

اجرا می‌شوند.

اگر این عملیات به یکدیگر وابسته باشند، این روش مناسب است.

---

# ۳۸.۱۱ - اجرای همزمان

اگر عملیات مستقل باشند:

```js id="w70xuq"
const [user, posts] = await Promise.all([
  getUser(),
  getPosts()
]);
```

این روش سریع‌تر است.

---

# ۳۸.۱۲ - Async Function همیشه Promise برمی‌گرداند

```js id="ixz4cq"
async function test() {
  return 100;
}
```

در واقع:

```js id="gdxv3i"
Promise.resolve(100);
```

برگردانده می‌شود.

---

# ۳۸.۱۳ - حلقه‌ها و await

اشتباه رایج:

```js id="8p2eyt"
for (const id of ids) {
  await fetchUser(id);
}
```

این کد به صورت **ترتیبی** اجرا می‌شود.

اگر عملیات مستقل باشند، بهتر است از:

```js id="ifx0ti"
await Promise.all(
  ids.map(fetchUser)
);
```

استفاده شود.

---

# ۳۸.۱۴ - Async Arrow Function

```js id="cq5x7k"
const load = async () => {
  return "Done";
};
```

---

# ۳۸.۱۵ - Async Method

```js id="d78p6j"
const userService = {
  async getUser() {
    return {
      name: "Ali"
    };
  }
};
```

---

# ۳۸.۱۶ - Top-Level Await

در فایل‌های **ES Module** می‌توان در بسیاری از موارد بدون تعریف تابع `async` از `await` در سطح فایل استفاده کرد.

مثال:

```js id="w2z5qk"
const config = await loadConfig();

console.log(config);
```

این قابلیت در فایل‌های CommonJS در دسترس نیست.

---

# ۳۸.۱۷ - Async / Await و Event Loop

اگرچه ظاهر کد همزمان است، اما همچنان:

* Promise ساخته می‌شود.
* Event Loop آن را مدیریت می‌کند.
* Callbackها در Microtask Queue قرار می‌گیرند.

بنابراین Async / Await فقط **نحوه نوشتن کد** را تغییر می‌دهد، نه مدل اجرای جاوااسکریپت را.

---

# ۳۸.۱۸ - Async / Await و Node.js

تقریباً تمام APIهای جدید Node.js نسخه Promise دارند.

مثال:

```js id="h4ngje"
const fs = require("fs/promises");

async function read() {
  const text = await fs.readFile("data.txt", "utf8");

  console.log(text);
}
```

این روش خواناتر از Callback است.

---

# ۳۸.۱۹ - چه زمانی از Async / Await استفاده کنیم؟

مناسب برای:

* خواندن فایل
* درخواست HTTP
* ارتباط با دیتابیس
* عملیات شبکه
* کار با Promise

---

# ۳۸.۲۰ - مزایا و معایب

## مزایا

* خوانایی بالا
* مدیریت آسان خطا
* نزدیک بودن ظاهر کد به برنامه‌های همزمان
* مناسب برای پروژه‌های بزرگ

---

## معایب

* فقط با Promise کار می‌کند.
* استفاده نادرست از `await` می‌تواند باعث اجرای ترتیبی و کاهش کارایی شود.
* برای عملیات کاملاً مستقل، استفاده نادرست از `await` پشت سر هم می‌تواند زمان اجرای برنامه را افزایش دهد.

---

# اشتباهات رایج

## ۱) استفاده از await خارج از async

این کار در اکثر شرایط باعث خطا می‌شود، مگر در محیط‌هایی که از Top-Level Await پشتیبانی می‌کنند.

---

## ۲) فراموش کردن try...catch

اگر Promise رد شود و خطا مدیریت نشود، ممکن است برنامه با خطای مدیریت‌نشده مواجه شود.

---

## ۳) استفاده پشت سر هم از await برای عملیات مستقل

این کار باعث کاهش سرعت برنامه می‌شود.

---

## ۴) فراموش کردن await

اشتباه:

```js id="rcklcq"
const user = getUser();
```

اگر `getUser` یک تابع `async` باشد، مقدار `user` یک Promise خواهد بود، نه نتیجه نهایی.

---

## ۵) استفاده از forEach همراه await

اشتباه:

```js id="pf03j9"
users.forEach(async (user) => {
  await save(user);
});
```

متد `forEach` منتظر پایان Callbackهای `async` نمی‌ماند. در چنین شرایطی معمولاً از `for...of` یا `Promise.all()` همراه با `map()` استفاده می‌شود.

---

# نکات حرفه‌ای

* برای عملیات مستقل از `Promise.all()` استفاده کنید.
* همیشه خطاها را با `try...catch` مدیریت کنید.
* اگر نتیجه یک Promise را لازم ندارید، بدون دلیل از `await` استفاده نکنید.
* از نسخه Promise محور APIهای Node.js (مانند `fs/promises`) استفاده کنید.
* در پروژه‌های بزرگ، توابع `async` را کوچک و تک‌مسئولیتی طراحی کنید.
* قبل از استفاده از `await` بررسی کنید که آیا واقعاً لازم است اجرای کد در آن نقطه متوقف شود یا خیر.

# پاسخ تشریحی

## پاسخ ۱

کلمه `async` یک تابع را به تابعی تبدیل می‌کند که همیشه یک Promise برمی‌گرداند.

---

## پاسخ ۲

خروجی:

```text id="8j9d6i"
50
```

زیرا مقدار `50` به صورت خودکار داخل یک Promise موفق (`Promise.resolve(50)`) قرار می‌گیرد.

---

## پاسخ ۳

زیرا اگر Promise رد شود، `await` یک استثنا ایجاد می‌کند و `try...catch` راه استاندارد برای مدیریت آن است.

---

## پاسخ ۴

در حالت اول، دو عملیات به صورت ترتیبی اجرا می‌شوند.

در حالت دوم، هر دو عملیات به صورت همزمان آغاز می‌شوند و سپس برنامه منتظر پایان هر دو می‌ماند.

---

## پاسخ ۵

زیرا `forEach` منتظر پایان Callbackهای `async` نمی‌ماند و کنترل مناسبی روی ترتیب و پایان اجرای Promiseها فراهم نمی‌کند.

---

# مینی‌پروژه

## پروژه: مدیریت فایل‌ها با Async / Await

یک برنامه Node.js بنویسید که با استفاده از ماژول `fs/promises` چند فایل متنی را بخواند.

### مرحله اول

یک فایل را بخوانید و محتوای آن را نمایش دهید.

```js id="8xyffv"
const fs = require("fs/promises");

async function readFile() {
  const content = await fs.readFile("data.txt", "utf8");

  console.log(content);
}

readFile();
```

### مرحله دوم

دو فایل مستقل را با `Promise.all()` به صورت همزمان بخوانید.

### مرحله سوم

در صورت وجود خطا (مثلاً نبودن فایل)، آن را با `try...catch` مدیریت کنید.

### مرحله چهارم

محتوای فایل‌ها را ترکیب کرده و در یک فایل جدید ذخیره کنید.

### اهداف پروژه

* تمرین نوشتن توابع `async`
* استفاده از `await`
* مدیریت خطا با `try...catch`
* استفاده از `Promise.all()`
* کار با `fs/promises`
* درک تفاوت اجرای ترتیبی و همزمان

---

# جمع‌بندی

Async / Await یکی از مهم‌ترین قابلیت‌های مدرن جاوااسکریپت است که بر پایه Promise ساخته شده و نوشتن کدهای ناهمزمان را بسیار ساده‌تر و خواناتر می‌کند. با استفاده از `async`، توابع همیشه Promise برمی‌گردانند و با `await` می‌توان منتظر نتیجه آن‌ها ماند، بدون اینکه از زنجیره‌های طولانی `then()` استفاده شود. با این حال، برای نوشتن کدهای بهینه باید تفاوت بین اجرای ترتیبی و همزمان را به‌خوبی درک کرد و در کنار `await` از ابزارهایی مانند `Promise.all()` نیز در زمان مناسب بهره برد.
