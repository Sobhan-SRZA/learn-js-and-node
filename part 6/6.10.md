# فصل 40 - Module System

در پروژه‌های کوچک ممکن است تمام کدها را در یک فایل بنویسیم.

اما وقتی یک پروژه واقعی Node.js ساخته می‌شود، معمولاً شامل:

* صدها فایل
* هزاران خط کد
* بخش‌های مختلف مانند Database، API، Authentication و Utilityها

است.

اگر همه چیز داخل یک فایل باشد:

* نگهداری سخت می‌شود.
* پیدا کردن خطاها دشوار می‌شود.
* توسعه پروژه کند می‌شود.

برای حل این مشکل از **Module System** استفاده می‌کنیم.

---

# Module چیست؟

Module یعنی تقسیم کردن برنامه به بخش‌های کوچک‌تر و مستقل.

هر Module می‌تواند شامل:

* متغیرها
* توابع
* کلاس‌ها
* آبجکت‌ها

باشد و قسمت‌های مورد نیاز را در اختیار فایل‌های دیگر قرار دهد.

مثلاً:

```
project
│
├── app.js
│
├── math.js
│
└── user.js
```

فایل `math.js` می‌تواند توابع ریاضی داشته باشد.

فایل `app.js` می‌تواند از آن استفاده کند.

# انواع Module در Node.js

Node.js دو سیستم اصلی برای Module دارد:

1. CommonJS
2. ES Modules

---

# بخش اول - CommonJS

CommonJS سیستم ماژول قدیمی‌تر Node.js است.

این سیستم از ابتدا در Node.js استفاده می‌شد.

دو دستور اصلی دارد:

* require
* module.exports

---

# module.exports

برای خروجی دادن اطلاعات از یک فایل استفاده می‌کنیم.

مثلاً:

فایل:

```
math.js
```

```js
function sum(a, b) {
    return a + b;
}

module.exports = sum;
```

---

حالا در فایل دیگر:

```
app.js
```

```js
const sum = require("./math");

console.log(sum(5, 3));
```

خروجی:

```
8
```

---

# Export کردن چند مقدار

می‌توانیم چند مقدار را ارسال کنیم.

```js
function sum(a, b) {
    return a + b;
}


function multiply(a, b) {
    return a * b;
}


module.exports = {
    sum,
    multiply
};
```

---

استفاده:

```js
const math = require("./math");


console.log(math.sum(2, 3));

console.log(math.multiply(4, 5));
```

خروجی:

```
5
20
```

---

# Destructuring با require

به جای:

```js
const math = require("./math");


math.sum(2,3);
```

می‌توانیم بنویسیم:

```js
const {
    sum,
    multiply
} = require("./math");


console.log(sum(2,3));
```

---

# تغییر نام هنگام Import

```js
const {
    sum: add
} = require("./math");


console.log(add(5,5));
```

---

# Export کردن متغیر

```js
const version = "1.0.0";


module.exports = version;
```

استفاده:

```js
const version = require("./config");

console.log(version);
```

---

# Export کردن Object

```js
module.exports = {

    name: "Node.js",

    version: 22

};
```

# require

برای وارد کردن Module استفاده می‌شود.

ساختار:

```js
const moduleName = require("module");
```

---

## Module داخلی Node.js

Node.js دارای Moduleهای داخلی است.

مثال:

```js
const fs = require("fs");
```

یا:

```js
const path = require("path");
```

---

# Moduleهای داخلی معروف Node.js

| Module | کاربرد        |
| ------ | ------------- |
| fs     | کار با فایل‌ها |
| path   | مسیر فایل‌ها   |
| http   | ساخت سرور     |
| events | Event System  |
| os     | اطلاعات سیستم |
| crypto | رمزنگاری      |
| url    | مدیریت URL    |

---


# ES Modules

ES Modules یا ESM سیستم استاندارد جاوااسکریپت است.

این سیستم در مرورگرها و Node.js جدید استفاده می‌شود.

به جای:

```js
require()
```

از:

```js
import
```

استفاده می‌کنیم.

---

# فعال کردن ES Modules در Node.js

دو روش وجود دارد.

---

## روش اول: package.json

در فایل:

```
package.json
```

قرار می‌دهیم:

```json
{
    "type": "module"
}
```

---

حالا Node.js فایل‌ها را به صورت ESM اجرا می‌کند.

---

## روش دوم

استفاده از پسوند:

```
.mjs
```

مثال:

```
app.mjs
```

---

# Export در ES Modules

مثال:

```js
export function sum(a,b){

    return a+b;

}
```

---

Import:

```js
import {
    sum
} from "./math.js";


console.log(sum(2,5));
```

---

# Export Default

هر فایل فقط یک default export می‌تواند داشته باشد.

مثال:

```js
export default function hello(){

    console.log("Hello");

}
```

---

استفاده:

```js
import hello from "./hello.js";


hello();
```

---

# تفاوت export و export default

## Named Export

```js
export function test(){

}
```

استفاده:

```js
import {
    test
}
from "./file.js";
```

---

## Default Export

```js
export default test;
```

استفاده:

```js
import test from "./file.js";
```

---

# Export چند مقدار در ESM

```js
const name = "Node";

const version = 22;


export {
    name,
    version
};
```

---

Import:

```js
import {
    name,
    version
}
from "./config.js";
```

---

# Alias در ES Modules

```js
import {
    name as appName
}
from "./config.js";
```

---

# Import کردن همه چیز

```js
import * as utils from "./utils.js";


utils.test();
```

---

# تفاوت CommonJS و ES Modules

| CommonJS             | ES Modules                   |
| -------------------- | ---------------------------- |
| require              | import                       |
| module.exports       | export                       |
| سیستم قدیمی Node.js  | استاندارد JavaScript         |
| synchronous loading  | طراحی شده برای async loading |
| پیش‌فرض قدیمی Node.js | استاندارد جدید               |

# اشتباهات رایج

## 1. ترکیب CommonJS و ES Modules

اشتباه:

```js
import express from "express";

const fs = require("fs");
```

بهتر است یک روش را انتخاب کنید.

---

## 2. فراموش کردن پسوند فایل در ESM

اشتباه:

```js
import user from "./user";
```

در ESM:

```js
import user from "./user.js";
```

---

## 3. استفاده اشتباه از default export

اشتباه:

```js
export default {

}
```

و بعد:

```js
import {
    data
}
from "./file.js";
```

Default با `{}` وارد نمی‌شود.

---

## 4. مسیر اشتباه Module

اشتباه:

```js
require("./math")
```

وقتی فایل وجود ندارد.

---

## 5. ساخت Moduleهای خیلی بزرگ

اگر یک فایل:

```
5000 lines
```

دارد، احتمالاً باید تقسیم شود.

---

# نکات حرفه‌ای

* در پروژه‌های جدید Node.js بهتر است ESM را یاد بگیرید.
* همیشه Moduleها را کوچک و مسئولیت‌محور طراحی کنید.
* از نام‌های واضح برای فایل‌ها استفاده کنید.
* Utilityهای مشترک را جدا کنید.
* Circular Dependency ایجاد نکنید.
* قبل از export کردن همه چیز، فقط چیزهای مورد نیاز را export کنید.
* ساختار پروژه را بر اساس مسئولیت‌ها تقسیم کنید.
* در پروژه‌های بزرگ از Layer Architecture استفاده کنید.
