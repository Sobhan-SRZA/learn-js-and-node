# فصل ۳۲ - Call Stack

## مقدمه

جاوااسکریپت یک زبان **Single Threaded** است؛ یعنی در هر لحظه فقط **یک کار** را اجرا می‌کند. اما اگر فقط یک کار را می‌تواند انجام دهد، پس چگونه می‌تواند هزاران تابع را مدیریت کند؟

پاسخ این سؤال در مفهومی به نام **Call Stack** یا **پشته فراخوانی** قرار دارد.

Call Stack مشخص می‌کند:

* در حال حاضر کدام تابع در حال اجراست.
* بعد از پایان اجرای یک تابع، اجرای برنامه از کجا ادامه پیدا کند.
* توابع با چه ترتیبی اجرا شوند.
* چرا گاهی با خطای **Maximum Call Stack Size Exceeded** مواجه می‌شویم.

در این فصل به صورت کامل با نحوه کار Call Stack در جاوااسکریپت و نود جی‌اس آشنا می‌شویم.

---

# ۳۲.۱ - Call Stack چیست؟

Call Stack ساختاری از نوع **Stack (پشته)** است که موتور جاوااسکریپت برای مدیریت اجرای توابع از آن استفاده می‌کند.

پشته فقط دو عملیات اصلی دارد:

* Push (قرار دادن روی پشته)
* Pop (برداشتن از روی پشته)

به همین دلیل آخرین تابعی که وارد Stack می‌شود، اولین تابعی است که از آن خارج می‌شود.

به این رفتار می‌گویند:

> **LIFO (Last In First Out)**

یعنی:

آخرین وارد شده → اولین خارج شده

---

# ۳۲.۲ - اولین عضو Stack

هنگام شروع اجرای برنامه، موتور جاوااسکریپت ابتدا **Global Execution Context** را روی Call Stack قرار می‌دهد.

مثال:

```js
console.log("Start");
```

Call Stack:

```
Global
```

پس از پایان اجرای برنامه:

```
Empty
```

---

# ۳۲.۳ - ورود توابع به Stack

هر بار که یک تابع فراخوانی می‌شود، یک **Function Execution Context** ساخته شده و روی Stack قرار می‌گیرد.

مثال:

```js
function hello() {
  console.log("Hello");
}

hello();
```

ترتیب Stack:

ابتدا:

```
Global
```

بعد از اجرای hello:

```
hello()
Global
```

بعد از پایان hello:

```
Global
```

پایان برنامه:

```
Empty
```

---

# ۳۲.۴ - مثال مرحله به مرحله

```js
function first() {
  console.log("First");
}

console.log("A");

first();

console.log("B");
```

روند اجرا:

شروع برنامه:

```
Global
```

اجرای:

```js
console.log("A");
```

Stack:

```
console.log()
Global
```

بعد از چاپ:

```
Global
```

اجرای:

```js
first();
```

```
first()
Global
```

داخل first:

```
console.log()
first()
Global
```

بعد از پایان:

```
first()
Global
```

سپس:

```
Global
```

در نهایت:

```
console.log()
Global
```

و در پایان:

```
Empty
```

---

# ۳۲.۵ - توابع تو در تو

```js
function one() {
  two();
}

function two() {
  three();
}

function three() {
  console.log("Done");
}

one();
```

ترتیب Stack:

```
Global
```

↓

```
one()
Global
```

↓

```
two()
one()
Global
```

↓

```
three()
two()
one()
Global
```

↓

```
console.log()
three()
two()
one()
Global
```

سپس همه به ترتیب خارج می‌شوند.

---

# ۳۲.۶ - چرا Stack مهم است؟

فرض کنید داخل یک تابع، ده تابع دیگر صدا زده شود.

جاوااسکریپت باید بداند:

* الان کجاست؟
* بعد از پایان تابع فعلی به کجا برگردد؟
* چه کسی منتظر نتیجه است؟

تمام این اطلاعات داخل Call Stack نگهداری می‌شود.

---

# ۳۲.۷ - رفتار Push و Pop

مثال:

```js
function a() {}

function b() {}

a();
b();
```

ابتدا:

```
Global
```

اجرای a:

```
a()
Global
```

پایان:

```
Global
```

اجرای b:

```
b()
Global
```

پایان:

```
Global
```

---

# ۳۲.۸ - ارتباط Call Stack با Execution Context

هر بار که تابعی اجرا می‌شود:

* Execution Context ساخته می‌شود.
* روی Call Stack قرار می‌گیرد.
* اجرا می‌شود.
* پس از پایان حذف می‌شود.

بنابراین:

Execution Context محتوای اجراست.

Call Stack محل نگهداری این Contextهاست.

---

# ۳۲.۹ - Recursion و Call Stack

بازگشت یا **Recursion** یعنی یک تابع خودش را دوباره صدا بزند.

مثال:

```js
function count(n) {
  console.log(n);

  if (n === 0) {
    return;
  }

  count(n - 1);
}

count(3);
```

Stack:

```
count(3)
Global
```

↓

```
count(2)
count(3)
Global
```

↓

```
count(1)
count(2)
count(3)
Global
```

↓

```
count(0)
count(1)
count(2)
count(3)
Global
```

بعد از رسیدن به شرط توقف، توابع یکی‌یکی از Stack خارج می‌شوند.

---

# ۳۲.۱۰ - خطای Stack Overflow

اگر Recursion شرط پایان نداشته باشد:

```js
function loop() {
  loop();
}

loop();
```

تابع همیشه خودش را صدا می‌زند.

در نتیجه Stack پر می‌شود.

و در نهایت با خطایی شبیه زیر روبه‌رو می‌شویم:

```
RangeError:
Maximum call stack size exceeded
```

---

# ۳۲.۱۱ - مثال واقعی Stack Overflow

```js
function print() {
  console.log("Hi");
  print();
}

print();
```

هر بار اجرای تابع:

* یک Execution Context جدید
* یک Push جدید
* بدون هیچ Pop

در نتیجه حافظه Stack تمام می‌شود.

---

# ۳۲.۱۲ - چگونه از Stack Overflow جلوگیری کنیم؟

همیشه برای Recursion شرط توقف بنویسید.

درست:

```js
function countdown(n) {
  if (n === 0) {
    return;
  }

  console.log(n);

  countdown(n - 1);
}

countdown(5);
```

---

# ۳۲.۱۳ - Call Stack و خطاها

وقتی برنامه خطا می‌دهد، نود جی‌اس معمولاً Stack Trace را نمایش می‌دهد.

مثال:

```js
function a() {
  b();
}

function b() {
  c();
}

function c() {
  throw new Error("Boom");
}

a();
```

خروجی مشابه:

```
Error: Boom

at c()

at b()

at a()
```

Stack Trace دقیقاً نشان می‌دهد که برنامه از چه مسیرهایی عبور کرده است.

---

# ۳۲.۱۴ - Stack Trace چیست؟

Stack Trace لیستی از تمام توابعی است که تا لحظه وقوع خطا در Stack قرار داشته‌اند.

به کمک آن می‌توان فهمید:

* خطا از کجا شروع شده.
* چه تابعی آن را فراخوانی کرده.
* مسیر اجرای برنامه چه بوده است.

در دیباگ کردن برنامه‌ها، Stack Trace یکی از مهم‌ترین ابزارهاست.

---

# ۳۲.۱۵ - مشاهده Stack در Node.js

در نود جی‌اس می‌توان Stack فعلی را مشاهده کرد.

مثال:

```js
function first() {
  second();
}

function second() {
  console.trace();
}

first();
```

خروجی مسیر اجرای فعلی را نمایش می‌دهد.

---

# ۳۲.۱۶ - Call Stack و عملیات ناهمزمان

گاهی تصور می‌شود که Call Stack هم‌زمان چند تابع را اجرا می‌کند.

این تصور اشتباه است.

عملیات ناهمزمان مانند:

* Timer
* Promise
* File System
* Network

ابتدا از Stack خارج می‌شوند و بعداً توسط **Event Loop** دوباره وارد Stack خواهند شد.

در فصل Event Loop این موضوع را کامل بررسی خواهیم کرد.

---

# ۳۲.۱۷ - خلاصه روند اجرای یک تابع

برای هر تابع این مراحل انجام می‌شود:

۱. تابع فراخوانی می‌شود.

۲. Execution Context ساخته می‌شود.

۳. روی Call Stack قرار می‌گیرد.

۴. کد اجرا می‌شود.

۵. مقدار بازگردانده می‌شود.

۶. Context از Stack حذف می‌شود.

---

# اشتباهات رایج

## ۱) تصور اینکه Call Stack همان حافظه برنامه است

خیر.

Call Stack فقط محل نگهداری Contextهای فعال است.

---

## ۲) اشتباه گرفتن Stack با Heap

Stack برای اجرای توابع است.

Heap برای ذخیره داده‌ها و اشیاء استفاده می‌شود.

---

## ۳) نوشتن Recursion بدون شرط پایان

این کار باعث Stack Overflow می‌شود.

---

## ۴) تصور اجرای همزمان چند تابع

جاوااسکریپت در یک Thread فقط یک Context را اجرا می‌کند.

---

## ۵) نادیده گرفتن Stack Trace

بسیاری از برنامه‌نویسان فقط متن خطا را می‌خوانند، در حالی که مسیر واقعی خطا داخل Stack Trace قرار دارد.

---

# نکات حرفه‌ای

* هنگام دیباگ کردن همیشه Stack Trace را از پایین به بالا بخوانید.
* توابع کوچک و کوتاه، درک Stack را بسیار آسان‌تر می‌کنند.
* برای جلوگیری از Recursionهای خطرناک همیشه شرط پایان بنویسید.
* اگر عمق Recursion زیاد است، گاهی استفاده از حلقه (`for` یا `while`) مناسب‌تر است.
* `console.trace()` ابزار بسیار مفیدی برای مشاهده مسیر اجرای برنامه است.
* هنگام خواندن کد، همیشه سعی کنید Stack را در ذهن خود شبیه‌سازی کنید.

# مینی‌پروژه

## پروژه: شبیه‌ساز Call Stack

برنامه‌ای بنویسید که چند تابع تو در تو را اجرا کند و ورود و خروج هر تابع را با `console.log` نمایش دهد.

ساختار پیشنهادی:

```js
function first() {
  console.log("Enter first");

  second();

  console.log("Exit first");
}

function second() {
  console.log("Enter second");

  third();

  console.log("Exit second");
}

function third() {
  console.log("Enter third");

  console.log("Working...");

  console.log("Exit third");
}

first();
```

### اهداف پروژه

* درک ترتیب Push و Pop
* مشاهده ترتیب واقعی اجرای توابع
* تمرین شبیه‌سازی Call Stack
* آشنایی بیشتر با Execution Context

### تمرین تکمیلی

این پروژه را توسعه دهید و تابع چهارم و پنجم را نیز اضافه کنید. سپس قبل از اجرای برنامه، ترتیب ورود و خروج هر تابع را روی کاغذ پیش‌بینی کنید و در پایان نتیجه را با خروجی واقعی مقایسه کنید.

---

# جمع‌بندی

Call Stack قلب سیستم اجرای جاوااسکریپت است. هر بار که تابعی فراخوانی می‌شود، یک **Execution Context** جدید ساخته شده و روی این پشته قرار می‌گیرد. با پایان اجرای تابع، Context از Stack حذف می‌شود و اجرای برنامه از محل مناسب ادامه پیدا می‌کند.

درک دقیق Call Stack نه‌تنها برای فهم توابع و بازگشت (Recursion) ضروری است، بلکه پایه‌ای برای یادگیری مباحث پیشرفته‌تری مانند **Event Loop**، **Callback Queue**، **Microtask Queue** و برنامه‌نویسی ناهمزمان در نود جی‌اس محسوب می‌شود.
