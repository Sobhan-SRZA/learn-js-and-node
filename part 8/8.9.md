# فصل 59 - File System (fs)

## مقدمه

تقریباً هیچ برنامه‌ای وجود ندارد که با فایل‌ها سروکار نداشته باشد.

برای مثال:

* ذخیره اطلاعات کاربران
* خواندن فایل‌های تنظیمات
* آپلود فایل
* دانلود فایل
* ذخیره لاگ‌ها
* ساخت فایل PDF
* پردازش تصاویر
* ساخت فایل‌های گزارش
* مدیریت نسخه‌های پشتیبان (Backup)

Node.js برای انجام تمام این کارها ماژولی داخلی به نام **File System** یا **`fs`** در اختیار ما قرار داده است.

این ماژول یکی از پرکاربردترین ماژول‌های Node.js است و تقریباً در تمام پروژه‌های واقعی از آن استفاده می‌شود.

در این فصل با تمام قابلیت‌های مهم `fs` آشنا می‌شویم.

---

# 59.1 - ماژول fs

برای استفاده از `fs` ابتدا باید آن را وارد کنیم.

```js
const fs = require("fs");
```

از نسخه‌های جدید Node.js، نسخه Promise-Based نیز وجود دارد.

```js
const fs = require("fs/promises");
```

یا:

```js
const { promises: fs } = require("fs");
```

در پروژه‌های جدید معمولاً استفاده از نسخه Promise-Based همراه با `async/await` پیشنهاد می‌شود.

---

# 59.2 - Sync و Async

تقریباً تمام متدهای `fs` دو نسخه دارند.

نسخه همگام:

```js
fs.readFileSync();
```

نسخه غیرهمگام:

```js
fs.readFile();
```

در پروژه‌های واقعی تقریباً همیشه نسخه Async انتخاب بهتری است.

# 59.9 - بررسی وجود فایل

در گذشته از `fs.exists()` استفاده می‌شد که اکنون منسوخ شده است.

روش مناسب‌تر:

```js
fs.access(
    "data.txt",
    (err) => {

        if (err) {

            console.log("File Not Found");

            return;

        }

        console.log("File Exists");

    }
);
```

# 59.19 - Watch

```js
fs.watch(
    ".",
    (event, filename) => {

        console.log(
            event,
            filename
        );

    }
);
```

این متد تغییرات فایل‌ها یا پوشه‌ها را پایش می‌کند.

رفتار `fs.watch()` ممکن است در سیستم‌عامل‌های مختلف کمی متفاوت باشد؛ بنابراین در پروژه‌های حساس باید این موضوع را در نظر گرفت.

# 59.21 - Sync یا Async؟

| Sync                  | Async              |
| --------------------- | ------------------ |
| Thread را متوقف می‌کند | غیرمسدودکننده      |
| ساده‌تر                | مناسب پروژه واقعی  |
| کندتر در سرور         | مقیاس‌پذیرتر        |
| مناسب اسکریپت‌های کوچک | مناسب API و Server |

---

# 59.22 - اشتباهات رایج

### 1) استفاده از نسخه Sync در سرور

متدهای همگام باعث مسدود شدن Thread اصلی می‌شوند.

---

### 2) فراموش کردن مدیریت خطا

```js
if (err) {

    return;

}
```

همیشه خطاهای مربوط به فایل را بررسی کنید.

---

### 3) استفاده از مسیرهای نسبی بدون دقت

مسیرهای نسبی به پوشه جاری برنامه وابسته هستند. استفاده از `path.join()` و `__dirname` (در CommonJS) یا معادل آن در ES Modules، احتمال خطا را کاهش می‌دهد.

---

### 4) استفاده از `readFile()` برای فایل‌های بزرگ

در این حالت کل فایل وارد حافظه می‌شود.

برای فایل‌های بزرگ از Stream استفاده کنید.

---

### 5) استفاده از APIهای منسوخ

برای مثال، به‌جای `fs.exists()` از `fs.access()` استفاده کنید.

---

# 59.23 - نکات حرفه‌ای

* در پروژه‌های جدید از `fs/promises` همراه با `async/await` استفاده کن.
* برای فایل‌های حجیم از Stream استفاده کن.
* همیشه مسیرها را با ماژول `path` بساز.
* قبل از حذف یا تغییر فایل، خطاها را مدیریت کن.
* از `fs.rm()` به‌جای APIهای قدیمی برای حذف پوشه‌های غیرخالی استفاده کن.
* در عملیات حساس، از نوشتن مستقیم روی فایل اصلی خودداری کن و ابتدا روی فایل موقت بنویس.
* برای پروژه‌های بزرگ، لاگ‌ها را به‌صورت Stream ذخیره کن تا مصرف حافظه کاهش یابد.

# 59.26 - مینی‌پروژه

## ساخت سیستم مدیریت فایل

در این پروژه، یک فایل گزارش ایجاد می‌کنیم، اطلاعاتی به آن اضافه می‌کنیم و سپس محتوای آن را نمایش می‌دهیم.

```js
const fs = require("fs");

fs.writeFile(
    "log.txt",
    "Application Started\n",
    (err) => {

        if (err) {

            return console.error(err);

        }

        fs.appendFile(
            "log.txt",
            "User Logged In\n",
            (err) => {

                if (err) {

                    return console.error(err);

                }

                fs.readFile(
                    "log.txt",
                    "utf8",
                    (err, data) => {

                        if (err) {

                            return console.error(err);

                        }

                        console.log(data);

                    }
                );

            }
        );

    }
);
```

نمونه خروجی:

```text
Application Started
User Logged In
```

# 59.27 - پروژه کامل

## ساخت File Manager

در این پروژه یک برنامه مدیریت فایل می‌سازیم که بتواند:

* فایل ایجاد کند.
* فایل را بخواند.
* فایل را ویرایش کند.
* فایل را حذف کند.
* فایل را کپی کند.
* نام فایل را تغییر دهد.
* اطلاعات فایل را نمایش دهد.
* محتویات پوشه را نمایش دهد.

### ساختار پروژه

```text
file-manager/
│
├── app.js
├── files/
└── backup/
```

### نمونه پیاده‌سازی

```js
const fs = require("fs");
const path = require("path");

const source = path.join(__dirname, "files", "note.txt");
const backup = path.join(__dirname, "backup", "note.txt");

fs.copyFile(source, backup, (err) => {
    if (err) {
        return console.error(err);
    }

    console.log("Backup created successfully.");
});
```

### قابلیت‌های پیشنهادی

* استفاده از `process.argv` برای دریافت دستورات
* پشتیبانی از دستورهای `create`، `read`، `copy`، `delete` و `rename`
* استفاده از `fs/promises` و `async/await`
* ثبت تمام عملیات در فایل `logs.txt`
* بررسی وجود فایل قبل از انجام عملیات
* نمایش پیام‌های خطای مناسب
* استفاده از Stream برای کپی فایل‌های حجیم

# 59.28 - جمع‌بندی

ماژول **File System (`fs`)** یکی از مهم‌ترین و پرکاربردترین ماژول‌های داخلی Node.js است. با استفاده از آن می‌توان فایل‌ها و پوشه‌ها را ایجاد، خواند، ویرایش، حذف، کپی و مدیریت کرد. همچنین با بهره‌گیری از نسخه Promise-Based، Streamها و ماژول `path` می‌توان برنامه‌هایی سریع، ایمن و مقیاس‌پذیر برای کار با سیستم فایل توسعه داد. تسلط بر `fs` یکی از مهارت‌های ضروری هر توسعه‌دهنده Node.js محسوب می‌شود.
