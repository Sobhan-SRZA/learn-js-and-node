# فصل 64 - Timers

## مقدمه

یکی از قابلیت‌های مهم در برنامه‌نویسی، اجرای دستورات در زمان مشخص یا با فاصله زمانی مشخص است.

در برنامه‌های واقعی Node.js بارها نیاز داریم که:

* یک عملیات بعد از چند ثانیه اجرا شود.
* یک کار به صورت دوره‌ای انجام شود.
* یک Cache بعد از مدت مشخص پاک شود.
* وضعیت یک سرویس بررسی شود.
* یک Job زمان‌بندی شود.
* عملیات پس‌زمینه انجام شود.

Node.js برای مدیریت زمان‌بندی عملیات‌ها چند ابزار داخلی در اختیار ما قرار می‌دهد:

* `setTimeout`
* `setInterval`
* `setImmediate`
* `clearTimeout`
* `clearInterval`
* `clearImmediate`

این قابلیت‌ها بخشی از معماری Event Loop در Node.js هستند و درک صحیح آن‌ها برای برنامه‌نویسی Async ضروری است.

در Node.js این قابلیت‌ها به صورت Global در دسترس هستند.

یعنی بدون Import می‌توانیم استفاده کنیم:


# 64.2 - setTimeout چیست؟

`setTimeout` یک تابع را بعد از مدت زمان مشخص اجرا می‌کند.

ساختار:

```js id="9r2p2c"

    callback,
    delay
);
```

مثال:

```js id="8e4z9a"
setTimeout(() => {

    console.log(
        "Executed after 2 seconds"
    );

}, 2000);
```

خروجی بعد از ۲ ثانیه:

```text id="7i8d4a"
Executed after 2 seconds
```

# 64.10 - Timers و Event Loop

Node.js عملیات Timer را در مرحله مخصوصی از Event Loop بررسی می‌کند.

چرخه ساده:

```text id="3x8v9s"

Timers

↓

Pending Callbacks

↓

Poll

↓

Check

↓

Close Callbacks

```

`setTimeout` در مرحله Timers بررسی می‌شود.

`setImmediate` در مرحله Check اجرا می‌شود.

# 64.11 - استفاده از async/await با Timer

یک الگوی بسیار کاربردی:

```js id="2h8f7p"
function delay(ms){

    return new Promise(resolve => {

        setTimeout(
            resolve,
            ms
        );

    });

}


async function main(){

    console.log("Start");


    await delay(2000);


    console.log("After 2 seconds");

}


main();
```

# 64.15 - تفاوت setInterval و Recursive Timeout

## setInterval

```js
setInterval(task,1000);
```

ممکن است:

* عملیات قبلی تمام نشده باشد.
* عملیات‌ها روی هم بیفتند.

---

## Recursive Timeout

```js
function task(){

    doWork();

    setTimeout(
        task,
        1000
    );

}
```

بعد از پایان عملیات زمان بعدی تنظیم می‌شود.

# 64.17 - اشتباهات رایج

## 1) تصور اینکه Timer دقیق است


## 2) فراموش کردن پاک کردن Interval

```js

```

```js

```

می‌تواند باعث مصرف منابع شود.

## 3) اجرای عملیات سنگین داخل Timer

```js

    heavyCalculation();

},1000);
```

## 4) استفاده زیاد از setTimeout برای جایگزین Thread

## 5) نگه داشتن Referenceهای غیرضروری

Timerهای بلااستفاده باید پاک شوند.

# 64.18 - نکات حرفه‌ای

* Timer را ابزار دقیق زمان‌بندی در نظر نگیر.
* برای Jobهای مهم از ابزارهایی مانند Queue یا Scheduler استفاده کن.
* همیشه Intervalهای طولانی را مدیریت کن.
* برای عملیات‌های طولانی Recursive Timeout بهتر است.
* Timerهای فعال را در Shutdown برنامه پاک کن.
* برای Retryها از Backoff Strategy استفاده کن.
* از Timer برای جلوگیری از Block شدن Event Loop استفاده نکن؛ عملیات سنگین باید جدا مدیریت شود.

# 64.22 - پروژه کامل

## ساخت Task Scheduler ساده

در این پروژه یک سیستم زمان‌بندی Task می‌سازیم.

قابلیت‌ها:

* اضافه کردن Task
* اجرای Task بعد از زمان مشخص
* حذف Task
* مدیریت Timerها

ساختار:

```text
task-scheduler/

│
├── app.js
```

---

نمونه:

```js id="qz8m4p"
class Scheduler {


constructor(){

this.tasks=[];

}


add(task,time){

const id =
setTimeout(()=>{

task();

},time);


this.tasks.push(id);

}


cancel(id){

clearTimeout(id);

}


}


const scheduler =
new Scheduler();


scheduler.add(()=>{

console.log(
"Backup Completed"
);

},5000);
```

# جمع‌بندی

ماژول Timer در Node.js یکی از بخش‌های مهم Async Programming است. ابزارهایی مانند `setTimeout`، `setInterval` و `setImmediate` به ما اجازه می‌دهند عملیات‌ها را در زمان مناسب اجرا کنیم.

درک Timers به همراه Event Loop برای ساخت برنامه‌های حرفه‌ای Node.js ضروری است؛ زیرا بسیاری از سیستم‌های واقعی مانند Queueها، Schedulerها، Cacheها و عملیات‌های پس‌زمینه بر پایه همین مفاهیم ساخته می‌شوند.
