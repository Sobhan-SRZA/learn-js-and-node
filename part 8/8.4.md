# فصل 54 - libuv

## مقدمه

اگر بخواهیم فقط یک کتابخانه را به‌عنوان مهم‌ترین بخش Node.js بعد از موتور V8 معرفی کنیم، بدون شک آن **libuv** است.

بسیاری از قابلیت‌هایی که Node.js را سریع و محبوب کرده‌اند، بدون libuv وجود نداشتند.

برای مثال:

* خواندن فایل‌ها به‌صورت غیرهمگام
* نوشتن فایل‌ها
* مدیریت هزاران اتصال شبکه
* اجرای تایمرها
* مدیریت Event Loop
* استفاده از Thread Pool
* اجرای عملیات I/O بدون مسدود کردن Thread اصلی

در واقع، **V8 فقط کد JavaScript را اجرا می‌کند**، اما این **libuv** است که امکان اجرای عملیات غیرهمگام (Asynchronous I/O) را فراهم می‌کند.

در این فصل، با libuv، وظایف آن، ارتباطش با Event Loop و Thread Pool و نقش آن در معماری Node.js آشنا می‌شویم.

---

# 54.1 - libuv چیست؟

**libuv** یک کتابخانه متن‌باز (Open Source) است که با زبان C نوشته شده است.

Node.js از libuv برای مدیریت عملیات غیرهمگام استفاده می‌کند.

به بیان ساده:

> libuv واسطه‌ای بین Node.js و سیستم‌عامل است.

این کتابخانه وظایف مربوط به I/O، تایمرها، شبکه و Event Loop را مدیریت می‌کند.

---

# 54.2 - چرا libuv ساخته شد؟

سیستم‌عامل‌های مختلف APIهای متفاوتی برای انجام عملیات ورودی/خروجی دارند.

برای مثال:

* Linux
* Windows
* macOS

هرکدام روش متفاوتی برای مدیریت فایل‌ها، شبکه و تایمرها دارند.

libuv این تفاوت‌ها را پنهان می‌کند و یک رابط یکسان در اختیار Node.js قرار می‌دهد.

در نتیجه، کد Node.js بدون تغییر روی سیستم‌عامل‌های مختلف اجرا می‌شود.

---

# 54.3 - جایگاه libuv در معماری Node.js

```text id="uvarch01"
JavaScript Code
        │
        ▼
     V8 Engine
        │
        ▼
   Node.js Runtime
        │
        ▼
       libuv
        │
        ▼
 Operating System
```

V8 مسئول اجرای JavaScript است، اما هر زمان نیاز به کار با فایل، شبکه یا عملیات زمان‌بر باشد، Node.js از libuv کمک می‌گیرد.

---

# 54.4 - وظایف اصلی libuv

مهم‌ترین وظایف libuv عبارت‌اند از:

* مدیریت Event Loop
* مدیریت عملیات File System
* مدیریت Socketها
* مدیریت Timerها
* مدیریت Thread Pool
* مدیریت DNS
* اجرای عملیات Async I/O
* ارتباط با سیستم‌عامل

---

# 54.5 - اولین مثال

```js id="libuv01"
const fs = require("fs");

console.log("Start");

fs.readFile("data.txt", "utf8", (err, data) => {
    console.log("File Loaded");
});

console.log("End");
```

خروجی:

```text id="libuv02"
Start
End
File Loaded
```

چه اتفاقی افتاد؟

1. JavaScript درخواست خواندن فایل را ثبت کرد.
2. Node.js آن را به libuv سپرد.
3. libuv عملیات را انجام داد.
4. پس از پایان، Callback را به Event Loop تحویل داد.
5. Event Loop آن را اجرا کرد.

---

---

# 54.7 - عملیات I/O

عملیات I/O شامل هر نوع تبادل اطلاعات با منابع خارجی است.

نمونه‌ها:

* خواندن فایل
* نوشتن فایل
* دریافت درخواست HTTP
* اتصال به دیتابیس
* ارتباط با شبکه
* خواندن Stream
* ارسال داده

تقریباً همه این عملیات از طریق libuv مدیریت می‌شوند.

---

# 54.8 - مدیریت تایمرها

```js id="libuv04"
setTimeout(() => {
    console.log("Hello");
}, 1000);
```

مدیریت این Timer نیز توسط libuv انجام می‌شود.

پس از پایان زمان مشخص‌شده، Callback آماده اجرا می‌شود و Event Loop آن را در زمان مناسب اجرا می‌کند.

---

# 54.9 - مدیریت شبکه

وقتی یک سرور HTTP ایجاد می‌کنیم:

```js id="libuv05"
const http = require("http");

const server = http.createServer((req, res) => {
    res.end("Hello");
});

server.listen(3000);
```

libuv مسئول مدیریت اتصال‌های شبکه و هماهنگی با سیستم‌عامل است تا درخواست‌ها بدون مسدود کردن Thread اصلی پردازش شوند.

---

# 54.10 - Thread Pool

برخی عملیات را سیستم‌عامل به‌صورت مستقیم و غیرهمگام انجام می‌دهد.

اما برخی دیگر نیاز به Thread Pool دارند.

به‌طور پیش‌فرض:

```text id="libuv06"
4 Worker Threads
```

عملیات رایج Thread Pool:

* File System
* Crypto
* zlib
* برخی عملیات DNS

---

# 54.11 - تغییر اندازه Thread Pool

تعداد Threadهای Thread Pool را می‌توان با متغیر محیطی `UV_THREADPOOL_SIZE` تغییر داد.

نمونه:

```bash id="libuv07"
UV_THREADPOOL_SIZE=8 node app.js
```

توجه داشته باشید که افزایش تعداد Threadها همیشه باعث افزایش سرعت نمی‌شود و باید با توجه به نوع پردازش و منابع سیستم انجام شود.

---

# 54.12 - Event Loop و libuv

Event Loop بخشی از libuv است.

وظیفه آن:

* بررسی صف‌ها
* اجرای Callbackها
* مدیریت فازهای مختلف Event Loop
* زمان‌بندی اجرای عملیات غیرهمگام

بنابراین، Event Loop و libuv ارتباط بسیار نزدیکی با یکدیگر دارند.

---

# 54.13 - مثال با چند عملیات Async

```js id="libuv08"
const fs = require("fs");

console.log("Start");

setTimeout(() => {
    console.log("Timer");
}, 0);

fs.readFile("data.txt", () => {
    console.log("File");
});

console.log("End");
```

خروجی تقریبی:

```text id="libuv09"
Start
End
Timer
File
```

ترتیب دقیق اجرای عملیات ممکن است بسته به شرایط سیستم، اندازه فایل و زمان پایان عملیات متفاوت باشد.

---

# 54.14 - ارتباط libuv با سیستم‌عامل

libuv برای هر سیستم‌عامل از API مناسب آن استفاده می‌کند.

برای مثال:

* Linux → epoll
* macOS → kqueue
* Windows → IOCP

اما Node.js این تفاوت‌ها را از برنامه‌نویس پنهان می‌کند و یک API یکسان ارائه می‌دهد.

---

# 54.15 - مزایای libuv

* اجرای عملیات غیرهمگام
* عملکرد بالا
* مدیریت تعداد زیاد اتصال
* قابل‌اجرا روی سیستم‌عامل‌های مختلف
* کاهش مصرف حافظه
* افزایش مقیاس‌پذیری برنامه
* هماهنگی کامل با Event Loop

---

# 54.16 - محدودیت‌های libuv

libuv معجزه نمی‌کند.

اگر محاسبات سنگین روی Thread اصلی انجام دهید:

```js id="libuv10"
while (true) {}
```

Event Loop متوقف می‌شود.

libuv نمی‌تواند این مشکل را برطرف کند.

برای این نوع پردازش‌ها باید از Worker Threads یا Child Process استفاده شود.

---

# 54.17 - نمونه واقعی

```js id="libuv11"
const crypto = require("crypto");

crypto.pbkdf2(
    "password",
    "salt",
    100000,
    64,
    "sha512",
    () => {
        console.log("Finished");
    }
);

console.log("Application Running...");
```

در این مثال، عملیات رمزنگاری توسط Thread Pool مدیریت می‌شود و Thread اصلی می‌تواند به اجرای سایر کدها ادامه دهد.

# 54.19 - اشتباهات رایج

### 1) تصور اینکه libuv فقط برای فایل‌ها استفاده می‌شود

libuv علاوه بر File System، مدیریت تایمرها، شبکه، DNS، Thread Pool و Event Loop را نیز بر عهده دارد.

---

### 2) تصور اینکه تمام عملیات Async از Thread Pool استفاده می‌کنند

خیر. بسیاری از عملیات شبکه توسط امکانات غیرهمگام سیستم‌عامل انجام می‌شوند و الزاماً از Thread Pool استفاده نمی‌کنند.

---

### 3) انجام پردازش‌های CPU-محور روی Thread اصلی

libuv عملیات I/O را مدیریت می‌کند، اما نمی‌تواند محاسبات سنگین JavaScript را از Thread اصلی خارج کند.

---

### 4) افزایش بی‌دلیل `UV_THREADPOOL_SIZE`

افزایش تعداد Threadها بدون بررسی عملکرد برنامه ممکن است باعث مصرف بیشتر منابع و حتی کاهش کارایی شود.

---

### 5) تصور اینکه libuv جایگزین Event Loop است

Event Loop بخشی از libuv است، نه یک سیستم کاملاً جدا از آن.

---

# 54.20 - نکات حرفه‌ای

* از APIهای Async به‌جای نسخه‌های Sync استفاده کن.
* هنگام طراحی برنامه، I/O و پردازش‌های CPU-محور را از هم جدا نگه دار.
* قبل از تغییر `UV_THREADPOOL_SIZE`، برنامه را Benchmark کن.
* برای فایل‌های بزرگ از Stream استفاده کن تا فشار کمتری به Thread Pool وارد شود.
* بدان که همه عملیات Async رفتار یکسانی ندارند؛ برخی مستقیماً توسط سیستم‌عامل و برخی توسط Thread Pool مدیریت می‌شوند.
* درک libuv به فهم بهتر Event Loop، Streams و عملکرد Node.js کمک می‌کند.

# 54.23 - مینی‌پروژه

## بررسی هم‌زمان File System و Timer

در این پروژه مشاهده می‌کنیم که libuv چگونه چند عملیات غیرهمگام را مدیریت می‌کند.

```js id="libuv13"
const fs = require("fs");

console.log("Application Started");

setTimeout(() => {
    console.log("Timer Finished");
}, 1000);

fs.readFile("data.txt", "utf8", (err, data) => {
    if (err) {
        console.error(err);
        return;
    }

    console.log("File Loaded");
});

console.log("Application Running...");
```

### خروجی تقریبی

```text id="libuv14"
Application Started
Application Running...
File Loaded
Timer Finished
```

> **نکته:** اگر خواندن فایل بیشتر از یک ثانیه طول بکشد، ممکن است ترتیب دو پیام آخر جابه‌جا شود. ترتیب اجرای Callbackها به زمان آماده شدن هر عملیات و فازهای Event Loop بستگی دارد.

### ایده‌هایی برای توسعه پروژه

* خواندن هم‌زمان چند فایل و مقایسه ترتیب اجرای Callbackها
* استفاده از `Promise` و `async/await` برای خواندن فایل
* مقایسه `readFile()` و `readFileSync()`
* اجرای چند عملیات `crypto.pbkdf2()` و بررسی تأثیر Thread Pool
* اندازه‌گیری زمان اجرای عملیات با `console.time()` و `console.timeEnd()`

# جمع‌بندی

**libuv** یکی از مهم‌ترین اجزای معماری Node.js است و نقش اصلی را در مدیریت عملیات غیرهمگام، Event Loop، Thread Pool، تایمرها و ارتباط با سیستم‌عامل ایفا می‌کند. این کتابخانه باعث می‌شود Node.js بتواند بدون مسدود کردن Thread اصلی، هزاران عملیات ورودی/خروجی را مدیریت کند. درک عملکرد libuv به شما کمک می‌کند رفتار واقعی Node.js را بهتر بشناسید، برنامه‌های مقیاس‌پذیرتری طراحی کنید و تصمیم‌های بهتری برای بهینه‌سازی عملکرد پروژه‌های خود بگیرید.
