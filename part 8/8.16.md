# فصل 66 - Worker Threads

## مقدمه

Node.js به صورت پیش‌فرض دارای یک مدل اجرای تک‌Thread است.

یعنی کد JavaScript اصلی برنامه روی یک Thread اجرا می‌شود و Event Loop وظیفه مدیریت عملیات‌های غیرهمزمان را برعهده دارد.

این معماری برای بسیاری از کارها عالی است:

* درخواست‌های HTTP
* کار با Database
* عملیات‌های I/O
* فایل‌ها
* Network

اما یک مشکل وجود دارد.

اگر یک عملیات سنگین CPU انجام دهیم:

* پردازش تصویر
* محاسبات ریاضی سنگین
* رمزنگاری سنگین
* پردازش داده‌های بزرگ

Thread اصلی مشغول می‌شود و Event Loop دیگر نمی‌تواند درخواست‌های جدید را پاسخ دهد.

برای حل این مشکل Node.js قابلیتی به نام **Worker Threads** معرفی کرد.

Worker Thread به ما اجازه می‌دهد JavaScript را در Threadهای جداگانه اجرا کنیم.

---

# 66.1 - Worker Thread چیست؟

Worker Thread یک Thread جداگانه برای اجرای JavaScript است.

ساختار:

```text
Main Thread

      |
      |
      ↓

Worker Thread
```

هر Worker:

* Event Loop مستقل دارد.
* Context اجرای جدا دارد.
* می‌تواند کد JavaScript اجرا کند.

---

# 66.2 - چرا Worker Threads ایجاد شدند؟

قبل از Worker Threads، برای کارهای سنگین معمولاً از:

* Child Process

استفاده می‌شد.

اما Child Process:

* حافظه جدا دارد.
* هزینه بیشتری دارد.
* ارتباط بین Processها سنگین‌تر است.

Worker Threads:

* سبک‌تر هستند.
* سریع‌تر ارتباط برقرار می‌کنند.
* برای پردازش CPU مناسب‌ترند.

---

# 66.3 - تفاوت Worker Thread و Main Thread

Main Thread:

مسئول:

* Event Loop اصلی
* HTTP Server
* مدیریت درخواست‌ها

Worker Thread:

مسئول:

* محاسبات سنگین
* پردازش‌های مستقل
* کارهای CPU Intensive

# 66.12 - مثال محاسبه سنگین

# 66.19 - مقایسه Worker Threads و Child Process

| Worker Threads    | Child Process   |
| ----------------- | --------------- |
| Thread جدا        | Process جدا     |
| سبک‌تر             | سنگین‌تر         |
| حافظه قابل اشتراک | حافظه جدا       |
| مخصوص JavaScript  | اجرای هر برنامه |
| ارتباط سریع‌تر     | ارتباط سنگین‌تر  |

# 66.20 - اشتباهات رایج

## 1) استفاده از Worker برای همه چیز

Worker برای عملیات CPU است، نه همه عملیات‌ها.

---

## 2) ساخت Worker زیاد

ساخت هزاران Worker باعث مصرف منابع می‌شود.

---

## 3) اشتراک حافظه بدون کنترل

استفاده اشتباه از Shared Memory باعث Race Condition می‌شود.

---

## 4) انتقال داده‌های خیلی بزرگ با Message

ارسال داده بزرگ بین Threadها هزینه دارد.

---

## 5) نادیده گرفتن مدیریت Worker

Workerهای باز باید مدیریت شوند.

---

# 66.21 - نکات حرفه‌ای

* برای CPU Intensive Task از Worker استفاده کن.
* تعداد Workerها را محدود نگه دار.
* برای پروژه‌های بزرگ Worker Pool بساز.
* عملیات I/O را به Worker منتقل نکن.
* خطاهای Worker را مدیریت کن.
* هنگام Shutdown برنامه Workerها را ببند.
* برای داده‌های مشترک از Atomics استفاده کن.
* برای Taskهای پیچیده معماری Queue طراحی کن.

# جمع‌بندی

**Worker Threads** یکی از مهم‌ترین ابزارهای Node.js برای حل مشکل پردازش‌های سنگین CPU است.

Node.js ذاتاً برای عملیات‌های I/O بسیار سریع است، اما برای محاسبات سنگین نیاز به Threadهای جدا دارد.

با استفاده از Worker Threads می‌توان:

* Event Loop را آزاد نگه داشت.
* محاسبات سنگین را جدا کرد.
* برنامه‌های مقیاس‌پذیرتر ساخت.

در پروژه‌های حرفه‌ای Node.js، ترکیب درست بین:

* Event Loop
* Worker Threads
* Child Process
* Queue Systems

باعث ساخت سیستم‌های قدرتمند و قابل توسعه می‌شود.
