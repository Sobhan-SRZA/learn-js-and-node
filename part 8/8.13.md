# فصل 63 - Crypto

## مقدمه

امنیت یکی از مهم‌ترین بخش‌های هر نرم‌افزار حرفه‌ای است.

تقریباً تمام برنامه‌های واقعی با داده‌های حساس سروکار دارند:

* رمز عبور کاربران
* توکن‌های دسترسی
* اطلاعات پرداخت
* کلیدهای API
* فایل‌های محرمانه
* ارتباطات امن

در Node.js برای انجام عملیات رمزنگاری و امنیتی، یک ماژول داخلی قدرتمند به نام **`crypto`** وجود دارد.

این ماژول بدون نیاز به نصب هیچ پکیج خارجی امکاناتی مانند:

* Hash کردن داده‌ها
* رمزنگاری (Encryption)
* رمزگشایی (Decryption)
* تولید رمزهای تصادفی
* ساخت Token
* تولید Key
* امضای دیجیتال
* بررسی صحت اطلاعات

را فراهم می‌کند.

---

# 63.1 - ماژول Crypto چیست؟

ماژول `crypto` یکی از ماژول‌های داخلی Node.js است.

برای استفاده:

```js
const crypto = require("crypto");
```

---

# 63.2 - مفاهیم پایه رمزنگاری

قبل از کار با Crypto باید چند مفهوم مهم را بدانیم.

---

## Encryption

تبدیل داده قابل خواندن:

```text
Hello
```

به داده غیرقابل خواندن:

```text
8f3a92x...
```

برای حفظ امنیت اطلاعات.

---

## Decryption

برعکس Encryption:

```text
8f3a92x...
```

تبدیل دوباره به:

```text
Hello
```

---

## Hash

تبدیل داده به یک مقدار ثابت.

مثال:

```text
password
```

تبدیل می‌شود به:

```text
5f4dcc3b5aa765d61d8327deb882cf99
```

ویژگی مهم:

* یک‌طرفه است.
* قابل برگشت نیست.

---

# 63.3 - Hash کردن داده

یکی از رایج‌ترین کاربردهای Crypto.

مثال:

```js
const crypto = require("crypto");


const hash =
crypto
.createHash("sha256")
.update("password")
.digest("hex");


console.log(hash);
```

خروجی:

```text
5e884898da280471...
```

---

# 63.4 - الگوریتم‌های Hash

الگوریتم‌های معروف:

| الگوریتم | توضیح         |
| -------- | ------------- |
| MD5      | قدیمی و ناامن |
| SHA1     | قدیمی         |
| SHA256   | رایج          |
| SHA512   | امن‌تر         |

در پروژه‌های جدید معمولاً:

* SHA256
* SHA512

استفاده می‌شوند.

---

# 63.5 - Hash کردن رمز عبور

مثال ساده:

```js
function hashPassword(password){

    return crypto
    .createHash("sha256")
    .update(password)
    .digest("hex");

}


console.log(
hashPassword("123456")
);
```

---

# 63.6 - مشکل Hash ساده

این روش برای رمز عبور واقعی مناسب نیست.

چرا؟

چون:

* حمله Dictionary ممکن است.
* Rainbow Table وجود دارد.
* Salt ندارد.

برای رمز عبور واقعی بهتر است از الگوریتم‌هایی مانند:

* bcrypt
* scrypt
* Argon2

استفاده شود.

---

# 63.7 - Salt چیست؟

Salt یک مقدار تصادفی است که قبل از Hash کردن به رمز اضافه می‌شود.

مثال:

بدون Salt:

```text
password
```

با Salt:

```text
password + x82jd91
```

نتیجه Hash متفاوت خواهد بود.

# 63.11 - HMAC

HMAC ترکیبی از:

* Hash
* Secret Key

است.

برای بررسی صحت داده استفاده می‌شود.

مثال:

```js
const hmac =
crypto
.createHmac(
"sha256",
"secret-key"
)
.update("message")
.digest("hex");


console.log(hmac);
```

---

# 63.14 - ساخت Key و IV

```js
const key =
crypto.randomBytes(32);


const iv =
crypto.randomBytes(16);
```

---

# 63.15 - رمزگذاری داده

```js
const cipher =
crypto.createCipheriv(
"aes-256-cbc",
key,
iv
);


let encrypted =
cipher.update(
"Hello Node.js",
"utf8",
"hex"
);


encrypted +=
cipher.final("hex");


console.log(encrypted);
```

---

# 63.16 - رمزگشایی داده

```js
const decipher =
crypto.createDecipheriv(
"aes-256-cbc",
key,
iv
);


let decrypted =
decipher.update(
encrypted,
"hex",
"utf8"
);


decrypted +=
decipher.final("utf8");


console.log(decrypted);
```

# 63.22 - اشتباهات رایج

## 1) ذخیره رمز عبور با Hash ساده

اشتباه:

```js
sha256(password)
```

برای سیستم واقعی کافی نیست.

---

## 2) استفاده از MD5 برای امنیت

MD5 شکسته شده و برای امنیت مناسب نیست.

---

## 3) قرار دادن Secret داخل کد

اشتباه:

```js
const key="123456";
```

کلیدها باید در Environment Variables نگهداری شوند.

---

## 4) استفاده دوباره از IV ثابت

IV باید تصادفی و مناسب باشد.

---

## 5) تصور اینکه Base64 رمزنگاری است

Base64 فقط Encoding است، نه Encryption.

---

## 6) ساخت الگوریتم رمزنگاری شخصی

هرگز الگوریتم امنیتی جدید اختراع نکنید.

از الگوریتم‌های استاندارد استفاده کنید.

---

# 63.23 - نکات حرفه‌ای

* برای رمز عبور از bcrypt یا Argon2 استفاده کن.
* Secret Keyها را داخل Environment Variables قرار بده.
* از الگوریتم‌های قدیمی مانند MD5 استفاده نکن.
* برای Tokenها از `randomBytes()` استفاده کن.
* برای مقایسه اطلاعات حساس از `timingSafeEqual()` استفاده کن.
* همیشه از الگوریتم‌های استاندارد و بررسی‌شده استفاده کن.
* Encryption و Hash را با هم اشتباه نگیر.
* اطلاعات حساس را Log نکن.

# 63.26 - مینی‌پروژه

# ساخت سیستم تولید Token امن

در این پروژه یک سیستم ساده تولید Token برای کاربران ایجاد می‌کنیم.

---

## کد پروژه

```js
const crypto =
require("crypto");


function createToken(){

    return crypto
    .randomBytes(32)
    .toString("hex");

}


const token =
createToken();


console.log(
"User Token:",
token
);
```

---

## خروجی نمونه

```text
User Token:

```

# 63.27 - پروژه کامل

## ساخت Password Reset Token System

قابلیت‌ها:

* ساخت Token تصادفی
* ذخیره Token
* تعیین زمان انقضا
* بررسی اعتبار Token

ساختار:

```text
password-reset/

│
├── app.js
└── tokens.json
```

---

نمونه:

```js
const crypto =
require("crypto");


function generateResetToken(){

    return crypto
    .randomBytes(32)
    .toString("hex");

}


const token =
generateResetToken();


const data = {

    token,

    expires:
    Date.now()+3600000

};


console.log(data);
```

# جمع‌بندی

ماژول **Crypto** یکی از قدرتمندترین ابزارهای داخلی Node.js برای توسعه نرم‌افزارهای امن است. با استفاده از آن می‌توان داده‌ها را Hash کرد، Token امن ساخت، عملیات رمزگذاری انجام داد و صحت اطلاعات را بررسی کرد.

در پروژه‌های واقعی، Crypto نقش مهمی در سیستم‌های احراز هویت، مدیریت کاربران، API Security و محافظت از اطلاعات حساس دارد. یادگیری صحیح مفاهیم Hash، Encryption، Key Management و Random Generation برای هر توسعه‌دهنده حرفه‌ای Node.js ضروری است.
