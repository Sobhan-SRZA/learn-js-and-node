# فصل 56 - Process

## مقدمه

هر برنامه‌ای که با Node.js اجرا می‌شود، در واقع یک **Process (فرآیند)** در سیستم‌عامل است.

وقتی دستور زیر را اجرا می‌کنید:

```bash
node app.js
```

سیستم‌عامل یک Process جدید ایجاد می‌کند و Node.js برنامه شما را داخل آن اجرا می‌کند.

Node.js برای دسترسی به اطلاعات و کنترل این Process، یک شیء سراسری (Global) به نام **`process`** در اختیار ما قرار داده است.

با استفاده از `process` می‌توانیم:

* اطلاعات برنامه را دریافت کنیم.
* آرگومان‌های خط فرمان را بخوانیم.
* متغیرهای محیطی (Environment Variables) را مدیریت کنیم.
* مسیر اجرای برنامه را بررسی کنیم.
* شناسه Process را دریافت کنیم.
* برنامه را خاتمه دهیم.
* رویدادهای مربوط به Process را مدیریت کنیم.

تقریباً تمام پروژه‌های واقعی Node.js به نوعی از شیء `process` استفاده می‌کنند.

---

# 56.1 - شیء `process` چیست؟

`process` یک شیء سراسری (Global Object) است.

بنابراین برای استفاده از آن نیازی به `require` نداریم.

```js
console.log(process);
```

---

# 56.2 - شناسه Process

هر Process یک شناسه منحصر‌به‌فرد دارد.

```js
console.log(process.pid);
```

خروجی نمونه:

```text
13520
```

---

# 56.3 - نسخه Node.js

```js
console.log(process.version);
```

خروجی:

```text
v22.x.x
```

برای مشاهده تمام نسخه‌های وابسته:

```js
console.log(process.versions);
```

---

# 56.4 - سیستم‌عامل

```js
console.log(process.platform);
```

خروجی‌های ممکن:

```text
win32
linux
darwin
```

---

# 56.5 - معماری پردازنده

```js
console.log(process.arch);
```

نمونه خروجی:

```text
x64
```

---

# 56.6 - پوشه فعلی برنامه

```js
console.log(process.cwd());
```

نمونه خروجی:

```text
C:\Projects\NodeApp
```

> **نکته:** `process.cwd()` پوشه‌ای را برمی‌گرداند که برنامه از آن اجرا شده است، نه لزوماً پوشه‌ای که فایل جاری در آن قرار دارد.

---

# 56.7 - تغییر پوشه جاری

```js
process.chdir("../");

console.log(process.cwd());
```

اگر مسیر معتبر نباشد، یک Exception ایجاد می‌شود.

---

# 56.8 - آرگومان‌های خط فرمان

فرض کنید برنامه را به این شکل اجرا می‌کنیم:

```bash
node app.js Ali 25
```

اکنون:

```js
console.log(process.argv);
```

خروجی:

```text
[
  'node',
  'app.js',
  'Ali',
  '25'
]
```

---

# 56.9 - دریافت آرگومان‌ها

```js
const name = process.argv[2];
const age = process.argv[3];

console.log(name);
console.log(age);
```

---

# 56.10 - متغیرهای محیطی

یکی از مهم‌ترین بخش‌های `process`:

```js
console.log(process.env);
```

نمونه:

```js
console.log(process.env.NODE_ENV);
```

---

# 56.11 - تنظیم متغیر محیطی

```js
process.env.APP_NAME = "My Application";

console.log(process.env.APP_NAME);
```

> این تغییر فقط تا زمانی معتبر است که Process فعلی در حال اجرا باشد.

---

# 56.12 - خروج از برنامه

```js
console.log("Application Started");

process.exit();
```

یا:

```js
process.exit(0);
```

کد خروج:

* `0` → موفق
* غیر صفر → وجود خطا

نمونه:

```js
process.exit(1);
```

---

# 56.13 - رویداد `exit`

```js
process.on("exit", (code) => {
    console.log(`Exit Code: ${code}`);
});

console.log("Finished");
```

این Event درست قبل از پایان Process اجرا می‌شود.

---

# 56.14 - مدیریت سیگنال‌ها

مثال:

```js
process.on("SIGINT", () => {
    console.log("Stopping Application...");

    process.exit(0);
});
```

اگر کاربر با `Ctrl + C` برنامه را متوقف کند، این Listener اجرا می‌شود.

---

# 56.15 - مدیریت خطاهای مدیریت‌نشده

گاهی Promiseها بدون مدیریت باقی می‌مانند.

```js
process.on("unhandledRejection", (reason) => {
    console.error(reason);
});
```

---

# 56.16 - مدیریت Exceptionهای مدیریت‌نشده

```js
process.on("uncaughtException", (err) => {
    console.error(err.message);

    process.exit(1);
});
```

> **نکته مهم:** ثبت این Event به معنی ادامه دادن برنامه پس از یک خطای بحرانی نیست. در بسیاری از پروژه‌ها، پس از ثبت لاگ و انجام پاک‌سازی‌های لازم، برنامه خاتمه داده می‌شود تا در وضعیت نامطمئن به کار خود ادامه ندهد.

---

# 56.17 - زمان اجرای برنامه

```js
console.time("program");

// Code

console.timeEnd("program");
```

برای اندازه‌گیری دقیق‌تر زمان اجرا نیز می‌توان از APIهای ماژول `perf_hooks` استفاده کرد.

---

# 56.18 - استفاده واقعی

```js
const username = process.argv[2];

if (!username) {
    console.log("Please enter username.");

    process.exit(1);
}

console.log(`Welcome ${username}`);
```

اجرا:

```bash
node app.js Ali
```

---

# 56.19 - اطلاعات حافظه

```js
console.log(process.memoryUsage());
```

نمونه خروجی:

```text
{
  rss: ...,
  heapTotal: ...,
  heapUsed: ...
}
```

این اطلاعات برای بررسی مصرف حافظه برنامه مفید هستند.

---

# 56.20 - زمان روشن بودن Process

```js
console.log(process.uptime());
```

نمونه خروجی:

```text
12.45
```

عدد نمایش‌داده‌شده بر حسب ثانیه است.

# 56.21 - مهم‌ترین ویژگی‌های `process`

| ویژگی         | توضیح                               |
| ------------- | ----------------------------------- |
| pid           | شناسه Process                       |
| version       | نسخه Node.js                        |
| versions      | نسخه وابستگی‌ها                      |
| platform      | سیستم‌عامل                           |
| arch          | معماری پردازنده                     |
| cwd()         | پوشه جاری                           |
| chdir()       | تغییر پوشه                          |
| argv          | آرگومان‌های خط فرمان                 |
| env           | متغیرهای محیطی                      |
| exit()        | خروج از برنامه                      |
| uptime()      | مدت زمان اجرای Process              |
| memoryUsage() | اطلاعات مصرف حافظه                  |
| on()          | ثبت Listener برای رویدادهای Process |

---

# 56.22 - اشتباهات رایج

### 1) استفاده از `process.exit()` بدون دلیل

خروج ناگهانی از برنامه ممکن است باعث از دست رفتن اطلاعات یا بسته نشدن صحیح منابع شود.

---

### 2) قرار دادن اطلاعات حساس داخل کد

به‌جای این کار، از متغیرهای محیطی (`process.env`) برای نگهداری اطلاعاتی مانند رمز عبور و کلیدهای API استفاده کنید.

---

### 3) فرض اینکه `process.cwd()` مسیر فایل جاری است

این متد پوشه‌ای را برمی‌گرداند که برنامه از آن اجرا شده است، نه مسیر فایل فعلی. برای مسیر فایل جاری در پروژه‌های CommonJS معمولاً از `__dirname` استفاده می‌شود.

---

### 4) نادیده گرفتن کد خروج

کد خروج (`Exit Code`) برای اسکریپت‌ها، ابزارهای CI/CD و سیستم‌عامل اهمیت زیادی دارد.

---

### 5) ادامه اجرای برنامه بعد از `uncaughtException`

پس از یک خطای مدیریت‌نشده، وضعیت برنامه ممکن است نامطمئن باشد. معمولاً بهترین کار ثبت خطا، آزادسازی منابع و سپس خروج کنترل‌شده از برنامه است.

---

# 56.23 - نکات حرفه‌ای

* تنظیمات برنامه را از `process.env` دریافت کن.
* برای ابزارهای خط فرمان از `process.argv` استفاده کن.
* هنگام خاتمه برنامه، منابعی مانند اتصال دیتابیس را به‌درستی آزاد کن.
* برای مدیریت سیگنال‌هایی مانند `SIGINT` و `SIGTERM` آماده باش.
* مصرف حافظه را با `process.memoryUsage()` در برنامه‌های بزرگ بررسی کن.
* از کدهای خروج استاندارد برای موفقیت و خطا استفاده کن.
* مقادیر موجود در `process.env` همیشه رشته (String) هستند؛ در صورت نیاز آن‌ها را به Number یا Boolean تبدیل کن.

# 56.26 - مینی‌پروژه

## ساخت ابزار خط فرمان نمایش اطلاعات سیستم

در این پروژه، یک ابزار ساده CLI می‌سازیم که اطلاعات مهم Process را نمایش می‌دهد.

```js
console.log("=== System Information ===");

console.log("PID:", process.pid);

console.log("Node Version:", process.version);

console.log("Platform:", process.platform);

console.log("Architecture:", process.arch);

console.log("Current Directory:", process.cwd());

console.log("Uptime:", process.uptime(), "seconds");

console.log("Memory Usage:");

console.log(process.memoryUsage());

console.log("Environment:");

console.log(process.env.NODE_ENV ?? "Not Defined");
```

### نمونه خروجی

```text
=== System Information ===
PID: 14532
Node Version: v22.x.x
Platform: win32
Architecture: x64
Current Directory: C:\Projects\App
Uptime: 8.52 seconds
Memory Usage:
{ ... }
Environment:
development
```

### ایده‌هایی برای توسعه پروژه

* نمایش اطلاعات به‌صورت جدول
* دریافت گزینه‌های خط فرمان مانند `--memory` یا `--env`
* ذخیره گزارش در فایل متنی
* نمایش تمام متغیرهای محیطی به‌صورت مرتب
* اضافه کردن نمایش نسخه سیستم‌عامل و اطلاعات CPU با استفاده از ماژول `os`
* تبدیل ابزار به یک CLI واقعی با پشتیبانی از دستورات مختلف

# جمع‌بندی

شیء سراسری **`process`** یکی از مهم‌ترین ابزارهای Node.js برای ارتباط برنامه با محیط اجرای آن است. با استفاده از آن می‌توان اطلاعاتی مانند شناسه Process، نسخه Node.js، آرگومان‌های خط فرمان، متغیرهای محیطی، مصرف حافظه و مدت زمان اجرای برنامه را دریافت کرد و همچنین رویدادهای مهمی مانند `exit`، `SIGINT` و `uncaughtException` را مدیریت نمود. تسلط بر `process` برای ساخت برنامه‌های حرفه‌ای، ابزارهای خط فرمان (CLI)، مدیریت تنظیمات و پیاده‌سازی خاموش شدن ایمن برنامه‌ها ضروری است.
