# فصل 58 - Streams

## مقدمه

فرض کنید یک فایل ویدیویی **۵ گیگابایتی** دارید و می‌خواهید آن را بخوانید.

اگر از روش‌های معمول مانند `readFile()` استفاده کنید، کل فایل ابتدا وارد حافظه (RAM) می‌شود و سپس پردازش خواهد شد.

این کار مشکلات زیادی ایجاد می‌کند:

* مصرف بسیار زیاد حافظه
* کاهش عملکرد برنامه
* احتمال تمام شدن حافظه (Out of Memory)
* کند شدن سرور
* کاهش مقیاس‌پذیری

Node.js برای حل این مشکل از مفهومی به نام **Stream** استفاده می‌کند.

به جای اینکه کل داده یک‌باره در حافظه قرار بگیرد، داده به **بخش‌های کوچک (Chunk)** تقسیم شده و به تدریج پردازش می‌شود.

به همین دلیل Streamها یکی از مهم‌ترین دلایل عملکرد فوق‌العاده Node.js در کار با فایل‌ها، شبکه و انتقال داده هستند.

---

# 58.1 - Stream چیست؟

**Stream** جریانی از داده است که به صورت تدریجی منتقل می‌شود.

به جای:

```text
File
 ↓
RAM
 ↓
Program
```

از این مدل استفاده می‌شود:

```text
File
 ↓
Chunk
 ↓
Chunk
 ↓
Chunk
 ↓
Program
```

---

# 58.2 - مزایای Stream

* مصرف بسیار کمتر حافظه
* مناسب برای فایل‌های بزرگ
* سرعت بیشتر
* شروع پردازش قبل از پایان دریافت داده
* مناسب برای انتقال اطلاعات در شبکه
* مناسب برای پردازش Real-Time

---

# 58.3 - انواع Stream

در Node.js چهار نوع Stream وجود دارد:

| نوع       | کاربرد                |
| --------- | --------------------- |
| Readable  | خواندن داده           |
| Writable  | نوشتن داده            |
| Duplex    | خواندن و نوشتن        |
| Transform | خواندن، تغییر و نوشتن |

---

# 58.4 - Readable Stream

Readable Stream برای خواندن داده استفاده می‌شود.

مثال:

```js
const fs = require("fs");

const stream = fs.createReadStream("large.txt");
```

در این حالت فایل به صورت Chunk خوانده می‌شود.

---

# 58.5 - دریافت داده

```js
const fs = require("fs");

const stream = fs.createReadStream("large.txt");

stream.on("data", (chunk) => {

    console.log(chunk.length);

});
```

هر `chunk` معمولاً یک Buffer است.

---

# 58.6 - پایان خواندن

```js
stream.on("end", () => {

    console.log("Finished");

});
```

---

# 58.7 - مدیریت خطا

```js
stream.on("error", (err) => {

    console.log(err.message);

});
```

---

# 58.8 - Writable Stream

برای نوشتن داده استفاده می‌شود.

```js
const fs = require("fs");

const stream = fs.createWriteStream("output.txt");
```

---

# 58.9 - نوشتن داده

```js
stream.write("Hello ");

stream.write("Node.js");

stream.end();
```

---

# 58.10 - پایان نوشتن

```js
stream.on("finish", () => {

    console.log("Saved");

});
```

---

# 58.11 - Readable + Writable

```js
const fs = require("fs");

const reader = fs.createReadStream("input.txt");

const writer = fs.createWriteStream("output.txt");

reader.on("data", (chunk) => {

    writer.write(chunk);

});

reader.on("end", () => {

    writer.end();

});
```

---

# 58.12 - Pipe

روش بهتر:

```js
reader.pipe(writer);
```

تمام عملیات انتقال داده به صورت خودکار مدیریت می‌شود.

# 58.13 - Duplex Stream

Duplex هم قابلیت خواندن دارد و هم نوشتن.

# 58.14 - Transform Stream

Transform نیز قابلیت خواندن و نوشتن دارد اما داده را هنگام عبور تغییر می‌دهد.

نمونه‌ها:

* Compression
* Encryption
* Decryption
* تبدیل متن
* Parsing

# 58.15 - ساخت Transform

```js
const { Transform } = require("stream");

const upper = new Transform({

    transform(chunk, encoding, callback) {

        callback(
            null,
            chunk.toString().toUpperCase()
        );

    }

});
```

# 58.16 - استفاده از Transform

```js
reader

.pipe(upper)

```

---

# 58.17 - جریان داده

```text
File

↓

Readable

↓

Transform

↓

Writable
```

---

# 58.18 - مثال واقعی

```js
const fs = require("fs");

const { Transform } = require("stream");

const upper = new Transform({

    transform(chunk, enc, cb) {

        cb(
            null,
            chunk.toString().toUpperCase()
        );

    }

});

fs.createReadStream("input.txt")

.pipe(upper)

.pipe(fs.createWriteStream("output.txt"));
```

---

# 58.19 - Backpressure

گاهی سرعت خواندن بیشتر از سرعت نوشتن است.

```text
Reader

↓↓↓↓↓↓↓↓↓

Writer
```

در این حالت حافظه به سرعت پر می‌شود.

Node.js با استفاده از **Backpressure** سرعت انتقال داده را کنترل می‌کند.

خوشبختانه زمانی که از `pipe()` استفاده می‌کنید، این مکانیزم به صورت خودکار مدیریت می‌شود.

---

# 58.20 - Encoding

```js
const stream = fs.createReadStream(
    "text.txt",
    {
        encoding: "utf8"
    }
);
```

در این حالت به جای Buffer، رشته دریافت می‌شود.

---

# 58.21 - HighWaterMark

```js
const stream = fs.createReadStream(
    "large.txt",
    {
        highWaterMark: 1024
    }
);
```

در این مثال اندازه هر Chunk تقریباً ۱ کیلوبایت خواهد بود.

`highWaterMark` اندازه بافر داخلی Stream را مشخص می‌کند و مقدار دقیق داده در هر Chunk ممکن است بسته به نوع Stream متفاوت باشد.

---

# 58.22 - مهم‌ترین Eventها

| Event  | کاربرد          |
| ------ | --------------- |
| data   | دریافت Chunk    |
| end    | پایان خواندن    |
| error  | مدیریت خطا      |
| finish | پایان نوشتن     |
| close  | بسته شدن Stream |

# 58.24 - اشتباهات رایج

### 1) استفاده از `readFile()` برای فایل‌های بزرگ

در این حالت کل فایل وارد حافظه می‌شود.

---

### 2) فراموش کردن مدیریت خطا

همیشه Event `error` را مدیریت کنید.

---

### 3) نوشتن بدون `end()`

تا زمانی که `end()` فراخوانی نشود، Writable Stream به پایان نمی‌رسد.

---

### 4) مدیریت دستی انتقال داده به جای `pipe()`

در بسیاری از موارد، `pipe()` ساده‌تر، خواناتر و ایمن‌تر است.

---

### 5) نادیده گرفتن Backpressure

در Streamهای سفارشی، اگر Backpressure را در نظر نگیرید، ممکن است مصرف حافظه به شدت افزایش یابد.

---

# 58.25 - نکات حرفه‌ای

* برای فایل‌های بزرگ همیشه از Stream استفاده کن.
* در صورت امکان از `pipe()` استفاده کن.
* تمام Streamها را به Event `error` مجهز کن.
* از Transform برای پردازش داده هنگام انتقال استفاده کن.
* هنگام ساخت Stream سفارشی، Backpressure را رعایت کن.
* برای پردازش متن، Encoding مناسب را مشخص کن.
* در پروژه‌های واقعی، از `stream.pipeline()` برای اتصال Streamها استفاده کن؛ این متد مدیریت خطا و بستن Streamها را ساده‌تر می‌کند.

# 58.28 - مینی‌پروژه

## ساخت ابزار کپی فایل با Stream

در این پروژه یک فایل را بدون بارگذاری کامل در حافظه کپی می‌کنیم.

```js
const fs = require("fs");

const reader = fs.createReadStream("video.mp4");

const writer = fs.createWriteStream("backup.mp4");

reader.pipe(writer);

writer.on("finish", () => {

    console.log("Copy Completed");

});

reader.on("error", console.error);

writer.on("error", console.error);
```

این روش حتی برای فایل‌های چندین گیگابایتی نیز مناسب است.

---

## پروژه کامل

### ساخت ابزار پردازش فایل متنی

در این پروژه:

* فایل بزرگ را به صورت Stream می‌خوانیم.
* تمام متن را به حروف بزرگ تبدیل می‌کنیم.
* فایل جدید تولید می‌کنیم.
* بدون بارگذاری کامل فایل در حافظه.

```js
const fs = require("fs");
const { Transform, pipeline } = require("stream");

const upperCase = new Transform({
    transform(chunk, encoding, callback) {
        callback(null, chunk.toString().toUpperCase());
    }
});

pipeline(
    fs.createReadStream("input.txt"),
    upperCase,
    fs.createWriteStream("output.txt"),
    (err) => {
        if (err) {
            console.error("Pipeline Error:", err);
            return;
        }

        console.log("File Processed Successfully");
    }
);
```

### چرا `pipeline()`؟

در پروژه‌های واقعی، استفاده از `pipeline()` نسبت به زنجیره ساده `pipe()` مزایای مهمی دارد:

* مدیریت خودکار خطاها
* بستن صحیح Streamها در صورت بروز خطا
* خوانایی بیشتر
* کاهش احتمال نشت منابع (Resource Leak)

---

## ایده‌هایی برای توسعه پروژه

* شمارش تعداد خطوط فایل
* حذف فاصله‌های اضافی هنگام عبور داده
* فشرده‌سازی فایل با ماژول `zlib`
* رمزگذاری فایل قبل از ذخیره
* نمایش درصد پیشرفت عملیات کپی
* ساخت ابزار دانلود فایل با Stream
* پیاده‌سازی آپلود فایل در یک سرور HTTP با استفاده از Stream

# جمع‌بندی

**Stream** یکی از مهم‌ترین مفاهیم Node.js و پایه بسیاری از قابلیت‌های آن است. به کمک Streamها می‌توان داده‌ها را به صورت تدریجی پردازش کرد، بدون اینکه کل آن‌ها در حافظه بارگذاری شوند. چهار نوع اصلی Stream شامل **Readable**، **Writable**، **Duplex** و **Transform** هستند که هر کدام کاربرد خاص خود را دارند. استفاده از ابزارهایی مانند `pipe()` و `pipeline()`، همراه با درک مفاهیمی مانند Backpressure، به شما کمک می‌کند برنامه‌هایی سریع، مقیاس‌پذیر و بهینه برای کار با فایل‌ها، شبکه و پردازش داده‌های حجیم توسعه دهید.
