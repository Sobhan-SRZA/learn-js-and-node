# فصل 52 - Event Driven

## مقدمه

یکی از مهم‌ترین دلایلی که Node.js می‌تواند تعداد بسیار زیادی درخواست را با سرعت بالا مدیریت کند، **معماری Event-Driven (رویدادمحور)** آن است.

تقریباً تمام بخش‌های مهم Node.js بر اساس Event کار می‌کنند:

* دریافت درخواست HTTP
* اتصال کاربران به سرور
* خواندن فایل
* نوشتن فایل
* اتصال به دیتابیس
* WebSocket
* Streamها
* Processها
* Timerها

اگر Eventها را به خوبی درک کنید، درک بسیاری از ماژول‌های Node.js برایتان بسیار ساده‌تر خواهد شد.

در این فصل با مفهوم Event، نحوه کار معماری Event-Driven و کلاس `EventEmitter` آشنا می‌شویم.

---

# 52.1 - Event چیست؟

**Event** به معنی **رویداد** است.

رویداد یعنی:

> اتفاقی که در برنامه رخ می‌دهد و می‌توان نسبت به آن واکنش نشان داد.

مثال‌هایی از Event:

* کاربر وارد سیستم شد.
* فایل خوانده شد.
* فایل ذخیره شد.
* درخواست HTTP دریافت شد.
* اتصال دیتابیس برقرار شد.
* پیام جدید دریافت شد.
* تایمر به پایان رسید.

---

# 52.2 - Event Driven یعنی چه؟

در برنامه‌نویسی Event-Driven، برنامه منتظر وقوع رویدادها می‌ماند.

وقتی رویدادی رخ داد، تابعی که برای آن ثبت شده است اجرا می‌شود.

به جای اینکه دائماً بررسی کنیم آیا اتفاقی افتاده یا نه، فقط منتظر Event می‌مانیم.

---

# 52.3 - یک مثال ساده

فرض کنید زنگ خانه به صدا درمی‌آید.

دو روش وجود دارد.

روش اول:

```text id="f7r9m1"
هر یک ثانیه در را چک کن

آیا کسی آمده؟

آیا کسی آمده؟

آیا کسی آمده؟
```

این روش ناکارآمد است.

روش دوم:

```text id="uvs4o8"
وقتی زنگ خورد

↓

در را باز کن
```

این دقیقاً همان Event Driven است.

---

# 52.4 - Event در Node.js

در Node.js بسیاری از عملیات به صورت Event انجام می‌شوند.

مثلاً:

```text id="k8m5zt"
request

↓

response

↓

close

↓

error
```

یا در Streamها:

```text id="n0e3jc"
data

end

error

close
```

---

# 52.5 - EventEmitter چیست؟

Node.js کلاسی به نام `EventEmitter` در اختیار ما قرار داده است.

این کلاس امکان:

* ساخت Event
* ثبت Listener
* ارسال Event
* حذف Listener

را فراهم می‌کند.

برای استفاده:

```js id="xj8m5u"
const EventEmitter = require("events");
```

---

# 52.6 - ساخت اولین Event

```js id="z7t2df"
const EventEmitter = require("events");

const emitter = new EventEmitter();

emitter.on("welcome", () => {
    console.log("Welcome!");
});

emitter.emit("welcome");
```

خروجی:

```text id="a3u9wc"
Welcome!
```

---

# 52.7 - متد `on`

برای ثبت Listener از `on` استفاده می‌کنیم.

ساختار:

```js id="m4h7pr"
emitter.on(eventName, listener);
```

مثال:

```js id="y5q1sn"
emitter.on("login", () => {
    console.log("User Logged In");
});
```

---

# 52.8 - متد `emit`

برای ارسال Event از `emit` استفاده می‌کنیم.

```js id="r8v2nb"
emitter.emit("login");
```

اگر Listener وجود داشته باشد اجرا می‌شود.

---

# 52.9 - ارسال داده همراه Event

```js id="p6l0gw"
const EventEmitter = require("events");

const emitter = new EventEmitter();

emitter.on("user", (name) => {
    console.log(`Hello ${name}`);
});

emitter.emit("user", "Ali");
```

خروجی:

```text id="g4e1zo"
Hello Ali
```

---

# 52.10 - ارسال چند پارامتر

```js id="h9y4tc"
emitter.on("order", (id, price) => {
    console.log(id);
    console.log(price);
});

emitter.emit("order", 105, 250);
```

---

# 52.11 - چند Listener برای یک Event

```js id="u2n8ak"
emitter.on("start", () => {
    console.log("Listener 1");
});

emitter.on("start", () => {
    console.log("Listener 2");
});

emitter.emit("start");
```

خروجی:

```text id="l1v9ef"
Listener 1
Listener 2
```

تمام Listenerها به ترتیب ثبت اجرا می‌شوند.

---

# 52.12 - متد `once`

گاهی فقط یک بار باید Listener اجرا شود.

```js id="q3s8yx"
emitter.once("login", () => {
    console.log("Executed Once");
});

emitter.emit("login");
emitter.emit("login");
```

خروجی:

```text id="v8d0ln"
Executed Once
```

---

# 52.13 - حذف Listener

```js id="k7c3oi"
function hello() {
    console.log("Hello");
}

emitter.on("welcome", hello);

emitter.off("welcome", hello);

emitter.emit("welcome");
```

خروجی:

هیچ چیزی چاپ نمی‌شود.

---

# 52.14 - Event خطا

در Node.js رویداد `error` اهمیت ویژه‌ای دارد.

```js id="c9b7rm"
emitter.on("error", (err) => {
    console.log(err.message);
});

emitter.emit("error", new Error("Something went wrong"));
```

---

# 52.15 - ساخت کلاس بر پایه EventEmitter

```js id="e6m2jd"
const EventEmitter = require("events");

class User extends EventEmitter {

    login(name) {
        console.log(`${name} logged in`);

        this.emit("login", name);
    }

}

const user = new User();

user.on("login", (name) => {
    console.log(`Welcome ${name}`);
});

user.login("Sara");
```

خروجی:

```text id="b4h1px"
Sara logged in
Welcome Sara
```

---

# 52.16 - کاربردهای واقعی EventEmitter

در پروژه‌های واقعی از Eventها برای موارد زیر استفاده می‌شود:

* ارسال ایمیل پس از ثبت‌نام
* ثبت لاگ فعالیت کاربران
* ارسال اعلان
* ذخیره گزارش‌ها
* سیستم پیام‌رسان
* Queueها
* اطلاع‌رسانی تغییر وضعیت سفارش
* اتصال و قطع اتصال کاربران

---

# 52.17 - مثال سفارش فروشگاه

```js id="t8x4jw"
const EventEmitter = require("events");

const emitter = new EventEmitter();

emitter.on("orderCreated", (id) => {
    console.log(`Order ${id} saved.`);
});

emitter.on("orderCreated", (id) => {
    console.log(`Email sent for order ${id}.`);
});

emitter.emit("orderCreated", 501);
```

خروجی:

```text id="y7l3nd"
Order 501 saved.
Email sent for order 501.
```

یک Event باعث اجرای چند عملیات مختلف می‌شود، بدون اینکه آن بخش‌ها مستقیماً به هم وابسته باشند.

---

# 52.18 - مزایای معماری Event-Driven

* کاهش وابستگی بین بخش‌های برنامه
* توسعه آسان‌تر
* افزودن قابلیت‌های جدید بدون تغییر کدهای قبلی
* مناسب برای سیستم‌های Real-Time
* مدیریت بهتر عملیات Async
* خوانایی بیشتر در معماری پروژه

---

# 52.19 - Event Driven در HTTP Server

وقتی سرور HTTP ایجاد می‌کنیم:

```js id="n2m5xr"
server.on("request", (req, res) => {
    res.end("Hello");
});
```

هر بار که درخواستی دریافت شود، Event مربوط به آن اجرا می‌شود.

---

# 52.20 - Event Driven و Stream

```js id="j6r8vp"
stream.on("data", (chunk) => {
    console.log(chunk);
});

stream.on("end", () => {
    console.log("Finished");
});

stream.on("error", (err) => {
    console.error(err);
});
```

تقریباً تمام Streamهای Node.js بر پایه Event هستند.

---

# 52.21 - اشتباهات رایج

### 1) فراموش کردن Listener قبل از `emit`

اگر قبل از ارسال Event، Listener ثبت نشده باشد، هیچ اتفاقی رخ نمی‌دهد.

---

### 2) استفاده زیاد از Eventها

هر ارتباطی نباید با Event انجام شود. استفاده بیش از حد باعث پیچیدگی و دشوار شدن دنبال کردن جریان اجرای برنامه می‌شود.

---

### 3) نادیده گرفتن Event `error`

در بسیاری از کلاس‌های مبتنی بر `EventEmitter` باید برای `error` Listener ثبت کنید تا خطاها به‌درستی مدیریت شوند.

---

### 4) ثبت Listenerهای تکراری

ثبت چندباره Listener یکسان می‌تواند باعث اجرای چندباره کد و حتی نشت حافظه (Memory Leak) شود.

---

### 5) فراموش کردن حذف Listener

در برنامه‌های بلندمدت، اگر Listenerهای بدون استفاده حذف نشوند، مصرف حافظه افزایش پیدا می‌کند.

---

# 52.22 - نکات حرفه‌ای

* برای نام Eventها از نام‌های واضح و معنادار استفاده کن.
* Eventها را برای اطلاع‌رسانی بین بخش‌های مستقل برنامه به کار ببر.
* در Eventها منطق سنگین و زمان‌بر قرار نده.
* برای Eventهای حساس، Listener مربوط به `error` را فراموش نکن.
* اگر Listener فقط یک بار لازم است، از `once()` استفاده کن.
* از ارسال تعداد زیاد پارامتر به Event خودداری کن؛ در صورت نیاز یک شیء ارسال کن.
* ساختار Eventها را مستندسازی کن تا سایر اعضای تیم بدانند هر Event چه داده‌ای ارسال می‌کند.

---

# 52.23 - تمرین

## تمرین 1

یک Event به نام `register` ایجاد کن که هنگام ثبت‌نام کاربر، نام او را چاپ کند.

---

## تمرین 2

دو Listener برای Event `payment` بساز؛ یکی پیام موفقیت پرداخت را چاپ کند و دیگری ثبت لاگ را شبیه‌سازی کند.

---

## تمرین 3

از `once()` استفاده کن تا Event `startup` فقط یک بار اجرا شود.

---

## تمرین 4

کلاسی به نام `ChatRoom` بساز که از `EventEmitter` ارث‌بری کند و هنگام ارسال پیام، Event مربوط به آن را منتشر کند.

---

# 52.24 - پاسخ تشریحی

## پاسخ تمرین 1

```js id="x1m8ps"
const EventEmitter = require("events");

const emitter = new EventEmitter();

emitter.on("register", (name) => {
    console.log(`${name} registered.`);
});

emitter.emit("register", "Ali");
```

**توضیح:**
Listener برای Event `register` ثبت شده و با اجرای `emit` نام کاربر دریافت و چاپ می‌شود.

---

## پاسخ تمرین 2

```js id="r7k2hn"
const EventEmitter = require("events");

const emitter = new EventEmitter();

emitter.on("payment", () => {
    console.log("Payment completed.");
});

emitter.on("payment", () => {
    console.log("Payment logged.");
});

emitter.emit("payment");
```

**توضیح:**
یک Event می‌تواند چند Listener داشته باشد و همه آن‌ها به ترتیب اجرا می‌شوند.

---

## پاسخ تمرین 3

```js id="u4f9jl"
const EventEmitter = require("events");

const emitter = new EventEmitter();

emitter.once("startup", () => {
    console.log("Application started.");
});

emitter.emit("startup");
emitter.emit("startup");
```

**توضیح:**
با استفاده از `once`، Listener پس از اولین اجرا به‌طور خودکار حذف می‌شود.

---

## پاسخ تمرین 4

```js id="n5d3cq"
const EventEmitter = require("events");

class ChatRoom extends EventEmitter {
    sendMessage(user, message) {
        this.emit("message", {
            user,
            message
        });
    }
}

const room = new ChatRoom();

room.on("message", (data) => {
    console.log(`${data.user}: ${data.message}`);
});

room.sendMessage("Sara", "Hello!");
```

**توضیح:**
کلاس `ChatRoom` از `EventEmitter` ارث‌بری کرده و با انتشار Event، بخش‌های مختلف برنامه را از ارسال پیام آگاه می‌کند.

---

# 52.25 - مینی‌پروژه

## ساخت سیستم اعلان (Notification System)

در این پروژه یک سیستم اعلان ساده طراحی می‌کنیم. هنگام ثبت‌نام کاربر، یک Event منتشر می‌شود و چند بخش مختلف برنامه بدون وابستگی مستقیم به هم واکنش نشان می‌دهند.

```js id="q8t4mv"
const EventEmitter = require("events");

class NotificationCenter extends EventEmitter {}

const notifications = new NotificationCenter();

notifications.on("userRegistered", (user) => {
    console.log(`Welcome ${user.name}!`);
});

notifications.on("userRegistered", (user) => {
    console.log(`Sending verification email to ${user.email}`);
});

notifications.on("userRegistered", (user) => {
    console.log(`Saving activity log for ${user.name}`);
});

function registerUser(name, email) {
    console.log("Creating user...");

    notifications.emit("userRegistered", {
        name,
        email
    });
}

registerUser("Ali", "ali@example.com");
```

### خروجی

```text id="m1k7az"
Creating user...
Welcome Ali!
Sending verification email to ali@example.com
Saving activity log for Ali
```

در این مثال، تابع `registerUser` فقط مسئول ایجاد کاربر است و از جزئیات ارسال ایمیل یا ثبت لاگ اطلاعی ندارد. هر قابلیت جدید تنها با اضافه کردن یک Listener جدید به Event قابل توسعه است.

---

## ایده‌هایی برای توسعه پروژه

* اضافه کردن Event برای ورود کاربران
* ثبت زمان وقوع هر Event
* ارسال پیامک علاوه بر ایمیل
* ذخیره اعلان‌ها در دیتابیس
* ایجاد سیستم صف (Queue) برای پردازش اعلان‌ها
* ارسال اعلان از طریق WebSocket به کاربران آنلاین
* افزودن امکان فعال یا غیرفعال کردن Listenerها در زمان اجرا

---

# جمع‌بندی

معماری **Event-Driven** یکی از ستون‌های اصلی Node.js است. با استفاده از `EventEmitter` می‌توان بخش‌های مختلف برنامه را بدون وابستگی مستقیم به یکدیگر با هم در ارتباط قرار داد. این رویکرد باعث افزایش انعطاف‌پذیری، توسعه‌پذیری و نگهداری آسان‌تر پروژه می‌شود و در بسیاری از بخش‌های داخلی Node.js مانند HTTP Server، Streamها، Processها و ماژول‌های مختلف مورد استفاده قرار گرفته است. تسلط بر Eventها، یکی از مهارت‌های ضروری برای ساخت برنامه‌های حرفه‌ای و مقیاس‌پذیر با Node.js است.
