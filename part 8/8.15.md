# فصل 65 - Child Process

## مقدمه

Node.js به صورت پیش‌فرض روی یک Thread اصلی اجرا می‌شود و معماری آن بر پایه Event Loop طراحی شده است.

اما در پروژه‌های واقعی گاهی نیاز داریم:

* یک برنامه خارجی را اجرا کنیم.
* یک دستور سیستم‌عامل را اجرا کنیم.
* پردازش سنگین را خارج از Thread اصلی انجام دهیم.
* چند عملیات مستقل را همزمان اجرا کنیم.
* با برنامه‌های دیگر ارتباط برقرار کنیم.

برای انجام این کارها Node.js قابلیتی به نام **Child Process** ارائه می‌دهد.

با استفاده از Child Process می‌توانیم از داخل برنامه Node.js، پردازش‌های جدید ایجاد کنیم.

مثال:

* اجرای دستور `git`
* اجرای اسکریپت Python
* تبدیل فایل‌ها با ابزارهای خارجی
* اجرای Command Line Toolها
* پردازش‌های سنگین CPU

---

# 65.1 - Child Process چیست؟

Child Process یعنی ایجاد یک Process جدید که توسط Process اصلی Node.js ساخته می‌شود.

ساختار:

```text
Parent Process

        |
        |
        ↓

Child Process
```

Process اصلی:

```text
Node.js Application
```

Process فرزند:

```text
External Command
```

یا:

```text
Another Node.js Script
```

# 65.2 - تفاوت Process و Thread

## Process

یک برنامه در حال اجرا است.

مثال:

```text
Chrome.exe
node app.js
python script.py
```

هر Process:

* حافظه جدا دارد.
* منابع مستقل دارد.

---

## Thread

یک مسیر اجرای داخل Process است.

Node.js معمولاً:

* یک Thread اصلی دارد.
* Event Loop روی آن اجرا می‌شود.

# 65.5 - exec()

`exec()` برای اجرای Commandهای سیستم‌عامل استفاده می‌شود.

مثال:

```js
const {
    exec
} = require("child_process");


exec(
"node --version",
(error, stdout, stderr)=>{


console.log(stdout);


});
```

خروجی:

```text
v22.x.x
```

---

# 65.10 - spawn()

برای اجرای Processهای طولانی استفاده می‌شود.

برخلاف `exec`، خروجی را Stream می‌کند.

مثال:

```js
const {
spawn
}=require("child_process");


const child =
spawn(
"node",
[
"script.js"
]
);


child.stdout.on(
"data",
(data)=>{

console.log(
data.toString()
);

});
```

---

# 65.15 - تفاوت exec و execFile

## exec

یک Command String دریافت می‌کند:

```js
exec(
"node app.js"
);
```

---

## execFile

فایل و آرگومان جدا دریافت می‌کند:

```js
execFile(
"node",

"app.js"
]
);
```

`execFile` امن‌تر است چون Shell اجرا نمی‌کند.

# 65.16 - fork()

`fork()` مخصوص اجرای فایل‌های Node.js است.

مثال:

فایل:

```text
child.js
```

```js
console.log(
"Child Running"
);
```

اجرای آن:

```js
const {
fork
}=require("child_process");


const child =
fork(
"./child.js"
);
```

# 65.23 - نکات حرفه‌ای

* برای Commandهای کوتاه از `exec` استفاده کن.
* برای Stream و خروجی زیاد از `spawn` استفاده کن.
* برای اجرای فایل Node.js دیگر از `fork` استفاده کن.
* هیچ‌وقت ورودی کاربر را مستقیم به Shell ارسال نکن.
* Processهای ایجاد شده را مدیریت و در زمان مناسب متوقف کن.
* برای پردازش CPU سنگین معماری جدا طراحی کن.
* Logهای Child Process را ذخیره کن.
* محدودیت منابع برای Processها در نظر بگیر.

# 65.27 - پروژه کامل

# ساخت سیستم Worker پردازش فایل

در این پروژه:

Parent:

* فایل دریافت می‌کند.
* Worker ایجاد می‌کند.

Child:

* فایل را پردازش می‌کند.
* نتیجه ارسال می‌کند.

ساختار:

```text
worker-system/

│
├── app.js
│
└── worker.js
```

---

## worker.js

```js
process.on(
"message",
data=>{


const result =
data.value.toUpperCase();


process.send(
result
);


});
```

---

## app.js

```js
const {
fork
}=require(
"child_process"
);


const worker =
fork(
"./worker.js"
);


worker.send(
{
value:"node.js"
}
);


worker.on(
"message",
result=>{


console.log(
result
);


});
```

---

خروجی:

```text
NODE.JS
```

---

## ایده‌های توسعه پروژه

* ساخت Worker Pool
* پردازش چند فایل همزمان
* اتصال به Queue
* مدیریت تعداد Workerها
* ساخت سیستم پردازش تصویر
* اضافه کردن Logging

# جمع‌بندی

**Child Process** یکی از ابزارهای قدرتمند Node.js برای اجرای پردازش‌های جداگانه است.

با استفاده از:

* `exec`
* `execFile`
* `spawn`
* `fork`

می‌توانیم برنامه‌های خارجی را اجرا کنیم، پردازش‌های سنگین را جدا کنیم و معماری‌های مقیاس‌پذیر بسازیم.

در پروژه‌های حرفه‌ای Node.js، زمانی که یک عملیات CPU Intensive یا یک برنامه خارجی نیاز به اجرا دارد، Child Process یکی از مهم‌ترین ابزارهای موجود است.
