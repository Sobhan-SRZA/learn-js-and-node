قبل از این فصل با **Function**، **Scope**، **Closure** و نحوه‌ی اجرای توابع آشنا شدید.

تا اینجا هر زمان می‌خواستیم یک کار را چند بار انجام دهیم، معمولاً از **حلقه‌ها (Loop)** استفاده می‌کردیم.

اما همیشه هم حلقه‌ها بهترین انتخاب نیستند.

گاهی اوقات مسئله به گونه‌ای است که راه‌حل آن، تقسیم شدن به مسئله‌های کوچک‌تر و مشابه است.

در چنین شرایطی از مفهومی به نام **Recursion (بازگشت)** استفاده می‌کنیم.

Recursion یکی از مهم‌ترین مفاهیم علوم کامپیوتر است و تقریباً در تمام زبان‌های برنامه‌نویسی وجود دارد.

بسیاری از الگوریتم‌های معروف، ساختارهای داده مانند **Tree** و **Graph**، سیستم فایل، موتورهای جستجو، کامپایلرها و حتی بخش‌هایی از Node.js از Recursion استفاده می‌کنند.

در نگاه اول ممکن است Recursion ترسناک به نظر برسد، اما اگر آن را قدم به قدم یاد بگیرید، متوجه خواهید شد که در واقع چیزی بیشتر از **یک تابع که خودش را صدا می‌زند** نیست.

در این فصل یاد می‌گیرید Recursion چیست، چگونه کار می‌کند، چه تفاوتی با Loop دارد، چه زمانی باید از آن استفاده کرد و چگونه از خطاهای رایج جلوگیری کنید.

---

# فصل 21 - Recursion (بازگشت)

Recursion یا بازگشت یعنی:

> یک تابع، خودش را دوباره فراخوانی کند تا زمانی که به یک شرط توقف برسد.

در ابتدا شاید این کار عجیب به نظر برسد.

چرا یک تابع باید خودش را صدا بزند؟

پاسخ ساده است.

گاهی حل یک مسئله با تقسیم کردن آن به نسخه‌های کوچک‌تر از همان مسئله بسیار ساده‌تر است.

---

# اولین مثال

```javascript
function count(number) {

    if (number === 0) {
        return;
    }

    console.log(number);

    count(number - 1);

}

count(5);
```

خروجی:

```text
5
4
3
2
1
```

---

در این مثال:

تابع ابتدا عدد را چاپ می‌کند.

سپس خودش را با عدد کوچک‌تر فراخوانی می‌کند.

وقتی مقدار به صفر برسد، اجرای تابع متوقف می‌شود.

---

# اجزای اصلی Recursion

هر تابع بازگشتی همیشه دو بخش دارد.

## ۱- شرط توقف (Base Case)

شرطی که مشخص می‌کند Recursion چه زمانی متوقف شود.

مثال:

```javascript
if (number === 0) {
    return;
}
```

---

## ۲- فراخوانی بازگشتی (Recursive Call)

قسمتی که تابع دوباره خودش را صدا می‌زند.

```javascript
count(number - 1);
```

---

اگر یکی از این دو بخش وجود نداشته باشد، Recursion درست کار نمی‌کند.

---

# اگر شرط توقف وجود نداشته باشد

```javascript
function hello() {

    hello();

}

hello();
```

خروجی:

```text
RangeError: Maximum call stack size exceeded
```

چون تابع هیچ‌وقت متوقف نمی‌شود.

---

# Call Stack چیست؟

هر بار که یک تابع اجرا می‌شود، JavaScript آن را داخل ساختاری به نام **Call Stack** قرار می‌دهد.

فرض کنید:

```javascript
function first() {
    second();
}

function second() {
    third();
}

function third() {
    console.log("Done");
}

first();
```

Call Stack تقریباً به شکل زیر است:

```text
third()
second()
first()
```

بعد از پایان هر تابع، از Stack خارج می‌شود.

---

در Recursion نیز دقیقاً همین اتفاق رخ می‌دهد.

هر بار تابع دوباره داخل Stack قرار می‌گیرد.

---

# Recursion مرحله به مرحله

مثال:

```javascript

    if (number === 0) {
        return;
    }

    console.log(number);

    countdown(number - 1);

}

countdown(3);
```

مراحل اجرا:

```text

↓

countdown(2)

↓

countdown(1)

↓

countdown(0)

↓

Stop
```

# مثال فاکتوریل

یکی از معروف‌ترین مثال‌های Recursion.

فرمول ریاضی:

```text
5! = 5 × 4 × 3 × 2 × 1
```

پیاده‌سازی:

```javascript
function factorial(number) {

    if (number === 1) {
        return 1;
    }

    return number * factorial(number - 1);

}

console.log(factorial(5));
```

خروجی:

```text
120
```

---

روند اجرا:

```text
5 × factorial(4)

↓

5 × 4 × factorial(3)

↓

5 × 4 × 3 × factorial(2)

↓

5 × 4 × 3 × 2 × factorial(1)

↓

5 × 4 × 3 × 2 × 1
```

# Loop یا Recursion؟

بسیاری از مسئله‌ها را می‌توان با هر دو روش حل کرد.

مثال:

Loop

```javascript
for (let i = 5; i >= 1; i--) {

    console.log(i);

}
```

Recursion

```javascript
function count(number) {

    if (number === 0) {
        return;
    }

    console.log(number);

    count(number - 1);

}

count(5);
```

هر دو خروجی یکسانی دارند.

---

# تفاوت Loop و Recursion

| Loop                  | Recursion                         |
| --------------------- | --------------------------------- |
| معمولاً سریع‌تر         | معمولاً خواناتر برای مسائل بازگشتی |
| حافظه کمتر            | حافظه بیشتر                       |
| بدون Call Stack اضافی | وابسته به Call Stack              |
| مناسب اکثر تکرارها    | مناسب مسائل درختی و بازگشتی       |

# مزایای Recursion

* کدهای کوتاه‌تر
* خوانایی بیشتر در مسائل خاص
* مناسب برای ساختارهای درختی
* مناسب الگوریتم‌های Divide & Conquer
* نزدیک‌تر به تعریف ریاضی بعضی مسائل

# معایب Recursion

* مصرف بیشتر حافظه
* کندتر از Loop در بسیاری از مسائل
* احتمال Stack Overflow
* سخت‌تر بودن دیباگ برای مبتدیان

# اشتباهات رایج

### ❌ فراموش کردن Base Case

بزرگ‌ترین اشتباه.

باعث Stack Overflow می‌شود.

---

### ❌ تغییر ندادن پارامتر

```javascript
function test(number) {

    if (number === 0) {
        return;
    }

    test(number);

}
```

هیچ‌وقت به شرط توقف نمی‌رسد.

---

### ❌ استفاده از Recursion برای همه مسائل

گاهی Loop بسیار ساده‌تر است.

---

### ❌ شرط توقف اشتباه

```javascript
if (number === 100)
```

در حالی که مقدار هرگز به 100 نمی‌رسد.

---

### ❌ Recursion روی داده‌های بسیار بزرگ

ممکن است باعث پر شدن Call Stack شود.

---

# نکات حرفه‌ای

* همیشه ابتدا Base Case را بنویسید.
* پارامتر را طوری تغییر دهید که به Base Case برسد.
* برای شمارش ساده معمولاً Loop بهتر است.
* برای ساختارهای درختی و بازگشتی، Recursion انتخاب مناسب‌تری است.
* قبل از نوشتن کد، روند اجرای Recursion را روی کاغذ رسم کنید.
* اگر Recursion بسیار عمیق است، استفاده از Loop یا ساختمان داده‌ی Stack را بررسی کنید.

# مینی‌پروژه

## نمایش ساختار پوشه‌ها (Directory Tree Viewer)

در این پروژه یک برنامه‌ی ساده می‌سازید که ساختار یک پوشه را به صورت درختی نمایش دهد.

در این فصل نیازی به خواندن فایل‌های واقعی ندارید؛ کافی است ساختار پوشه‌ها را با آرایه و آبجکت شبیه‌سازی کنید.

نمونه داده:

```javascript
const files = [
    {
        name: "src",
        children: [
            {
                name: "controllers",
                children: [
                    { name: "user.js" },
                    { name: "auth.js" }
                ]
            },
            {
                name: "routes",
                children: [
                    { name: "index.js" }
                ]
            }
        ]
    },
    {
        name: "package.json"
    }
];
```

### مراحل پروژه

1. پوشه‌ای با نام `directory-tree-viewer` ایجاد کنید.
2. فایل `index.js` را بسازید.
3. تابعی بازگشتی برای پیمایش ساختار بالا بنویسید.
4. عمق هر سطح را با فاصله یا کاراکترهایی مانند `│` و `├──` نمایش دهید.
5. اگر آیتم دارای `children` بود، دوباره همان تابع را برای فرزندان فراخوانی کنید.
6. خروجی را در ترمینال نمایش دهید.

نمونه خروجی:

```text
src
├── controllers
│   ├── user.js
│   └── auth.js
├── routes
│   └── index.js
package.json
```

### هدف پروژه

در پایان این مینی‌پروژه، درک خواهید کرد که چرا Recursion بهترین انتخاب برای پیمایش ساختارهای درختی است. همچنین با الگویی آشنا می‌شوید که در بسیاری از پروژه‌های واقعی Node.js مانند پیمایش سیستم فایل، ساخت منوهای تو در تو، پردازش JSONهای پیچیده، Template Engineها و ابزارهای خط فرمان مورد استفاده قرار می‌گیرد.
