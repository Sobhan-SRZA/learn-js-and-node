قبل از این فصل با مفاهیم بسیار مهمی مانند **Function**، **Scope** و **Lexical Scope** آشنا شدید.

اگر این فصل‌ها را به خوبی یاد گرفته باشید، اکنون تمام پیش‌نیازهای لازم برای یادگیری یکی از قدرتمندترین مفاهیم JavaScript را دارید.

مفهومی که بسیاری از قابلیت‌های مدرن JavaScript و حتی بخش بزرگی از Node.js بر پایه‌ی آن ساخته شده‌اند:

**Closure**

بسیاری از برنامه‌نویسان تازه‌کار در اولین برخورد با Closure تصور می‌کنند که موضوع بسیار پیچیده‌ای است، در حالی که Closure چیز جدیدی نیست.

در واقع Closure فقط نتیجه‌ی طبیعی کار کردن **Function** و **Lexical Scope** با یکدیگر است.

اگر Scope را درست فهمیده باشید، درک Closure بسیار ساده خواهد بود.

Closure در پروژه‌های واقعی Node.js تقریباً همه‌جا دیده می‌شود:

* Callbackها
* Event Listenerها
* Middlewareها
* Express
* Promiseها
* Async/Await
* Factory Functionها
* Module Pattern
* Cacheها
* Rate Limiterها
* Loggerها
* Sessionها
* Dependency Injection

در این فصل یاد می‌گیرید Closure چیست، چگونه ساخته می‌شود، چرا تا این اندازه مهم است و چگونه در پروژه‌های واقعی از آن استفاده کنید.

# فصل 20 - Closure

Closure یکی از مهم‌ترین مفاهیم JavaScript است.

اگر بخواهیم خیلی ساده آن را تعریف کنیم:

> Closure یعنی یک Function بتواند حتی بعد از پایان اجرای Function والد، همچنان به متغیرهای آن دسترسی داشته باشد.

در نگاه اول این موضوع عجیب به نظر می‌رسد.

چگونه ممکن است یک تابع تمام شده باشد اما متغیرهای آن هنوز وجود داشته باشند؟

پاسخ این سؤال همان Closure است.

---

# قبل از Closure

مثال ساده:

```javascript id="8d2ncp"
function greet() {

    const name = "Sobhan";

    console.log(name);

}

greet();
```

اینجا همه چیز طبیعی است.

متغیر `name` داخل تابع وجود دارد.

---

اما بعد از پایان تابع چه اتفاقی می‌افتد؟

```text id="df1pw5"
Function Finished
```

به طور معمول انتظار داریم تمام متغیرهای داخل تابع از حافظه حذف شوند.

در بیشتر مواقع همین اتفاق نیز رخ می‌دهد.

اما همیشه نه...

---

# اولین مثال Closure

```javascript id="6k8rtq"
function outer() {

    const name = "Sobhan";

    function inner() {

        console.log(name);

    }

    return inner;

}

const hello = outer();

hello();
```

خروجی:

```text id="3rmtg7"
Sobhan
```

---

سؤال مهم:

تابع `outer` تمام شده است.

پس چرا `inner` هنوز به متغیر `name` دسترسی دارد؟

پاسخ:

زیرا Closure ایجاد شده است.

---

# قدم به قدم بررسی کنیم

مرحله اول:

```javascript id="b9u4kw"
const hello = outer();
```

تابع `outer` اجرا می‌شود.

---

داخل آن:

```javascript id="jlwmn5"
const name = "Sobhan";
```

ساخته می‌شود.

---

سپس:

```javascript id="7t9mrc"
return inner;
```

تابع داخلی برگردانده می‌شود.

---

اکنون:

```javascript id="gjl0tb"
outer
```

تمام شده است.

اما چون تابع `inner` هنوز به `name` نیاز دارد، JavaScript آن را از حافظه حذف نمی‌کند.

---

وقتی:

```javascript id="z6nkqy"
hello();
```

را اجرا می‌کنیم:

```javascript id="xyv0am"
console.log(name);
```

هنوز مقدار وجود دارد.

این دقیقاً Closure است.

---

# تعریف دقیق‌تر

Closure ترکیبی از:

* Function
* Scope
* Lexical Environment

است.

هر Function هنگام ساخته شدن، Scope اطراف خود را نیز به خاطر می‌سپارد.

به همین دلیل حتی بعداً نیز به آن متغیرها دسترسی خواهد داشت.

---

# مثال شمارنده

یکی از معروف‌ترین مثال‌های Closure:

```javascript id="o6hf91"
function counter() {

    let count = 0;

    return function () {

        count++;

        return count;

    };

}
```

استفاده:

```javascript id="3b7vys"
const increment = counter();

console.log(increment());
console.log(increment());
console.log(increment());
```

خروجی:

```text id="xz7uwh"
1
2
3
```

---

چرا مقدار `count` هر بار صفر نمی‌شود؟

زیرا Closure آن را حفظ کرده است.

---

# ساخت چند شمارنده

```javascript id="h8dz9v"
const first = counter();

const second = counter();
```

حالا:

```javascript id="cyj9pr"
console.log(first());
console.log(first());

console.log(second());
console.log(second());
```

خروجی:

```text id="s0db1v"
1
2
1
2
```

هر Closure حافظه مستقل خودش را دارد.

# Closure و پارامترها

```javascript id="g4rjxm"
    return function (value) {

        return number * value;

    };

}
```

استفاده:


```text id="mrkrgx"

```

می‌توان چند نمونه ساخت.

```javascript id="m31w0t"

console.log(triple(5));
```

خروجی:

```text id="rshc2x"

15
```

# خصوصی‌سازی داده‌ها

یکی از کاربردهای مهم Closure ایجاد داده‌های خصوصی است.

```javascript id="l4g2wd"
function bankAccount() {

    let balance = 0;

    return {

        deposit(amount) {

            balance += amount;

        },

        getBalance() {

        }

    };

}
```

استفاده:

```javascript id="9zkvgh"

console.log(account.getBalance());
```

خروجی:

```text id="8u0s4r"
100
```

اما:

```javascript id="epm0sw"
console.log(account.balance);
```

خروجی:

```text id="jlwm1h"
undefined
```

زیرا `balance` خصوصی است.

# آیا Closure باعث نشت حافظه می‌شود؟

به خودی خود خیر.

اما اگر Closure به داده‌های بسیار بزرگ اشاره کند و دیگر به آن نیاز نداشته باشیم، ممکن است Garbage Collector نتواند آن داده‌ها را آزاد کند.

مثال:

```javascript id="6e2vzw"
function createData() {

    const hugeArray = new Array(1000000).fill(0);

    return function () {

        return hugeArray.length;

    };

}
```

تا زمانی که Closure وجود دارد، `hugeArray` نیز در حافظه باقی می‌ماند.

# اشتباهات رایج

### ❌ تصور اینکه Closure فقط در توابع تو در تو وجود دارد

Closure نتیجه‌ی دسترسی تابع به Scope اطرافش است و در بسیاری از الگوهای برنامه‌نویسی دیده می‌شود.

---

### ❌ استفاده از Closure برای نگهداری داده‌های بسیار بزرگ

ممکن است حافظه بی‌دلیل اشغال شود.

---

### ❌ استفاده از متغیرهای Global به جای Closure

در بسیاری از موارد Closure جایگزین بهتری برای متغیرهای Global است.

---

### ❌ فراموش کردن اینکه هر بار اجرای Function یک Closure جدید می‌سازد

```javascript id="5d9wnq"
const a = counter();

const b = counter();
```

این دو کاملاً مستقل هستند.

---

### ❌ پیچیده کردن بیش از حد کد

Closure ابزار قدرتمندی است، اما همیشه ساده‌ترین راه‌حل را انتخاب کنید.

# نکات حرفه‌ای

* از Closure برای مخفی کردن داده‌های داخلی استفاده کنید.
* هر Function را تا حد امکان کوچک و خوانا نگه دارید.
* برای ساخت Factory Functionها از Closure استفاده کنید.
* در پروژه‌های Node.js، Closure یکی از بهترین روش‌ها برای نگهداری تنظیمات و State است.
* اگر Closure داده‌های بزرگی را نگه می‌دارد، پس از پایان کار مرجع آن را آزاد کنید تا Garbage Collector بتواند حافظه را بازیابی کند.

# مینی‌پروژه

## سیستم مدیریت شمارنده (Counter Manager)

در این پروژه یک ابزار خط فرمان می‌سازید که با استفاده از Closure چند شمارنده مستقل را مدیریت می‌کند.

### مراحل پروژه

1. پوشه‌ای با نام `counter-manager` ایجاد کنید.
2. فایل `index.js` را بسازید.
3. تابع `createCounter()` را پیاده‌سازی کنید.
4. داخل آن متغیر خصوصی `count` ایجاد کنید.
5. متدهای زیر را برگردانید:

   * `increment()`
   * `decrement()`
   * `reset()`
   * `value()`
6. دو شمارنده مستقل ایجاد کنید.
7. بررسی کنید که عملیات روی یکی از شمارنده‌ها روی دیگری تأثیری نداشته باشد.
8. خروجی هر عملیات را در ترمینال نمایش دهید.

نمونه خروجی:

```text id="9ptq1h"
==============================
Counter A

Value: 0
Increment
Value: 1
Increment
Value: 2

==============================

Counter B

Value: 0
Increment
Value: 1

==============================
```

### هدف پروژه

در پایان این مینی‌پروژه، به‌صورت عملی درک خواهید کرد که Closure چگونه وضعیت (State) را بین فراخوانی‌های مختلف حفظ می‌کند، چگونه می‌توان داده‌های خصوصی ایجاد کرد و چرا این الگو در توسعه‌ی پروژه‌های حرفه‌ای Node.js برای ساخت ماژول‌ها، سرویس‌ها، Cacheها، Loggerها، Sessionها و بسیاری از ابزارهای دیگر کاربرد گسترده‌ای دارد.

> **نکته مهم:** بسیاری از قابلیت‌هایی که در فصل‌های آینده یاد می‌گیرید، مانند **Moduleها، Promiseها، Middlewareها، Eventها و حتی بعضی از الگوهای طراحی (Design Patterns)**، به‌صورت مستقیم یا غیرمستقیم بر پایه‌ی **Closure** کار می‌کنند. اگر این فصل را به‌خوبی درک کنید، فهم بخش بزرگی از معماری داخلی JavaScript و Node.js برایتان بسیار ساده‌تر خواهد شد.
