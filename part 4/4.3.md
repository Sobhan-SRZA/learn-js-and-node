قبل از این فصل یاد گرفتید که متغیرها، Scope و Functionها چگونه کار می‌کنند.

اما احتمالاً با کدهایی روبه‌رو شده‌اید که در نگاه اول عجیب به نظر می‌رسند.

مثلاً:

```javascript
sayHello();

function sayHello() {
    console.log("Hello");
}
```

این کد بدون هیچ مشکلی اجرا می‌شود.

اما اگر همین کار را با یک متغیر یا Arrow Function انجام دهیم:

```javascript
console.log(name);

const name = "Sobhan";
```

برنامه با خطا مواجه می‌شود.

چرا؟

آیا JavaScript کدها را از بالا به پایین اجرا نمی‌کند؟

پاسخ این سؤال در مفهومی به نام **Hoisting** قرار دارد.

Hoisting یکی از مفاهیمی است که بسیاری از برنامه‌نویسان تازه‌کار آن را اشتباه متوجه می‌شوند. حتی بعضی از برنامه‌نویسان با تجربه نیز تصور نادرستی از آن دارند.

در این فصل یاد می‌گیرید که JavaScript قبل از اجرای کد چه کارهایی انجام می‌دهد، چرا بعضی متغیرها قابل استفاده هستند و بعضی دیگر خطا ایجاد می‌کنند، تفاوت `var`، `let`، `const` و Functionها در Hoisting چیست و چگونه از بروز خطاهای رایج جلوگیری کنید.

---

# فصل 19 - Hoisting

Hoisting یکی از رفتارهای داخلی موتور JavaScript است.

برای درک بهتر Hoisting ابتدا باید بدانیم که JavaScript کدها را مستقیماً از اولین خط اجرا نمی‌کند.

قبل از شروع اجرای برنامه، موتور JavaScript یک مرحله آماده‌سازی انجام می‌دهد.

در این مرحله:

* متغیرها شناسایی می‌شوند.
* Functionها شناسایی می‌شوند.
* Scopeها ساخته می‌شوند.
* حافظه اولیه برای بعضی از متغیرها اختصاص داده می‌شود.

به این فرآیند، **Hoisting** گفته می‌شود.

---

# Hoisting چیست؟

کلمه Hoisting به معنی:

> بالا کشیدن

است.

اما این نام کمی گمراه‌کننده است.

در واقع JavaScript کدها را جابه‌جا نمی‌کند.

بلکه قبل از اجرای برنامه، اعلان‌ها (Declarations) را پردازش می‌کند.

به همین دلیل بهتر است Hoisting را اینگونه تعریف کنیم:

> Hoisting فرآیندی است که در آن JavaScript قبل از اجرای کد، اعلان متغیرها و Functionها را پردازش می‌کند.

---

# مراحل اجرای JavaScript

به صورت ساده JavaScript دو مرحله دارد.

مرحله اول:

```text
Parsing
```

یا آماده‌سازی برنامه.

در این مرحله:

* Scopeها ساخته می‌شوند.
* متغیرها ثبت می‌شوند.
* Functionها ثبت می‌شوند.

---

مرحله دوم:

```text
Execution
```

اجرای واقعی کد.

در این مرحله:

* دستورات اجرا می‌شوند.
* مقدارها به متغیرها اختصاص داده می‌شوند.
* Functionها فراخوانی می‌شوند.

---

# Hoisting در Function Declaration

تابع‌های Declaration به طور کامل Hoist می‌شوند.

مثال:

```javascript
sayHello();

function sayHello() {

    console.log("Hello");

}
```

خروجی:

```text
Hello
```

اگرچه تابع پایین‌تر نوشته شده است، اما JavaScript قبل از اجرای برنامه آن را می‌شناسد.

---

تقریباً می‌توان تصور کرد که موتور JavaScript چنین چیزی می‌بیند:

```javascript
function sayHello() {

    console.log("Hello");

}

sayHello();
```

البته این فقط یک مدل ذهنی است و دقیقاً اتفاقی نیست که داخل موتور JavaScript رخ می‌دهد.

---

# Hoisting در Function Expression

```javascript
sayHello();

const sayHello = function () {

    console.log("Hello");

};
```

خروجی:

```text
ReferenceError
```

چرا؟

زیرا فقط متغیر `sayHello` ثبت شده است اما هنوز مقدار Function به آن اختصاص داده نشده است.

---

همین موضوع درباره Arrow Function نیز صدق می‌کند.

```javascript
sum(10, 20);

const sum = (a, b) => {

    return a + b;

};
```

خروجی:

```text
ReferenceError
```

---

# Hoisting و var

متغیرهای `var` Hoist می‌شوند.

مثال:

```javascript
console.log(score);

var score = 100;
```

خروجی:

```text
undefined
```

چرا؟

زیرا در مرحله آماده‌سازی، متغیر ساخته می‌شود اما مقدار اولیه ندارد.

تقریباً مانند:

```javascript
var score;

console.log(score);

score = 100;
```

---

نکته مهم:

این فقط یک مدل ذهنی برای درک Hoisting است.

---

# Hoisting و let

```javascript
console.log(score);

let score = 100;
```

خروجی:

```text
ReferenceError
```

در نگاه اول ممکن است فکر کنید `let` Hoist نمی‌شود.

اما این تصور اشتباه است.

---

# آیا let و const Hoist می‌شوند؟

بله.

هر دو Hoist می‌شوند.

اما تفاوت مهمی با `var` دارند.

متغیر ثبت می‌شود اما تا زمانی که به خط تعریف آن نرسیم، قابل استفاده نیست.

به این بازه زمانی:

```text
Temporal Dead Zone
```

یا به اختصار:

```text
TDZ
```

گفته می‌شود.

---

# Temporal Dead Zone (TDZ)

TDZ یکی از مهم‌ترین مفاهیم JavaScript است.

فرض کنید:

```javascript
console.log(age);

let age = 20;
```

بین ابتدای Scope تا خط تعریف متغیر، برنامه در TDZ قرار دارد.

هرگونه دسترسی به متغیر در این ناحیه باعث:

```text
ReferenceError
```

می‌شود.

---

همین موضوع برای `const` نیز وجود دارد.

```javascript
console.log(name);

const name = "Sobhan";
```

خروجی:

```text
ReferenceError
```

---

# مقایسه var و let

```javascript
console.log(number);

var number = 10;
```

خروجی:

```text
undefined
```

---

```javascript
console.log(number);

let number = 10;
```

خروجی:

```text
ReferenceError
```

---

```javascript
console.log(number);

const number = 10;
```

خروجی:

```text
ReferenceError
```

---

# چرا var خطرناک است؟

فرض کنید:

```javascript
if (user) {

    var message = "Login";

}

console.log(message);
```

اگر شرط اجرا نشود:

```text
undefined
```

برمی‌گردد.

اما با `let`:

```javascript
if (user) {

    let message = "Login";

}

console.log(message);
```

برنامه بلافاصله خطا می‌دهد.

این رفتار باعث می‌شود باگ‌ها زودتر پیدا شوند.

به همین دلیل امروزه استفاده از `let` و `const` توصیه می‌شود.

---

# Hoisting در Scope

```javascript
function test() {

    console.log(name);

    let name = "Node";

}

test();
```

خروجی:

```text

```

TDZ فقط در Global نیست.

هر Scope مستقل TDZ مخصوص خود را دارد.

# Hoisting و Block Scope

```

خروجی:

```

# Hoisting و const

```javascript
const age = 20;
```

پس از رسیدن برنامه به این خط، مقداردهی انجام می‌شود.

قبل از آن:

```text
TDZ
```

وجود دارد.

---

# Hoisting در عمل

کد زیر:

```javascript
var a = 1;

function test() {

    console.log(a);

    var a = 5;

}

test();
```

خروجی:

```text
undefined
```

چرا؟

زیرا Scope تابع ابتدا این‌گونه آماده می‌شود:

```javascript
function test() {

    var a;

    console.log(a);

    a = 5;

}
```

---

اما اگر:

```javascript
let a = 1;

function test() {

    console.log(a);

    let a = 5;

}

test();
```

خروجی:

```text
ReferenceError
```

---

# آیا باید روی Hoisting حساب کنیم؟

خیر.

اگرچه شناخت Hoisting ضروری است، اما نباید کدی بنویسید که به آن وابسته باشد.

بهترین روش این است که:

* ابتدا متغیرها را تعریف کنید.
* سپس از آن‌ها استفاده کنید.

---

# بهترین روش

به جای این:

```javascript
print();

function print() {

    console.log("Hello");

}
```

اگرچه این کد درست است، اما بسیاری از تیم‌ها ترجیح می‌دهند:

```javascript
function print() {

    console.log("Hello");

}

print();
```

زیرا خوانایی بیشتری دارد.

# کاربرد Hoisting در Node.js

در پروژه‌های واقعی Node.js دانستن Hoisting اهمیت زیادی دارد.

به ویژه در:

* Moduleها
* Functionها
* Callbackها
* Express
* Middlewareها
* تست‌نویسی
* Dependency Injection
* کلاس‌ها

شناخت Hoisting باعث می‌شود رفتار برنامه را بهتر پیش‌بینی کنید.

---

### ❌ تصور اینکه let و const Hoist نمی‌شوند

آن‌ها نیز Hoist می‌شوند اما در TDZ قرار دارند.

---

### ❌ استفاده از متغیر قبل از تعریف

حتی اگر برنامه اجرا شود، این کار خوانایی کد را کاهش می‌دهد.

---

### ❌ وابسته شدن به Hoisting

کدهایی که به Hoisting وابسته هستند، نگهداری سخت‌تری دارند.

---

### ❌ استفاده از var

در پروژه‌های جدید تقریباً هیچ دلیلی برای استفاده از `var` وجود ندارد.

# نکات حرفه‌ای

* همیشه ابتدا متغیرها را تعریف کنید و سپس از آن‌ها استفاده کنید.
* از `const` به عنوان انتخاب اول استفاده کنید.
* در صورت نیاز به تغییر مقدار، از `let` استفاده کنید.
* از `var` در پروژه‌های مدرن استفاده نکنید.
* Functionها را نیز قبل از استفاده تعریف کنید تا خوانایی کد بیشتر شود.
* اگر با `ReferenceError` مواجه شدید، یکی از اولین مواردی که بررسی می‌کنید باید TDZ باشد.

# مینی‌پروژه

## آزمایشگاه Hoisting (Hoisting Playground)

در این پروژه یک برنامه آموزشی می‌سازید که رفتار Hoisting را به‌صورت عملی نمایش می‌دهد.

### مراحل پروژه

1. پوشه‌ای با نام `hoisting-playground` ایجاد کنید.
2. فایل `index.js` را بسازید.
3. چند مثال برای `var`، `let` و `const` بنویسید و خروجی هر کدام را مشاهده کنید.
4. یک `Function Declaration` ایجاد کرده و آن را قبل و بعد از تعریف فراخوانی کنید.
5. همین آزمایش را برای `Function Expression` و `Arrow Function` انجام دهید.
6. یک مثال از `Temporal Dead Zone` داخل یک تابع ایجاد کنید.
7. نتایج هر آزمایش را با استفاده از `console.log` و توضیحات مناسب نمایش دهید.

نمونه خروجی:

```text
==============================
Hoisting Playground

Example 1: var
Output: undefined

Example 2: let
Output: ReferenceError

Example 3: const
Output: ReferenceError

Example 4: Function Declaration
Output: Hello

Example 5: Arrow Function
Output: ReferenceError

==============================
```

### هدف پروژه

در پایان این مینی‌پروژه، درک دقیقی از فرآیند Hoisting، تفاوت رفتار `var`، `let`، `const`، `Function Declaration`، `Function Expression` و `Arrow Function` خواهید داشت. همچنین مفهوم **Temporal Dead Zone (TDZ)** را به‌صورت عملی تجربه می‌کنید و یاد می‌گیرید چرا در پروژه‌های حرفه‌ای Node.js بهتر است همیشه متغیرها و توابع را قبل از استفاده تعریف کنید.

> **نکته مهم:** Hoisting موضوعی نیست که هر روز مستقیماً از آن استفاده کنید، اما درک صحیح آن باعث می‌شود بسیاری از رفتارهای ظاهراً عجیب JavaScript برایتان کاملاً منطقی شوند. از این فصل به بعد، هر زمان با `ReferenceError` یا رفتار غیرمنتظره‌ی متغیرها روبه‌رو شدید، ابتدا Scope، Hoisting و **TDZ** را بررسی کنید.
