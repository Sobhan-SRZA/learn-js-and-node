# بخش اول — آشنایی با Node.js

# فصل ۲ — نصب محیط توسعه

---

# مقدمه

قبل از اینکه اولین پروژه Node.js خود را بنویسیم، باید محیط توسعه (Development Environment) را آماده کنیم.

یک محیط توسعه مناسب باعث می‌شود بتوانید:

* پروژه‌های خود را اجرا کنید.
* پکیج‌های موردنیاز را نصب کنید.
* پروژه‌ها را دیباگ (Debug) کنید.
* از ابزارهای حرفه‌ای توسعه استفاده کنید.
* بدون مشکل پروژه‌های دیگران را اجرا کنید.

در این فصل تمام ابزارهای ضروری را نصب می‌کنیم و با نقش هر کدام آشنا می‌شویم.

> **نکته:** در این آموزش از آخرین نسخه پایدار (LTS) ابزارها استفاده می‌کنیم، زیرا برای پروژه‌های واقعی و Production مناسب‌تر هستند.

---

# ابزارهای مورد نیاز

برای شروع توسعه با Node.js به ابزارهای زیر نیاز داریم:

| ابزار    | کاربرد                        |
| -------- | ----------------------------- |
| Node.js  | اجرای برنامه‌های JavaScript    |
| npm      | مدیریت Packageها              |
| VS Code  | ویرایشگر کد                   |
| Terminal | اجرای دستورات                 |
| Git      | مدیریت نسخه پروژه             |
| GitHub   | نگهداری و اشتراک‌گذاری پروژه‌ها |

در ادامه هر کدام را بررسی می‌کنیم.

---

# Node.js

Node.js مهم‌ترین ابزار این آموزش است.

پس از نصب Node.js، امکانات زیر در اختیار شما قرار می‌گیرد:

* اجرای فایل‌های JavaScript
* npm
* npx
* دسترسی به ماژول‌های داخلی Node.js
* امکان اجرای پروژه‌های Backend

---

# انتخاب نسخه مناسب Node.js

در صفحه دانلود Node.js معمولاً دو نسخه مشاهده می‌کنید:

## LTS (Long Term Support)

ویژگی‌ها:

* پایدار
* تست‌شده
* مناسب پروژه‌های واقعی
* مناسب شرکت‌ها
* پشتیبانی طولانی‌مدت

**پیشنهاد این آموزش: استفاده از نسخه LTS**

---

## Current

ویژگی‌ها:

* جدیدترین قابلیت‌ها
* مناسب تست ویژگی‌های تازه
* احتمال تغییرات بیشتر
* مناسب توسعه‌دهندگان علاقه‌مند به نسخه‌های جدید

اگر تازه‌کار هستید، از نسخه **LTS** استفاده کنید.

---

# نصب Node.js

به وب‌سایت رسمی Node.js مراجعه کنید و نسخه LTS متناسب با سیستم‌عامل خود را دانلود و نصب کنید.

در بیشتر سیستم‌ها نصب به سادگی چند بار فشردن دکمه **Next** انجام می‌شود و نیازی به تغییر تنظیمات پیش‌فرض نیست.

پس از پایان نصب، ترمینال را یک‌بار ببندید و دوباره باز کنید.

---

# بررسی نصب Node.js

برای اطمینان از نصب صحیح، دستور زیر را اجرا کنید:

```bash
node -v
```

نمونه خروجی:

```text
v22.18.0
```

عدد نسخه ممکن است در زمان مطالعه این آموزش متفاوت باشد و این کاملاً طبیعی است.

---

# بررسی npm

پس از نصب Node.js، ابزار **npm** نیز به‌صورت خودکار نصب می‌شود.

برای مشاهده نسخه npm:

```bash
npm -v
```

نمونه خروجی:

```text
10.9.3
```

---

# npm چیست؟

npm مخفف **Node Package Manager** است.

وظایف اصلی npm:

* نصب کتابخانه‌ها
* حذف کتابخانه‌ها
* بروزرسانی Packageها
* اجرای Scriptهای پروژه
* انتشار Package در npm Registry

تقریباً تمام پروژه‌های Node.js از npm استفاده می‌کنند.

در فصل‌های بعدی به‌صورت کامل با npm آشنا خواهیم شد.

---

# npx چیست؟

همراه npm ابزاری به نام **npx** نیز نصب می‌شود.

npx اجازه می‌دهد برنامه‌ها را بدون نصب دائمی اجرا کنید.

مثال:

```bash
npx create-vite@latest
```

یا

```bash
npx eslint .
```

این ابزار برای اجرای ابزارهای موقت بسیار کاربردی است.

---

# Corepack

نسخه‌های جدید Node.js ابزار **Corepack** را نیز ارائه می‌دهند.

Corepack مدیریت Package Managerهایی مانند:

* pnpm
* Yarn

را ساده‌تر می‌کند.

در بسیاری از پروژه‌های جدید، فعال بودن Corepack توصیه می‌شود.

---

# pnpm

pnpm یک Package Manager مدرن برای Node.js است.

مزایای آن:

* نصب سریع‌تر
* مصرف فضای کمتر
* مدیریت بهتر وابستگی‌ها
* عملکرد مناسب در پروژه‌های بزرگ

اگرچه در این آموزش بیشتر از npm استفاده می‌کنیم، آشنایی با pnpm برای آینده مفید خواهد بود.

---

# Yarn

Yarn نیز یک Package Manager محبوب است که توسط Meta معرفی شد.

ویژگی‌ها:

* سرعت مناسب
* مدیریت Cache
* قابلیت Workspaces
* مناسب پروژه‌های Monorepo

امروزه انتخاب بین npm، pnpm و Yarn بیشتر به نیاز پروژه یا تیم بستگی دارد.

---

# Visual Studio Code

برای نوشتن کدها از **Visual Studio Code (VS Code)** استفاده می‌کنیم.

چرا VS Code؟

* رایگان
* سبک
* افزونه‌های فراوان
* پشتیبانی عالی از Node.js
* دیباگر داخلی
* ترمینال داخلی
* تکمیل خودکار هوشمند

---

# افزونه‌های پیشنهادی VS Code

برای شروع، نصب افزونه‌های زیر پیشنهاد می‌شود:

| افزونه            | کاربرد                      |
| ----------------- | --------------------------- |
| ESLint            | بررسی خطاهای کد             |
| Prettier          | قالب‌بندی خودکار             |
| Error Lens        | نمایش خطاها داخل کد         |
| GitLens           | امکانات پیشرفته Git         |
| EditorConfig      | هماهنگ‌سازی تنظیمات ویرایشگر |
| npm IntelliSense  | تکمیل خودکار نام Packageها  |
| Path IntelliSense | تکمیل مسیر فایل‌ها           |
| Docker            | کار با Docker (در آینده)    |

> در ادامه آموزش، هر زمان افزونه‌ای لازم باشد آن را معرفی خواهیم کرد.

---

# ترمینال (Terminal)

تقریباً تمام پروژه‌های Node.js از طریق ترمینال مدیریت می‌شوند.

نمونه دستور:

```bash
node index.js
```

نمونه دیگر:

```bash
npm install
```

بنابراین یادگیری کار با ترمینال یکی از مهارت‌های مهم توسعه‌دهندگان Node.js است.

---

# ترمینال VS Code

یکی از امکانات بسیار مفید VS Code، ترمینال داخلی آن است.

برای باز کردن ترمینال:

* **Windows / Linux:** `Ctrl + ``
* **macOS:** `⌃ + ``

یا از منوی:

```text
Terminal → New Terminal
```

استفاده کنید.

مزیت ترمینال داخلی این است که دیگر نیازی به جابه‌جایی بین پنجره‌ها نخواهید داشت.

---

# Git

اگرچه Git مستقیماً بخشی از Node.js نیست، اما تقریباً تمام پروژه‌های حرفه‌ای از آن استفاده می‌کنند.

کاربردهای Git:

* ذخیره تاریخچه تغییرات
* همکاری تیمی
* بازگشت به نسخه‌های قبلی
* مدیریت شاخه‌ها (Branch)

در ادامه آموزش فرض می‌کنیم Git روی سیستم شما نصب است.

---

# GitHub

GitHub محلی برای نگهداری و اشتراک‌گذاری پروژه‌ها است.

مزایای استفاده از GitHub:

* پشتیبان‌گیری از پروژه‌ها
* همکاری تیمی
* انتشار پروژه‌های متن‌باز
* ساخت رزومه برای بازار کار

اگر قصد فعالیت حرفه‌ای دارید، داشتن یک حساب GitHub تقریباً ضروری است.

---

# بررسی کامل نصب

پس از نصب ابزارها، دستورات زیر را اجرا کنید:

```bash
node -v
```

```bash
npm -v
```

```bash
git --version
```

اگر هر سه دستور نسخه‌ای را نمایش دادند، محیط توسعه شما آماده است.

---

# ساخت اولین پوشه پروژه

یک پوشه جدید ایجاد کنید:

```text
learn-node
```

و وارد آن شوید:

```bash
cd learn-node
```

در فصل بعد اولین پروژه Node.js خود را داخل این پوشه ایجاد خواهیم کرد.

---

# اشتباهات رایج

❌ نصب نسخه Current به جای LTS بدون دلیل مشخص

❌ نصب چند نسخه مختلف Node.js بدون مدیریت نسخه

❌ فراموش کردن بررسی نسخه پس از نصب

❌ استفاده از Command Prompt قدیمی به جای Windows Terminal یا ترمینال VS Code (در صورت امکان)

❌ حذف تصادفی مسیر (PATH) هنگام نصب Node.js

---

# نکات حرفه‌ای

* همیشه از نسخه **LTS** برای پروژه‌های Production استفاده کنید.
* نسخه Node.js هر پروژه را در فایل `package.json` یا مستندات آن بررسی کنید.
* از به‌روزرسانی‌های ناگهانی نسخه اصلی (Major Version) در پروژه‌های در حال توسعه خودداری کنید، مگر اینکه سازگاری آن را بررسی کرده باشید.
* یادگیری کار با ترمینال از همان ابتدا، سرعت توسعه شما را به‌طور چشمگیری افزایش می‌دهد.

# پروژه کوچک

## پروژه: آماده‌سازی محیط توسعه

### هدف

اطمینان از نصب صحیح ابزارهای موردنیاز و آماده‌سازی فضای کاری.

### مراحل

1. نصب Node.js (نسخه LTS)
2. نصب Git
3. نصب Visual Studio Code
4. ایجاد پوشه‌ای به نام `learn-node`
5. باز کردن پوشه در VS Code
6. اجرای دستورات زیر در ترمینال:

```bash
node -v
npm -v
git --version
```

### چالش

یک فایل متنی به نام `environment-info.txt` ایجاد کنید و نسخه‌های نصب‌شده Node.js، npm و Git را در آن ثبت کنید. این کار در پروژه‌های تیمی برای مستندسازی محیط توسعه بسیار مفید است.
